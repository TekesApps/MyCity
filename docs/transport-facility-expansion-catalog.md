# 交通设施扩展目录 T52：公交、轨道、水运、机场与停车楼

设计补充v0.5.1，2026-10-19。按玩家新增需求补齐设施谱系和必须配套的运营依赖；只改文档，不写实现。本篇细化既有CAT-T-04至09，**不新增一级CAT、不改变90类总数，也不把这些B类候选自动加入现有23类首版可执行范围**。v0.5.0基线是有范围的首期设计，不能解读成所有交通方式已经设计到可运行。

“百度的码头”按摆渡／轮渡码头归档；若用户后续指其他类型再按实际用途修订。火车可采用电力牵引，但“电车”若指路面有轨电车，不能直接用普通铁路站换外观替代：共用轨道／车站抽象，街道混行、路口优先、站台形式与车辆兼容规则须分别有profile。纯观光摆设不能声称有运输能力。

## 1. 完整设施谱系

| 现有CAT | 必须明确的设施／规格 | 设施之外还缺的机制 |
| --- | --- | --- |
| T-04 停车 | 地面停车场、**坡道式多层停车楼**、地下车库；可作为独立经营建筑，不只住宅附属车位 | 真实车辆／保管位置、车位占用与进出、停留／取车、收费、步行接驳与停车换乘；楼层／坡道是几何与设备变体 |
| T-04 机械／充电分支 | 升降／机械立体停车、带充电车位 | 机械停车另需升降设备／取车队列／电力与故障救援；充电另需电量／SOC／充电功率及收费，不随普通停车楼免费开启 |
| T-05 公交 | 路边站、港湾站、首末站／换乘总站、停保场／维修车库 | 线路／方向、停站表／时窗、实际车队及班次、候车／上下客／满载、车辆与道路共用容量、运营核算；车库不自发提供客运线路 |
| T-06 街道有轨电车 | 路面站／岛式站、终点回车设施、停车检修场；独立路权和混行规格 | 轨道兼容、与道路交叉／混行冲突、转向／折返、牵引供能与调度；不能同时按独立铁路和普通道路获得两份容量 |
| T-06 城市轨道 | 地铁／高架站、出入口／站厅／站台、换乘站、车辆段 | 结构层位／安全疏散、步行换层及站台容量、区间与折返、班次；地下空间本身不代表已实现地铁／隧道 |
| T-06 普通客运铁路 | 小型停靠站、城市客运站、大型枢纽、尽头／通过式站、检修设施 | 可行轨道／进路／站台占用、列车编组及兼容、到发／换乘、跨图班次与真实外部站；铁路电气化是牵引路线，不自动变成有轨电车 |
| T-07 货运铁路 | 货运站／货场、仓储装卸站、集装箱联运站、编组／调车设施 | 货车—场站—列车—目的场站—货车各段保管／装卸、到发／编组／存车、运价；客站不能只改用途标签就接危险／散装货 |
| T-09 客运水运 | 摆渡／轮渡码头、两岸渡口、城市水上公交站、客运码头／客运站 | 两端泊位、船舶／班次、航道／航行时间、上下客、步行接驳；允许车辆上船的车客渡另有车道／装船及质量容量 |
| T-09 货运港口 | 小型货运码头、一般件杂货港、集装箱码头／大型港区；专用散货／液货为独立相容分支 | 水深／吃水／泊位适配、装卸设备／堆场／仓库、船期、陆路接驳及货物相容；集装箱规格不是把所有货物无成本装成同一箱 |
| T-08 机场 | **小／中／大三档**，各有跑道／滑行道／机坪／航站楼／货站与地面接入的具体组合 | 航空器兼容、航班／旅客／货运、空域／噪声、地面服务、维修与公司核算；规模档不能代替真实瓶颈与手续 |

铁路客货可共用实际兼容轨道，但争用同一进路／区间／站场能力；兼容与调度未定义时不允许共线，不能各按满负荷独立计算。公交、铁路、航空、水运、停车场的运营公司可以不同，市政府可投资或依法采购服务，沿已有市场主体／实缴股权／分红和财政规则，不能自动合并钱包。

## 2. 机场的三档是组合规格，不是三个万能等级

| 规模候选 | 服务定位 | 必须确定的实物及经营边界 |
| --- | --- | --- |
| 小型机场 AP-S | 小规模区域客运／通勤，也可配置独立通用航空用途 | 有限机型／跑道与时段、有限机位／旅客或货运模块、安保／地面服务、道路接驳；不因“小型”免基础维护／噪声或无限跑道利用 |
| 中型机场 AP-M | 城市区域客运、多条线路，可选有真实货站的货运 | 更大航站楼／机位／滑行与接驳，客货模块分开配置和计量；不承诺需求自然填满，不凭航站楼面积提升跑道能力 |
| 大型机场 AP-L | 区域枢纽／中转，多跑道或更复杂站坪的候选组合 | 跑道间相关冲突、转机路径／时间／行李或货物流程、联运与边界容量、噪声走廊、分期建设及长期支出；不能把多跑道能力直接相加 |

S/M/L是同一类设施在相容机制下的规格族。通用航空、客运、货运、枢纽中转是用途／流程维度，不等同于大小；国际边检等新制度需求另列依赖，不默认随大型档解锁。本阶段不填未经联合配置的跑道米数／班次／容量或仿真现实机场定额；执行profile必须在补足几何、机型、资源与预算后固定这些值。

机场公司负责资产、机位／航站／地面服务和收费；航空公司负责飞机／航班、机组、燃油或实际牵引能源、维修、空座风险和票价收入。旅游、商务、工业活动相关出行从既有真实人群／交易或明确外部需求源派生，不能按“每座机场自动产生若干游客”发收入。相同旅客在到达／转机／离港统计中的阶段口径须标明，不把转机两段算成两次新增居民消费。

## 3. 独立停车楼的最小契约

停车楼是一栋可选中、可改造／拆除、具有产权和独立运营主体的真实建筑。需要的字段按通用组件扩展，不先给每个车位新建常驻实体：

- 空间：site／楼体／楼层、合法车行入口／出口、坡道与净空、人行门／无障碍及疏散、与道路／步行网连接；入口服务率、坡道／冲突组及合法等待空间可先于空位数成为瓶颈。
- 存放：可用／关闭／已预留／实际占用车位、真实车或有权保管凭据、到达／离开、当前所在及预定取车位置。按同条件车位池聚合，但不能抹掉谁停了哪辆车、取车权和未付费用；不逐车位每帧扫描。
- 经营：投资／建设日历、照明／通风／电梯等聚合设备包、水电、消防／保洁／维护、收费单位及宽限／封顶规则，实际停留来源累计计费，不靠跨日／重复进出舍入套利。
- 交通：驾驶到场→入口等候／停车→步行到楼门／换乘站；返程必须回可取车地点。已满、未建成或关闭时不吸入更多车，显示寻找合法替代／放弃与交通后果，不免费在路边消失。
- 权益与退出：保管责任、破损／故障、经营者欠费、取车与临时通道、拆除前通知／清空和未结账。取消许可证／停车楼拆除不删除存车或债务；不能因车主欠费而无条件终身锁人／锁车。

先补普通坡道停车楼，不把“立体”限定成机械升降库。地下停车另依地下结构／排水／疏散，机械停车另依设备及救援，充电另依SOC；这些都是明确的扩展门。居民停车、访客停车、货车装卸／候装、公交停保、站前即停即走是不同使用权与占用规则，不共用一个数字反复出售。

## 4. 车站／码头／港口的共同模型

共用Root＋空间／权利／端口／共享瓶颈／资产成本维护／环境／经营主体；在此之上组合**站场、线路、运输服务、运营企业、实际需求**，不能把五者缩成一座站房。

| 对象 | 最小持久事实与约束 |
| --- | --- |
| 站场／停靠点 | 地理位置／层位、可进模式、站台／泊位／登乘组、步行门／货门、换乘路径、停靠／装卸／安全占用；共享站厅／停车只一份容量 |
| 线路／路由 | 实际方向、合法道路／轨道／航道／空域连接、停站序、服务窗及不可达状态；外部端须有有限对手站与返程 |
| 班次／运输服务 | 可用车船机／列车、资格人员、出发／到达／停留、载客／货容量、供能／维护、取消／晚点；车站建成不自动生成班次 |
| 旅客链 | 来源家庭／外部有限群体、目的／时间、步行—候车—上客—车内—换乘—到达；同一批次的实际人数不在每段复制，不能忽略候车／末班／满载 |
| 货物链 | 商品及相容性、原所有者／现保管者／承运、批次及成本、装卸／存储／分段运输、交接验收与付款；同一货物不能公路与铁路各交付一次 |
| 企业链 | 设施业主／运营者、运输企业、外包及采购方分别有合同／钱账；运费、票款、接驳／站费、补贴、成本和分红不重复入账 |

站内商铺、政务办公与其他用途可以引用已有共享空间／受限复合定义方向，但不因为站房升级就免面积、设备、租赁／用途和需求限制。复杂枢纽多个站台／泊位会触及端口／图节点上限；应先定义有真实吞吐的端口组及内部有界关系，超过原每设施8口／全局配额须显式重算，不把所有细节偷偷塞进一条无限“站内连接”。

## 5. 环境、程序与16GB准入

公交停车／车辆段、轨道／货场、港口和机场要按实际活动产生噪声／空气等源，传播到住宅、岗位和通行者；机场飞行走廊与铁路线路影响不只在设施site内。直接作业与交通段来源分开核重，不能凭站点数量再发一次同源排放。没有水污染／燃油系统时不声称已支持泄漏／净化；新增污染通道须另有单位／源与预算。

玩家命令沿E49精确对象／区域引用，W50登记→调查需求及替代→权利／居民／经营者沟通→补偿／安置→适用法案与拨款→真实资金和资源→分阶段工程→联合验收／投运→观察。码头要有水域／岸线权，轨道要有线路连续路权，机场要有空域／噪声及地面影响依据；不是有地、有钱就准建。站房验收、线路可达、班次运行和真实收益分别有证据。

性能策略仍为同路由／同班次有界人群批次、实际车辆或班次占用、站点／装卸队列、容量与失败事件，而非每位乘客每帧一个Agent。聚合可减少计算，不得聚掉人数、保管／付款责任、不同换乘期限或共享容量。所有后台城继续同钟运行；跨图服务份额不能复制车队／船队／飞机或外部订单。

**当前没有给本篇新机制分配新增常驻内存，也未证明它们可装进现有2.65／3／4GiB预算。** 每一批提升到可执行范围之前，必须提交字段／writer／数量与字节预算、初始输入及额外负载；不能沿用v0.5.0纸面预算就宣称新增轨道航空仍已满足16GB。原OD4096／货运10000／服务池64不是所有班次／乘客／机位的新免费表。

## 6. 后续收敛顺序及每批完成条件

按依赖建议：①道路公交（站点／线路／班次／票价及补贴）；②普通坡道停车楼与停车换乘；③地面有轨电车／客运铁路／货运铁路，先共用基础再分别补混行与联运；④轮渡与一般货运码头／港口；⑤三档机场及航空公司。该顺序是设计／实现依赖建议，不要求玩家从公交“升级”才能建铁路，也不引入隐藏等级奖励；机械停车、SOC、地铁／跨层结构、专用危险货与航空复杂中转分别延后。

每批只有同时补齐以下项目才可修改首版范围：具体基准规格／几何与量纲；线路／时窗／车辆／人员／资源／外部端；真实需求和容量竞争；独立主体的完整成本与收入；权限／程序／安全退出；有界状态和16GB联合预算；同根输入与可重放验收。当前交付是**目录与依赖完整性补充**，不宣称公交／铁路／机场运行模型已完成。v0.5.0的原设计冻结不被倒改，本次形成有版本的新需求扩展记录。
