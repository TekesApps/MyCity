# Agent主导的对象选择、区域调整与改造 E49

设计修订v0.4.49。根据玩家明确要求，首版的城市建造／治理／调整主入口是**给Agent的文本命令**，以后语音输入转成同一命令；地图负责看城市、精准选对象／选区、预览及观察后果。不是要求玩家逐项点菜单、拖道路才能完成建设。沿[G47](first-release-game-design.md)、[建设工具](construction-tools.md)与[事项流程](civic-project-workflow.md)执行，不建立一个可以绕过Agent／授权的地图编辑器。

## 1. 输入、选择和执行的分工

玩家可不选地图直接说“把河东那条主路加宽”，团队调查并返回候选，必要时让玩家用名称／编号确认；也可先点一栋楼、一段路或框一片区域，再说“把这个入口改到南边”“先改善这一片通勤”。选择是给命令准确上下文，不是施工、授权或改产权。模型必须读取选择记录和对象状态，不能从截图猜像素坐标。

地图基本操作限导航、图层、检查、点／框／多选、在方案中选候选、批准／停止；拖拽只是标注意图／画候选选区，不直接改正式几何或自动生成施工指令。曲线控制点的精确求解、道路拓宽与逐栋改造由团队调用统一工具形成可检查方案；纯文字用户可用对象ID／名称／方位／道路桩号做同一件事。保留结构化基本操作作为无模型的明确降级入口，但默认主流程／引导不要求操作传统建造面板。

文本命令、未来语音转写、地图指代和显式对象编号共享同一目标／计划／operation协议。语音只增加输入模态，不新增权限、廉价直写工具或另一套模拟。语音实现／声学模型／唤醒词不进首版；首版保留转写文本、来源与目标确认字段即可。

## 2. 每栋楼和每段路都能被准确寻址

每个实际建筑／设施／道路／独立重要植被有稳定ID与revision，可由地图选中或名册查到；房屋H单元／O经营者／入口是宿主的关联对象，检查器可进一步切换，不把16户当16栋楼。低LOD或无动画时仍能按真实实体选择，不因视口抽样漏掉真实建筑。

| 目标形式 | 捕获的精确依据 | 不允许的隐含扩大 |
| --- | --- | --- |
| 单对象 | world/branch、typed object_ref／revision、选择快照与地图，必要子单元／端口／角色 | 不因同名／同格把另一栋楼当目标；看楼不等于能动房东的钱 |
| 道路局部 | 同一canonical road_ref／revision、方向、中心线弧长[s0,s1]、对应几何版本 | 不以路网缓存边ID代替永久道路；曲线细分不改变真实桩号／长度 |
| 多选 | 同快照有限对象清单／查询结果内容摘要、数量、过滤条件及分页游标 | 不悄悄只改可见100个；不因后来新建房屋自动纳入 |
| 区域 | 冻结region_ref、多边形／孔洞／地图／框架，明确“相交”或“完全包含”的选择口径 | 默认只包含完整site；相交项单列待取舍，不能切掉半楼／跨界施工 |
| 关系引用 | “这栋楼的唯一进水管”“这条路沿线店铺”展开为真实依赖图及冻结对象集合 | 不把报价／影响范围误作产权或施工授权范围 |

选中摘要常驻输入框上方，例如“已选：住宅R-04#117，16户，A城，rev38”；选择变化不偷偷改变正在审批的旧方案，发送命令时冻结当时选择。输入框中的引用标记可移除／替换并查看；发送后新点选只影响后续命令。无明确目标时先只读查找，同名或多个候选影响重大动作时给自包含选项；不得随机挑一栋施工。

未进入已接受计划的选择使用原查询快照租约，默认60现实秒，受原查询／工作域额度约束；捕获与后续分页均重查可见权限。过期返回snapshot_expired，重新捕获并显示对象／版本差异，禁止用最新查询续旧游标。已接受计划持久化必要目标ID／版本／集合证据与来源页，计原项目正文／磁盘，不为selection永久钉住整世界快照。

新增只读`city.capture_selection`：输入snapshot_ref、对象／道路桩号／region或现有查询集合；输出不可变selection_ref、world/branch、map、typed目标、几何／对象版本、选择口径、总数及覆盖、有效来源页。它不锁土地／钱包，不授施工权。现有resolve_region/query_objects/get_object仍负责具体来源，selection只是冻结这些引用的轻量投影。

单页默认64、上限128行；单同步草案最多100动作／单区域4096顶点沿原预算。大选区分阶段物理项目／有界异步调查，不把1万栋一次复制到模型上下文；模型看到同一冻结总集、代表摘要和分页证据。每期接受工程独占原128事项／工程档案，资金／空间／通知分期但不因拆100次免同一个事项的程序／总额校验。

## 3. 调整是合法动作，不是任意写属性

| 请求 | 首版解释与可调整对象 | 必须付出的代价／检查 |
| --- | --- | --- |
| “修好／加强维护这栋楼” | 真实维护、范围内更新、施工或资源采购，归原业主与维护profile | 工料／人员／费用与现场、实际condition改变，不直接set condition=100 |
| “这栋楼入口朝南／改到这边” | 支持模板的人行入口改造及内部组／连接切换，旧出入在途先安全退出 | 真实新门／通道、产权／净空、旧入口保留与新门验收、全链路交通重算；不免费旋转整栋楼 |
| “这楼水电不够／重新接入” | 原类型受支持的设备／支线增容、合法隔离与临时供给，保持真实H／O与计量 | 电水实物／源／容量和费用，不能光改capacity数值或重复收父子账 |
| “这里换成商业／加几层” | 先查模板、用途和产权；未支持的结构／用途改造返回限制，可提出重建或其他合法方案 | 首版不任意缩放／加楼层、不自动生成复合用途；改变私人建筑只能建议／补助／法定项目，不能代私人同意 |
| “把这段路加宽” | road.upgrade，选择T01合法规格、增量路权／占地、接入／交叉口、工期与交通阶段 | 不只改贴图；临街房屋／管线／地块／门和权利受影响都列出，必要拆迁另审批 |
| “调整这片区域” | 先把目标展开为交通／服务／维护／用途等有限子计划，统一观察／累计授权 | 选择区域不等于允许拆区内所有房屋，程序、私有权、预算、互相竞争容量仍分别通过 |
| “这个桥加宽／提高／改接线” | 采用相同目标引用／方案／成本与后果流程；桥体／桥面／接线分别作为关联对象 | 桥梁机制仍按首版延期范围，当前不能执行桥体施工；保留意图／说明限制，禁止把桥当普通地面道路偷偷执行 |

首版物理修改仍采用building.place、connection.build、utility.upgrade、road.upgrade、object.demolish及新增`object.retrofit`的受限子类型（入口迁改／已有设备包合法更新）。retrofit不是通用`set_property`：必须指旧对象／修改profile、范围、原H/O／权利／占用、费用／工作量、端口依赖、旧新版本与完整验收；钱、税、工资、满意度和人口不能由它直接写。

入口迁改只支持同一矩形模板的合法南／东／北／西人行门变体及净走廊，不移楼／不把设备口当人门。基准报价max(1000币,楼体K×2%)、最低5游戏日／40净班组h，另有真实外接延长／停供／安置费用；此为合成候选，校准0.5—2倍。新门验收／内部组切换前旧门不封，若无维持两者的空间／权利就先提供真实替代或拒方案。过渡旧门引用与新门真实口联合计原8口上限，两个口若共享楼梯仍只有一份吞吐；拆旧不删已在途来源。

## 4. 道路加宽的首版可执行规格

保留CAT-T-01基准W8：8m路权、6m车行／每向1条3m聚合车道、人行总2m、600当量/h/向、30km/h、人行共享600人次/h。新增同CAT规格W16：16m路权、12m车行／每向2条3m聚合车道、两侧各2m人行、1200当量/h/向、仍30km/h、人行共享1200人次/h。这是规格变体而非第24类／逐车道仿真；实际吞吐仍受交叉口、转向、入口、队列与需求限制，不保证加宽就有效。

标准W8→W16等宽主段长L时，主段新增处理面积8L m²、主体估价1200L币。每端20m过渡宽度线性从新增0到8m，单端新增80m²；两端合计再160m²／24000币。完整项目长度L_project＝L＋40m，最低日历max(2,ceil(L_project/50))日、工作量为8倍该日历班组h；阶段沿原10/50/30/10。最终以完整新旧铺装包络差的实际并集面积计一次资本／工料／G06，曲线／接头包络不得用中心线长度近似漏算；1200L仅为直线等宽主段，不含过渡。新增铺装资本化到原道路改良范围，原安装锚点／老化与未改部分不重置，维护报价按新实际K及范围重核。管线迁改、路口扩展／地价补偿及停供／安置独立增量，不已含却再收费，也不因“沿路”免费挪管。

必须选择对称扩各4m或明确向某侧扩8m，给出完整路权／工程及临时作业包络。桩号局部升级至少20m，端部各20m衔接范围须纳入方案，若触及路口／端口或权利边界则重新求完整接入，不用100m选区只改中间一小截后隐藏接口冲突。长度不足／曲率／过渡无法在支持模板内完成时说明限制，不任意缩过渡来穿边界。

候选分期：在已取得的扩展土地施工，原车行／人行合法保持时可用原容量50%保守工况（每向300／人行总300）并计实际占道；不具备该几何净空则必须另有绕行／暂停新需求的合规方案，不能固定套50%把物理封路说成可通。新路验收后原子切拓扑与端口引用，旧在途按实际旧几何退出；旧新版本引用同一S04真实路段／路口冲突组，旧占用先扣新接纳余量，不各发600／1200两份资源。无法可靠映射共享占用则先阻新、排空旧段再切换，增容不提前卖给新OD／企业。施工扬尘／车辆／噪声沿O10／RUN36实际源，周边住户和商户的费用、交付／到岗与满意度继续真实反应。

具体输入基线仍用W8保证原LOAD43数量与预算，W16另作功能验收构造，不静默把所有道路变宽来解决中图拥堵。用户选中一次升级的新增记录／几何／临时占用仍进入原域，单预演／单模型请求额度不因区域大而放宽。

## 5. 一次改造命令的可见过程

直线100—240m主段140m，含两端过渡的项目180m，新增1280m²／参考192000币，最少4日／32净班组h；路权／管线迁改与补偿另核。

“选中道路R17的100—240m段→输入‘向北侧加宽，别拆这排住宅，预算不超过30万’”应产生：冻结R17/桩号／住宅及硬限制→调查实际范围与产权／门／管线→返回可行W16或受阻原因→预览新增路权、施工阶段、预算与维护、通勤／物流及受影响名单→在有效现有授权内执行，超范围才提出具体新授权→真实日历施工→观察同窗效果／未满足和账目。若R17为东西向道路，“东侧”不是横向扩展侧，团队先用地图方向解释并澄清，不猜成北侧。

“选中住宅B12→‘入口改到南边’”先检查现门和模板；本来已经南门就返回现状和真正瓶颈，不为完成对话收一遍改门费。要改善到岗可提出通道／路口／供给问题，不强迫玩家知道内部工具名。改造取消保留已经投入和旧责任，关闭Agent聊天也不停止已接受工程。

未来语音显示可编辑转写和目标标记，明确“识别文字／已理解意图／已接受项目”三态；低置信的拆除／对象／金额／方向不静默执行，先只读准备并请求必要澄清。高置信且在既有明确授权内的常规动作继续执行，不为每句语音强制二次确认。显式新授权或高影响拆除确认复用文字流程，不因语音绕过，也不让转写模型自己替玩家批准。

## 6. 验收与延期

验收必须同时覆盖纯文字按ID／方位定位、地图单体／局部桩号／区域指代、同名歧义、发送后改选择不改旧方案、旋转与低LOD仍选到每一真实建筑、区域分页不漏对象、W8→W16真实成本／权利／交通及保存恢复、无改造必要时不收费、取消后半成品保留。未来语音复用同一组工具／回执测试，另加转写／噪声／打断／敏感词歧义测试；首版不因未实现语音阻文本玩法。

桥隧／轨道／飞行、任意加层／缩放、任意复合楼、逐房间编辑仍延期；选择／调查／保存意图可以支持，执行能力不得伪报。根组件保证对象可解释寻址，不保证所有属性都能由市长改。技术实现按T47，现有主模拟预算／原表／聚合粒度不增；配置和新增资格之外不暗开系统。
