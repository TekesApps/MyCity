## 1. Root是统一入口，不是巨型父类

v0.4.22组合新事实落点按 [经济运行契约](physical-economy-runtime-contract.md)：原宿主1 KiB只引用扩展，新增128×256 B宿主、512×128 B功能绑定与2048×16 B依赖／meter关联共0.125 MiB在原模拟域重划。下文原表仍只拥有原事实，不复制现金、库存、权利、占用或计量余数；新增复合字段不再笼统挤入原宿主。候选仍后续B、须布局／索引验收，满16冻结版本不阻止旧实例记账／延期／安全退出。

Root Component为土地上可定位的建筑、独立设施、道路、植物斑块等提供统一身份、查询和操作入口。它引用真实权威记录，不另造一份拥有全部字段的对象，也不要求每对象一个agent。家庭、企业账户、法案等有自己的身份／记录；经营单位通过host_ref关联空间对象，不复制建筑几何或被迫成为一栋建筑。

Root的六个属性组P01—P06在 [双向对照表](property-system-metric-matrix.md) 有同一编号：

| 组 | 语义字段及类型 | 权威落点／更新规则 |
| --- | --- | --- |
| P01 身份 | object_ref＝world_id／branch_id／kind／stable_id／generation | 按类型解析既有对象记录；稳定ID不从地址、坐标或模板名称推导，跨分支写入须重新绑定 |
| P02 类型与模板 | kind、不可变template_ref／template_revision、schema_revision | 实例的模板绑定保存在本类原描述／版本记录，静态正文共享；更新catalog不自动改已有实例 |
| P03 修订与来源 | instance_revision、creation／migration_receipt_ref、commit_sequence | 原对象及事务日志；改动有来源，旧引用不能静默指向新对象 |
| P04 空间锚定 | geometry_ref、frame_ref、terrain／z_reference、可选host／subregion_ref | 原几何或宿主有界子区，Root只引用；layer分类派生，不代替真实z或权利 |
| P05 生命周期引用 | lifecycle_ref、适用投运／停用／拆除来源 | 引用工程／设施及场地事实；建筑建成、企业营业、房屋入住分开，Root展示不成为第二写入者 |
| P06 能力声明与解析 | 有界能力种类及facet_refs／availability结果 | 从冻结模板及既有运行记录解析；最多下表16类，非每实例分配16个独立对象／数组 |

查询必须区分absent（类型无此组件）、not_applicable（该字段不适用）、not_built（尚未形成实物／能力）、inactive（合法停用）、shortfall（能力存在但缺供给）、unknown、unsupported及有效的0。缺字段不默认零，未注册组件不能由agent写出名称就启用。这些是统一状态语义，工具仍沿用原status／reason机制。

法律、权限和当前资源校验是所有写操作及适用持续运行的共同约束，不是可卸载的“守法组件”。P06不是授权来源；模型自报judge、owner或新增能力不能取得系统写权限。

## 2. 身份映射与实例边界

| 类型 | Root怎样找到真实记录 | 分割／更换／退出 |
| --- | --- | --- |
| 建筑／独立设施 | 原建筑／设施描述及geometry_ref；关键设施状态按4096条表关联 | 拆除清场不复用旧身份；工程、住户、现场和债务先合法处理 |
| 道路／公共穿行通道 | 原节点／边和几何版本 | 真正穿行计入路网；旧边被在途引用时保留版本和位置依据 |
| 植物斑块／重要树 | 4096×64 B植物表＋宿主／空间引用 | 转换／合并原子移交覆盖和约束，不复制环境作用 |
| 建筑附属庭院 | 宿主稳定身份＋最多8个共享／功能子区的局部身份及版本 | 从属不是可任意级联删除；先移交共享权、占用和责任 |
| 住宅单元／经营单位 | 32768住房表／4096运营单位表，通过host_ref定位 | 房屋单元和operator_id独立，业主／经营者更换不重建楼、不重置租约／工资 |

住宅单元／经营单位可经统一查询入口返回关联分面，但不为每项新建完整Root实例或可视对象。数据表槽复用必须校验代际；语义身份终止及对应tombstone按原存档／幂等机制保存，不能让旧计划操作后来新对象。

## 3. 十六类可组合能力

P编号是属性组，完整字段、读写与指标见双向表；能力只负责类型化组织，状态仍在指定权威表。

| 能力 | 属性组 | 内容与必要边界 |
| --- | --- | --- |
| C01 Spatial | P07 | 实体／施工／维护／生长包络、面积口径、z及共享子区；不新增体素 |
| C02 Access | P08 | 最多8个外部口／设施、每口一个锚点、门位／方向／模式／时段，原65536端口表 |
| C03 RightsAndSharing | P09、P10 | 所有／运营／维护、账户绑定、使用许可和共享关系；不自动合并产权 |
| C04 ProjectLifecycle | P11 | 有限工程阶段、工时、最低日历、输入、安全收尾及验收；原128工程档案 |
| C05 ResourceDemand | P12、P13 | 有单位的需求曲线／最低量及实获、消耗、短缺；水电与实体商品分开 |
| C06 Capacity | P14、P15 | 用途／单位／窗口明确的设计能力与实际预留／占用，唯一物理瓶颈，不造人 |
| C07 Employment | P16、P17、P22 | 岗位／工种资格／班次、匹配／到岗、计薪及日周月付款；非家庭平均学历 |
| C08 Production | P18.production | 可选有界配方、设备／关键工种瓶颈；与每个运营单位必需的P18.common经营状态分开 |
| C09 GoodsAndTrade | P19、P20 | 所有者库存、采购／销售、在途和实际交付；不凭订单创造商品 |
| C10 FinanceBinding | P21 | 绑定原账户、预留及未清偿义务；组件不内置钱包／复制余额 |
| C11 HousingAndLiving | P23、P24、P26、P34 | 房屋／居住关系、家庭来源、实际消费及8维满意度；非每栋楼一套市民 |
| C12 Education | P25 | 背景／技能／资格与有限成人课程；教学工时、时间和资金真实约束 |
| C13 PublicService | P27、P28 | 类型化医疗／警务／消防等能力、派遣／占用／响应；床位不当商品库存 |
| C14 Maintenance | P29 | 有来源的维护策略、交付、条件和减容；拨款／付钱不等于已作业 |
| C15 NaturalEvolution | P32 | 成熟／覆盖／条件及冻结最大增长包络；有限自然状态不等于完整生态 |
| C16 Externalities | P30、P31 | 版本化声源／排放系数、真实活动到环境场／暴露的映射，未知不当零 |

P33是全体对象适用的制度／权限上下文，不是第17个可选组件。P34是家庭的游戏状态，经房屋关联查询；不是每个具有C11的建筑都再保存一份家庭满意度。

能力组合存在前置约束：Production必须绑定真实运营者／账户、适用资源和交付引擎；Employment需劳动来源及可达工作口；PublicService需其人员／接入／资源和适用容量；Housing需真实单元／产权／居住登记。自然斑块可无雇佣、无市政水电，无对应能力不推断它没有空间或保护责任。

每个运营单位不论制造、零售、医疗或教学，都必有P18.common：operator_id／host引用、经营profile、operating_status及实际活动来源引用；它们是原128 B运营记录的统一分面，不依赖可选C08，不另增组件／记录。C08只声明P18.production配方／设备等字段。S06管理通用经营状态；P27／P28及教育记录引用该状态和各自实际服务／课程进度，不能另写一个相互矛盾的“营业”布尔值。关闭新增业务不删除既有患者／课程／在场责任。

交付profile必须指定唯一delivery_adapter：制造活动由S06，电／水由S05，运输通行由S04，零售转移／废物最终接受由S07，医疗／警消防服务由S09，教学由S03，维护由S10。C08或“行业系统”不自动成为所有交付的第二写入者；P18.common只引用相应活动事实。

## 4. 每个字段必须完成的定义

字段定义至少包括：稳定字段路径／P组、类型与单位／数量精度、S静态／A权威／R关系／D派生／V显示类别、适用对象、默认来源与范围、唯一逻辑写入者、读取系统、变化触发与失效对象、游戏时间／区间、存档／预算落点、缺测／不支持处理及对应M指标。

S参数可共享，A事实和R有效关系必须按原权威持久保存；D可重算但要有覆盖／版本／年龄，不能拿新算法覆盖历史已承诺金额；V仅表现，不参与经营／法律判定。满意度P34虽叫“分数”，属于影响未来行为的A游戏状态，必须存档；城市平均满意度才是D指标，不能混用。

同一字段只能有一个逻辑事实写入者。不同系统可向其发出有来源的意图／事件，由原事务提交器原子更新；不允许生产、行业和电网各自扣一次煤，或市场和消费各自写一份库存。复合记录按字段键分工，不能用“都能改这张表”代替契约。

## 5. 模板、实例和迁移

首版不提供任意key/value实例扩展或无限组件字典。实例差异仅使用既有有界字段：姿态／几何、选定端口／锚点、owner／operator、合法价格／工资策略引用、状态／库存和实际权利等；未定义差异先补字段落点和预算，不把JSON正文当免费热状态。

容量、结构、门位、配方或权利变化不得只热换template_revision：先形成冻结新版本、差异、合法迁移／工程及资源／收尾安排，再原子绑定；不能因模板升级让旧幼树瞬间成熟、住房翻倍、门换墙、设备修好或旧欠款消失。仅显示资产更新也不能改变物理占地／可达性。

每个候选模板要逐项说明创建、建设、投运、运行、维护、停用及拆除的前置与后果，缺一个必要组件／模型时保持template_unconfigured／unsupported，而不是建立空壳后宣告正常营业。

## 6. 现有状态字段落点与元数据预算

| 必要事实／差异 | 现有落点，禁止复制的部分 |
| --- | --- |
| 建筑模板绑定／姿态／状态及投运回执引用 | 原建筑／设施描述目标1 KiB与几何记录；邻图分页解析，不另加Root头 |
| 关键设备条件／维护引用 | 4096×128 B关键设施表；若不适用则不占该表 |
| 经营模板／工资策略／岗位汇总 | 4096×128 B运营单位，雇佣引用32768×32 B边；冻结条款正文分页 |
| 房屋权利／租售／入住引用 | 32768×64 B住房；家庭／资格／情绪依原家庭／课程／来源，不写进楼 |
| 门／连接／开放与容量引用 | 65536×32 B端口；独立占用归8192×64 B组，不在端口后藏队列 |
| 共享权与物理约束 | 8192×16 B关系、宿主子区／路网／真实设施、唯一容量组；关闭待移交仍占位 |
| 植物模板／成熟／覆盖／条件 | 4096×64 B植物表，几何／最大包络外引原几何域 |
| 法规、许可和承诺依据 | 原256规则／法案／案件、工程、住房权益或一般合同及日志回执，按类型区分 |
| 资金、债务、库存、在途、服务 | 各自已有明确表，不在组件内再保存可独立使用副本 |

以上是**字段必须落入的目标记录**，不是已经证明每个字段装得下。真实布局要列定长字段、代际／引用、对齐和外部页；超尺寸须先重预算或缩减尚未承诺的能力。不能用“只是引用”省略实例事实、许可状态或变长反查成本。

v0.4.19的基础Root分面不新增每实例状态表，区域仍39.0078125 MiB有效载荷、44 MiB额度。模板热缓存全世界最多64页×4 KiB＝0.25 MiB，建筑／设施、最多16行业模板及所需参数profile共用，正文超页分页但热页不突破64。该缓存归原0.35 GiB模拟域扣除区域后的314.4 MiB中，基础分配留下314.15 MiB；v0.4.22再划0.125 MiB候选复合扩展后现为314.025 MiB其他模拟用途。不在区域表或资产域再计第二份，几何／贴图按原域单记。

64页是缓存工作配额，不是允许无限创建模板版本；活跃绑定／固定历史仍按原存档和索引准入，淘汰热页不能改已有实例。指标／查询schema描述同样不是每对象一份，回传和上下文沿原AgentKit／UI配额。应用2.65 GiB常态、3 GiB软上限、4 GiB峰值警戒均保持待测目标。

## 7. 双向收敛与通过条件

先用 [首版模板](first-release-object-templates.md) 的住宅、煤电厂、公园走完整生命周期，再用 [属性—系统—指标表](property-system-metric-matrix.md) 做三条检查：模板所有必填P组有权威和额度；每个系统的输入有真实生产者，写回不冲突；每个M指标能追到字段、分母／时间和覆盖，指标反馈只能经规则／行为／合法操作进入状态，不直接反写结果。

分类为必需但尚未配置的字段明确列为缺项；不支持的后续模型留范围说明，不让模板伪造已对齐。完成静态对照仅证明设计能追踪，不证明实际字段布局、模拟收敛、经济平衡或16 GB性能。

## v0.4.20：组件之外还有内容目录

[类型与技术路线目录](building-types-and-technology-catalog.md) 将形态、业务机制、规格和权属分开。C01—C16与P01—P34是语义契约，不限制建筑只有13种，也不赋予风况、水质、储能SOC或住宿等尚未定义的机制。目录范围与就绪双轴不新增每实例状态，沿冻结模板／类型schema查询；后续机制先补唯一权威／系统／指标与预算，再开放。

## v0.4.21：受限组合不是任意规则编辑

[复合设施与成本模型](composition-and-cost-model.md) 给出后续组合契约：宿主＋展开后≤4功能单元＋真实共享支撑，各范围产权依据及主责管理授权明确；宿主总8共享／功能子区（H套内布局另计）／8外接端口，版本／身份／实际用途、权利／占用和依赖须有界存储。父对象不复制子对象资源、产出或收益，规则profile不能被玩家任意覆盖。

候选全世界16个被引用冻结组合版本、单元最多8聚合设备类别，仍须字段布局与记录／缓存准入，不是新增免费表或首版开放承诺。现有C／P／S／M编号保持原范围，商租／摊位许可／新市场状态先补唯一权威和预算。
