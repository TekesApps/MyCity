# 自定义复合设施与实物—经济成本模型

现行修订：v0.4.22，2026-10-19；初稿v0.4.21。目标是用同一套有界原理管理预定义建筑、自定义组合、广场摊位和纪念物：真实空间／设备→资源与工程需求→实际成本→有支付能力的需求／合同→交付与收款→维护、退出及城市后果。本文是设计契约，没有游戏代码；不以本模型已写出为理由开放尚未支持的办公、轨道、旅游或商业租赁机制。

交付、故障超占用、计量／退款、同质设备／市场竞争及具体预算按 [实物经济运行契约](physical-economy-runtime-contract.md) 执行；本文提供模型总览，不把可丢缓存当新增事实落点。

## 1. 定义机制、预定义资产与自定义方案

v0.4.23 [两份完整案例](worked-examples-housing-retail-and-stalls.md) 将住宅＋底商、广场两摊按同一30日游戏窗口展开至面积、设备／水电、资本／维护、租金／许可／押金、库存／工资与逐方现金。示例参数不代替规则profile或实际运行；供方边界收款不当利润，隔离账本不当整个世界经济预测，混合／许可仍B。

Root／能力提供共用契约，预定义资产是完成几何与profile配置的方案，自定义则在同一规则内组合，不是修改世界经济规律。

| 可由玩家／agent选择 | 必须由规则或实际世界决定 |
| --- | --- |
| 已支持用途、相容设备档位、数量、面积／位置、开放与班次、合法经营／价格策略 | 单位设备／结构需要的材料、工时／最低工期、功率／用水／维护曲线、作用来源和真实容量 |
| 支撑设施的共用方案、产权／管理／付款方、经营者／合法合同 | 是否确有共享、空间／网络／安全可行性、费用归属、人员／库存／资金及市场需求 |
| 不同装修／技术profile、真实升级／改造项目 | profile能力边界、相容性、寿命／维护责任和版本，不能同时免费获取互斥优点 |

玩家可选择省电设备、简装修、较低租金或减少营业时段，各自有实际代价与市场后果；不能手填负能耗、零必要维护、无限容量、固定满租或“每天吸引一万人”。未配置规则返回template_unconfigured，缺机制返回unsupported；更改规则系数属于另一个有版本的场景规则集，不冒充标准经济下的自定义资产。

## 2. 从实际配置核算需求，而非给整栋楼一个任意标签

每个已支持的设备／结构profile定义：单位及可用数量／规格范围、额定功率、待机／工况曲线、容量与必要班组、用水／材料／废物、建设／装修／维护／更换、占地和接入／外部性。照明、空调、泵、商业设备等以**有界设备类别×数量**汇总，候选每功能单元最多8类，各类数量范围由profile限制；冻结定义归模板／P12曲线，原实例只存已定义的有界状态，不逐灯泡、插座或水龙头创建独立agent／状态表。

| 项目 | 核算口径与约束 |
| --- | --- |
| 照明／空调／设备 | 安装功率＝Σ数量×额定W；运行功率由真实活动／时段和profile工况计算，待机另列，不按显示动画开关 |
| 电量／接网 | 能量kWh＝∫实际功率kW×游戏小时；设备额定、同时峰值、接入口／电网可行、实际获电分别记录。额定7 kW不是每日7 kWh |
| 水 | 清洁／卫生等有依据的基础量＋实际活动用量，统一m³／时段；管网流率与窗口内水量分开，不能以缴费代替实际送水 |
| 管线与接入 | 实际长度、管径／容量档位、相容层位、土方／接头／穿越、维护及损耗；首版抽象水电不因此宣称已有精细压力／多电压模型 |
| 建筑结构／装修 | 实际楼面／围护／结构、选定材料／装修、工时与工程阶段；同一公共走廊不重复装修，必要专属设备不能被“共用”抵消 |
| 人员／设备利用 | 班次、资格、工时／工况和真实到岗约束；额定设备不表示员工全天工作，降低人员不能保留需要该班组的满额产出 |
| 维护与替换 | 真实作业、输入与停机；费用估算／预留／实际支付和实际维护完成分开，不按付费即恢复设备 |

示例只演示单位：20盏15 W灯＝0.30 kW，4台1.5 kW空调＝6 kW，2台40 W终端＝0.08 kW，1台0.8 kW冷柜，安装总功率7.18 kW。某游戏日灯开10 h、空调按已配置60%工况运行8 h、终端10 h、冷柜按50%工况24 h，则用电3＋28.8＋0.8＋9.6＝42.2 kWh。工况率来自该例profile，不是任意省电开关；实际接网与启动／同时峰值另检查，缺电反馈实际业务，不先满产再补一张账单。

上述设备模型是P12资源profile的设计约束，不承诺所有设备类型已配置；新设备若需要温控、SOC、质量或故障等新增动态事实，仍须按目录B类机制先定义／预算，不能藏进一条曲线。设备清单明确替代／覆盖原整栋负荷profile的哪部分，不能再与已包含同一设备的整栋能耗相加；未拆开的部分只能使用一个不重复的整体profile。公共电表和分表按实际计量边界分摊同一交付，不能水电网、房东和商户各消耗一次同一电量。

## 3. 空间组成和共同支撑

一个组合方案由宿主几何、功能单元、共享支撑、使用关系／合同及依赖构成。初轮设计限制：**一层组合，展开后最多4个功能单元，宿主总共最多8个子区／8个外部端口**。功能单元不是C能力数量；一个零售单元可以有多种能力，但每个实际经营者、住房单元、库存和队伍仍有自己的真实记录。不得把已有复合模板算一个单元继续套娃。

- 每层真实可用面积覆盖独占功能区、共同支撑和结构／未分配部分；同一口径下不重复分配。不把GIA、NIA、GEA和土地site混加，不因地下／多层而复制地块权利。
- 走廊、庭院、厕所、装卸或管线按相容性真实共用；独占房间不能同时出租两份完整独占权。时分共享要有明确窗口、清场／转换时间、许可和实际人员／货物退出。
- 对每个共享资源j，新接纳／新预约前检验既有有效承诺＋新增≤当前支持容量，同一来源预留转实际不双计。并发人数、工作位、泊位、水电流率分别约束，平均日负荷不能抵高峰。故障减容后可真实超占用／超承诺，保留actual与overcommitted，阻止不相容新增并安全退出，不能裁人／删占用使不等式成立。
- 通道和设备具有唯一容量、身份、维护方和费用，故障／封闭影响全部依赖者。服务池或原网络已表达的容量不再发行；独立空间组沿原S04权威。
- 初轮只允许明确主产权／管理责任方，多个合法使用／经营主体；不新增复杂共有产权。安全隔离、公私开放、噪声／作业和必要维护空间不可因合建免除。

政务办公＋商店、车站＋商店都能在此结构描述，但前者的实体办公机制、后者的轨道／换乘机制仍是 [目录](building-types-and-technology-catalog.md) 后续B。车站商店不能把所有乘客自动当顾客、让顾客穿越未授权付费区，或把一趟换乘再重复生成一份游客出行。

设计阶段先用“普通零售＋成人培训＋共享庭院”验证已有业务如何组合；这仍需多用途绑定／验收／收支等缺口补齐后开放，**不把目录混合楼从后续B直接改为首版A**。多楼共用绿化等已定义共享能力保持原范围。

## 4. 成本自底向上，节省须有来源

建设估算＝各专属部分真实工程量报价＋共同支撑工程量报价（一次）＋实际接口／隔离／复杂施工投入＋适用土地／权利取得支出。按物料、工时、设备、工程阶段、责任主体和时点解释，不用可叠加“综合体优惠10%”抵消投入。复杂、超大或高保障方案通常需要更多真实支撑与协调，但不设所有规模必定指数涨价；允许有依据的规模／共享收益。

| 成本层 | 估算与实际账务区别 |
| --- | --- |
| 土地／权利 | 实际买入与租用采用各自合同。买地支出不在每月再伪造一次土地租金；机会成本可作分析但不是无对手方的现金扣款 |
| 建设／装修／接网 | 报价、承诺／预留、按进度实际投入／支付分别保留；承包总价已包含的材料／工资不能再加一笔同成本 |
| 日常经营 | 实际采购、水电、工资、租金、维护／清运、适用税费；同一窗口、币种／单位和付款方，钱与物各守恒 |
| 更新／停工／退出 | 设备更换、真实停业、收尾／拆除／废物和未结责任；未来预测不能伪装已支出，也不能因为停业删掉债务 |

不同装修／节能技术只有在profile明确投入、服务品质／资源曲线、维护与兼容限制时可比较；不能用一个“豪华”标签同时免费提高客流、降低耗电、增加容量。参数引用要冻结版本，不能工程完工后热改成更便宜材料退还历史成本。

共享例：两个分建方案各有私用工程200／300和等效支撑100，总700游戏币；合法合建共享一份支撑100，但需要真实接口／隔离投入40，则总640，节省60，来源是少建一份支撑100再多花40。若共同支撑不够、必须扩容160，则总700，节省0。三者功能／保障是否等效先验，不拿缩减服务的方案假装同等便宜。

## 5. 地价、租金、业态与市场反馈

成本影响开发和业主报价意愿，地点影响客源、通勤、运输、环境与替代选择；**成本或高地价不保证有人愿意付租，低成本高收益也不天然是漏洞**。应阻止的是没有真实权利、需求、交付或付款方却生成收入。

| 环节 | 规则 |
| --- | --- |
| 地点／土地估值 | 可达性、合法用途／强度、周边环境、已核验交易／报价等形成有来源／时点／覆盖的估值或区间；它是派生参考，不是现金／收入。无市场数据标unknown或声明场景参考，不捏造邻地成交 |
| 业主报价 | 在合法价格策略内参考取得／维护成本、地点、装修／适配、替代房源与空置，选择租售报价。成本回收目标不是市场保底收益 |
| 商户选址 | 可达且有支付能力的真实需求、竞争／替代、营业时段、劳动／货运、面积设备适配、资金及租金／其他成本决定候选与进入意图；不能看高租金就自动生成高端商户 |
| 履约与生存 | 有合同也须真实开业、交付与支付。销售不足／欠租／缺现金通过缩班、调整价格／业态、合法退出等慢周期行为反馈，不立即删除人或债务 |
| 地价反馈 | 已发生的可达性／需求／交易等影响下一评估窗口，不在同一微步内用“高地价→高租金→高价值”自我乘数。估值与价格选择用冻结快照、明确评估周期和变化约束，规则未配置不宣称收敛 |

住宅租金／权益沿现有P23；商业场地租赁、多租户时段许可与真正土地市场是后续设计缺口，不能把住房租约换名使用或凭估值创造地款。它们需先定义合法使用单位、计量／到期、合同与记录落点、承租现金和退出责任。外部场景报价可供规划比较，但没有真实对手方／支出不能当成已经成交。商业rent低只降低实际租金收入；市政主动低价还需明确实际业主与政策／财政依据，不补出一份“差价收益”。

统一分析同时给出现金流与收益口径：营业额≠利润，销售≠已收款，采购≠同期全部耗用，融资／补贴≠营业收入。会计成本／折旧／税费未定义时，只报告已支持的收入、成本和净现金流；估值上涨不算可花钱。内部租金、水电转收费、补贴和税费是实际账户间转移，不能在整个世界又计一份新增商品／财富。

示例：某30日游戏公历月商店实收20000，实际付货款9000、工资4000、租金3000、水电700（示例42.2 kWh/日×30×0.5游戏币/kWh＝电费633，水费67）、维护200、许可费100、清运100，经营净现金流2900。它不含取得／装修／更新支出，也不假称完整会计利润。若预期需留3000经营现金余量，其他条件相同下可承受租金上限2900，而非业主报价3000就保证满足目标；若实收降至14000、支出暂未调整，则预计净现金流−3100。实际能否全付还取决于期初现金和已有受保护义务，现金不足按原规则保留未付债务／拒绝无资金承诺，不能为凑预测支出生成透支；租金不会因成本存在而自动付清。

## 6. 广场摆摊也是一种有权利和责任的经营

摊位是临时／轻量空间配置，不是无地价、无资源、无维护的隐形商店。可以自带设备、租借广场接电／接水，或在无此需求的profile下不接入；零消耗必须有依据，不能靠未填字段得来。

| 必须声明 | 模型含义 |
| --- | --- |
| 真实范围与时段 | 摊面、顾客停留／排队、装卸／整理、开放与撤场；永久占用与临时使用权区分，不因摊车小而占满消防／行人通道 |
| 使用许可／付款 | 有范围、期限、经营类型、收费及责任的真实许可；同一时段不能重复卖排他位置。免费政策可为零收费，但使用权／容量和清运成本不消失 |
| 实际经营 | 普通一般商品可复用O03的需求／库存／销售机制；每个实际经营者仍占运营单位、账户、劳动／库存等。许可费不自动保证客流 |
| 公共接入 | 广场总电口／水口／空间容量是真实共同资源，各摊位按分配使用和计费；外接电价不是凭空发电，房东服务费也不第二次消耗同一度电 |
| 清场／废物 | 真实清运、损坏／维护、在途／在场与撤场后责任。时段到期触发核验，未清场不把空间重新卖给下一方 |

预包装一般商品摊位只是可复用O03的候选，不宣称已定义食品；烹饪、餐饮、冷链、食品安全和完整多商户许可机制仍后续B。每个摊位须有合法宿主子区或独立设施身份（二选一）及真实经营单位，不能仅凭坐标营业。有期限的使用许可按现有一般合同／空间关系／占用目标额度落点，仍须补期限、计费／退款、提前关闭、清场和剩余责任条款，不能暗变已经支持商业租约／转租市场。广场商业化需检验剩余公共用途／容量及合法程序；不能把全部公共空间既算公共服务又全天独占出租。临时性只改变工程／许可／撤场profile，不绕过真实创建或记录配额。

## 7. 公共建筑、纪念物不要求每项直接赚钱

医院、行政与公共空间可以有持续负经营现金流，提供法定或玩家选择的公共服务；模型仍要列真实财政来源、成本、服务效果和替代方案。财政不足影响新承诺／维护并依法处置，不自动生成收入维持满额运行。不能把“每项都能测成本收益”误解成“每项必须直接盈利”。

纪念物有土地／空间、实体建设、维护／照明／清洁、修复／安全和拆除责任；若无经营设备／人员，其不适用项有依据。效果可以是已支持的景观或视觉表现，不强迫每个物件都有商品产出。游客、纪念品／票务、文化等模型未支持时，吸引力／收入标unsupported，不能凭美术名字生成固定钱或人口。

未来访问吸引若开放，只改变有来源、时间／预算和替代地点的有限需求池中的选择；重复同类景观按重叠／替代与有界偏好计算，不把多个固定满意度奖励线性叠加。访问还受真实到达／停留、入口和公共空间容量影响；游客付费归真实经营者，原居民消费不能同时又记成外来财富。具体偏好、饱和与旅游来源未配置前不声称已产生这些效果。

## 8. 平衡由约束、需求与后果形成，而非统一万能评分

| 要防的漏洞 | 可检验条件／后果 |
| --- | --- |
| 超级楼免费容纳所有功能 | 真实楼面／结构、4单元展开上限、总8口／8子区、各typed容量、人员／物料／资金及相容性分别准入 |
| 用一个共享标签反复打折 | 共享必须指出少了哪一份实体投入；共用支撑只建／维护／交付一次，必要接口／隔离和峰值扩容另有实物来源 |
| 极低成本＋高租金＋永远满租 | 报价可以高，真实承租支付／需求和替代约束不可免；空置／欠租／经营亏损真实保留，不发保底收入 |
| 嵌套／拆楼绕限 | 按实际展开和同一项目、共享物理瓶颈计；独立合法多楼可以建，但各自实际状态、工程／权利／接入成本都计入 |
| 公有业主向自有部门收租就创造财富 | 各账本可展示转移，汇总消除内部转账，不重复记真实外部收益／成本 |
| 低价／省电技术样样占优 | profile技术可行域校验，比较相同服务／保障／周期；必要参数和运行事实不可自定义覆盖。确有更优技术可被选，但有真实取得／改造和维护条件 |
| 无限纪念物吸引与无限广场摊位 | 占地、成本、维护、同一需求／时间／购买力、重叠偏好和空间／网络实际容量共同限制 |

平衡评审采用成本／现金、服务量／可达性、资源、时间／可靠性、环境、土地与法规等并列结果；不把它们先合成一个允许“高收益抵扣违法”的分数。短期便宜与长期维护、集中共享与共同故障、较低租金与业主收入、更多客流与拥堵／噪声都能形成选择；不预设每次合建都比所有分建方案差，也不禁止有真实经济依据的高收益。

## 9. 定义、准入、存储与系统对照

自定义方案沿目录／工具流程：选择支持的功能与profile→生成展开清单／真实几何和依赖→算需求／工程与费用→权限／用途／共享／峰值及配额校验→用有来源市场快照评估现金流与敏感性→冻结版本／批准→真实工程及分项投运→实际监测→合法调整或退出。共用支撑未投运不能先开需要它的单元；撤掉商户不能删其他单元的门／在场／合同或维护责任。方案比较要带窗口、单位、profile／价格版本、缺项、需求与价格假设、付款方和分项解释，预测不得标成实际收入。

组合schema／使用许可是新增设计缺口，不宣称有完整内存实现。候选初始准入目标：全世界最多16个仍被引用的冻结自定义组合版本，每定义展开≤4功能单元，无间接嵌套，正文共用原64热页；16是组合版本槽额度，不是行业模板16额度，同一设计两个固定版本占2槽，同一版本的每个实例仍按实际资源分别收费。受现有实例／权利／缓存／目录实际字节的联合约束，不能16×免费复制全套对象。

冻结组合定义存储有界单元局部身份、用途／profile引用、面积／时段分配与共享依赖；每实例新增绑定／分配／同质设备状态按运行契约显式0.125 MiB候选扩展落点，原宿主1 KiB只存扩展引用；原子实体／权益和共享关系仍各有唯一事实，不把新增状态只藏在可丢缓存。活跃／责任仍引用的旧版本占定义额度并持久固定，不能更新／归档绕开16，超额拒绝新版本／新增使用，保留既有事实。确需多个版本同时存在时各占槽；真正不再被状态／义务引用的定义才可移出活跃集合，持久历史仍受原磁盘／索引准入。

16定义／4单元是后续实现的保守候选边界，不是证明这些字段已装进原记录。设备类别数量、分配／依赖记录、计价／计量余数、版本／代际、索引、调度与保存／历史都须列实际字段布局。装不下或需要新动态状态，先缩范围或独立重预算；**区域39.0078125／44 MiB和应用2.65／3／4 GiB现行目标，以及原模拟域内0.125 MiB候选扩展预留，均不为整个后续复合／市场模型背书**，也不因新增文档自动增加一份未计表。

## 10. 必须验证的模型案例

1. 相同配置用不同日历档推进：实际工时／电量／现金守恒；7.18 kW安装与42.2 kWh/日不能混算，空调缺电限制相应活动。
2. 分建／合建相同功能比较：支撑一次、扩容与接口真实；共同停电／封门／维护影响所有依赖者，不产生双倍容量。
3. 房价／租金报价翻倍但需求不变：不自动满租、不增加承租现金，欠租／空置可解释；低价招租增加需求也不能超容量。
4. 摊位许可重叠、夜间清场延期、广场断电／垃圾满载：新进入／新许可受阻，旧占用／债务不丢，不因期限到了自动腾空。
5. 部门向同一业主内部付租、房东代收电费：账户分别真实，世界汇总消除转移，水电交付不重复，维护报价不再加一遍内含工资。
6. 三个同类纪念物和一个纪念物对比：只有已支持／已配置景观作用，维护成本真实；未来吸引模型不能创造新需求／钱或无限满意度。
7. 调低收入、提高电价／工资、断共享接入和停止维护，分别展示现金／产能／环境传播；参数敏感度不能以一个固定平衡分数代替。
8. 套娃、5单元、9口／9子区、满16定义及旧版本固定、场景规则改动：明确拒绝／新规则版本，保留已有权利和在途；政务＋商业／车站商业仍能报告各自缺失机制。

实际数值／收敛规则、商业场地／土地市场／公共办公和旅游等仍需后续专题收敛，静态案例不证明已完成经济平衡或16 GB运行验收。
