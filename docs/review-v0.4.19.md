## Advisor复核发现与修正

按用户指示咨询advisor，初审指出两类接口问题；修改后只读复核确认以下问题已解决，本次范围无新增阻断项。

| 原问题 | 修正 |
| --- | --- |
| 经营状态放在可选生产组件，零售／医疗／教学可能缺营业状态 | 每个运营单位必须有P18.common；C08只增加可选production，不另建营业布尔值 |
| 通用生产可能与电水／服务／课程重复交付 | profile声明唯一delivery_adapter；common引用实际活动事实，不二次生产 |
| 同一共享容量被多个系统各写一份 | P15按资源键单写；服务／货运使用独立空间组时向S04请求，既有床位／库存不重复发行 |
| 出行完成率混用本窗出发和跨窗到达 | M05固定同一出发集合及观察截止时刻；窗口流量另列 |
| 工资履约率将历史欠薪付款计入本期债权分子 | M11固定同一到期债权集合，实际付款按归属分配；历史清偿另列 |
| 按批次等权或平均各批P95造成误导 | M06／M15按实际人次／请求等声明权重；跨批用有界分布／样本，明确近似与未完成量 |

## 静态验算与验证边界

模板算术：H1主体192 m²、site 560 m²、3层576 m²、4单元240 m²、最多16人；H2主体480 m²、site 1280 m²、5层2400 m²、16单元1120 m²、最多64人。剩余楼面不自动变成额外房源。零售300÷20＝15参考FTE；医疗10个同时岗位连续一周需10×24×7÷40＝42参考FTE。

制造满班80产品／88原料／8废料，半瓶颈40／44／4，只在已声明共同物料当量内守恒。煤电10 MW×1 h＝10 MWh，对应5游戏煤单位、100 m³水；泵水100 m³/h×0.5 kWh/m³＝50 kW。培训120÷2＝60有效教学日，仍受最低90日历日及到课／资格条件约束。

统计反例：旧批100人出发、90人在本窗到达，新批20人出发、10人到达，批次完成率分别90%与50%；本窗100到达÷20出发的500%只能说明口径混错。旧欠薪清偿300、本期到期1000且归属本期已付600，本期履约60%，不能算90%。99人耗时10、1人耗时100的同口径经验P95为10；不能对两个批次的P95等权求平均。

静态检查通过：50份Markdown、363个相对文件／章节链接、围栏及2个既有JSON示例；另核对C／P／S／M定义及引用编号、模板数量、关键算术、26项区域预算及diff空白。这些不验证模拟器运行。

## 16 GB预算及下一步

区域26项仍为39.0078125 MiB／44 MiB，余4.9921875 MiB。本轮明确模板热缓存64页×4 KiB＝0.25 MiB，从原0.35 GiB模拟域扣区域后314.4 MiB中划出，其他模拟用途314.15 MiB；不增加区域表，也不在资产域重复计费。应用常态2.65 GiB、软上限3 GiB、峰值警戒4 GiB保持待测目标。

13个候选模板不是13个已可玩的资产，必要资源／工期／工资／维护／环境／服务profile尚需逐项配置；缺项不能当零执行。现有定长记录能否容纳稳定引用、资格、满意度／暴露锚点及对齐，仍须字段布局验证，超额先缩范围或重预算。求解收敛、经济平衡、保存恢复、高清渲染及最高日历档吞吐均须实现后在16 GB真实设备验证。本轮完成的是可追踪的设计对齐。
