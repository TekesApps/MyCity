# v0.4.3 工程日历、拆除与环境后果修订

日期：2026-10-18。纯文档版本，未写游戏代码或运行性能基准。用户明确：30天工程经历30个游戏日，日历可按一天一分钟、一天一秒等档位推进；拆除也有工程进度，并考虑交通、空气污染和噪声。

## 1. 规则变更

- [游戏日历](game-time.md)：观察／经营／快速／高速四个目标档，暂停另列。高速使用版本化聚合／事件策略，不再要求所有档位遍历10游戏秒细步。
- [工程生命周期](construction-lifecycle.md)：原子接受、持续施工、原子投运分开；阶段工作量、班次、养护、临时供给和资源决定进度，不是日期一到自动完工。
- 拆除经历停用迁出、断管围挡、主体拆解、废料运输及清场验收；未清场不可重复利用土地，回收料不能提前出售。
- 施工／拆除占道、工程车辆、扬尘、机械排放和昼夜噪声进入模型；高速保留排队积压、累计暴露、噪声峰值和实际费用。
- 长期受阻只告警，现场与半成品保持；取消不退款重置或恢复已拆建筑。
- 已冻结工程在摘要中推进工作量和后果，最终永久几何／网络落地仍待详细验收，不暗中加载第二套完整城市。

按用户此前指示咨询advisor，采用上述事务／工程分层及有界快速策略。摘要后台自动永久投运、完整施工物料学、真实分贝／污染测量不在首版承诺中。

## 3. 验收与尚待验证

检查缺料／缺钱／缺班组导致停工；养护等待不被多派人跳过；阶段完工后组投运失败保留实物；拆除取消不复原；废料接收容量不足不释放土地；占道影响消防到达；污染与噪声在白天／夜间及邻图摘要均持续。

高速要测试最早事件截断、库存耗尽、合同到期、班次及日夜转换、交通积压、数值稳定、费用舍入与监测覆盖，事件过密时降低实际倍率。物理施工模板的现实工期之后按来源校准，当前工时样例不当作现实行业统计。

本轮只检查文档链接、JSON示例、预算和时间算术，并扫描早期即时建造／固定细步冲突。未将文档通过宣称为工程仿真、快速算法或性能验收。
