# v0.4.2 整体审查与静态验收记录

日期：2026-10-18。对象：v0.4.1 当前文档；结果版本 v0.4.2。本轮仅文档，没有游戏实现、Rust 测试、真实模型端到端或 16 GB 性能跑分。

按用户要求，遇到边界判断时咨询 advisor，只读检查容量、运行投入、权威、账务和内存。advisor 确认两处实质矛盾，其余项作为必须补齐的约束，不将它们误报为已证明实现不可行。

## 1. 发现与处理

| 问题 | 判断 | 本轮修订 |
| --- | --- | --- |
| 本地保底与固定外售同级，但示例先保底再分出口 | 实质矛盾 | 明确占用、既定保底、固定合同、可中断的顺序，同步示例 |
| 公共服务自由容量漏列占用，保底与预留可能重复扣 | 实质矛盾 | 占用与未转占用预留互斥；本地／外地是归属而不是再扣一遍 |
| 按分钟发电但按小时消费燃料 | 时间语义遗漏 | 运行投入分钟预留／实耗；小时制造消费不得再次扣减 |
| 上一期供电状态可能被当作本期能源 | 可行性约束遗漏 | 当期联合可行分配、真实启动门、有界求解和保守失败处理 |
| 两条摘要通道共享一个物理瓶颈 | 容量约束遗漏 | 共享 resource_id，路线累计不超过同一资源上限 |
| 本地库存和区域账本可能各减一次 | 权威模糊 | 同一个区域状态提交器，账本是其事件／会计记录，显示只读投影 |
| 摘要按品类合并后所有者份额不清 | 财产权约束遗漏 | 保留 owner／品类／连通仓储／预留状态，重开不能任意均分 |
| 长期合同与有限滚动窗口承诺混淆 | 合同语义遗漏 | 分开价格／续购框架、已锁窗口和续期失败责任 |
| 住院、返程超过资金窗 | 风险边界遗漏 | 收尾储备、有限授信和上限后的处理，保留义务但不无限透支 |
| 退款／抵扣／债权混用 | 资金守恒遗漏 | 释放预留、现金退款、非现金抵扣、应收应付分开，禁止重复兑现 |
| 32 MiB 只有总数没有字节和条款复杂度 | 预算未闭合 | 给紧凑载荷、记录数、索引、缓存和余量假设，按实际字节准入 |
| 本地 harness 辅助进程在原预算外 | 预算遗漏 | 计入产品进程树，常态 2.50→2.65 GiB，保留 0.40 GiB余量 |
| 30 天监测、历史日志和长期去重可能无限常驻 | 长期增长遗漏 | 分层热桶、磁盘分段与页索引；磁盘满时停止可靠写入之前暂停 |
| 预演固定旧图状态可能阻止切图回收 | 峰值遗漏 | 预演计入固定／脏页，切图先结束租约，有界分块和统一峰值准入 |
| 地图断路等于地图移除，未结义务可能被丢 | 生命周期遗漏 | 断开仍运行本地摘要；有未结义务时拒绝移除，重连保留身份 |
| 总览仍写早期“不切图”，最新跨图协议又定义重开 | 跨文档冲突 | 标记历史演进，必要模式转移以最新共同契约为准 |

## 3. 可复算的设计案例

下列是规则的预期结果和算术校验，不是实现已经通过这些测试。

| 案例 | 输入 | 必须得到的结果 |
| --- | --- | --- |
| 容量不重复扣 | C=10、已占用4、未占用预留3，其中2为本地保底 | 自由容量3，不再额外减本地保底2 |
| 超占用降额 | C=6、已有不可中断占用7 | 自由容量0、缺口1，不能删除第7个义务或全部算正常交付 |
| 供电短缺顺序 | 有效8 MW、既定本地保底6、A/C各合同2 | 本地最多6，A/C同级各1；若物理可达限制更低则继续裁剪 |
| 功率与电量 | 2 MW持续60游戏秒，损耗0 | 交付100/3 kWh；每kWh价格0.60时使用费20货币单位 |
| 煤炭竞争 | 库存10、运行预留3、销售请求8 | 销售8不能全部成功；无其他约束时最多7，燃烧后不在小时再扣3 |
| 共享通道 | 同一桥容量100，两条同级需求各80，无其他流量 | 总量≤100，比例方案各50，不能各80 |
| 预留转实付 | 买方现金100、预留30、卖方现金40，付款20 | 买方80、剩余预留10、可用70，卖方60，现金总额仍140 |
| 破产退款 | 应退20，责任方可用现金5且无别的退款托管 | 最多退现金5，剩15形成配对应收／应付，买方不能收到20现金 |
| 跨窗住院 | 一小时资金窗结束，患者仍占床 | 占用继续；按收尾储备／有限信用处理，既不删患者也不默认无限授信 |
| 模式转换 | 企业甲/乙有各自库存、现金、未清债权 | 摘要与重开保持逐owner守恒，不仅保持全城总量 |
| 区域条数 | 当前中图5000个在途，全世界上限10,000 | 当前记录是全世界集合的子集，不额外复制5000份主体 |
| 元素预算 | 紧凑载荷及显式缓存约26.508 MiB | 32 MiB余量约5.492 MiB；实际开销大时降低准入，不当作已测尺寸 |
| 监测热桶 | 128指标×(1440分钟桶+720小时桶)×64B | 有效载荷16.875 MiB，其余索引另计，不能无限增加指标 |
| 总常态预算 | .35+.25+.85+.25+.35+.20+.40 GiB | 合计2.65 GiB，辅助进程不藏在域外 |

## 4. 后续实现必须验证的失败边界

1. 一项交换在权限、资金、容量、通道或状态空间任一步失败，不能留下部分预留和扣款。
2. 故障降额、共享桥瓶颈、水电耦合求解到限，仍不超过真实物理／库存上限。
3. 重复交付／退款回执、托管转支付、抵扣兑换和债权清偿不重复创造现金或库存。
4. 住院、返程和货运经历停止合同、断网、预算用尽及切图后仍有可追踪状态。
5. 世界运行长期后热内存不随历史无限增长，磁盘满时拒绝新写并暂停，不删去重证据。
6. 预演写放大、保存和切图争用内存时统一准入；不足则返回未知／保留旧状态，不加载双份世界。
7. 真正16 GB Mac 的完整产品进程树和GPU资源满足待测门槛，当前32 GB机器不能代替该证据。
