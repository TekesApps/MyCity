# 属性、运算系统与指标的双向对照

设计补充：v0.4.19，2026-10-19。P＝属性组，S＝逻辑系统，M＝指标族；编号与 [Root／组件](root-component-contract.md)、[首版模板](first-release-object-templates.md) 对齐。这里的“双向”是从字段到指标、从系统／指标反查字段，**不是指标可以直接给事实赋值**。

## 1. 字段和箭头的语义

S静态参数来自冻结模板／profile；A权威运行事实；R有身份、版本和有效期的关系；D有来源可重算的结果；V只作画面。下文S00等系统编号与字段类别“S静态”按上下文区分，不是代码实现模块名。

三类箭头分别为：P→S读入；S→P依法写回事实；P／S→M形成观察。M→行为／提案／合法计划→相应系统→P才是反馈，不能从“满意度低”直接改人口、从“缺电率高”直接增加发电量或让模型写入最终判决。

金额用游戏货币的固定精度整数及舍入规则，资源需resource_code＋单位／量化，时间为统一游戏时刻／区间，人数／户数／岗位／车辆／席位／床位和流率分别计数。P组内每个实际字段还要保留schema路径；本表列出首版必需字段族，不能拿一个P编号当任意JSON扩展口。

同一表可包含不同逻辑所有者的字段，如order.*归S07、transport.*归S04，但同一字段键／资源来源／区间只有一个写入者。各系统发意图／事件，通过S00统一事务提交与幂等恢复；S00不是另一套独立业务模型。静态参数的合法修改也由相应系统形成新版本，不能由指标回写。

## 5. 三条反馈路径与失败例子

**修路目标**：M06显示延迟→查P08真实门／单行、P15共享瓶颈、P20在途和P33限制→S01提出合法道路／入口方案→真实施工→S04重新分配→观察M04／M07／M18／M19及M06，不从“想缩短通勤”直接减少旅行时间。

**工业改善**：M07低且M04正常→查P13实获水电、P19可用库存、P18设备／配方与P21资金→真实采购／网络扩容或维护→S05／S07／S10更新事实→S06新的可行活动→M07和M17改变。不因“工厂升级”把岗位、工资和产品全乘倍数。

**住宅环境诉求**：M18／M19及家庭P34、M21有已知不利结果→S12依法形成冻结区域／高度／时段规则或S01提出有依据改善→硬生效立即失效相关新进入／运行→实际来源活动／路径变化→S11新的覆盖观测→S13按游戏时间更新满意度。没有航空／声模型时不能宣称已改航／降噪；指标不会直接把住宅人清空。

## 6. 双向审查门与剩余工作

- 从模板向前：每个组合C可展开到必需P字段／状态，映射其唯一来源和现有配额；必需profile未配置不通过投运。
- 从系统反查：每个输入字段有明确生产者与游戏时序，按字段键单写；循环启动只沿已有电水联合可行／启动投入规则，不免费补输入。
- 从指标反查：每个M有同口径分子／分母、范围／窗口／单位及覆盖；无来源标unknown／unsupported，缺字段回到P定义及预算补齐。
- 从反馈反查：任何状态变化经行为、规则或合法工程／交易，不从D指标直写A事实；迁移和停用保存原义务／在途／在场。
- 从资源反查：模板／分面不生成新Root表，64×4 KiB模板热页归原模拟域0.25 MiB，原区域39.0078125／44 MiB及应用2.65 GiB目标不增。实例字段与外部页、运行精度／锚点装不下时先改布局／预算，不让Root引用藏新事实。

本版完成的是字段族—模板—逻辑系统—指标族的可追踪设计。各个模板的最终资源／工期／工资／维护／环境／服务profile、字段级内存布局／满意度精度和求解／数据覆盖／经济平衡仍需后续逐项配置和验收；缺项是显式未配置，不能据“矩阵有一行”宣告所有实际数值与性能都已经对齐。
