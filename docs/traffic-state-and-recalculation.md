# 交通基础状态、阶段求解与日常运行

设计补充，2026-10-18。落实玩家提出的“保留交通基础数据，阶段性求解，平时复用并呈现”。本节是 MyCity 的设计选择；不推断原作内部拥有完整逐人档案。来源与原作差异见 [资料研究](sc4-research-and-gaps.md)。

## 1. 三种不同的逐人模拟

| 层次 | 做什么 | 当前决定 |
| --- | --- | --- |
| 逐人通勤记录 | 保存稳定 ID、住宅接入组、实际岗位、时段、方式和共享路径引用 | 可评估的受限实验，不等于完整人生模型 |
| 逐人路线选择 | 分批选择共享候选路径，相同约束复用寻路结果 | 可与群体方案比较，不为每人重复全城搜索 |
| 逐秒个体活动 | 每人逐秒移动、跟驰、换道、购物与社会交往 | 首版不采用；画面仍抽样 |

默认首版仍以群体与稀疏 OD 为基线；逐人周期方案只替换需求与选择层，不改变容量、运输、环境、结算或视觉接口。不能同时将个人和其所属群体作为两份需求。未来默认方案取决于相同负载下的比较结果，而不是认为“逐人”必然昂贵或必然准确。

## 2. 什么数据要保存

| 数据层 | 内容 | 保存与恢复原则 |
| --- | --- | --- |
| 基础状态 | 路网有向连接、转向限制、通行模式、容量与施工限制；住宅真实接入；人口需求；真实岗位及匹配占用 | 存档权威数据，不能靠动画或随机重建 |
| 选择计划 | 起终点、出发时段、方式、候选路线／采用份额、对应人口／岗位和网络版本 | 候选可重算；已接纳行程引用的采用路径／版本和位置依据固定至可合法释放，非可丢缓存；保留种子／切换事件支持回放 |
| 运行状态 | 各时段积压、在途货物、已出发未完成需求、边界转移和已计量费用 | 连续保存；重新分配不能清空或复制 |
| 计算结果 | 计划需求、实际通过量、延误、旅行时间、排放源强及其覆盖和收敛状态 | 带时间／规则／网络版本；缓存可失效，已经产生的账务和累计暴露不能撤销 |
| 视觉对象 | 镜头内抽样车辆与行人、动画进度 | 可重建；不参与人口、交通或经济守恒 |

对首版群体方案，需求人数是权威记录，无须先构造同等数量的个人对象。逐人实验中，人数由个人记录汇总，两者选一个作为人口主表示，避免双重写入。岗位容量与岗位匹配分别记录；未匹配者保留为未就业，不用邻城出口代替真实岗位。

跨城出行有统一来源地图、居住接入、真实目的地／岗位及需求组 ID，经过中间城市不重新产生一名劳动者。摘要也保存边界流量对应的来源、目的与容量引用；图内细路线可以按已声明精度重建，权属、岗位占用、积压和未结费用不得随机重建。

## 3. 稳定城市怎么运行

先求出早峰、日间、晚峰与夜间等代表窗口的需求曲线和路线份额；窗口数量、时间边界与方式支持写入规则版本。夜间不能无条件为零；购物、货运和服务出行按各自能力与时段声明。

稳定区间可复用分配方案，按当前时段实际推进流量和积压；长期稳定且满足前提时可按 [快速策略](game-time.md) 解析累计。不需要每帧、每个居民重新寻路，也不重复播放一份已经完成的历史交通。

缓存的是“下一段时间怎样分配需求”，不是“今天这些人已经到达”。每天生成新的时段需求，未出发／已出发需求的结转政策明确标记；在途或等待者不能又生成第二份同一行程。往返分别生成，各有方向与出发窗口，不因往返计算把岗位占用翻倍。取消或过期也要记未完成结果，不能当作正常到达。

返程依赖去程实际到达；去程滞留者不能从工作地生成返程，取消和次日新需求也受同一行程状态约束。

每条路按方向与时间窗口记录计划需求、实际通过量、积压、旅行时间，并支持查询来源贡献。来源细分采用有界稀疏引用或按需汇总，禁止创建无界路段×OD矩阵；超预算降低解释细分精度并标记覆盖，不能减少总流量和积压。拥堵是需求、服务率与积压的结果，不能只比较全天总量，也不能把流量直接当成同时在路上的车数。

## 4. 何时重新计算

| 触发 | 处理 |
| --- | --- |
| 新增／迁出人口、换岗位、班次或方式变化 | 对相应需求增减，先检查已有路线与接入 |
| 道路断开、方向改变、施工封闭 | 生效时立即禁止失效通行；受影响行程等待、合法改道或失败，不等例行重算 |
| 容量、费用或拥堵成本明显改变 | 更新受影响路线与相关 OD，并检查替代走廊 |
| 新路开通 | 还要检查未使用该路的相关 OD，不能只沿旧路径反查而永远发现不了捷径 |
| 例行逻辑周期 | 检查缓存依赖与成本偏差，分批刷新，必要时扩大到全局 |

“新增100名通勤者”只新增100人的需求，但可能令桥梁越过容量阈值，改变原有居民的选择。路段→路径→OD 的反向依赖加速局部失效；替代走廊与周期检查补足仅依赖旧路线看不到的影响。极端断路或反馈扩散允许退回有预算的全局求解，不能承诺永远只算变化的人。

硬失效与软陈旧分开：旧路已断不能继续放行；只是可能有更快路线时，可在合法容量内暂时保留旧选择并报告陈旧。增量索引本身受字节预算控制，超额时使用有界扫描，不能无限追加依赖。

## 5. 计算完成与城市稳定是两件事

路径分配采用固定逻辑工作额度、有限迭代、分批调整与成本平滑；结果在预定模拟边界发布，不按后台线程实际完成墙钟随机生效。初始最多3轮是预算，不代表3轮必定达到均衡。周期、成本偏差阈值、刷新上限与收敛容差须作为版本化参数在原型前定值并测试，当前不编造已校准参数。

未收敛时发布当前可行分配，超额需求进入积压或未完成量。既有路线不能因为重算未完成就超容量通过；新需求也不能无条件算已到岗。显示路径／流量版本、数据年龄、失效量、未满足量、重算状态及近似级别。无法在预算内安全推进时降低实际游戏倍率，必要时暂停，不用“稳定”标记掩盖未算完。

交通分配收敛只是给定需求下的近似稳定；人口、企业、工资、施工和库存随后变化仍会产生新需求。人口与私人开发用更慢周期和迟滞，避免堵车→全体迁出→路空→全体迁入的振荡。

## 6. 噪声、排放与画面怎样换算

实际交通按路段、时段、车型组成、速度／排队状态形成排放源强和噪声贡献，再结合传播、距离、屏障、气象近似及持续时间计算暴露。首版系数是版本化游戏模型，未经校准不得标成真实环境测量。

可以缓存固定道路的传播系数；不能把昨天的污染浓度原样当成今天结果。空气污染还有滞留、扩散与消散；昼夜噪声、持续暴露与峰值分开统计。若采用分贝口径须按声能叠加，不能算术相加分贝；若采用游戏指数则明确单位。

流量稳定也不代表货物、服务与费用可以停算。画面从对应窗口的实际流量、方向、旅行时间抽样，高速可减少动画；统计结果不依赖可视车辆数量。

## 7. 16 GB 基线与比较验收

中地图以5万居民为比较负载，不等于5万劳动者同时出行。若实验为5万人各设64 B记录，载荷为3.0517578125 MiB；若每人单存平均100条4 B边索引，另需19.073486328125 MiB，因此优先共享路径。以上未计索引、候选路线、依赖、临时求解和预演副本，不能据此证明实际性能。

默认4096个活跃OD等既有额度不因实验无限增加。异质需求超过预算时兼容聚合或明确未解决，不静默删人；个人记录放入当前地图0.35 GiB模拟域，替代／关联现有人口表示，路径与反向依赖分别计费。摘要继续使用有界表示，不能在区域44 MiB表外为7个邻城另放无限个人档案；要跨图保留全体个人身份须先提出持久化与内存方案并重新评审。

比较群体基线与逐人周期实验在同样道路、人口、规则下的求解耗时、缓存复用、峰值内存、未收敛量和结果差异。测试新增人口、主要桥梁关闭、新路开通、替代路线振荡、跨图循环、保存恢复与1日/秒目标速度。比较方案不要求数值逐位相同，但人口、岗位、容量、运输和资金守恒必须成立。

首轮个人实验限定为该地图持续详细运行的测试场景，保存恢复要保留其稳定身份；尚不支持把该实验地图切成摘要。切图前需结束实验或另行设计显式、守恒的个人→群体转换并告知身份连续性终止；不能重开时随机重建个人却声称身份未变。生产基线的群体跨图恢复仍按现有契约运行。

首版保留阶段求解与缓存，不承诺完整逐人身份；是否默认开启个人通勤记录，要等16 GB目标机与高速混合负载证据。

## 建筑出入口是真实交通端点

[出入口契约](building-access-and-traffic.md) 把模板门位／方向、实际合法连接、道路侧／高程／有向锚点及开放状态纳入基础状态。需求从有效住宅／经营单元的合法入口进入网络，步行／顾客／货运／维护分模式验证，临街和最近路段不能代替接入。多门分配同一OD需求，不重复生成出行；口、走廊、道路及目的地容量各自约束。

入口只作相关出行起终点，公共穿行通道另建合法连接，不得形成免费掉头／穿楼捷径。路段内锚点仍需真实距离、方向及转向，临时求解占原预算。关闭／围墙／施工等失效保留在途等待／退出／改道，新道路也检查潜在受益接入组；未完成重算标数据年龄／unresolved，不把未求解当作无路。入口状态引用新增全世界端口表，不为每门复制一份完整路网节点或每帧A*。

## v0.4.18真实占用与硬失效

[空间运行契约](spatial-runtime-contract.md) 要求共享穿行边计入真实网络，门仍只作起终点，边内锚点计真实位置／方向／距离。法规、权限、时段和实体等硬变化先阻止新受限进入，再分批重算；软成本数据可标年龄。缓存绑定实际模式资格、网络／接入／规则／地形、锚点和有效时间，不能共享几何即共享许可。

OD／有界需求仍占4096联合额度，接纳前保留去程、在场与适用返程来源；货运／服务保持原主体，容量组只计同一占用的令牌／汇总。释放摘要与原回执只驱动一次原子释放；满槽不能删除在场来源、另建无界访客或队列表，也不保证所有端口同时有独立队列。
