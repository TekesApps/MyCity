# 从市长命令到运行结果的闭环契约

版本：设计草案 v0.4，2026-10-18。补充既有准备文档缺失的任务权威、设施投运、模拟时钟、持续观察与恢复规则。具体工具以 construction-tools.md 为准；计算预算以 performance-budget.md 为准。v0.3 采用 [三档地图](map-sizes.md)，以 16 GB 和中地图作为基础目标，单张地图内各分区使用统一时钟。邻图未打开时的跨地图周期、容量与账本由 [统一运行契约](cross-map-runtime.md) 补充并优先适用。当前无实现或端到端验收。

## 1. 四种对象不能共用一个“完成”状态

| 对象 | 权威与状态 | 完成含义 |
| --- | --- | --- |
| 市长目标 Goal | MyCity 目标服务；草拟／待澄清／有效／观察中／达标／受阻／已取消 | 在明确观察窗口内满足结果条件 |
| 规划方案 Plan | 工具服务；草案／已评估／过期／已接受／放弃 | 方案被接受仅表示取得执行资格 |
| 建设项目 Project | 模拟核心；已接受／执行中／部分完成／受阻／建成／已取消 | 授权的建设步骤完成，不代表设施已投运或城市目标已达标 |
| 观察任务 Monitor | 模拟调度器；已注册／采样中／待数据／告警／结束 | 按指标与窗口给出结果，agent 不在线也继续采样 |

工具响应 status 是调用结果，不替代上述对象状态。Goal 达标保留事件时间与证据，持续承诺由独立长期 Monitor 跟踪，之后出现倒退产生新告警，不改写历史。

MyCity 目标是游戏业务状态，与 harness 自身的 Goal／自动继续机制是不同对象，不把会话中一句话当作持久化市政任务。

## 2. 命令接收与目标编译

1. 宿主接收 mayor_command_id，绑定当前世界分支、城市、玩家身份和可选选区；重复输入传输按 ID 去重。
2. 命令解析为目标草案：范围、动作意图、预算、禁止事项、指标、时限、优先级、默认值及未决指代。
3. 校验能力并呈现规范化解释。默认值在既有市长政策内自动采用；重大歧义、无法支持的硬目标或超授权事项进入待澄清。
4. 目标服务记录生效版本，再允许规划。创建或修改权限、确认破坏性动作的依据只能来自玩家或已有效的授权政策。
5. 规划与执行请求携带 goal_id + goal_revision。新指令通过明确的 supersedes／amends 关系更新目标，阻止旧版本继续提交；无关联的新命令作为独立目标，不任意取消已有项目。

每个目标的约束区分：施工不变量（每次操作都必须满足）、规划容量条件、运营结果条件和软偏好。把它们混成统一的布尔“可执行”会导致误判。

例如“两万人入住”是结果条件；“总建设投资不超五千万”和“不拆现有居民楼”是施工不变量。结果不可保证时可以尝试建设并持续观察，但必须向玩家解释风险，不能伪装成施工时已证明。

## 3. 授权如何创建和更新

玩家授权与制度依据分开，见 [立法、行政与司法](governance-council-and-justice.md)。立法、拨款与司法命令由制度引擎依据程序生成，不能由agent自签；它们不替行政计划获得玩家授权，也不能被玩家授权绕过。规则化市民申诉不需涉案市长批准；有效停止令、裁决义务与既定自动清偿不等待败诉市长再次同意，保留制度来源及回执。

市长输入的授权经宿主目标／授权服务生成 authorization_ref；agent 可以提出授权申请和读取当前范围，不能调用工具给自己增权。

宿主的接受动作与授权变更同样有玩家事件、版本和操作回执。角色在输入中自称“财政负责人”不会改变权限。

撤销授权从下一原子提交边界生效，停止尚未提交的建设／政策步骤；已生效部分保持。待执行项目按资源类别处理预留；已开工现场、半成品与安全维护不因撤权被当作空地释放。不取消合法的日常居民消费和企业运行。

首版用同一市长管理两个城市分区作为原型默认，账本和政策仍独立。跨区项目逐步列清成本分担、所有权、运营维护方和收费方；未明确这些项不能接受跨区建设。

## 4. 首版时钟与系统更新频率

世界日历与档位以 [游戏时间](game-time.md) 为准：观察1日/10分钟、经营1日/分钟、快速1日/10秒、高速1日/秒均为目标速度。工程工期按游戏日历，不按现实等待。

此前10秒细步和分钟／5分钟／小时更新属于精细策略候选，不能要求高速仍遍历所有小步。快速使用有版本聚合／事件区间，遇投入耗尽、班次、工程节点、账期和状态变化截断，所有联动地图共同推进，账务与未完成需求不丢失。实际速度达不到目标时如实显示。

暂停停止施工、拆除、人口、订单和观察窗口；允许草拟或原子接受项目，不推进工程量。游戏退出不按现实离线补完工程，agent断线不自动暂停已获授权的工程。观察的精度与覆盖须标明策略，不能用快进后的末值冒充整段无违例。

## 5. 建成与投运：修复设施互相依赖

设施与工程状态独立：accepted／scheduled／preparing／constructing → built_uncommissioned → commissioning → operational／degraded／offline，并有停工／取消／待精细验收。建筑几何可以建成但未具备运行条件；只有投运或实际供给成功后才增加有效服务能力。

草案动作依赖无环，端口可引用同组预分配对象。commissioning_group先验证最终设计，各动作按工期施工，全部满足验收时才联合投运，不要求同一模拟步建完。施工进度、停工和拆除以 [工程生命周期](construction-lifecycle.md) 为准。

分期方案允许先建尚未投运的资产，前提是明确标记、不虚报服务，并有合法资金和已评估的后续连接。require_operational表示最终组投运门，而非接受时保证未来供给。验收失败保留已建实物和已耗费用，不能逆转历史施工。

水泵需电、电厂需水、供煤需交通等运营依赖可能成环，不能以未来供应作为当前可用供应。首局提供配置化且计费的边界水电接入点、启动资金和明确初始库存；独立供给模式需另有模板与授权。缺启动条件时报告 bootstrap_dependency_cycle 并停止投运，不凭空发电或出水。

每轮供给在本期库存和网络上联合验证投入与输出，先预留运行投入，再按实际运行扣减。上一期只作求解初值，不能当作本期免费能源；独立启动门与求解失败处理见 cross-map-runtime.md 第 19 节。服务不足按公开优先级分配，更新降额和停运。水网首版为连通性及边容量分配，不承诺水压／水力学；电网首版同样不承诺真实潮流分析。

## 6. 交通、人口与交易怎样接在一起

土地格保存索引和汇总，人口在建筑／邻里群体上聚合，就业和消费在分区出行模型里匹配。空格没有独立市民、agent 或订单循环。

需求先按邻里交通分区聚合，再通过真实建筑端口和道路节点验证接入。统计上住在同一分区不代表每栋建筑都自动获得道路；孤立建筑不享受同区通达建筑的可达性。

为有限候选岗位／商店／供应商匹配建立稀疏需求，未匹配与未到达单独计数，不能把样本外需求当成已满足。超出搜索预算标记 approximate／unresolved 并保留需求，不声称没有岗位或供应商。

货运批次带真实起终点、货量和剩余行程，折算成道路容量负荷；可视车辆是采样表达，既不重复计流量，也不决定全城流量。订单因拥堵延期、改道或取消，并记录交付费用和库存变化。

首版通勤／购物为周期代表流量，不储存逐人逐日出行列表。系统显示“模型估算出行量”，不将代表流量称为完整的逐人轨迹。

## 7. 经济引导、守恒与土地权属

[家庭生活](citizen-households-and-living.md) 将有限培训、住房租赁与空置无租约全款交易纳入首版。按单元／家庭账户检查资金与权利并原子清算，押金非房东收入；租约／住房权益有独立预算，不能拿1024条一般交换合同假装承载所有住户。邻城生活与租金持续，居住权、实际停留、常住登记分别恢复，失房不当步删除人口或选票。

[行业与就业](industries-employment-and-effects.md) 补充真实雇主、必要工种、到岗、工资资金窗口及家庭账户。工资计付后才形成可支付消费，不用收入指标另造现金；企业／居民／物流／市政分开记账，行业层只约束设施交付，不重复生产电量、服务或一般商品。人口统计拆并不重新分配账户产权与工资债权。

私人开发要求地块资格、需求、资本、接入和模板条件；新开发立即增加 construction_revision，并受项目预留约束。已有项目预留防止私人开发抢占，预留外的自动开发不能绕过空间校验。

首版不模拟复杂土地拍卖：私人已占用土地默认不可征用；市长需单独授权并按模板安置／补偿规则处理。土地划分与 zoning 不自动转移产权。

首版不必模拟所有建筑材料，必须在 capabilities 中列明资源域：建设可暂采用现金成本＋容量规则，运行至少有煤炭及一种一般商品。没有实现的钢材、水泥等不宣称已核验供应。

账本明确城市、企业、居民、物流与外部账户。税、商品款、维护费和运费分别记对应方，燃料消耗和污染排放记数量去向；外部贸易、迁入资本与初始拨款都有来源，避免凭空增减资金和库存。

破产时不以负库存或未经授权透支继续施工。缺货、断供、订单违约、人口迁出和私人企业停业具有明确状态与原因，团队可解释并提出调整，不自动替玩家增税或借债。

## 8. 持续观察是工具能力

目标必须绑定 metric_spec：指标 ID、单位、作用区域、分母、采样周期、基线、阈值、持续时间、截至游戏时间、数据新鲜度和缺测规则。

例如“改善通勤”需展开为平均／P95 旅行时间、可完成出行比例、需求人口及未完成出行数；不能仅在成功到达者里算平均时间，让断路后出行者减少反而显示通勤改善。

观察基线在执行前冻结；指标定义版本、模型版本和数据覆盖率保留。至少显示施工前后趋势和同期变化，前后对比只能说明相关变化；若要说“这条路导致改善”，需基于同一初始快照做对照预演，且标为模型反事实估计。

原型达标样例：服务接入率 ≥99%，未完成通勤比例 ≤5%，并连续维持 3 个游戏日；这些只是演示阈值，实际任务按市长目标和游戏配置设置。没有样本、无需求或分母为零时返回 not_applicable／insufficient_data，不能自动当达标。

Monitor 是模拟任务，不靠持续模型轮询。city.events 使用世界分支范围的持久事件游标，断线按游标补读；事件过期返回明确缺口并要求重新读取权威状态，不能静默跳过告警。注册时定义告警阈值、恢复阈值、最小保持时间和去抖周期；首版默认每目标最多每游戏小时一条非紧急汇报，关键失效可即时提示。规则聚合后再触发 City Team 分析。

## 9. 观察后的调整与停止

工具观察得到事件 → 团队读取证据 → 判断既有目标与授权是否覆盖修复 → 形成新草案 → 校验与执行 → 新观察窗口。

原型每目标自动再规划最多 3 次，每次间隔至少 1 游戏小时；超预算、反复不可行或到截止时间未达成时进入受阻并请求取舍，不能无限建路、无限花模型费用。

因数据陈旧而重评估不必都算新施政决策，但计入工具计算预算。已取消或被新版本替代目标的监测可保留只读历史，不继续自动施工。

财务、服务不足和污染是多个目标共享的约束；单个目标不能以局部达标覆盖更高优先级禁令。默认优先顺序为明确禁止／授权边界 → 基础运行保底 → 已接受项目 → 新发展目标；玩家可以在合法范围内调整优先级。

## 10. 预留、租期和两个时钟

模拟条件、工程调度、物流与目标达标使用游戏时钟；网络超时、模型费用和用户操作等待使用现实时间，字段明确区分。

已接受项目的合法预留写入世界，由项目游戏时间计划管理。暂停或保存退出不消耗游戏时限；agent 断线不立即取消合法施工，也不新增授权。

工程受阻1游戏日仅触发告警／重评估。现场、半成品、安全区和已购材料保持实际占用；尚未开工的远期预留可按明确期限释放，恢复重新校验，不能因通用超时释放半成品用地。草案不占地占款，网络计算锁与短期缓存按现实超时回收，不冒充项目预留。

## 11. 日志、回执与崩溃一致性

城市操作由 MyCity 自己的命令日志与检查点负责持久化，不能依赖 agent transcript。每次接受／应用／取消事务连同 operation_id、预算变动、空间预留和状态转换记录为同一权威提交，在落盘成功后发布成功回执。

崩溃恢复从完整检查点及其后的已提交日志重放；未提交日志不应用。回执与实际状态不会出现“建筑存在但操作去重记录丢失”的分叉。日志去重索引在世界分支生命周期内有效；归档后也保留必要 tombstone。

完整存档固定同一 simulation_tick 与命令提交序号，包含目标、监测滚动窗口、项目预留、订单在途和随机状态。只把源文件写成临时文件再替换不足以保证这些跨对象语义，仍需要整体事务／日志边界。

联动地图共用 world_id／branch_id，map_id 区分地图；跨图存档按同一 region_tick 和 commit_sequence 一致保存。加载旧进度生成整个联动世界的新 branch_id，不能只回滚一个城市而保留邻城收款；取消旧分支工具写入通道；可继续显示旧会话历史，但修改工具必须重新绑定世界和目标，操作 ID 不能跨分支混用。

## 12. 闭环验收

| 场景 | 需要的证据 |
| --- | --- |
| 新命令／追加命令／修改命令 | 有明确目标归属和版本，旧任务不误取消或继续提交 |
| 接受／建成／投运／达标 | 四种状态可区分，服务未接通不得虚增容量 |
| 泵站循环依赖 | 原子组可连接新对象，无启动供应时准确报告循环 |
| 私人开发竞态 | 自动开发也增加版本，不能抢占已预留土地 |
| 长期达标 | 指定窗口内持续满足，缺测不当作通过 |
| 断路指标 | 成功旅行平均时间下降不能掩盖未完成出行增长 |
| agent 离线／暂停 | 城市调度与现实超时语义清楚，无虚假采样 |
| 自动再规划 | 有次数、冷却和预算边界，失败进入受阻 |
| 崩溃点 | 状态、账本、预留和去重记录同时恢复 |
| 观察因果 | 实际趋势和模型对照预演明确区分 |


## 13. 邻图运行与观察

RegionRuntime 在游戏运行时推进所有已连接地图，未打开者用摘要，不运行高清几何和逐栋循环。游戏暂停／退出暂停整个世界；模型离线不暂停。详细与摘要表示的切换是日志化事件，同一地图不能同时由两者生成生产、库存或账单。

监测附 map_id、source_mode、coverage、measured_tick。摘要账本与交付是真实模型结果，逐栋响应等空间细节可能待验证；不能一概称准确或一概当作无效数据。完整转移和回放规则以 cross-map-runtime.md 为准。

## 14. 有界运行与持久化

区域时钟推进前必须保证当前事务可落盘；磁盘满、无法可靠提交时暂停世界，不继续发布成功回执。长期幂等证据走分页持久索引，不要求全量常驻内存。监测的热桶、对象数、记录大小与超预算准入以 performance-budget.md 第 12—14 节为准。
