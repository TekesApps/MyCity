# 首版财政经常收支、工资税与长期维护契约

设计裁定：v0.4.33，2026-10-19。落实 [全局台账GAP-01](global-design-coverage-and-freeze.md)，定义可统一配置的首版财政规则，不继续扩展单栋楼或单次救助案例。全部税率、程序、周期均为虚构游戏规则，不对应现实税法；当前无实现、平衡或16 GB性能证据。与旧文档笼统“税收／工资入账”口径冲突时，本契约的有限类型及毛薪／净薪规则优先，历史冻结案例不追溯改账。

## 1. 财政主体和六种数不能混用

财政按city_id的真实账户与管辖运行，不按map_id、土地格、建筑数量或agent角色自动生成。一个财政主体可跨地图，多个财政主体也可在同图；总部、住宅登记、劳动地点和实际收款主体分别明确。

| 数量 | 唯一含义／落点 | 不能当什么 |
| --- | --- | --- |
| 财政现金 | 原账户已发生真实转入减转出 | 不能含应收税、未来服务报价、资产估值或拨款数字 |
| 有效预算／拨款额度 | 制度批准的可承诺用途／期限上限 | 不是现金，也不替代玩家权限、合同或资源 |
| 未付确定承诺 | 已依法接受且尚未支付的合同／工资／采购金额，沿原来源 | 不与之后实际付款重复计预算，不因新年度删除 |
| 受保护现金 | 同一原现金中按明确义务／窗口保护的份额 | 不是第二份余额；支付时释放相同保护并转账，不再扣一次费用 |
| 应计／应收应付 | 已发生但可能未到支付日或尚未支付的权利义务 | 不等于实缴收入／实际支出；不得拿应收保证开工 |
| 预测／长期负担 | 有版本、窗口与不确定性的派生测算 | 不是已经预留的钱或已完成维护 |

资金、拨款和合同承诺分别按来源去重。财政负责人只能在有效规则与玩家授权内提出／执行方案，不能取用企业／家庭的钱来修正市府指标；模型现实费用仍独立于游戏财政。

## 2. 首版收入白名单

| 收入来源 | 首版规则／真实付款方 | 经常性判定／限制 |
| --- | --- | --- |
| 受支持雇佣工资税 | 下节唯一首版税种，雇主结算毛薪时同步扣缴至指定财政 | 只计实际已缴；来源是已登记真实劳动，不给空岗位或未付欠薪造税收 |
| 已支持公共服务／供应收费 | 真实服务／水电／共享能力的合同或有效条例费用，实际使用／购买方付款 | 仅财政本身是合法收款主体且实际交付时计该财政经常收入；EU／WU／医院等独立运营账户收入不自动上缴财政 |
| 财政持有普通住宅的租金 | 财政确为已支持H房源所有者／出租方，租约真实履行、实际收款 | 沿原H账务与维护／押金责任；不新增土地出租、商业租赁或房产投资机制 |
| 有限启动／专项拨款、捐助 | 已声明出资者、现金、金额、用途、期限与有效依据 | 一次性／有限转移，单列，不因日历刷新；不作为没有期限的经常收入 |
| 资产处置、退款／追偿／赔偿回款 | 仅原已支持交易或经核定原权利实际清偿 | 非经常收入，不以售地、未实现房价或追偿预测担保维护；抵扣同一原成本／损失后展示 |

首版不开放利润税、增值／销售税、房产估值税、土地增值税、财富税、关税或任意自然语言税种；未支持的罚金、发债、贷款、保险及企业自动利润上缴／分红也不能由改一个税率字段启用。私人商品买卖与工资仍各归真实主体，不把全城销售额加总成市府收入。

普通服务收费必须对应真实能力和付款依据；没有交付的部分按原条款处理，不能把“服务费”当无限通用税。公共代付清同一原费用，不能既记财政采购收入，又让家庭／业主再付一次。公共企业需按原账户／运营范围单独核算，不因同属市政就复制现金或隐藏经营补贴。

## 3. 唯一首版税种：已登记雇佣工资税

### 税基、归属和法源

应税范围限于已登记居民劳动份额／雇佣关系下的工资及明确纳入同工资来源的停工保底；**税基是实际清偿的毛工资**，不是本期理论岗位、应计未付工资、家庭全部转入或营业额。奖金、佣金、按揭／财产收入／补偿综合计税仍未支持；解约补偿等非工资类型首版不纳入此税，沿原义务处理。不能把普通工资重命名补助／承包费规避，来源类型由合法雇佣／服务契约决定。

City Team及司法等抽象行政专业服务、外部承包／合格作业采购不是新增居民工资税基；它们没有额外本地人口与雇佣来源，不据此形成虚构税收。将来映射成真实居民雇佣须重新准入，不能同时取两种口径。

税收归**劳动区间所属已登记运营地点的城市**：随工资来源固定city、适用税率／规则版本、起止与应税类别；家庭居住地、总部或转账经过城市不再征一次。雇主地点／城市／规则生效改变时切新劳动段，旧欠薪补发仍按原劳动段。无法确定唯一受支持工作地点的异地用工配置不进入首版承诺，不能发薪时猜归属。公私雇主的已支持真实居民工资适用同一规则，不按雇主名称豁免。

税率使用整数基点，0—2000 bp（0—20%），配置默认1000 bp（10%），1 bp步长；这些是待平衡游戏参数，不是保证财政充足的比例。每城首个税规则必须在开局已合法生效或按原法案程序产生，税率为0同样是显式配置。无规则时不能擅征；新税只适用生效后的劳动区间，不追溯旧欠薪。既有案例原冻结税率／范围继续适用，不把本默认10%补进历史账。

### 工资支付与扣缴同一事务

工资按原日结、周结或公历月结周期到期，本税不再加家庭申报／月底缴税周期。劳动发生时记录毛薪应付，雇主保护已接受班次的**毛工资**；家庭尚无可花收入，财政尚无实收税。清偿一个已到期来源的毛薪G时，同一提交完成：雇主−G、家庭＋（G−税）、劳动归属财政＋税，并按G减少原工资债权；雇主不能先付净薪、把税款继续自由使用。

部分清偿只对本次G扣缴，剩余毛薪仍欠；同一到期／优先级内按原稳定来源顺序，不能专挑低税段消灭高税工资。款项来自原毛薪保护，不额外扣第二份税预留；税不侵吞其他家庭或其他已接受工资的资金。法律规则、现金／保护、N累计、工资余额与回执联合校验并原子提交；失败保持原资金／债权，不提供“净薪已付但税没记”的中间成功。

### 累计与尾差

全世界新增有界**工资扣缴累计源**，以（真实家庭账户、劳动归属财政城市）为稳定键，同城多雇主、日／周／月结、离职／换岗位／迁居和税率改版不重置。跨城市分别占源，不能跨城平均或转移税款余数。

金额先用既有游戏货币最小单位。源内N是已实际清偿应税毛薪各段的精确计税分子：Σ（G最小单位×该劳动段bp率）；N不是现金、税款余额或历史实缴。每笔新增清偿税额为：

`tax = floor((N + G × rate_bp) / 10000) - floor(N / 10000)`

原子提交后更新N；分数余量为N mod 10000，不另存可推导的第二计数。拆付款、换雇主、改发薪周期不能反复舍弃小数；不同税率仍按各段正确权重累计。同城同家庭未达最小货币单位的分数继续保留，不因换年或换岗位清零。现金统计实际扣缴与退补另读原账本，不能拿floor(N/10000)冒充净实缴。

## 4. 更正、退税与欠款的有限闭环

首版普通税票更正申请期为原工资清偿receipt后1个游戏公历年，按原周年／闰年规则；这是预先生效的虚构程序参数，不是现实法定时效。期限内可靠收件固定申请时刻，排队／复核不丧失该请求。仍在更正期或有已收件请求、已知待修错误／审计异常的累计世代不得销毁；事务损坏／重复恢复不能靠时效掩盖。更正权已明确终结的旧世代不再接受普通税基调整，证据仍按原存档规则保存。

正常扣缴没有独立“雇主代扣未缴税债”——税与工资同时清算；雇主没发毛薪就是工资未清偿，不先向市府计一笔可花税款。税率改低、家庭迁居或旧欠薪补发都不自动触发退税。

首版只允许有原receipt、原应税来源与有效核定依据的三类计税基础更正：误用该劳动区间税率、错误劳动归属城市、错误应税类别。不得由agent直接改N／税率历史，不能用新条例追溯否定合法旧税。重复现金税转账而N并未重复计入时，仅核退原错误现金，不改变正确N。工资返还／负工资、年度汇算、家庭扣除、亏损抵税和任意现金抵扣暂不支持。

更正从**原票当前有效且尚未被本次覆盖的贡献**求差，串行校验同一税源版本及更正覆盖，检查N非负／引用和整数边界；更新当前有效N与其派生余数，并保存原事件和更正回执。不是回滚历史，也不是永远不修正错误累计。按提交时N前后整数商差，分别形成财政退款或家庭补缴的原义务：未支付退款是财政应付，不是家庭现金；补缴未收是财政应收，不是实缴。未来正常工资只按更正后的N增量扣税，历史退补独立清偿，不暗自拿工资抵补税／待退款。

跨城更正联合预检旧／新税源、义务与索引，原子更新双方N和退补责任；旧财政未退款不能当新财政已收款，不能因两方净额相同就只做一笔无来源抵消。相同更正幂等返回原回执，不重复减原始整票分子；争议、证据不足或缺少可判定类型继续原程序，不由LLM猜税额。

退款实际从原责任财政真实可用／有法定依据的现金支付；不足保留退款债与到期、按既定保护／优先级执行，不自动借贷。已核退金额／已退／未退及原税覆盖从持久回执／有界反查查询，禁止同一税款同时退款、抵扣和赔偿。税欠款／退款义务沿原65536条表，申请／裁决引用同一本金，不增加税务司法钱包。

## 5. 支出与长期维护的全成本边界

| 支出类别 | 必须包含／归属 | 不能省略或重复 |
| --- | --- | --- |
| 经常运行 | 已支持行政／司法／City Team、公共雇佣／采购、道路管网／环境卫生维护、公共服务、公共资源消耗 | 抽象团队费用不能再算一份本地岗位／工资税；合同已含人材不在同财政重复加人工 |
| 资本与退出 | 工程、改造、更换、必要接入、安置、拆除／废物、合法补偿和安全收尾 | 建筑造价不是完整生命周期；付钱不等于施工／修复完成 |
| 有期限转移 | 有法源的公共代付、援助、跨城转移等 | 必须有对象／用途／上限／起止；不变成永久兜底或同成本重复收费 |
| 已确认历史义务 | 已发生未付工资、工程尾款、退款／赔偿及裁判责任 | 缩预算、跨年、换管理或关设施不能删债；不能只看“新单”忽略旧尾款 |

每项公共资产／已购买长期服务须有原主体／管理主责／实际作业方、供给、普通维护、故障触发、更新／退出与付费依据。可扩建容量要同时评估新增运行和交通／排放等后果，不能只报建设价。私人设施仍由原责任主体维护，不因缺钱自动进市府预算；公共补助需要独立有限授权。

真实经常现金支出与长期更新资金目标分开。更新目标根据已有寿命／条件／受支持更换报价、剩余窗口和残余物／净回收成本计算；缺参数显示unknown，不能默认为0或用房价上涨冲抵。为更新保护的现金仍在原账户，不是本期维护已交付／已支出，也不等同完整会计折旧；更换发生时按真实工程与钱结算，不再重复计一份已花“更新基金”。

## 6. 年度预算与跨年承诺

财政年度为游戏公历[1月1日,下一年1月1日)，常规预算由议会按原公示／表决／生效程序批准。首个不完整年度按开局有效授权区间运行，不用按比例自动生成钱。预算有city、年度／有效版本、可承诺用途、金额、政策与资金证据；最多12行分类（如行政、司法、交通、管网、公共服务、环境卫生、资本、转移、应急与退出等），未使用类别不造空余额。

每行检查`已实际付款 + 尚未支付的确定承诺 <= 有效授权上限`，同一来源从承诺变付款只转换一次；预算调剂／追加必须经有权限的版本化程序，不能让agent自行搬额度绕用途。现金和玩家支出权限另检查，批准额度不替代资金。撤减预算不能注销原已经发生／有效接受义务，超新上限的既有部分单列受保护历史负担，限制新增并报告。

跨年先封闭旧实际区间、保留应付／未履行承诺与保护，再生效新预算。上一年未用额度**不自动**变下一年新额度；旧已签合同的续存只是原确定承诺，不重发一次授权或款项。跨年新承诺须原已有效的明确跨年／多年度授权及真实资金窗口，不能靠“明年会批准”签约。按来源区分承诺原授权期、实际服务期及付款期，报告可分别查看，不把同一笔支出在两个年度都计新承诺。

预算换年未及时通过时，仅原宪章预置、有限的既有义务／必要维持权限可适用，且仍需真实现金；不是无限按上年预算续期。未签新采购／新发展支出不自动继续。公示、法案及预留来源满额时走原规则排队／受阻，不能静默延长税率或支出权限；税规则是否持续以其自身有效期间为准，不由年度预算倒改。

## 7. 现金承诺门、维护续期与财政退出

接受新建设、人员、服务和维护窗口同时校验：有效预算及用途、玩家授权、现金／保护、实际供给／作业、状态／收尾记录，以及必要产权／制度程序。预测税收不是其中现金；工资税进入财政的同刻顺序沿 [闭环phase](closed-loop-contract.md)，不能抢先花尚未提交的收入。

维护默认规划参考窗口30游戏日，实际接受窗口沿模板／合同，不强制全城改同一周期。**只有已接受窗口的确定投入及独立、可执行的安全收尾形成保护**；未来30／90日估计不等于全额预付或已收工资税。跨更长窗口的计划区分确定承诺与有条件后续，不用同一78同时担保运行、全部安置和下一个窗口。

保护来源必须可追到合同／工资／工程阶段／法定义务，受限资金不可用；实际付款减少同一现金并释放相同保护。没有足够窗口资金就不接受新增承诺，不能先让工人免费维护。已发生耗用、故障、安全责任和旧债仍须记录，不能用“未接受新单”拒记。

每个有限补助／接管到期前，复核后续实际付款者、作业与管理主责、真实资金、交接／安全退出和未决责任；到期结旧再接新，不自动续补。换管理不免原不可委托责任，旧债回原债权人；无人出资须报告未资助维护／安全缺口，不能强摊守约人、注销住户或伪报移交成功。新一轮公共支出必须另有适用权限／真实钱，如实计为继续公共资助，不改名称隐藏无限兜底。

## 8. 持续运转的观察口径与政策反馈

按完整游戏快照列三种不同结论：

- **当前可执行**：已落实本窗口额度／资金／投入与退出，不等于以后有收入。
- **经常运行可维持候选**：有覆盖的经常实收与经常运行／维护相匹配，历史义务和更新目标没有被漏掉；仍受需求、劳动、交通、人口、价格／来源与规则变化影响。
- **结构性缺口／资料不足**：持续靠一次性拨款／卖资产／未付维护过日子，或缺少足够观测／参数；不能显示“平衡”。

每公历月封闭一次报告，按游戏日有界重评资金／维护阈值；另看滚动30日实际与未来30／90日已签确定承诺＋有覆盖预测。首次不足30日标insufficient_history；预测注明已落实、条件性和未知，不捏造置信度。首轮观察建议至少3个不重叠30日窗口，比较经常净流入、经常运行支出、法定旧债／欠维护、更新现金目标、最低可用现金与已筹资天数；阈值是待平衡参数，不保证城市永久稳定。

合并展示时同一财政控制范围内的纯内部转账相消。市府自己出毛薪又收回同一笔工资税，可在明细分别列，但经常收支／覆盖率同时用一致合并口径扣除这项自付自收，不能靠加公务员毛薪创造可持续税基。独立企业／公共运营主体收入和成本保留自身账本，未经支持的上缴不是财政收入；现金净变化、预算执行、应计结果和真实服务质量分别显示。

经济循环应是：真实经营／劳动→毛薪支付→净收入消费与实缴工资税→依法公共支出→真实服务／供给／劳动。税是现金转移，不是创造财富；进口持续净支出会消耗本地钱，有限外部销售／合法转移可带来现金，均必须有真实买方／额度与运输。不能以无限出口、自动移民资本或补助强行维持任意开局。

当出现缺口，City Team提出范围明确的缩减／分期新建设、减少未接受采购、依法调整有限税率／实际收费、真实运营效率／产业与交通改善、有限转移或合法接管／退出；每种选择保留权利、工期和真实后果。不得直接写财政收入指标、随意涨旧合同价、挪保护款、自动借债或让服务无成本继续。

## 9. 字段、权威、容量与16 GB预算

不加通用“税属性”到每个建筑。原C10财务绑定、P17工资／P21财务与S08账本继续权威；制度S12固定合法范围／税率／归属版本，工资来源固定劳动区间，S08统一转账／扣缴／更正，S13只读报告。下表为财政专用契约，不是给143条通用路径追加免费动态JSON。

新增**全世界32768关系×16 B＝0.500 MiB**扣缴累计源，以及**全世界64个活跃预算期×1 KiB＝0.0625 MiB**。预算期包含各城当期、待生效、旧期仍需维持热描述的共同配额，每期最多12分类；64不是每城64。只剩已明确移交义务／原票的旧期可归档，不能为省槽免债。

扣缴16 B目标为两个4 B紧凑句柄＋N8 B；它**不包含**工资条款／代际目录／反查／变长键表的字节。已有稳定身份、4 MiB索引／分配器、工资正文页／制度工作页和原存档限额承接实际反查与证据，若句柄或索引装不下就重预算／限制新配置，不能硬塞32 B岗位边、96 B账户或32 B义务，也不能声称已证明sizeof。静态税率用原256规则槽，每城新法与旧待结版本仍共同占用。

原27项43.0078125 MiB加0.5625，现**29项43.5703125／44 MiB，余0.4296875 MiB**；在原区域余量内重划，不增0.35 GiB模拟域、314.025 MiB其他模拟用途或应用2.65／3／4 GiB目标。新累计不占4096供应计量，也不为每个税源占1024一般采购C／建立家庭年度申报表。完整身份／索引／页／保存高水位仍未验，剩余余量不是免费对齐／键表的证明。

税启用／新应税用工／工作城市改变前，联合预检现有已承诺工资所需关系、政策、义务与预算期来源。带余数／未结工资／更正请求的关系不因离职／换年删除或归档绕过32768；只有该累计世代所有历史税票更正权按第4节明确终结，且关系已结束、无累计余数／未结工资／尾责／审计异常，证据已持久移交才可回收。仅“暂时没人申请”或“票据已归档”不满足；仍有更正权必须保留同一有效N。以后新世代不得从零累计再减旧世代票据；不得通过分页规避32768全世界关系上限。不同财政规则／旧工资来源仍可在原义务保留，不按每次发薪常驻无限工资单。

## 10. 定义关闭与后续验收

本轮关闭GAP-01的**首版规则定义**：收入白名单、唯一税种与归属／周期、工资同步结算、累计／退补、年度预算／跨年、维护与退出、持续运转观察及显式状态预算均有落点。未关闭统一开局／完整参数／反馈稳定性／真实字段和性能；默认10%与现有成本不能据此认定已经平衡。

实现前验收入口收敛为规则／不变量，不增加城市故事：毛薪＝净薪＋实税且清同一毛薪债；同城拆雇主／支付不丢余数、跨城不双征；税改生效切段／旧欠薪保留；有覆盖更正和跨城退补原子不重复；预算承诺变付款只计一次／跨年不抹债；预测不当现金、维护与收尾不重复保护、临时援助不自动续期；同一策略、规则版本与事件序列可确定重放；不同速度／摘要策略保持现金、义务、计税、权限等硬不变量，并满足其已声明近似误差界限。原型再将它们接入同一开局和16 GB联合负载，不从几笔静态算式宣称城市可持续。
