# 人口群体模型与市民／车辆表现

版本：设计草案 v0.4，2026-10-18。明确玩家提出的方向：首版不做逐人逐车的完整社会模拟，以聚合模型产生城市结果，再用受约束的随机动画表达。

## 1. 产品决定

阶段性求解与缓存是基线优化，不需要逐帧全城重算。逐人保存有限通勤计划、共享寻路的实验仍可评估，与逐人完整社会模拟分开；详见 [交通状态与重算](traffic-state-and-recalculation.md)。首版默认表示仍按下述群体方案，实验通过负载比较后再决定是否替换。

人口、就业、收入、消费和迁移按群体计算；通勤、购物和货运按稀疏需求及交通网络计算。画面中的市民与车辆是这些结果的可视样本，不能反过来决定经济与交通总量。

用户可以看到像独立个体一样活动的人和车，但没有必要让每位居民拥有姓名、完整亲属关系、人生历史、每天每次购物和单独的全城路径搜索。家庭财务与住房归属则按 [市民生活](citizen-households-and-living.md) 保留，不因群体模拟而平均分配私人资产。

这一选择既减少计算与状态复杂度，也使交通和政策后果可解释。首版把计算预算用在通达性、路段容量、就业和供应反馈，而不是每个人的生活细节。

## 2. 哪些资源可能消耗最多

尚未实现，不能以实测口吻排序。按当前设计，预期热点如下：

| 工作 | 为什么昂贵 | 首版处理 |
| --- | --- | --- |
| 交通路径与流量重算 | 路网大、起终点多，断路使缓存失效 | 聚合 OD、一对多查询、缓存、固定迭代和工作预算 |
| 高清渲染 | 高分辨率、建筑、阴影、透明效果和人物数量 | 实例化、LOD、裁剪、受限可视数量与场景比例 |
| 城市隔离预演 | 额外运行一份交通、经济和人口状态 | 最多一个完整预演、共享只读数据、分层预测 |
| 复杂几何建设 | 曲线包络、地块切割、碰撞与保护区 | 空间索引、局部求解、按需执行，不每步全城重算 |
| 人口／企业周期更新 | 群体和企业数量、模型复杂度 | 日／小时周期批处理，稀疏活跃集合 |
| 模型推理 | 网络延迟、token／费用；本地模型还占 CPU／GPU／内存 | 一个协调会话按事件触发，默认远端模型预算 |

若改成逐人逐车，活动安排和大量个体寻路很可能加入主要热点；但“每个人存一条记录”本身不一定比交通重算更贵，真正成本来自更新频率、搜索次数与交互复杂度。

headless 模拟可能先受交通限制，4K 密集近景可能先受 GPU 限制，预演时又可能先受 CPU／内存限制。必须分别测，不能预设永远只有一个最大瓶颈。

## 3. 群体如何表示

群体可按住宅／邻里、基础技能、就业状态、收入档和通勤目的聚合，保存人数、劳动参与、收入／支出摘要和需求权重。没有活动的人不需要逐帧更新。

例如一个群体表示“这个街区 240 名居民，其中 110 名劳动参与者、80 个已匹配岗位”，岗位与消费通过共享分配模型计算，避免同一岗位被多个群体重复使用。

16 GB 中地图正常档 5 万居民、5000 群体是待测预算，平均每群体 10 人，并非固定每 10 人建一个对象。早期原型可以更粗，群体只按模型需要拆分，不能为了视觉上的每个人强行增加群体数。

接入条件不同的建筑不能完全混在一个平均群体里，从而把道路断开的住宅也算成正常通勤；至少保留其接入／服务分组。过小群体按兼容规则合并，权重和总人数保持守恒。

## 4. 交通代表流量

底层计算起点、终点、周期需求、可行路径、路段流量、旅行时间与未完成出行，不保存每个居民一天的完整轨迹。

道路容量、路口瓶颈、货运负荷和通勤延迟由模型决定。模型车辆当量与画面车辆数分开：可视 5,000 辆不代表全城只有 5,000 次出行，也不能把这 5,000 辆再次加进模型流量。

模型的流量单位使用车辆当量／游戏小时，行人可用人数／游戏小时，旅行时间为游戏秒。人口出行转车辆当量时使用配置化的方式份额、载客率和货车当量；首版交通模式按 capabilities 声明。

周期流量不是同时在路上的车数。估算局部在途数量应结合流量与局部旅行时间，再按显示比例采样；不会直接把每小时一千辆画成同时一千辆。

## 5. 表现层的随机性怎样受约束

画面层根据模拟快照为当前可见路段与街区分配有限的可视预算，使用独立随机种子产生间隔、速度差、外观、短暂停留和局部动作。

| 模型结果 | 画面表达 |
| --- | --- |
| 人口与商业活跃度高 | 可见行人更密集、店铺周边活动增加 |
| 某方向通勤流量大 | 对应路段和方向车辆更频繁 |
| 路段拥堵 | 车辆减速、有限可见排队和更长停留 |
| 工业货运增加 | 运输路径上的货车比例提高 |
| 商业停业或居民迁出 | 相关街区活跃度逐步下降 |
| 断路／封闭 | 停止跨断点生成流线，既有表现平滑退场或等待 |

随机性只在模型给定的流量、方向、可用空间和速度范围内变化。外观随机不应出现大量车辆穿墙、在无路处通行或逆向穿越单行道。

可视个体沿已生成的路段／人行走廊及缓存路径片段移动，用曲线参数推进和轻量局部排队；不为每个可视人物做全城 A*、真实碰撞物理或社交推理。更精细的避让属于独立视觉质量预算。

## 6. 摄像机、LOD 与连续性

只在可见范围和少量边缘缓冲区维持具体个体，远景改用更低密度实例、流量纹理或统计图层。离开视野的对象可以回收，不维持全城不可见人物的逐帧动画。

摄像机靠近时从同一世界快照和局部表现种子恢复一致的密度；短期缓存减少来回移动时明显跳变。模拟随机数与视觉随机数分离，在同一已进入城市内转动相机、修改画质或改变可视数量都不得改变经济结果和模拟回放摘要。详细／摘要模式切换的近似和额外回放日志见 cross-map-runtime.md。

未实现逐人身份时，点击市民显示“该地区居民样本／所属群体与出行类型”，不要编造为真实持久居民履历。未来若加入少量可跟踪人物，应单列对象预算与持久化规则，不将所有市民升级成同等复杂度。

## 7. 可视预算与降级

16 GB 中地图初始可视上限建议：2000 车辆＋2000 行人，共 4000 个活动实例；小地图各 1000，大地图扩展各 5000。上限不是每帧必须全部出现的数量，也不包含建筑实例。

这些是全视口预算，不按每土地格分配固定数；多个游戏视口共享总预算，不能开一个地图窗口就把预算翻倍。具体 CPU／GPU 时间和网格复杂度须实测。

超视觉预算先降低远景密度、角色细节与动画频率，保持图层统计和模型流量不变。可视采样率、LOD 与实际统计可查询；界面不把抽样动画称为一比一全量交通。

暂停冻结活动表现；暂停下的相机移动仍可改变可见对象集合，但不产生新的模型行程。倍速提高游戏推进速率，视觉可做平滑和采样，不需要把动画物理频率与模拟倍速同步增加。

## 8. 必须保留的模型真实性

减少个体计算不意味着取消交通后果。以下结果必须由底层算出：道路连通与容量、路段拥堵反馈、岗位可达性、未完成需求、运输到货时间、库存、供水供电与跨区污染。

不能只用“人口多就画堵车”代替路网模型，也不能仅在镜头附近模拟经济。当前地图内所有行政／经济分区持续参与模拟，镜头外无需可视个体，但不能停止必要的交通和经济计算。已连接且未打开的地图只常驻轻量摘要并持续运行，详细资源不常驻。

若底层是汇总交通，界面不承诺每个可视车队长度都与真实排队长度严格一致；用热力图和指标展示权威拥堵，用动画提供一致的体验。

## 9. 验收

- 把可视人物／车辆上限设为 0 或提升，保持同一命令日志和种子，模拟关键摘要一致。
- 来回移动／缩放摄像机，不改变人口、订单和路段流量。
- 稳态下可视方向、密度和速度与模拟结果相关，随机性不会改变道路合法性。
- 断路后不再跨断点展示正常通行，未完成需求在权威指标里保留。
- 降低画质和远景个体后帧时间改善，模拟质量与交通求解配置不偷偷下降。
- 人物点击信息准确说明为样本，不伪造完整居民身份。
- 同时报告群体数、OD 数、实际寻路次数、可视实例数和帧时间，避免只报人口数。

## 10. 工地与快进画面

施工人员、机械和拆解动画由阶段进度采样，实际工时、废料、排放和道路占用来自工程模型。快速档可跳过视觉中间帧，不能跳过模型后果；镜头外与摘要工程仍按获批规则推进。详细规则见construction-lifecycle.md及game-time.md。

## 家庭必要状态与统计批次

聚合计算不代表合并财产权或丢失家庭差异。[统一闭环契约](closed-loop-contract.md) 单列最多32768条家庭必要状态，同户多劳动来源／课程引用已有劳动匹配与教学状态；统计画像可重建，既有家庭失业、失房或暴露变化不要求再申请画像槽。它不增加逐人日常agent，画面样本仍不能冒充这些家庭的完整个人履历。
