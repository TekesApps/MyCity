v0.5.14状态更新：[P-BOOT有限启动输入实验](m0-boot-runtime.md)已另行实现并实测通过；本篇v0.5.13记录中的P-BOOT not_run为当时状态。真实公用网、全源统一执行器、区域经济共同运行、完整日历工资、长期平衡与16GB联合门仍未通过。

v0.5.13实施契约，2026-10-19。仅实验Rust模型，不做UI或AgentKit；经济平衡不在本阶段。按[M0计划第4节](m0-implementation-plan.md#4-经济原型分清算对运转和好玩)验证真实执行，不把预写终值当结果。

## 1. 固定实验profile与权威

pe0-30d-v1只适用于laboratory_only世界，四方财政／家庭／加工企业／有限库存供应方。期初输入沿原600Q原料及30000币现金；企业有一个空原料槽和30个已预留空产成品批次槽，各有唯一零值资本来源，未增加现金或产品。每批10Q，原料40币、8h直接劳动80币，产成品成本120币；保留独立取得批次，FIFO实际出库，不重置旧批成本。

资金／保护和库存仍在原World表，经济状态只保存时钟／阶段、唯一在途碎片、有效工时、实际消费／收入成本、税和债务来源。原库存出库后才进入在途，入库／消耗后清在途；不能两处同时存在。经济受管库存不允许generic MoveStock绕过活动。现金保护记录原账户的一部分，不重复扣钱；generic保护释放不得侵占活动仍依赖的保护。

单一实验时钟按游戏秒推进，每命令最多1h，遇事件截断；本实验暂不与Region内生推进混装，拒绝同时启用，避免两个独立钟改同一批工资。暂停不调用推进；不读取墙钟，未完成同一事件的存储失败不越过。开日事件在下一时间区间开始时执行，关日在末边界执行，观察day3末不能偷偷发出day4采购。

## 2. 日内真实活动

每日00:00查原料／企业可用现金和已预留输出槽，再保护采购40与工资80。无料且无企业已存原料时不接纳新班次，不造工时或工资。若上一停工留下合法原料可用，下一班使用该批，不重复买料。

原料00:00发运，采购款实际支付或核销已有预付，货从S移入C名下在途，约定为发运转属；01:00才到C可生产库存。实验通道来源／1000m／1h、在途10Q、每日总20Q显式冻结；它是有限交通原语，不证明车辆、道路拓扑或实际运费模型。profile电／水／废物系数显式为0，不能复用为正式厂房免费运行。

01:00开始劳动，按8个小时事件累计实际工时。09:00支付毛薪80（F净72、G工资税8），生产实际扣10Q原料并形成10Q产品及成本120。F整单6Q／120币、G整单4Q／80币：不足资金／库存则记录拒绝并继续，不卡死世界，不自动贷款或改成免费交易。接纳时保留真实资金、移出对应批次至在途，10:00到达后付款与实际消费、销货收入／成本同一事务确认。保护／交付／费用不能双计。

成本确认采用售出部分的批次成本。低现金分支day3只G买4Q，收入80、销货成本48、利润32、未售6Q成本72；后续新批不能覆盖它。已接受班次暂停／取消时工资保证仍按已声明条款履行，未形成产品的工资费用化，不把保障工资虚增库存。实验支持显式停止当前已接受班次，用来验证停工损失与原料保留；在途仍必须到达，不能靠取消删货。

## 3. 税、预付、债务与退出

工资税随实际工资付款确认；生产直接工资资本化入该批。利润税应计为floor(max(本窗累计销货收入−累计销货成本−停工工资费用,0)×10%)，每天只更新累计应计和差额；降低应计不退现金。day30边界到期真实缴纳，钱不足保留税债，不把预算授权当现金。

已有合法债务从独立实验输入来源登记，不生成现金；到期可部分支付，仅使用未保护现金，剩余债权保留。来源是实验合法事实，不等于已实现法院流程。停止活动前先准备退出／封账，把税等义务物化；只有在途／班次／保护清理完毕，未付义务已交持久责任登记（原债务人及债权人不变）才释放active标志。关闭活动不删除债／存量资产，关闭后义务钟仍可推进。

预付款只允许一个有限未来原料订单，数量受真实S库存和剩余30日范围约束。已发运的转属货及真实劳动不回滚；取消只对未发运部分形成唯一退款义务。退款以S真实可用现金支付，缺额保留原债权；重复取消不能再创债或发钱。预付款不是收入，发运才按约定结转；还未发运的预付余额是卖方负债。

## 4. 本轮验收目标与范围

P-E0须真实推进30日并得到G/F/C/S=8080/560/8160/13200，世界现金30000，原料余300Q、消费F180/G120Q、在途与C余货0、税清零。P-E1在独立分支实跑：F低现金day3拒整单、S20Q day3无新班次、旧债部分偿付后移交退出、预付部分已履约及取消／不足退款；另外验证停工工资费用化与累计税下调。

所有经济命令经Engine prepare／持久hook／apply，时钟、事件覆盖、钱／货、税债同一WAL回执；要测半途恢复、响应后重试、IO失败不发布和约束拒绝无部分生效。独立批次／固定30日记录／有限债务槽按实际sizeof归原模拟及运行域，不预设旧4MiB Engine门必然覆盖新增状态；最终实测与剩余门在完成后登记。

正式市场、真实家庭需要、住房租金、折旧／分红、月薪完整周期、公用网与完整交通、长期平衡、16GB吞吐均未由该profile覆盖。P-BOOT泵与机组互锁不是本实验的免费附送通过项。

## 5. 输入、命令与可观察性

[真实实验开局](../fixtures/m0-economy-opening.json)是T03四主体的扩展，空槽的来源只确认空槽、不造资产。模型命令为advance／suspend_shift／prepay／cancel_future／settle_debt／handoff_debt／begin_exit／close，经System权限的Action::Economy进入同一事务。无set_balance或set_final_state。债权槽1为外部已有债、2为退款、3为利润税，外部来源不得使用生成保留ID 2／3。保护仍关联原账户；退出的登记移交只转持久管理责任，不改变债务人与债权人，不冒充司法裁判。

WorldView升级mycity-m0-state-v4，含30日实际接纳／拒单原因、有效工时、工资、采料、产量、实际消费、销货成本、税差额、在途、未付款和保护。源码fingerprint作为Store规则身份，不兼容旧存档拒载；未做自动迁移。通用Engine的1024回执和WAL64MiB门保留，满域安全拒新，不将有限实验宣传为无限期经营。

经济Clock是明确阶段状态而非墙钟／动画。它复用T04事务与T06存储；尚未接成T05所有到期源与Region双钟的统一P0—P5执行器。为防止虚假的联合通过，当前拒绝经济与Region同时装配，也拒绝经济加独立generic Resource池；私有实验通道只有一个权威。空间版P-E0只绑定不可变T07资产及共同根，1000m通道未从地形／道路求路，不能宣称真实通勤、货车、坡度或跨城容量已验。

可离线运行（输出目录必须不存在）：

```sh
cargo run --release --locked --offline -p mycity-headless -- economy-probe fixtures/m0-economy-opening.json /tmp/mycity-economy-new
cargo test --workspace --release --locked --offline
cargo clippy --workspace --all-targets --release --locked --offline -- -D warnings
```

驱动逐小时执行活动及实际Store提交；在原料在途、产成品在途、税前／税后，以及欠款／退款／停工后重新打开并重试原operation。P-E0用v2空间存档，独立P-E1变体用v1账本存档；每分支记录自己的真实输入hash，不把原始开局hash冒充修改后的输入。报告没有通过所需检查就不输出成功。
