# M0：完整检查点、日志轮转与重试凭证

本阶段只扩展Rust/headless的持久边界，无UI。业务时间、资金、库存、在途及已有责任不会因检查点推进或重建。旧版存档没有跨源码迁移承诺：rules identity仍需与创建时一致。

## 契约

- 每512条热回执，在接收下一条新操作前自动轮转；同ID重试优先匹配热／冷凭证，不能先清热窗口再把重试当新请求。
- 完整检查点保存World、Arena槽位／代数／空闲顺序、期初来源、账户／库存及原始成本、Region私有ID／时间、Boot作业／失败／WIP、Exchange在途／保护款／损耗、resources／leases和next_token。恢复走专用API，不重发期初资本，不执行空业务命令。
- 文件读取先限长；恢复校验集合、身份、owner、租约、同池容量及现有经济／Boot／Exchange守恒。损坏或缺少CURRENT所确认的任何依赖，拒载，不回退旧根。
- 业务sequence与发布generation分开。业务提交及检查点发布都递增generation，根槽由generation确定；连续两个无业务提交的检查点也不能覆盖仍被CURRENT确认的根。
- 发布顺序：不可变检查点（含本窗口成功及失败原回执、前一档案引用）→空WAL新段→新根→CURRENT改名及目录同步→切换内存／清热窗口→删除旧WAL。任一不确定错误隐藏writer，重开判断已确认边界。
- 重试凭证包含actor、完整payload hash、原结果和动作。旧操作同actor同payload返回原结果；换actor或payload拒绝，不增加sequence、不支付第二次。冷档案读取错误不能解释成“没找到”。

## 有限增长与预算

热回执上限仍为1,024条，正常512条轮转；单检查点8MiB、单状态快照512KiB、活动WAL64MiB，存档目录计量阈值128MiB。旧回执通过哈希链保留在磁盘，不全量常驻RAM，也不删除旧凭证后继续承诺永久重试。当前每个档案重复保存一次完整状态，优先简化验证；规模化索引／压缩／档案导出另测。

128MiB是实验目录的显式停止边界，并非无限年数保证；磁盘满时仍有可靠背压／退出的要求，由下一阶段的常规与应急配额实现。本阶段不将此算作P-CAP全部完成。恢复逐段校验档案；重试先读取每段最多32KiB的哈希绑定索引，命中operation才读取最多一个8MiB档案。不会将全部历史常驻内存。更大档案目录的索引与吞吐仍需原型校准。

Arena恢复重建固定容量，而非直接信任反序列化Vec capacity。Engine仍受4MiB准入、World受128KiB准入。检查点序列化／反序列化是额外暂存开销，不能只报owned容量代替RSS，也不能将M4／32GiB结果算作16GB验收。

## 验证与范围

测试入口：`crates/city-storage/tests/checkpoint.rs`、`crates/city-storage/tests/exchange.rs`。覆盖超过两倍原热回执容量、原成功／失败跨轮转重试、恰好512条时的重试、连续空检查点、生产中／失败未清／断链在途检查点与继续运行、档案损坏拒载，以及六个检查点发布点的真实子进程退出。原始输出置于[evidence](evidence/m0-t09-checkpoint/tests.txt)。

这是文件系统API／进程退出证据，不是断电认证。非自愿收件、有限容量下退出与CLI分页由后续交付接续；真实30—60分钟组合运行尚未在本阶段宣称完成。
