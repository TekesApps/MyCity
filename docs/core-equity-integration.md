# 股权、经营留存与退出集成边界

状态：D有界候选已完成真实Store/CLI实测：同一来源的162项core、26项storage/退出测试及严格检查通过。实缴、可信税债、普通分红、财政再支出和清算资本返还均实际入账；WAL/检查点重开和精确重放已测。来源、资源及主线整合验收以阶段证据为准；不是完整城市经济或16GB门通过。

## 1. 唯一账本和提交边界

股权登记、有限期初出资来源、留存收益游标和税务覆盖状态放在有界World/TownState中；现金、库存成本、工资、债务和履约仍以已有Engine/Timeline/Store为权威。股权模块不建立平行现金总账，也不从调用方接收任意“净利润”。

`TownSettle`在事务候选中实际验证并应用 `SettlementBatch.lines`、Timeline工资差额、账户转移和库存变更。未来的留存收益增量必须在这个同一候选事务内、由成功应用的真实行构造，再与账户和库存状态一并提交。失败回滚时留存收益也回滚。现有Store按操作ID处理重放；相同命令重放应返回原结果，不能再次增加留存或派息。

`MarketSummary` 仍只是World范围的最后一次日结汇总，不能独立重建历史利润。候选实现直接在 `TownSettle` 的同一Prepared候选中读取实际成功行，并与持久游标一起提交；不得从未执行的规划批次预先记账。

## 2. T08实际字段能说明什么

### 已有权威来源

| 事项 | 当前可用数据 | 对账含义 |
| --- | --- | --- |
| 商品收入 | 成功应用的 `PlanLine::Sale.goods_payment`、`shop_account` | 该款从买方实际转到店主账户时，才是该店主的商品收入。买方支付的运费、电力附加额属于各自收款账户，不能计作店主商品收入。 |
| 已售库存成本 | 同一 `Sale.goods_basis` | 仅对真实售出的数量结转成本；调用时检查权威库存切片。 |
| 库存成本池 | Stock/InventorySnapshot 的 `quantity`、`basis`、`origin_quantity`、`origin_basis`、`offset` | `stock_slice_basis`按累计整数floor差额切片，拆单、恢复和连续售出保持总成本守恒。剩余库存的 `basis` 仍为资产成本，不进入本期已售成本。 |
| 生产后库存成本 | 成功应用的 `PlanLine::Produce.output_basis` 及对应最终Stock字段 | 现行公式是 `input_basis + utility_cost + capitalized_labor + freight_cost + disposal_cost`。上述投入成为该批库存成本，不能同时当期再扣一次费用。 |
| 已发生工资 | Timeline `Payroll.accrued` 相对持久 `PayrollCursor.accrued` 的差额 | 作为工资应计成本；不以实际付了多少代替已发生工资。未付金额仍是应付工资债务。 |
| 实际工资现金流 | Timeline `Payroll.paid` 差额与Timeline账户转移 | 只用于现金流和应付核对，不再次增加工资成本。 |
| 当期闲置工资 | MarketSummary中的 `idle_labor_expense = wages_accrued - labor_basis` | 当前生产规划把部分工资按产量资本化进 `output_basis`；不能将全部工资再作为当期费用。闲置部分已经是未资本化工资费用。 |
| 已发生的直接生产付款 | Produce行中的 utility、freight、disposal金额及收付账户 | 对生产企业，这些付款已经放入output_basis，待该库存售出时随goods_basis成为成本。对服务提供方，它们是现金收入，但提供方自己的供给、维护和固定成本尚未完整建模。 |

### 有限、无重复的商品经营收益口径

在某一完整封账区间、所有输入均可信且覆盖完整时，T08商品经营净额候选为：

```text
实际商品销售款
- 实际售出库存的 goods_basis
- 未资本化工资 idle_labor_expense
- 已实现、且有权威记账来源的其它期间费用和适用税
```

`goods_basis`已包括此前资本化到所售批次的原料、生产资源、生产物流/处置和资本化工资成本。未售商品相关成本继续留在库存资产。生产行的utility/freight/disposal以及 `labor_basis` 不可在本期重复扣除。

销售订单的freight与utility附加款直接由买方付给对应账户；它们不是店主的商品销售收入。若接收方是独立运输、电力或水务公司，这些收入必须与其自身真实供给、燃料/采购、工资、维护、税及其他成本一起核算。当前公共服务主体成本未闭合，不能只拿其收款作为可分利润。

## 3. 工资、税、利润及现金不可混为一项

Timeline工资在推进时按到期规则尝试付款。对利润应计使用 `accrued`，对现金变化使用 `paid`；若余额不足，未付款部分既不能消失，也不能算成已付现金。生产工资的资本化部分通过库存成本，在货品实际售出时归入goods_basis；闲置或未资本化工资由idle_labor_expense当期承担。任何集成都必须在“工资全额当期费用”与“部分资本化后随销售结转”的口径中选定与当前库存basis一致的一套，不能二者叠加。

候选实现有固定的日 realized-margin 税种与可信Claim source metadata；assessment和应付税claim在TownSettle同一Prepared中生成。税债本金和paid仍只保存在普通Timeline Claim；Claim只带32位稀疏来源索引，具体Tax或Loan出处按claim ID保存在Timeline最多256行的有界表中。Loan出处只由真实Timeline::Lend在现金转移与债权同一candidate创建，普通Claims不能自称贷款。表满时同一Prepared拒绝，不丢来源或债务。空表省略序列化字段、零索引省略序列化属性，以保留旧空Timeline/普通Claim的wire形状。Claim固定行宽用编译期断言限制为48字节；来源表最多16KiB，Engine、Prepared和预留准备工作区分别计入模型容量。本候选Rust实测Claim=48B、来源行56B、256行表14,336B，三份payload为43,008B；Engine owned=4,125,880B，World inline=74,176B，仍需联合物理预算与后续系统增量验证。它只是未校准原型，当前只对正日margin计税、不支持税亏结转。ExitPolicy布尔字段本身仍不能证明税覆盖；每个期间须能从实际生成的权威Tax Claim追溯，否则派息拒绝。未完成的普通Claims即使已经付清也会阻断派息；只有实际Lend债权完整清偿后可作为已知融资记录，不把本金计作利润。已在有限Store场景实际运行并验证重开/重放；完整长期经营仍未验证。

当前系统也没有覆盖折旧、资产减值、租赁、法律费用、全部长期维护或所有其他生产成本的企业总账。只要该企业存在这些未入账项目，销售收入减已知T08成本不是净利润，不能称可分配收益。首版只能为明确声明完整的狭窄主体开通派息；完整性由Engine核对权威来源，不能由玩家或profile布尔值自行断言。

## 4. 最小安全留存收益与派息门

候选实现已在既有持久Town/World状态保留有界、版本化累计游标；每次成功TownSettle按公司和权威交易行累计一次，游标与operation ID和已结算日对应。有限Store实际防重复、回滚、重开及库存basis核对已通过；不代替整城联合验收。

派息上限应为以下值的最小值，且任一输入未知时为零：

```text
可分留存 = max(0,累计已实现净收益 - 历史累计亏损 - 已声明未付股息)
可用现金 = 现金 - protected - 未清债权/工资/税 - 已承诺的最低经营/安全资金
可派金额 = min(可分留存, 可用现金, 通过偿债能力与来源限制后的允许金额)
```

分红不是仅由现金余额决定。工资和Timeline Claims由Timeline原记录提供；未到期债务也应计入保护，不能因为Exit planner暂时只支付到期款就用于派息。当前C的 `build_exit_snapshot` 能从Timeline构造实际应付Claims/Payroll arrears，并带入公司的cash/protected；这适合作为债权输入源。其它未列入Timeline或未绑定的债权、税、损失或最低维护要求须阻断派息。

候选派息在单个Engine事务里核对完整账期、股东登记、权威债权/税/工资覆盖和可用现金；实际金额不得超过调用请求、正留存收益或可用资金，以确定余数规则按持股份额真实转账，并同事务扣减留存游标。任一付款或溢出失败，候选整体回滚。Store exactly-once已在候选实缴、经营日结、分红和清算的丢回复/恢复路径实测；全模型验收另列。

## 5. 初始资本、外来现金和股份

Assembly来源只有 `CashCapital` 与 `InventoryCapital`，本身不记录历史股东。候选 charter 使用有界 `opening_sources`，将每个具体 source ID 绑定到一名登记股东；chartered company account 和每个期初自有 stock 保存对应的不可变 source ID/初始 basis。装配时逐项核对来源类型、金额、资产归属和持股份额，缺项、复用或不相等均拒绝。每家公司最多32个期初来源，超过上限即拒绝。

期初 endowment 是显式的开局所有权声明，不等于历史上实际发生过的出资交易。`EquityContribute` 是另一条路径：同一个Engine候选中真实扣出资账户、增加公司账户并更新持股登记，失败时一起回滚。它是实缴资本，不是营业收入，不抵消经营亏损，也不产生分红额。运行期间只保留 charter 的原始 source 关联，不用已变化的现金和库存余额重新估算开局资本。

未分类的普通转账和库存流入不能自动变成股本或可分收益；对应公司的普通Transfer/MoveStock入口在首版保守拒绝。原材料采购仍没有完整的主线接口，期初已绑定的原料库存只能作为有限开局存量，不能据此声称企业可持续自融资或可持续采购。

Engine候选用私有 `CommittedCashTransfer` 证明把股权更新绑定到真实 staged transfer；来源账户、公司收款账户、实付金额和发行股数必须对应。Store operation journal负责exactly-once。核心接线已通过候选Store/CLI及检查点/WAL重开验证，真实16GB与长期负载尚未验证。

## 6. 企业退出与清算剩余分配

目前T08-C退出路径在Engine候选中读取真实现金/protected、Timeline Claims、工资和公司的实际库存切片。Exit planner先按优先级处理债权；不允许债务/未来债务未清、库存未处置或核算/法律覆盖不完整时分配股东剩余。

普通经营派息候选使用持久EquityRegister与实际账户转账；C清算残余付款分别累计到 `cumulative_capital_returned` 与 `cumulative_liquidation_surplus_distributed`，不写入普通 `retained_earnings_cents` 或税基。有限Store/CLI已完成真实清算分配。

清算必须以持久EquityRegister为唯一股东来源，并在候选中验证版本、完整性和账户关系。债权行动执行并更新Timeline后，才允许把债清后的真实资本余额交给分摊器；这笔资本返还不得冲减经营留存或修改税基。实际Engine/Store接线与有限清算案例已测，主线组合与更多域仍需后续联合验证。资金不足或有未支持负债、未核税、未核资产、未完成法定流程时停止清算。

股东尾差采用最大余数法，并以稳定 `EquityParty` ID打破并列；行按party排序后应用。有D charter时，Engine把清算残值总额交给同一个equity最大余数分配器；旧无D planner保留原型先floor后按输入顺序尾差规则，不改变历史WAL语义。

## 7. 当前未完成边界

- 持久股权登记、真实出资action、普通留存收益派息及有限日 realized-margin 税原型已经有界Store/CLI实测；税务规则不是完整法制或校准税制。
- 期初资本使用source ID到holder的显式endowment绑定，不代表历史付款凭证；原材料采购仍未形成持续闭环。
- 税只按原型正日实现margin评估，尚无税亏结转；任何未知收入、债务或成本来源都会阻断分红。
- 没有覆盖电力、运费及其他公共服务主体的完整收入成本。
- 没有外来受限现金来源标记，也无法从混合余额判断哪些钱不可分。
- C清算资本返还与普通经营派息已有不同持久游标字段，已在有限场景分别实测；二者不得相互抵扣或混入经营亏损/税基。
- 当前候选已验证编译、核心测试、Store exactly-once、checkpoint重开与4MiB Engine/128KiB World静态owned余量；整城物理预算、真实16GB及经济校准未通过。


## 8. 计算契约与后续粒度校准接口

权威输入是已装配且绑定来源的 charter/期初 endowment、既有账户与库存成本池、Timeline 原债权/工资、真实 TownSettle 成功行及持久税务游标。输出是同一候选中的真实收付款、股数、应付税债、留存/已分配累计、清算状态；不从动画、调用方声称的利润或余额反推收益。租赁/维护等尚未接入的费用来源必须阻断普通派息，不能当成零成本。

关键事件是实际出资、完整日结、到期付款、派息、开始退出和清算付款。无这些事件且无新到期义务时，股权比例和累计状态保持不变，不需要逐股东每日模拟。所有事件使用现有日历与 operation ID；倍率只改变现实等待，不能改变税期、偿债或权益。

可以等价合批同一候选中的已验证累计和收付款，但必须保留原整数取整、库存成本切片、稳定尾差顺序及全部债权保护。按日正 margin 计税的 `max(0, margin)`、舍入、库存耗尽、贷款到期和保护现金阈值均不能未经证明跨日乘算；各日利润有正负变化时不能改成净额一次计税。参考路径继续是原 TownSettle/Timeline 的逐事件事务，后续优化以同一期初、事件和来源比对钱物债权精确不变量，另列允许近似指标。

当前策略有界：每世界4个 charter、每公司8名直接股东、32项期初来源；Timeline 共享256项稀疏 Tax/Loan 来源，20,000条原 Claim 仍权威。表满应安全背压，不能静默删债权/来源或降低人口。该来源表未实现长期归档压缩，不能据此声称支持无限期经营；新增租赁等来源必须重新测联合容量。声明上限与实际分配分别记账，含 Engine、Prepared、保留准备区、快照/恢复多份放大，不能只乘一个字段宽度。

继续复用现有事务、CLI及来源固定的验证收据观察实际结果。当前 stage 的命令总耗时/进程 RSS 只作微型观察，不是各任务类别 p95/p99 或全城速度；不新增逐主体高频日志。后续校准仍需补企业/租赁/交通类别的有界计算区间、ready-age 和联合负载样本，当前无完整自适应控制器，也未实现GPU。完整 M0 冻结实验与新聚合策略实验分开报告。
