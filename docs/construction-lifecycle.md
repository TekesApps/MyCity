# 建设、拆除与工程进度

设计修订：文档 v0.4.3，2026-10-18。玩家要求建筑建设和拆除都遵循现实尺度的工程日历。本文取代“提交后在一个模拟步内建成”规则；时间速度以 [游戏日历](game-time.md) 为准。具体模板工期以后按明确现实案例校准，本文演示参数不是行业平均工期或已验证施工模型。

## 1. 三件不同的事

物理工程之前的调查、比选、产权安置、必要公示／听证及拨款按 [市政事项流程](civic-project-workflow.md) 分级处理。意向、筹备档案或议会支持不等于已接受工程；筹备本身有工时／费用授权，不预先获得施工土地和资金。接受工程及阶段开工还要检查确定方案的当前制度、产权、现金与安全收尾条件。

1. 原子接受项目：验证授权、最终几何、施工占地、阶段依赖、预算和状态空间，建立项目／预留。
2. 持续施工／拆除：依阶段积累工作量和日历等待，实际花费资金、占用施工能力并产生环境／交通后果。
3. 原子投运／场地验收：重新验证当前条件，一次发布可用设施、道路拓扑或已清场土地。

原子性约束每次状态变化和对应扣款，不要求几个月的工程瞬间完成。合法半成品是世界状态，不能把它当事务失败整体回滚。

## 2. 工程对象与阶段

Project 包含稳定ID、所属地图／城市、业主／承包方、冻结施工包、日历计划、阶段DAG、已完成工作量、资源预留、实际费用、现场状态、预计完成时间、风险和日志。

| 建设阶段 | 典型工作与完成门 |
| --- | --- |
| 准备／场地处理 | 围挡、清理、临时道路、水电、施工占地，不能侵入保护区 |
| 基础 | 土方、地基、基础施工与规定的最小养护等待 |
| 主体 | 结构工程量、班组与必要机械能力 |
| 安装与配套 | 内部设备、管线、道路和建筑端口，必要分支可并行 |
| 验收 | 工程检查、最终几何、资金／合同及安全条件 |
| 投运 | 当前水电、维护道路、人员、启动投入和服务接入均满足 |

状态为 accepted／scheduled／preparing／constructing／built_uncommissioned／commissioning／operational，另有 blocked、suspended、cancelled、awaiting_detailed_validation。工程量完成、设施投运、人口入住和市长目标达标分别报告。

模板字段包括阶段工作量、最低日历时长、班次、允许并行、资源需求、最大生产率、阶段费用和施工排放。现实月长度按日历展开；工作日与日历日分开，不能把30个工作日默认当30个连续日历日。

## 3. 进度由工作量产生

阶段有效施工量 = 在合法班次内，对“实际分配班组能力×生产率×约束系数”的时间积分，并受投入、场地、前置依赖和最大安全生产率限制。人数和机械按聚合能力分配，不做每个工人的完整生活模拟。

养护、沉降或检查等待采用明确的最小日历时长，不因多派班组就自动消失；同一班组不能同时全额服务两项工程。存在并行阶段时按依赖图求关键路径，不能简单把所有阶段天数相加或取平均。

总体百分比按模板冻结的工程量权重计算，不按已花多少钱倒推。剩余时间要同时展示已完成量、当前速率、等待与不确定性；缺资源时不能让日期到了就完成。

演示：某阶段需160标准班组工时，正常每天8小时、分配1个班组，则需20个有效工作日；仅完成40工时后还差120工时。加速只缩短现实等待，不能把160改成80。若该模板另规定最低30日历日，则工程量完成后仍需满足该时间门。

首版可用抽象施工包／承包服务计量材料与机械；没有实现的钢材、水泥等必须声明 unsupported／abstracted，不声称完整物料仿真。已实现的材料和施工水电从区域同一库存／容量分配中扣减，不能既卖出又使用。

## 4. commissioning_group 的新语义

组内道路、泵站和水电连接可先后施工，组引用同一冻结的最终拓扑。require_operational=true 表示组完成时必须联合验收并原子投运，不代表接受项目时立刻建成，也不保证几个月后一定有足够运行投入。

验收失败保持已建实物和费用，记录待接入／待启动；不得退回几个月前。建设期间若需要临时水电和通行能力，必须来自已存在／明确获准分期投运的设施，不能调用未来泵站的纸面供给建设它自己。

可独立使用的分段必须在模板中明确独立验收边界。未验收路段不开通，未投运电厂不发电，部分建成医院不自动提供全部床位。

## 5. 拆除同样是工程

拆除不是点击后删除对象。模板需声明清空／安置、断开水电及服务、围挡／封路、主体拆解、废料运输、清理修复、最终场地验收等阶段及工作量。

业务退出与实体消失分开：拆除前先按授权迁移／终止服务和清空占用；进入断供或停业阶段即从有效容量扣除，不能一边拆医院一边把其全部床位出售。已有患者、队伍、库存和产权按对应规则处置，不能直接抹掉。

主体逐步拆解、残骸堆放和废料清运保持实际状态；土地直到清理／验收后才可重新开发。只拆完主体不等于整块地可用，也不能在地基／废料仍占地时把同一位置出售两次。

取消拆除仅停止未做部分，已拆结构不会自动复原；需要评估加固、修复或继续清场。废料按实际拆解产生库存，必须有可达且有接收／处理容量的处理点，允许显式计费的预设边界接收方；不能随时间凭空消失。回收料只有实际产出后入库，不在接受拆除时提前出售。地块与废料所有权、运输费用、可回收材料和处置费用分开记账，不能把拆除返还全部建造成本。

## 6. 工程的交通、空气污染与噪声

| 来源 | 必须反映的后果 |
| --- | --- |
| 施工围挡、占道、升级改造 | 道路有效宽度／容量改变、慢行或封闭、出入口迁移与绕行 |
| 建材／废料运输 | 增加实际货运批次和路网负荷，不因画面抽样减少而消失 |
| 土方、拆解和机械作业 | 扬尘及机械排放，按阶段强度和运行时长注入空气模型 |
| 施工机械与交通 | 工地及道路噪声，按班次、距离、日夜累计暴露 |
| 清理和修复 | 残余占地、废料容量、修复工时和阶段费用 |

空气污染保留背景电厂排放、道路交通和工地来源，来源ID及地域归属明确，避免工程货车在交通模型和工地模型里重复记同一尾气。工地扬尘是独立来源，不因车辆尾气已计就被省略。首版若只支持统一游戏污染指数，应明确不等同真实PM浓度。

噪声首版用无量纲noise_exposure_index及日／夜暴露规则，不冒充真实声学分贝预测；若后续引入dB须使用能量叠加与相应单位。安静时段不能用低日均值掩盖高夜间干扰。

停工可停止主要作业排放，但围挡、临时封路、保安照明、残余扬尘／维护按状态继续。取消项目不会当步恢复道路或清空污染。占道使消防／急救变慢时，共享公共服务覆盖与合同履约也要反馈。

## 7. 资金、现场和长期停工

总投资授权、当前阶段托管、已花费用、未付工程款及收尾储备分别保存。每阶段开工前保证其输入和安全停工费用；长期工程不默认一次锁死未来所有现金，也不拿未授权未来税收当现款。

已消耗投入和施工成果不可退；未付托管可按合同释放；已购材料仍归原owner并记录库存位置。暂停单工程可发生约定的现场维护、设备租赁和融资费用，未实现的费用类型不偷偷计入。

原“受阻1游戏日自动释放所有未用预留”改为告警阈值：已开工场地、基础、半成品、安全缓冲和必要通道保持占用直到合法清场。尚未开工的远期地块或租赁可按明确期限释放／续期，不能释放后把半成品当空地。

恢复施工需检查当前授权、现场、剩余预算、模板版本、班组和供给。设计变更另有版本、差额工作量和增量成本，不把旧进度任意套到新模型上。

## 8. 未打开邻城的工程

已在详细模式精确验证并冻结的施工包，离开地图后可继续工作量、阶段消耗、占道状态、噪声／排放与费用调度。包内保存最终几何哈希、稳定资产ID、阶段占地、依赖、工程量、模板和授权版本，不能在摘要中自由改位置或扩大占地。

首版保守边界：摘要可推进到built_uncommissioned；新增永久建筑／路网的最终几何落地和投运进入awaiting_detailed_validation，待进入该图验证，不凭哈希断言当前几何仍合法。旧几何与工程增量分别持久化，重开不重复施工、消耗或收费。

临时围挡、预先验证的封路／降容和施工排放必须在摘要继续生效，不能因邻城未打开使工地零污染或道路恢复满容量。未批准的新几何计划仍排队，不暗中加载第二张详细图。

## 9. 工具和观察

现有create_plan／propose_layout／evaluate_plan增加工期、阶段、施工包、占道、排放／噪声、临时供给与关键路径评估。apply_plan返回项目已接受，不返回整组已完工。

建议新增city.project_query、city.project_control（在授权内暂停／恢复／改阶段优先级）及city.project_change_propose。取消、变更及付款沿用统一幂等、版本和账本规则；agent不能通过暂停恢复重置工期、退款或洗掉污染。

工程观察至少显示：当前阶段、工作量／百分比、已过日历与有效施工时间、计划／预计完工日、停工原因、阶段费用、剩余授权、占地／占道、空气与噪声增量、待验收条件。建筑长高或拆解动画是进度采样，不能反过来决定工程完成。

## 10. 工作集和验收

初轮全世界128个活跃事项／工程档案槽由筹备、实施、停工及收尾共享，每档案最多一个当前施工包／Project、每工程最多16阶段，热描述上限16 KiB，合计2 MiB；筹备受理前就准入，接受工程时复用同一槽，不另加128个筹备。Goal／Plan／Project／Monitor状态仍分别保存，筹备不创建已接受Project。档案计入区域40 MiB及原0.35 GiB模拟域；几何与长历史按引用存盘，索引／事件及预演仍受对应配额。满额暂缓新增，不删除已有半成品或未结义务。

活跃槽保留整改、安置、安全收尾及未移交责任；正常运营设施在验收／责任移交后可归档。只剩已确定工程尾款须先原子移交到有界未清偿义务表并保留执行引用，才能释放工程槽。维护、运营合同及Monitor由对应既有状态继续承担；Goal是否达标单独观察，归档不消除未结责任，见 [闭环契约](closed-loop-contract.md)。

验收：30天模板在正常条件下经历30游戏日；倍速不缩工期；缺工／钱／投入停工；养护门不被多工人跳过；取消不重置成果；拆除到清场前土地不可复用；施工车影响交通，昼夜噪声与扬尘可观察；摘要工程持续但不跳过最终精细验收；保存恢复进度及费用不重复。
