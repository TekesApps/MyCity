# 工程、交通与停运联合候选

本分支基于v0.5.120，合并道路投运候选d6edb2b和企业停运候选ae9a57a。仅完成源码合并、Rust1.85.1格式化和diff检查；没有编译、运行CLI或恢复验证。所有下列行为均为待测契约，不是通过记录，不能作为M0或0.1联合验收。

```text
town_transport road-effect NEW_WORLD
town_transport road-suspend NEW_WORLD
town_transport road-withdraw NEW_WORLD
town_suspend NEW_WORLD --loss
```

road-effect继续覆盖同一Store中施工耗料付款、验收前道路容量2、完整结清日界验收、次日容量10，以及对应销量40→200和历史proof恢复。源码检查发现旧候选期初成品200不足支撑两日共240销售；本候选明确登记400成品及400取得成本的期初来源，不追加免费库存。原d6edb2b候选保留，尚未实际跑出失败或通过记录。

road-suspend使用相同工程/图/容量绑定流程，但成品期初为0及0成本来源，使用实际工资产生的工时、已登记原料库存2、配方及明确公用成本输入生产400成品。道路施工承包商单独登记为账户5，工厂与工资付款方为账户3，避免把工厂工资同时当成施工劳务。工厂销量预期先受容量约束为40，扩容次日为200。第三日之前提交停运，检查点后同op重放，第三日实际运输proof仍校验，但工厂不再生产、销售或产生新工资；原库存和现金不变，城市现金守恒，最后重新打开并检查三日历史运输收据。

独立town_suspend CLI/Store测试还负责“两店中一家停运、另一家继续销售”；本联合CLI只有一家工厂/商店，停运后可能全市场没有供应，不把这一情况称为全城停摆机制。

亏损候选已经以0c34651和907d01a合入本分支源码，尚未构建或执行。`--loss`提高显式公用成本，要求实际结算后账面权益下降、无利生产停止而工资成本仍发生，再提交停运；既有债权不注销，另一家商店继续销售。这里的权益投影仅为现金、库存取得成本及既有工资/债权余额之和，不等于完整会计利润或已校准的持续经营模型。所有输出中的断言仍须由未来真实CLI执行产生，源码存在不代表验证通过。

道路撤回候选已合入源码：拆除申请与审批期间保留新增容量，审批后在完整且已结算日界开工，原子撤回该工程增量，下一服务日起使用基础容量及新的版本。发布时间与撤回时间永久保留；历史运输凭证按各自服务日校验。`road-withdraw`候选覆盖施工、投运、两道拆除审批、撤回、废物接收、关闭和冷恢复，尚未执行。不能据此称中断、重试、失败回滚或历史凭证恢复已通过。

限定范围：施工劳务仍是明确的承包商有效工时输入，尚未来自全城就业分配；公用容量与单价为显式接口配置，尚非实时电网/水网；运输采用固定群体OD重复规则，企业停运只过滤经营报价，不声称OD已经内生响应。道路效果只支持同一工程发布一次、撤回一次，不支持重建、多项目叠加或拆除时额外封闭基础车道。停运不是资产冻结、优先清偿或法律关闭，未知程序不会自动批准。原库存、欠薪和债务不抹除。

正式8小时测量期间不得构建或运行本候选。结束后按独占窗口复用外置共享target，先执行core/storage release回归、严格检查，再运行上述两个新目录CLI及四个原运输场景。旧兼容分别验证v119交通profile/proof，以及由冻结旧writer实际导出的已验收工程WAL/checkpoint；新读者只能打开实验副本，不能对保留原件做恢复清理。累计物量、现金、工时、历史proof、恢复重试与原Engine预算须共同对齐，任何一项失败均保留源码/日志/可执行文件和必要完整原件，不缩场景或阈值制造通过。
