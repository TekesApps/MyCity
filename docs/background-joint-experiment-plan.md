# W4有限联合实验输入与验收细化

本页是在[W0—W4冻结条件](background-compute-acceptance.md)内细化联合实验。实施与当前验收状态见[W4运行专题](background-joint-runtime.md)，本计划本身不构成通过。仍须实际≥1800秒墙钟、七游戏日、故障恢复、同刻完整进程组资源，以及独立advisor最终联合审查；不得用快跑、空等补时或W3工件替代。

## 1. 真实业务组合

下一版使用版本化Joint期初fixture，保留Region／Boot／Exchange／Timeline，新增两个有真实账户来源的household接受日／周工资；旧Economy不得启用或重复计算同一劳动。工资按实际工作区间累计，核对应计、到期、实付及欠付，不以约定工时直接替代实际记录。Boot至少实际启动泵／机组中的受支持设施，核实资源消耗、启动／停运、容量后果；不强制其在资源枯竭后一直运行。

税采用既有Region Obligation加不可变规则映射表示的**每日固定额营业税**，不增加一套平行可支付税账。映射必须明确税种、原义务ID、纳税公司、财政账户、固定额规则、首到期、周期、生效／终止及期初欠税。独立核验读取规则，按七日到期次数算应计税，分别验证实收和未付，不能将累计到期额称作财政收入。至少一次真实不足支付形成欠税，再用有来源的实际资金清偿旧欠税。

若实验以企业间借款补流动性，实际放款与借款债务必须同一Envelope建立，债权只记一次，写明债权人、债务人、本金、到期及期末未到期余额；不能给公司凭空加现金或把借入本金当营业收入。合同Claims与税义务分别追踪，不重复登记一笔债。固定额税之外的利润税、工资扣缴、一般申报／司法征收不属于本次通过范围。此有限税语义经advisor确认可以复用通用付款记录，但必须用规则映射及实际现金／欠款证据验收，不能只改显示名称。

至少真实发运并交付两份有限货运，核对商品库存、占用／释放容量、运费及销售结算；空气源只取实际运输活动。已交付后不能继续排放，关城重开及故障不能重复交付或付款。期初空间与水电／资源实验规则保持版本绑定；不扩到完整交通网、真实排放或所有行业。

## 2. 持续推进与恢复

在1800秒内分批推进七游戏日，持续有时钟／业务／场任务、阶段性保存及查询，记录每个推进区间的真实时间；不可先把所有任务跑完再睡满30分钟。每个必要空气窗口仍≤3600游戏秒，输入及业务窗口沿真实Due边界切分，不为省测试跳过P4。达到七日后的结束核验时间与实际运行时长分别报告。

实际worker／Sim故障分布到不同job，每job最多三次尝试。覆盖至少一处计算中worker失效及一处Sim提交边界／回复丢失恢复；原票可找回、纯候选可重算，工资／税款／货款／欠债不重入。终止／取消／耗尽负例可以独立短实验，不能用负例暂停替代主联合负载。App断连不授权Sim自行推进新日历。

对照在宿主中运行同一期初输入的直接CPU Engine：业务命令使用自己的revision，领域输入／规则／截止一致；必要空气直接从固定输入求解，不能拿故障分支的结果文件当参考。只允许操作回执、执行代际、管理revision等预先列明的差异；业务World状态、现金库存、应收应付、实际工资税债和完整空气State逐窗口或最终精确比较。保存CPU对照与指令记录，另明确相同数值算法不是独立物理模型验证。

## 3. 完整进程组与工件

采样从首次子进程启动前开始，到所有已知角色／孤儿停止后结束。记录宿主（含同进程CPU对照）、Sim、worker、监督／采样开销的pid／ppid、时间戳和RSS；取同一时刻的总和峰值，不能把各自峰值相加或只报父进程rusage。角色PID变更及孤儿仍进入追踪，短于采样间隔的峰值可能遗漏须明示。共享页在RSS求和中可能重复，也须注明。

同时记录真实宿主内存、系统内存／swap观察、磁盘实际文件与持久charge、archive／checkpoint增长、延迟、重试数、队列／任务上限及未测限制。输入、规则、源码、操作／回执、采样原文、世界和必要资产摘要、恢复点及核验器须可重跑。日志本身设字节／记录上限，不让测量产生无界内存或磁盘。

当前宿主是32GiB，测量只证明该配置下有限负载；无真实16GB设备，16GB门维持not_run。经济平衡、全城规模、UI／渲染／GPU／AgentKit、8小时压力、物理断电、完整M0均不因本实验通过而改变状态。最终advisor针对实际联合实现和工件审查，不能以本页计划代替最终审查。

## 4. W4实施中的模型快跑（未发布、非联合验收）

当前工作区已新增`m0-background-joint-opening.json`及`m0-background-joint-policy.json`：两个有来源的household工资账户；ID1对应每日固定200000分营业税，公司3→财政1，到期第1—7日、期初欠税0；ID1合同债1000分于第2日到期。第2日后关闭城1、激活城2，第3日后恢复城1，故两个工资关系实际工作各48小时。

第4日的有限零息借款由供应方4向公司3实际放款850000分，新增Timeline::Lend在一个事务内同时放款和创建ID100本金债权，第10日才到期；不提供利息、抵押或通用金融市场。它复用Claims有限额度，不扩大热债权上限。因现有Timeline命令要求单动作，不能把普通Transfer和Claims拼成一个被允许的Envelope；采用有类型单动作保证钱／债同成败。资金不足、持久钩子失败及重复请求的模型反例已测。

直接CPU七日快跑实测：税应计／实收1400000分，曾欠税201612分并于借款后清偿；日／周工资分别336／528分，原合同债实付1000分，850000分借款本金保留未到期；总现金3000000分守恒。两个真实货运交付，泵与机组依前置启动。独立Sim→worker→Store的七日快跑实测173个窗口，用约68.04秒，并逐检查点与直接CPU完整业务／空气状态一致；这不是1800秒耐久、故障联合、全进程组RSS或16GB通过。当前工作区尚未冻结W4发布源码，快跑输出仍为开发验证，不替代最终归档证据。

下一实施项是Rust联合CLI与采样：七日按小时目标分布到至少1800秒墙钟（首个60／120秒启动与交付另保留），整个期间持续推进，不能先算完再空等。worker计算故障与Sim根提交后丢回复分配到不同job；Sim故障选择已发生日工资／税款的P4窗口，重开原票后对照钱债不重复。

采样以一次ps快照识别宿主后代及此前观察到的孤儿，保留pid／ppid／RSS／状态和出生身份，角色由进程创建事件补充；不记录其他应用命令行。采样命令自身也属组内测量开销，CPU对照在宿主内，不能漏计；同一快照求和而非个别峰值相加。建议250ms间隔、有限日志和运行前后系统内存／swap观察，明确短命进程峰值可能遗漏。最终还需实际工件、独立核验器及advisor针对联合实现与实测结果的审查。


## 5. 长跑前的实现冻结约束（W4待验）

实际联合入口为`mycity-headless joint-probe NEW_DIR WALL_SECONDS`：0仅快跑；1800—2100为真实分布式墙钟运行。源代码与fixtures冻结后才能启动正式长跑，期间不得换源码／重编不同输入的同路径binary；原始命令、事件、170个目标检查点和采样写入有界工件。

联合对照已由WorldView摘要扩为完整业务快照：完整World（含Inbox）、resources、leases、next_token、完整Timeline。仅归零world revision，排除journal和后台执行管理；空气完整State另行比较。资源容量改变但WorldView不变的反例须被识别。实际Sim及独立CPU每个检查点都比这份快照，不能以只比余额或显示指标替代共享容量／收件责任。

交付后第120秒，按冻结policy里的两个收件sequence实际结清各5分费用并归档，最终应计=实付10分、closed=2、无剩余收件责任。独立事实断言还包括两份货运各1000mQ／2000分货款／20分运费，泵和机组各完成一次、消耗1000单位实验燃料／支付500分费用、库存输出及容量释放、财政现金实际增加1400000分、原合同1000分已付、新借款850000分未到期未付；不是只把两条同实现路径相等作为真实活动的证明。

采样日志64MiB／12000行、单行128KiB；命令日志32MiB／单行128KiB；每次ps输入最多4MiB／8192进程行，只有本实验后代及已知身份被落盘。出生字符串来自ps lstart，属于秒级身份观察；监控不授予任何世界写入权限。采样ps自身计入快照总和，CPU对照／采样线程归宿主同一PID。正式结果保留未观察到的已声明PID、最大采样间隔和最后进程组，不能把未采到当成零占用或将观测峰值称作严格真实峰值。为保证主要故障角色与最终重开Sim有采样，注入前／停机前等待至多2秒取得对应角色样本；该实验屏障时间计入运行与延迟，不隐藏开销。
