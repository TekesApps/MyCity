## First supported contract

- One managed physical venue uses **simultaneously present people**, including learners, teachers, staff and visitors. Enrollment entitlement is a separate business constraint. A quantity of one means one person, never one class, a seat-sale quota or a throughput rate.
- One canonical venue entity maps to exactly one original Resource ID in the same world/branch; resource/unit/entity mappings and aliases are globally unique within the bounded registry. Reusing old Housing/Boot/transport resources as people-count rows is forbidden unless root explicitly performs a separately reviewed authoritative migration; this module does not support that migration.
- Root validates initial game endowment, actual delivery/commissioning, ownership, operator, allowed purpose and permit version. These are game facts, not real-world school API requirements. Nonzero IDs, hashes, public request DTOs or original generic capacity tokens alone never prove these facts.
- Acceptance immediately holds the original pool's reserved quantity for the entire accepted window. V1 deliberately rejects some future nonoverlapping bookings because it holds capacity immediately; that is a conservative scheduling restriction, not a proven physical shortage. It does not build a second calendar or pool.
- Groups enter and exit atomically, with fixed integer population including all participant roles. Actual entry converts the group's exact original reserved lease to occupied; actual safe exit alone releases it. No partial entry/exit in v1.
- Cancellation releases only not-entered reservations and requires current root-verified cancellation authority. Due time, city closure, permit revocation, owner/operator change or shrinkage cannot delete Actual or old responsibilities. They may stop new commitments. Actual remains until a root-verified physical exit event, including overdue/closed/revoked cases.
- Each use references original scope/token, venue/resource identity, accepted registry/permit version, activity group, people, window and original source event. Root writes usage metadata and original pool mutation atomically. Root must preserve exact operation identity and use original receipts for retries, including after release; the pure module does not issue durable-success receipts.

## Implemented source API and exact host responsibilities

The module is a stateless rule surface over borrowed rows; no owned registry/runtime container is required. Serde is provided on per-row metadata and compact selectors. Root may store them in its original bounded Rows within the optional World Box. Borrowed views and opaque evidence are not deserialized. Exact public rule signatures:

```rust,ignore
pub fn validate_opening(view: OpeningView<'_>) -> Result<(), ValidationError>;
pub fn validate_recovery(snapshot: Snapshot<'_>) -> Result<RecoveryReport, PlanError>;
pub fn plan(snapshot: Snapshot<'_>, request: Request,
            evidence: &VerifiedRootEvent) -> Result<Candidate, PlanError>;
pub fn bind_reserved_offer(before: Snapshot<'_>, after: Snapshot<'_>,
            request: Request, evidence: &VerifiedRootEvent)
            -> Result<Candidate, PlanError>;
```

`OpeningView` borrows scope/registry/offers/original resources and a complete root-authenticated directory of non-venue resource IDs. Resource ownership domains must partition the provided original resource rows; a venue cannot claim a row already owned by another domain. Registry aliases and entity IDs conflict in both directions; an alias grants no extra resource. `Snapshot` additionally borrows original leases, bounded policies/use states, source revision and optional root-verified completed clock. A legitimate genesis revision0 remains Known zero. Empty/partial clock is Unknown, not tick0. No original Resource/Lease types were modified to add comparison traits.

`VenueDefinition` fixes venue/resource/aliases/owner/operator/purpose/permit version; `UseOffer` fixes use/group/partition, role-specific population and separate enrollment term, purpose/operator/window, at most four source refs and accepted version. `UseState` retains original CapacityToken/actor/resource/units, accepted scope/revision/operation/owner/operator/version, accepted/last event, accepted/entered/released time and phase. The accepted version is the original offer's acknowledged permit/registry version, not a new mutable generic revision counter. `UseStatus` is Reserved, Actual, Cancelled or Released. Terminal rows remain resident and consume the64-record quota.

`SourceRef` has kind/scope/revision/operation_id/event_id/source_id. Genesis requires revision/op/event zero and nonzero source_id; runtime accepted/last provenance requires GameEvent, original scope, nonzero operation/event IDs and source_id zero, with base revision allowed to be zero. This records original operation identity; no fake receipt or success revision is generated. Retained-source duplicate checks are bounded, not a replacement for full-history original receipt replay. Root must prohibit reusing an old game event identity under another operation after intermediate references have moved out of metadata.

`Request` fixes use_id/operation_id/kind/occurred_at. Accept and CancelReserved select a fixed offer without a caller clock; Enter/SafeExit require explicit occurred_at equal to the root completed tick. Private `VerifiedRootEvent` binds the full resolved offer/venue, request, actor, permission, original event source/time and exact token where required; `VerifiedCompletedClock` is also field-private. Their crate-visible constructors mark the future root validation boundary and are not proof that the adapter exists. Account Accept must match original operator. System Enter/SafeExit validates exact group/event/time/token and cannot be minted by an Account. Current closure/revocation/changed owner/operator disallows new acceptance/entry but does not invalidate safe exit of old Actual responsibility. Dynamic migration Actions are not implemented here.

`plan(Accept)` returns an original-pool Reserve request with **no** accepted state or token. Within one exclusive single-Action transaction, root prepares the original resources/leases in its existing temporary rows. `bind_reserved_offer` compares before/after source and metadata, requires exactly one new matching reserved lease and exact reserved-counter increment, unchanged other rows/old leases, and no reuse of retained tokens. It returns a metadata Insert, never mutates original rows or commits. Root then atomically publishes both original pool and metadata through its durable path. Do not independently commit the preliminary Reserve candidate.

For Enter/Exit/Cancel, Candidate carries original Occupy/Release token and a metadata transition with source event/time. Root applies phase and last_event in the same original transaction; Enter records entered_at, SafeExit records released_at, and Cancelled retains no entered/released physical timestamps. Original accepted provenance remains unchanged. Transition validation rejects duplicate/phase-mismatched enter/exit, stale context, wrong permissions/token and concurrent Actual use of the same frozen group. `CapacityGateRejected` means this conservative original-pool admission policy refused the request; it does not certify physical shortage. Quota/Unknown/Integrity remain separate from that gate.

Recovery validates all active managed use/lease correspondences in both directions and checked sums against original counters, including actor/operator, scope, tokens, people, event and lifecycle metadata. It retains terminal tombstones and old Actual even when counts exceed effective capacity; its overcommit report is not permission to add capacity or remove responsibility. A missing lease, orphan managed lease, duplicate token/use/event mapping, changed original identity or counter mismatch is not automatically repaired. New-root optional-slot restore/clear, old-save behavior and original Engine invariant compatibility remain root integration work.
