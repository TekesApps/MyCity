## 1. 所有模板都要交的清单

每个模板必须有稳定template_ref、冻结版本、适用范围／能力状态，以及下列声明；实际参数可引用有界共享profile，不复制长文到每实例。

| 声明 | 必填内容 |
| --- | --- |
| 几何／接入 | footprint／site／z／净距、可变参数、允许旋转／镜像、最多8门／管网口和必要用途、外接／共享区规则 |
| 人与能力 | 住房／工作位／访客／床位／吞吐等各自单位；设计量、投运条件和受谁共享，不合并成人口容量 |
| 人员／经营 | 是否需要运营单位、工种／班次／资格、工资计提与日／周／月支付、营业／工作时段 |
| 资源／费用 | 待机／负荷水电、原料／库存、启动／维护／收尾、实际付款方／收款方与资金窗口 |
| 运行／外部性 | 配方或服务、瓶颈、废物／排放／噪声profile、短缺／失效后果及作用来源 |
| 生命周期／责任 | 建设／最低日历／投入、投运验收、停运、改造、拆除、住户／在场／库存／债务及安全退出 |
| 记录／指标 | 必填P组、系统输入／写回和M指标；对应对象、端口、人员、库存、合同／服务／组及存档额度 |

建成设施公共组合B＝Root＋C01空间、C02接入、C03权利、C04工程、C05资源、C06容量、C10财务绑定、C14维护、C16外部性，P33法律上下文始终适用。B是结构检查集合，不强迫每设施有独立钱包、每字段非零或每影响已支持；不适用项有明确原因。自然植物子对象按Root＋C01／C03／C15／适用C16另行引用，不套B雇佣／工程要求。

## 3. 配方、工资、资格与公共profile

I-MFG使用已有演示配方：每10消费品单位需11原料当量单位并产1废料单位。满额8小时班理论80产品、88原料、8废料；已有瓶颈例实际5产品/h则40产品、44原料、4废料。两者是同一配方的不同实际活动，不能把工资人数占比再乘一次。这里只在该配方声明的共同物料当量口径内守恒，不把不同现实吨／件混加。

I-MFG的40同时岗位来自此设备／班组方案，不套用另一示例1800 m²÷40 m²/FTE＝45 FTE，也不将参考FTE、实际人数和到岗混用。I-LOG／C-RET的50／15是对应参考排班的FTE，不因此承诺7×24营业；连续运营必须按真实工时、班次和资格配置额外人员。

煤电10 MW运行1游戏小时最多交付10 MWh（还受网限／损耗等约束），该活动需5煤单位和100 m³水；不可再由S06“工厂产出”重复发电／烧煤。泵站100 m³/h在该示例耗50 kWh/h＝50 kW，先满足实际水源和电力条件，不能只根据名称获得免费水。

工资profile分别保存计薪口径和发薪周期，日／周／公历月结均可；同样时薪20、40实际应付小时得800，不能把“月结”解释成每月自动领满额工资。初期资金保护、计提／应付／实付和欠薪仍按既有合同规则，不为模板增加工资钱包。

首轮沿用最多3技能层、8资格标签、16实体商品。可映射的8个资格标签示例为电气、管网、医疗、护理、消防救援、警务、车辆驾驶、成人授课；它们是有版本的游戏标签，不是真实执照。高技能不自动获得任一资格；具体课程／岗位还查背景、技能、主题与班次。施工特殊资质仅由已有明确班组／外部供方能力承诺，无第9个隐式居民资格；缺少的专业模型返回unsupported。

实体商品候选代码只在原16额度内选择：煤、一般原料、一般消费品及制造废料、生活垃圾、拆除废料、绿化废料、适用种植投入，v38另登记燃煤固体残余物G09，合计9类、余7不自动启用。不同废物需相容接收profile，不能混成一种免费消失的库存；后续细食品／药品／钢水泥未配置时不得声称已模拟。水电流量、床位、队伍、教学席位是类型化资源，不占商品代码也不当作可随意兑换的货物。

[LC38生命周期包](first-release-lifecycle-inputs-and-exit.md)明确G09与G04不同，接收设施须有真实相容规格／余量；不将9个代码变成9张新动态表，固体终点不等于消失。

每个模板的资源、维护、排放／噪声、生命周期、权利及计价profile必须有稳定版本、单位和来源。环境profile只能映射已有最多8个环境通道；系数未配置为template_unconfigured／unknown，不视为零排放。首版绿地仅对已支持景观／休憩产生有界影响，不能给出未经模型支持的碳汇、温度或声学达标。

## 4. 行业模板数量与对象数量不同

候选行业／经营角色使用原16行业模板额度，不按13种空间模板或每实例增加一套行业：

| 经营profile | 对应经营行为 |
| --- | --- |
| O01／O02／O03 | 一般制造／物流／零售 |
| O04／O05 | 煤电／供水 |
| O06／O07／O08 | 医疗／警务／消防 |
| O09 | 卫生接收／处置 |
| O10 | 有实际工地／来源及有界工时的施工承包服务 |
| O11 | 有真实劳动／工具／输入及交付的园林维护 |
| O12 | 成人教学服务 |

共12种，余4不是已具备的农业／金融等能力。每个受支持的经营主体×实际经营单元／地点仍占4096运营单位配额；同址可有多个合法O，不能拆名复制同一主体同一范围的业务；同一模板可有多个实例。住宅不自动是一家企业，公园直接管理／公共容量不自动增加园丁岗位；外包园林方真实存在时另计其经营单位，City Team不冒充施工／园丁劳动。O10临时工地同样有来源和单一实际地点，不能在多地重复使用同一班组。

每个O01—O12单位均必需P18.common通用经营状态／活动来源，不受表中是否组合C08影响。C08仅添加可选生产／设备字段，零售、医疗及教学等不因此缺少营业／关闭状态；各单位的唯一交付adapter按Root契约绑定，服务／课程自己的进度不复制一份经营状态。

## 5. 模板必须占哪些既有记录

下列为每实例的准入清单，不是另加一套内存；p为实际端口数且p≤8，q为原表尚未表达的独立物理约束组数，g为真实植物斑块数，s为登记使用关系数。

| 类型 | 必需记录／额外实际关系 | 不得隐含生成 |
| --- | --- | --- |
| R-H1／R-H2 | 1建筑、p端口、4／16住房；真实住户各占家庭／账户，适用q组／s关系 | 空房不预生成4／16家庭和钱包，不每户复制门 |
| I-MFG／I-LOG／C-RET | 1建筑／设施、1运营单位、p端口、实际岗位边／库存／订单和账户绑定、适用q组 | 岗位不自动满员，订单不自动产出／到货，承运不复制库存 |
| M-COAL／M-PUMP | 1设施、1运营单位、适用1关键设施、p端口、人员／资源／供给计量；对外池／边界按实际占原额度 | 不按模板再生成一份电网／水网流量 |
| M-MED／M-POLICE／M-FIRE | 1设施、1运营单位、适用关键设施、p端口、实际队伍／患者等原交付占用；对外共享池≤全世界64 | 床位／出勤队伍不是20个新居民／两个免费车队 |
| M-WASTE | 1设施、1运营单位、p端口、兼容库存／最终存量及实际货运／处理 | 处理率不是无限填埋量，运输方另有真实记录 |
| M-PARK | 1独立设施或合法宿主子区（二选一）、p端口／通道、适用q组、g植物、s共享关系、实际维护协议 | 不凭space_ref创建免费实体，1片绿地不按每楼复制 |
| M-TRAIN | 1设施或合法宿主子区、1运营单位、p真实端口、教学席位／实际128批次额度、教师／学员时间与费用 | 不为每学员再建教室／入口，课程结束不自动匹配高薪岗位 |

建筑及独立设施数量沿当前小／中／大场景1000／4000／8000联合准入；宿主子区共享已存在物理入口时只引用，不重复占p。一般采购／跨主体许可占1024合同，住房沿32768独立权益描述；账户／库存／货运／服务／组／使用关系各按原全世界限额，未来收尾状态也事前落实。非全部设施都必占关键设施表，适用条件在模板声明；不能以表满将需要条件管理的设施伪装成“不适用”。

## 6. 四类对象的生命周期门

| 阶段 | 住宅 | 工业／商业 | 市政设施 |
| --- | --- | --- | --- |
| 创建／建设 | 权利、合法住房用途、冻结几何／门、真实工程和资金 | 用途／设备／装卸、工程投入和合法运营主体安排 | 合法拨款／现金或真实非市政付款方、必要服务／源资格、阶段工程 |
| 投运 | 实物验收、产权单元登记、必要水电／入口；房源可交付后才接家庭 | 设备／入口、资金与劳动保障／资源／许可满足；有能力不等于已有订单 | 电厂燃料／电网、泵站水源／电、医院班组／床位、警消防队伍和车辆口等类型门 |
| 运行／维护 | 实际入住、租金／消费／垃圾，断供保留家庭权利 | 实际到岗／库存／需求取瓶颈，工资与销售现金真实结算 | 真正交付／响应、持续占用及投入；拨款／付款不等于实际维护 |
| 停运／关闭 | 不当步驱逐／删户，保留实际接入和安置需要 | 不删雇佣／欠薪／库存／在途；停止新增受限承诺 | 既有患者／队伍／访问／在途安全处理，原来源与容量令牌不丢 |
| 拆除／退出 | 居住权／产权、合法安置、断接与实际清场 | 库存／材料处置、雇佣和债务、现场及共享依赖移交 | 服务替代／容量退出、资源和法律责任、工程／环境／共享空间义务 |

停止营业不等于建筑已经拆除。只剩确定金钱责任时按已有债权表原子移交后归档；现场、住户、患者、使用权或争议仍未处理就不得释放对应活跃槽。只在游戏原有规则允许的地方简化程序，不用模板创建绕过议会、司法或玩家授权。

## 7. 三条完整样例与反向缺项检查

后续B的混合楼／摊位数字验证另见 [住宅底商与广场完整实算](worked-examples-housing-retail-and-stalls.md)：新候选A-MIX／B-PLAZA并非直接给R-H1增加商铺或将M-PARK免费变多商户市场，原13基础样例数量／首版范围不变，所有实际子实体与权利仍计费。

**住宅R-H1**：4单元验收登记→实际2户共5人迁入并占原账户／家庭→由同一住宅口发通勤／购物需求→工资实际入账后交租与消费→按真实居住／暴露更新满意度→封门时保留家庭和在途→合法安置／清场后退出。M01单元入住率2/4＝50%，M02为5人，不是设计16人；若工作未到岗、钱未到账，不能靠“有岗位／有收入指标”付租。

**煤电M-COAL**：冻结设备／门位／管网／最大运行及影响profile→真实工期／投入→合格班组和煤／水／钱落实→当期网络可行时交付，10 MW×1h示例用5煤和100 m³水→同一活动生成对应已配置排放／噪声→影响真实居民暴露／诉求→新规生效先阻止受限新活动，存量按过渡→停运保全和真实拆除，燃煤消耗不退。没有合格员工／运行水／电网可行解就不能以名牌10 MW报M09已供电。
