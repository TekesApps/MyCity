## 1. 需求、可行活动与收益必须是同一个区间的事实

在规则、班次、工况、网络／库存、资金、法律、维护或市场约束不变的区间[t0,T)内，依据冻结profile求实际可行活动x及全部必要投入，而非先算满产再按供电比例少付费。

1. 需求声明区分已安装、可调度、计划活动和必要待机；profile明确总功率口径，或“待机＋活动增量”口径，二者选一，不能重复加待机或漏待机。
2. 设备／班组／输入／网络／占用和合法运行共同约束x。活动相关负荷随x变化；安全／必要待机、实际启动等非比例项依profile单独保留。无法满足必要输入时按已配置降级／停止规则处理，不能保留需要该输入的完整营业／生产效果。
3. 同一区间经S05等联合可行，按唯一delivery_adapter和事务序列提交实际活动、资源消耗／预留释放、合法应付工时、交付及相应库存／义务。工资依实际合法应付工时，不能简单按产量同比砍工资；待机、启动和失败作业已实际消耗的投入不因无产出退回。
4. 任何改变区间条件的事件提前截断区间；先结旧段再生效新profile／价格／班次／法律／设备状态。暂停、重载、换地图、显示帧率或现实日历档不改实际游戏积分。不能用整日42.2 kWh示例掩盖中途停电的真实分段。

活动事实与钱分别由原权威写入；原子一致性不要求每台设备每秒新建一张发票。合法稳定区间允许有审计依据的积分／应计压缩，不能跨资金耗尽、实际交付变化或换规则压成虚假恒定结果。求解到迭代上限仅提交本区间已核验可行量，未解量保留，不能抄用旧满产。

## 2. 实物计量、费用分摊和舍入分别守恒

按同一物理边界和区间：主表实际交付＝各已计分表实际用量＋公共实际负荷＋该边界内明确损耗。上游已扣网络损耗不能在楼内再扣同一份。分表不得各宣称主表全额；未覆盖／不闭合须报告差异与来源，不能把差额无条件当免费公共用量或伪造负损耗。

物理计量依据真实负荷，不按租金／面积分摊凭空改变；共同照明等实际公共用量和账单可按冻结相容协议分摊成本。协议权重须非负且覆盖同一实际公共费用一次，分摊给租户后业主仍保留对供方的原义务，不能变成两个独立可消费额度。房东服务费若存在是独立有依据收费，不是第二份电量。

计量使用统一定点单位、时间精度和逐来源余数；金额按合同费率／账期在同一原票依据上结算。**细分时间步、拆租户、换版本、换经营者、关闭重开都不能清零尚未处理的余数**。最终可表示最小单位的分摊采用确定的尾差归属，父总额与子份额相等；若原来源不可兼容迁移，先结清到支持精度再变更，不将小额逐条截断为零。精度不足时限制可接受profile／费率，不把不可表示的费用假装免费。

一份电水交付只有一个物理来源键和一个累计事实；本扩展新增的水电等交付由原通用计量段拥有物理累计／对应金额余数，不改变原工资、住房租金等各自应计字段的权威。功能绑定只持有meter_ref及状态依据，不再独立累加同一余额。公共费用分摊／到期状态归实际合同，停用仍有未结责任的计量段不能释放重用，满4096计量段先拒绝新配置，不挤掉旧读数。

## 3. 容量约束是接纳门，不是删掉故障后果的理由

新预约／新进入／新开工前，按typed资源和实际重叠窗口检验**既有有效承诺＋新增≤当前支持容量**，同一来源的预留转实际占用只转换一次，不将同一份人数同时加为预留与实际。不能用全天平均抵高峰，时分共享还需清场／转换窗口。

故障、封门或减容可能让真实占用／既有承诺超过新有效容量，此时记录overcommitted／缺口，保留actual与责任，不裁人、改小库存、抹掉预约或拒绝记录延迟。阻止不相容新增，按既有法律／服务过渡和安全退出处理；到期不是自动离场。原4释放桶满后依既有来源／持久到期索引退化，不能临时造无界队列。

主宿主8共享／功能子区（H套内布局另计）／8口和4后续功能绑定上限按真实展开检验，不给每子单元再发8口；合法多实体可分开建，但共同瓶颈、同一事项审批和实际成本不得通过拆名绕开。16冻结组合版本满时拒绝需要新版本的改造／新增使用，**不能阻止旧版本原位记账、维护延期、清场、停运与安全退出**；只剩已依法移交责任的版本才可释放。

## 4. 设备、装修、维护与更换不可刷新历史

聚合设备的数量、技术profile和条件／年龄必须相容。候选扩展只支持一个功能单元内按冻结清单安装的同质成套状态：各设备类可有自己的静态寿命／曲线，但同一次成套安装／更换锚点及已声明维护规则共同推进。未配置设备寿命／待机／维护后果则不能启用相应经营保障。确需各设备类独立运行累计／磨损状态时，必须按实际占已有相容计量／关键设施状态或另行重预算，不能在128 B绑定后藏8份动态状态。

- 运行／时间／环境按profile积累已支持磨损和维护到期，条件影响实际可用容量／资源需求；空置不默认零老化、停机不默认零保全费，所有零值须明确适用。
- 修理只恢复实际完成、规则允许恢复的条件；付款／更名／换经营者／profile迁移不能恢复年龄、消除维修欠账或法定义务。装修只更新真实施工的范围，不同时刷新主体、全部设备和旧许可。
- 当前候选只允许真实**整单元成套更换**重置对应成套安装状态，并计工程、停运、拆除／残余物和真实投入。局部修理可按支持规则记条件变化但不刷新安装年龄；单台换新后需异龄表示的部分更换当前unsupported，不能把新旧设备年龄平均或以换一台刷新整组。
- 跨单元共享有条件／维护要求的真实设备必须绑定唯一实体／适用关键设施状态，不能每单元各存一份可独立更新的condition；没有相应状态／设备profile不接纳该共享。

维护订单、施工阶段、人员／材料和既有到期资金／债权沿原权威。维护量不因多张合同重复交付，保养不等于整套换新；空置／经营退出仍要有真正的保全责任方。报废／拆除只有真实残余物产生并找到去向才释放相应实体与条件记录。

## 5. 选址预测、竞争分配与实际成交闭合

单店独立情景可以问“如果只开这家店”，但标为独立假设、**不可把多家独立预测相加**。组合／城市预演必须引用同一份家庭／企业的需求、现金、时间及可达性来源，在商户间竞争分配后才汇总。共享客流不等于各店各得到全部客流，路过不等于购买；未到达／未交付与已消费分开。

| 阶段 | 可接受的产物／不可越过的限制 |
| --- | --- |
| 估值／报价 | 有规则、snapshot／窗口／覆盖的参考与意向，不产生现金／预留；报价不是成交，挂牌价不能当已核验地价样本 |
| 候选评估 | 合法用途／几何／设备／接入／劳动／资源／资金先可行，再比较同窗口有来源现金流、真实取得／改造／搬迁／旧约退出成本和不确定性 |
| 进入／租赁／采购意图 | 要有真实经营者与资金来源，不能从“预计高收益／将来租金”启动第一笔支出；初始资本／外部供方沿原有限开局条件，不能每次新建公司刷新赠款 |
| 共同提交 | 多个并发意图按原确定性公平／事务顺序重查同一需求／现金／库存／空间与权利锁；失败保留原状态，不能同一商铺租两家或同一家庭现金花两次 |
| 交付／应计／收款 | 原来源需求只满足一次；真实交付、商品所有权、合法应付和实际付款各按原adapter／S08；到期不自动到账，按未付债务与既有保护处理 |
| 观察／调整 | 同范围同窗口比较实际与原预测，缺测保留unknown。销售不足、空置、缺工／断供或欠费分别解释，不能直接修改收入／租金指标使计划成功 |

自买自卖／同一控制主体内部转移和抵扣不能当作新增最终需求／世界外部收入；土地／房产估值参考须排除该类循环及作废／未付成交、去除同一成交的多次转载。参考来源不足标unknown或场景参考，不能用自己的报价和循环转手抬价再自动放贷、补贴、增税或确认现金收益；首版仍无自动贷款，后续税基／信用需各自合法规则。

### 有界行为评估的候选初值

以下为游戏设计初值、待平衡，不是现实市场参数：正常选址／调价评估每1游戏日一次，读取最近完整快照，最多8个候选；同一预演内共用需求与资金、逐候选复用缓冲。无新增候选或精度不足只报告已探索结果，不能宣称不存在其他地点。全世界仍最多32项分析任务、1个完整预演，不按每商户并发启动agent或复制全世界。

主动换址采用同口径未来30游戏日预测，扣真实搬迁／改造／旧约退出现金后，优势连续2个日评估窗口超过max（原地同一未来30游戏日预测窗口运行现金支出的10%，1游戏币），且上次主动换址已过30游戏日，才形成迁移意图；再走合法权利／工程／资金门，不瞬移库存／员工／门位。主动规则不妨碍已关闭、失去许可或危及安全时立即停止新增和处理既有义务。预测不足不触发自主扩张；硬失效不能等每日评估才执行。

报价调整／估值也只在声明窗口对未来新成交生效，既有合同价格沿其冻结条款；变化上限、价格策略及需求模型未配置则不启用自主调价。上述节流和迟滞是避免无成本来回搬迁的候选规则，不证明价格收敛或所有策略平衡，须敏感度验证。真实土地交易／商业租赁仍B，住宅已有租约和真实家庭行为不被此候选规则覆盖。

## 6. 摊位／空间许可的最小完整生命周期

许可必须同时有真实宿主／使用范围与时段、合法主责任方、真实经营者、用途、实际接入／排队／清场、费用／付款时点、可退规则、押金／损害／收尾界限和提前关闭依据。未配置任一必要项，不得接受可经营许可；普通租赁、转租和食品服务等缺机制不能靠许可文字暗中启用。

| 情形 | 钱与占用怎样处理 |
| --- | --- |
| 未开始使用即取消 | 只释放尚未使用的权利／资金预留；已有调查／准备等依法实际交付费用按条款处理，不退为新收入 |
| 已开始／部分使用 | 封闭实际区间、应计使用费／实用水电／作业和已发生责任；不能拿全额退款又保留已获得服务 |
| 未履行的预付款 | 依原发票剩余可退金额从真实责任方余额／退款托管退回；无余额形成配对债权，不无中生钱；同原因／不同原因不得重复兑现 |
| 押金／担保 | 是原账户受限现金及返还义务，不是许可费收入；依法认定损害后按依据扣减／转移，余款返还，不先没收又另收同额维修赔偿 |
| 提前关闭／故障 | 按责任、已交付／未交付和有效法令／合同计抵扣／赔偿／退款，原相同本金不重复变成多份权利；禁止任意扩成无限授信 |
| 续期／变更经营者／换模板 | 先结旧区间，原身份／债务／余数及在途／在场继续有来源；新窗口重查收费、现金／收尾、空间／电口／排队和记录，旧权利未退出不能又租给别人 |
| 到期／撤场 | 到期核验不等于清场；停止不合法新增销售，保留旧交付／返程／废物／损害责任和真实占用。安全退出后移交确定欠款方可释放活动来源／合同／版本 |

跨月／跨图、暂停和崩溃均沿原区间／版本／提交序列幂等；退款、折抵、押金转移和债务清偿引用同一原事实，不能在许可撤销后再重播一次。限额满时先拒新／不续未承诺窗口，不拒绝旧许可原位记账、法定损害收件与清场。无容量可靠保存既有事实时依原安全边界停进度处理，而非免除责任。

## 7. 后续B扩展的明确落点与16 GB边界

不再把所有新增事实笼统宣称装进宿主原1 KiB。为后续组合试验在**原0.35 GiB模拟域**中显式预留0.125 MiB，禁用时可不分配，仍不是机制已获准开启：

| 候选全世界表 | 数量×目标记录 | 载荷 | 唯一拥有的新增事实 |
| --- | --- | --- | --- |
| 复合宿主扩展 | 128×256 B | 32 KiB | 宿主／冻结组合版本绑定、最多4单元关联、分配／依赖版本及失效／迁移依据；原宿主只引用此扩展 |
| 功能绑定扩展 | 512×128 B | 64 KiB | 功能身份／host／角色与原运营等引用，最多8设备类别配置引用／数量，同质成套安装／条件状态及实际使用依据；不复制钱包、库存、岗位或meter累计 |
| 依赖／主分表关联 | 2048×16 B | 32 KiB | 有代际类型化句柄的设备／支撑依赖或meter映射，仅关系不是读数／使用权／容量；完整依据引用冻结正文 |
| 合计 | 128 KiB | 0.125 MiB | 候选紧凑记录，不是实际sizeof证据 |

这三表只拥有组合新增事实；各类余额／库存／人数／物理占用仍归原权威。同一设备条件若已有关键设施等原表承载，功能绑定只引用，不再各存可独立写回的condition；新增成套锚点／条件也须逐字段确认无旧权威。512功能上限是128×4的共同上限，2048关联也共享，不能每宿主各有2048；关联不足拒新配置，既有关系更新保留。原8192共享使用权边有法律／责任含义，新增依赖边只指向原权利，不再创第二份许可。扩展状态全世界唯一，详细／摘要只投影同一来源，切图不复制或重新生成。
