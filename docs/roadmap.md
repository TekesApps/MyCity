# 首版计划与验收

设计版本 v0.4（2026-10-18）。当前已核对本机硬件并完成静态规模算账，尚无工程实现、游戏性能基准或真机游戏验收结果。下列数值是原型预算，完成测量后再确定正式规格。

v0.4.24先审核 [粒度收敛准入卡](model-granularity-and-convergence.md)，再逐项消除 [覆盖矩阵](object-definition-coverage.md) 中首版的参数／表示缺项，并按 [字典](capability-field-dictionary.md) 与 [27类契约](common-object-contracts.md) 冻结最小模型。验收包含共享设备计数、共同需求、峰均差异、事件切段、重放／跨图守恒和满额退化；先验证粗模型能支撑决策，不能靠不断新增字段充当完成度。

## 阶段 0：收束规则与验证预算

v0.4.23原型输入参考 [住宅底商／广场摊位案例](worked-examples-housing-retail-and-stalls.md)：冻结2030年4月游戏窗口与各方期初现金／实物，按事件复核面积／设备／水电、工程／维护、月末工资前资金、押金／租金／许可、母子账单、库存与销量下降。退出接收／运力和全过程合同峰值须真实准入；静态案例不自动开放B机制，不以正现金流代替全部成本／市场或硬件验收。

v0.4.22交叉验收按 [经济运行契约第8节](physical-economy-runtime-contract.md#8-交叉验收清单)：同区间活动／投入、主分表／尾差、故障超占用、维修不刷新全龄、共同竞争需求、许可退款／清场／版本满额与同刻恢复。后续B的128宿主／512功能／2048依赖有0.125 MiB域内候选预留，先补字段／反查／到期与持久成本再开放；每日评估、8候选和30日比较／冷却等初值须敏感度测试，不从静态算术认定平衡或16 GB通过。

纳入 [资料研究补全](sc4-research-and-gaps.md) 的最小垃圾／维护闭环和 [交通阶段求解](traffic-state-and-recalculation.md) 的状态分层。先对照群体OD与逐人周期记录，不直接承诺完整个体模拟。

- 确认人口互动上限的具体含义、城市分区关系及市长可控制范围。
- 确定市长命令、City Team 角色、预算授权与拆除确认规则，参见 [团队设计](city-team.md)。
- 选择首个 AgentKit endpoint，并验证公开工具扩展能完成一次真实查询与受控提交。
- 建立明确的长度、面积、时间、人口、货量和货币单位。
- 初始小地图为 64×64 格，基础验收中地图为 128×128 格，大地图扩展为 256×256 格；每格均 16 米，当前地图内至少两个行政／经济分区；规模为可配置参数。
- 以真正的 16 GB Mac 为基础验收机，记录芯片和显示模式；现有 M4／32 GB 仅作为开发机，不能替代最低配置证明。
- 采用 [性能预算](performance-budget.md) 的三档工作负载，中地图正常档目标为 5 万居民、4000 建筑、10,000 有向路网边和稀疏 OD；这些是待测目标，不是已测上限。

- 评审 [空间精度](spatial-contract.md) 与 [建设工具](construction-tools.md)，明确完整施工占地、模板及范围校验。
- 形成工具 JSON Schema、模板配置与几何样例；数值配置版本化。

完成标准：一份可运行原型所需的参数表、可校验工具协议和确定的验收场景。

## 阶段 1：地形与窗口原型

- 创建 Rust 工作区和锁定依赖。
- 实现 macOS 窗口、全屏、Retina 缩放和地形渲染。
- 导入高度图，设置物理尺寸和海拔范围，显示坡度与海平面。
- 支持等距相机的平移、缩放和旋转。
- 保存并重新加载地形。

完成标准：同一高度图重复导入得到相同地形；高程端点映射正确；全屏与缩放后拾取位置仍正确。

## 阶段 2：曲线道路与市政设施

- 支持曲线道路新建、连接、拆除和简单交叉口。
- 将建筑出入口连接到交通图。
- 随道路铺设水、电网络，并展示独立的连接与容量状态。
- 不支持的坡度、相交和占地冲突可解释且不破坏已有世界。

完成标准：弯曲道路可连接两片开发区；删除关键连接后，受影响建筑与管网状态正确更新；道路可视长度与模拟长度一致。

## 阶段 2A：市长命令与 City Team 最小闭环

- 用一个协调会话承载部门职责，接入 TekesAgentKit 的公开会话与状态接口。
- 实现目标草案／更新、城市查询、候选选址、规划、分层预演、提交、持久化监测和执行结果查询。
- 支持“在指定区域规划住宅并连接道路和水电”，公共设施用原子投运组；私人建筑随后由经济模型开发。地图显示草案、建成、投运和目标状态。
- 实现持续预算授权、世界版本检查、重复提交去重及取消待执行步骤。
- 断线后先查询操作回执，不自动重发结果未知的建设操作。

完成标准：真实 agent 经所选 harness 的工具通道完成查询 → 计划 → 校验 → 提交 → 读取结果。脚本或合成模型可用于协议验证，但不能替代真实模型的玩法验收；完整人口与经济效果在后续阶段验证。

## 阶段 2B：真实尺度工程与日历

- 采用 [游戏时间](game-time.md) 目标档，先验证时钟、事件边界和守恒，再测高速吞吐。
- 按 [工程生命周期](construction-lifecycle.md) 实现建设与拆除阶段、有效工时、养护、停工和验收，取消不复原半成品。
- 工程占道、运输、扬尘、机械排放和昼夜噪声进入交通／环境模型；清运到有容量处理点后才能释放土地。
- 摘要推进已冻结工程，最终几何与拓扑验收仍等待精细校验。

完成标准：30日工程经历30游戏日，倍速只改变现实等待；施工／拆除后果不被高速跳过。没有通过前不宣称1日/秒已实现。

## 阶段 3：人口与交通闭环

- 加入住宅、商业、工业及基本容量。
- 生成人口群体、岗位匹配、通勤和消费出行；不做逐人生活与逐车全城寻路。
- 按 [人口与表现层](population-and-presentation.md) 采样市民和车辆，视口变化／动画开关不得影响模拟摘要。
- 加入道路容量、拥堵反馈及未完成出行统计。
- 交通变化反馈到就业、经营和慢周期人口迁移。

完成标准：相同初始条件下，改善瓶颈降低相关出行成本；断路降低可达岗位；新增工业带来可解释的通勤与货运负担。不会因单步拥堵立即清空人口。

## 阶段 4：跨区环境与自动交易

- 两个相邻城市分区持续同时运行。
- 燃煤电厂消耗煤炭并提供电力、岗位、排放和货运需求。
- 环境作用跨区传播，边界采样连续。
- 商业负责人调整政策，市场规则自动撮合；订单包含预留、发货、在途、到货和结算，并计入交通负荷。
- 地图边界提供受容量限制的外部商品供应。

完成标准：邻区可观察到污染输入；交通瓶颈改变订单成本和交货时间；断路时货物不会瞬移；减少供煤能够影响电力供给与建筑运行。

## 阶段 4A：跨地图统一运行

- 建立区域时钟、地图身份、类型化容量与单个交换账本。
- 当前详细中图加未打开邻图摘要，统一供电、服务、贸易和边界交通。
- 验证报价、预留、交付与结算分离，故障时不虚构容量。
- 重开邻图对齐到当前游戏时间，不重播生产收费；旧进度回滚整个联动世界。

完成标准见 [跨地图运行](cross-map-runtime.md)：邻图会消耗运行资源和本地服务，短缺反馈当前城，开关地图无资源套利。

## 阶段 4B：跨区公共服务

- 先以医疗容量共享验证采购、预留、交付与结算，再扩展警务和消防的派遣／响应模型。
- 支持当前地图真实设施与轻量外部供方，两者共享容量规则但不得重复记账。
- 把交通拥堵、断路、有效容量和应急优先级反馈到覆盖与费用。

完成标准：小地图或分区无自建设施时可购买服务；不可达／超容量／未完成服务不得虚报成功。具体见 [共享服务验收](shared-public-services.md)。

## 阶段 5：首个可玩版本

- 玩家只输入施政命令即可完成小镇建设、预算调整和问题追问，无需手工执行建设步骤。
- 团队结合实际指标汇报进展，呈现部门分歧，并允许市长中途修改目标。
- 增加建设成本、税收、维护费用和公共采购预算。
- 提供交通、污染、水电、人口就业和商品流图层。
- 支持暂停、倍速、基本编辑撤销和完整存档加载。
- 完成真实 Mac 全屏、高分辨率与长时间运行检查。

完成标准：玩家无需开发调试工具，能建成并管理一个具有区域联系的小城市；能从界面理解主要发展瓶颈。

## 场景验收清单

| 场景 | 操作 | 预期证据 |
| --- | --- | --- |
| 目标归属 | 追加命令、修改旧命令和独立新命令 | 目标关系、版本与授权明确，旧版本不能继续施工 |
| 投运依赖 | 泵站连路／水／电，以及缺启动供给 | 组内原子连接；缺资源保持未投运，不能虚报服务 |
| 观察窗口 | 断路、无样本、暂停和 agent 离线 | 监测持续且不虚报；未完成需求计入，暂停不积累运营样本 |
| 自动开发 | 私人开发与 agent 项目竞争地块 | 自动开发同样更新版本，遵守预留与保护边界 |
| 崩溃恢复 | 在落盘／回执各边界中断 | 世界、账本、预留、操作 ID 与监测窗口一致恢复 |
| 市长命令 | 输入建镇目标、预算和环境约束 | 团队完成建设链路，地图及回执反映真实状态 |
| 部门协调 | 给出互相冲突的预算与建设目标 | 团队说明冲突并提供可执行取舍，不虚报达成 |
| 持续授权 | 多步建设耗用同一项目预算 | 累计预留与支出不越界，拆除规则生效 |
| 并发与去重 | 使用过期计划或重发同一操作 | 过期计划重新评估，同一操作只建设和扣款一次 |
| 取消与恢复 | 执行中停止，再断线重连 | 已提交步骤保留，未执行步骤停止，未知结果先查回执 |
| 模型离线 | 断开 agent 连接 | 城市模拟继续，界面不将未执行建议显示成建设结果 |
| 比例与占地 | 旋转、跨索引格放置建筑，并连接道路水电 | 米制尺寸、完整占地与端口正确，不以中心点判断合法 |
| 严格边界 | 建筑附属地、路权或挖填边坡侵入保护区 1 cm | 明确拒绝，无部分建设或扣款 |
| 能力缺失 | 要求首版验证下游水质或建桥 | 声明不支持，未经接受不放宽硬约束 |
| 高度图 | 导入具有已知灰度端点的样图 | 海拔、方向和物理尺寸可校验 |
| 曲线道路 | 建曲线并接入两个建筑 | 连通、长度与出入口一致 |
| 管网 | 升级道路附带管网，再拆关键连接 | 容量更新及断供范围可解释 |
| 通勤 | 对比连接前后或断路前后 | 可达岗位和旅行时间有对应变化 |
| 拥堵 | 增加固定起终点需求，随后扩容 | 流量、未完成需求与成本变化可解释 |
| 跨区污染 | 电厂位于城市边界附近 | 邻区污染非零，风向改变分布 |
| 贸易 | 改变供应价或运输瓶颈 | 商业负责人改变供应来源或订单分配 |
| 到货 | 订单在途时阻断道路 | 延迟、改道或取消符合规则，货物不瞬移 |
| 守恒 | 连续生产、消费、运输与结算 | 库存与资金变化均有来源和去向 |
| 存档 | 在订单在途时保存并加载 | 时间、库存、订单、账本和随机状态保留 |
| 重复运行 | 同一构建、种子与命令记录 | 关键状态摘要一致 |
| macOS | 全屏、移动到外接屏、改变缩放 | 文字清楚，拾取准确，无表面尺寸错误 |

自动检查优先覆盖拓扑、守恒、订单状态和重复运行；画面、交互和显示器行为依靠真实运行验收。

## 性能测量

以 [性能预算与本机评估](performance-budget.md) 为准，使用固定三档负载，不只报告人口。世界日历与精细／聚合策略以 [游戏时间](game-time.md) 为准。

验收按 headless → 交通／几何热点 → 三种分辨率 → 正常档混合 30 分钟 → 真实模型完整链路顺序执行。Release 构建，记录电源／显示模式、活跃对象数、p95／p99 耗时、峰值内存、未收敛量与实际加速倍率。

中地图常态内存目标 2.65 GiB、软上限 3 GiB、峰值警戒 4 GiB；单步 p95 目标不超过 20 ms。60 FPS 需在至少 60 Hz 显示模式下实测；4K 场景允许渲染比例调整。以上为门槛，未验证前不作承诺。

另测最多 8 张参与地图（1 详细、最多 7 摘要）、64 个共享服务池与 44 MiB 区域工作集。当前城 5000 在途批次属于全世界 10,000 上限子集，不能重复计数；其他字节准入按 performance-budget.md 执行。

现行128个事项／工程档案在原2 MiB内共享筹备、实施、停工及收尾，受理前占槽、接受工程复用；完成责任移交后归档，运营／合同／监测继续，叠加负载仍遵守总内存门槛。

同时记录单个目标的模型调用数、token／费用、工具延迟和完整预演耗时。只允许一个有界完整预演，计入写时复制和固定快照；保存／切图默认先结束预测租约。禁止每个格子或每个模拟步调用模型。

## 首版之后

1. 应用内地形搜索、DEM 导入与来源管理。
2. 更精细的曲线道路地块生成与多等级道路。
3. 公交、铁路与多模式交通，随后评估车道和信号灯模型。
4. 更复杂的商品、企业、价格形成和市政政策。
5. 自由三维视角、建筑美术和更大规模区域。
6. 根据实测瓶颈扩展并行模拟、增量寻路策略或 GPU 计算；基础阶段缓存与失效检测属于首版。

## 开工前待确认

- “人口互动上限”是否还包含城市之间明确的交换额度，或只指容量与可达性？
- 多个城市是否由同一市长管理，还是各有商业负责人和政策？首版暂按共享区域、独立城市账本设计。
- 自动市场是否只覆盖公共事业与城市分区净供需，还是展示每家企业？首版建议内部保留简化企业，界面先聚合展示。
- 首个 endpoint、视觉风格和性能目标实测结果；开发机配置已核对，16 GB 目标机仍需实测，地图容量已有提议基线。

这些问题不妨碍先完成地形、窗口和道路原型；正式平衡与扩展前必须形成明确决策。

采用 [本轮审查矩阵](review-v0.4.2.md)：单库存不能重复燃烧／出售，共享通道不超量，缺钱退款不造现金，长住院不无限授信，逐所有者重开守恒，产品进程树、长期监测、磁盘满和切图峰值均受预算。文档通过不代替实现验证。

## v0.4.4 补充验收

按 [资料研究验收](sc4-research-and-gaps.md) 和 [阶段交通比较](traffic-state-and-recalculation.md) 测试新增人口传播、断桥、新路发现、未收敛积压、跨城真实岗位、邻城垃圾满载和设施维护减容。维护状态新增0.5 MiB已计入原区域32 MiB；新增内容不得暗增群体维度或绕过全世界库存／合同／服务池上限。

## v0.4.5 团队经营验收

按 [编制与知识](team-staffing-and-knowledge.md) 验收小城富裕扩编、大城现金不足缩编、一人兼任工时、续薪失败、解聘补偿与权限交接、知识归档、摘要付薪及现实费用上限。全世界128名册槽64 KiB在原区域32 MiB内，32任务与16 MiB知识热页在原AgentKit域；单活动模型请求与单预演不随编制放大。更多专家的价值用实际规划比较衡量，不设固定正确率加成。

## v0.4.6 制度闭环验收
