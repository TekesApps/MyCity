# M0-T09：实际区域履约、共池和恢复

v0.5.15，2026-10-20。实现[跨图现行规则](regional-snapshots-and-interaction-ledger.md)的有限联合原型：实际货物／电／水交付及费用，人口、Boot作业、交付使用同一权威资源池；统一交互钟、关闭地图后的既有履约、断链和持久恢复。仍只有Rust／headless，没有UI。不将该阶段扩大为完整P-XMAP、P-CAP或全部T09已通过。

## 1. 装配与真实来源

[期初输入](../fixtures/m0-exchange-opening.json)明确三城：1城本地年龄100年、2城0、3城4000秒；全存档人口4400，1城有1998名匿名同属性迁移意向，目的地有实际住房余量。全世界只有原四个账户、14个Stock、一份Region／Boot／Exchange，不复制每城余额。账户home_city、库存保管city／上限、设施home_city均明确；市场主体C2与C3是不同企业，S4兼实验供应／运输承包，G1为财政。此匿名迁居不携带个人股权、住房、税务或其他隐藏权益，未代替具名家庭迁居。

原六个Boot池不变，另有S4的5Q货物（成本20币）、五个独立购入批次储位、C2的接收电池和水箱。资本来源唯一消费；接收池初始均为空。8份在期初明确签约的有限订单，不是关闭城自主产生的新市场需求；可取消未来未发运部分，拒绝把正在运输的事实当成取消后消失。当前不实现新建报价、无限续单或全市场撮合。

三城以1024m正方形地图的全局厘米框架放置：1城x=0、3城x=102400、2城x=204800。因此1到2非相邻，须经3城。六条**有类型**直线段各长1024m：货运两段高度0、电两段＋5m、水两段−3m，中心端点和接续关系从位置校验。不能将人口路段变成水电通道。

[空间包](../fixtures/m0-exchange-spatial.json)将主城／邻城ID及origin绑定到这些位置；三城显式复用同一经过校验的全有效、全干燥z0合成平地模板。Store创建和重开都要求该不可变空间包及正确frame绑定，缺包、错误neighbor或非此平地模板拒载，不先建一个半成品目录。只保留一份地形模板。既有T07步行道路并未被宣称为卡车、电线或管道；本轮验证专用计量终端链的坐标／距离／类型和共同存档，不证明车辆动力、建设合法性、真实街网接入、独立多城DEM、潮流或水力学。

## 2. 同池容量与实际运输

| 链／设施 | 唯一Resource | 单位与限制 | 行程／计量 |
| --- | --- | --- | --- |
| 人口／货运1→3→2 | 201／202，各2000槽 | 每名匿名迁居者占1槽；每Q货物保守占20槽，取整向上；同一路段合计不超池 | 各段60秒，整段行程120秒均持全链租约 |
| 电1→3→2 | 101／103，各1槽 | 每槽24kW的60秒保守计量窗，每批≤400Wh；源电池、目的电池另受真实物量／储位门 | 两段各1秒传播＋60秒计量，共62秒 |
| 水1→3→2 | 102／104，各1槽 | 每槽10L/s的60秒保守计量窗，每批≤600L；源池／目的池独立受限 | 各段512秒（2m/s），另60秒计量，共1084秒 |
| 原Boot泵／机组 | 同一101／102 | 沿[P-BOOT](m0-boot-runtime.md)同时占两池1槽 | 既有60秒作业至实际完成／故障清场才释放 |

101／102强制绑定到Boot home_city出发的电／水段；201／202只能绑定货运，103只能属电、104只能属水。交换电／道路resource ID也拒载，不能凭输入绕过共池。Resource、lease、token仍在原Engine，人口原Route上限是约束条件而非另一份可用配额。所有路径按资源键排序一次认领；后段不足会整批回滚，不持半份锁等待。

接纳时需要真实库存、买方可用资金、目的接收储位、全链租约，以及电水正常损耗的接收余量；最多4个在途槽，满了无扣货／扣费／半份锁地拒新。目的空间包括全部已接纳在途，不用“尚未到货”把同一位置再卖一次。实际人口2000意向／1998执行会占1998槽，从而阻止需20槽的1Q货物；反向也验证货物阻止原本有意向、有住房的人口接纳。

货物出库后只在一个Shipment中存在，保存原lot、origin quantity／basis、offset及实际成本。目的提前不可用；交付后生成买方取得批次，成本为真实货价＋已付运费。原Fragment保留在只读履约凭证，不能当成第二份库存计量。买方批次使用保留ID区，期初来源不得占用该区。电水原池允许明示的混合成本，出库时冻结源池截面；购入池不把原供方成本冒充买方取得成本。

每电／水段按0.99留存向下取milli-native-unit；100Wh／100L经两段实际收到98.01Wh／98.01L，1.99进入单独有界热／水损耗终点。出发前把所有在途的将来损耗计入接收预留，不等发生后才发现无处记账。Utility Shipment是**明确有界的源端暂存／计量WIP**：每槽至多400Wh电池缓冲或600L收容，且只使用已有真实输入；不是把电无限存在线路里。断链可保守持有该缓冲及全链容量，不模拟分布电磁瞬态、管段压力或损耗沿线空间场。

## 3. 实际费用、成本及债务

货运订单1Q，单价20币/Q，交付货价20币；电单价0.01币/Wh、水0.02币/L，按实际净到货数量向下取分，分别0.98／1.96币。每路径段运费0.10币，共0.20币，在接纳时实际支付承包方；它是已履行的接收／保管及全链预留服务费，断链不退。货价仅在原买方账户内保护，到达才实付卖方。保护不重复扣钱，也不制造托管账户余额；generic支出／保护释放不得侵占未结货价。

正常场景另保留原合法既有分期合同：C3→C2，每30秒10币、到90秒到期，实际三次共30币；不是付给S4的运费，也不是当前订单的第二次收费。不能看见本次交付收入才倒填更早分期款：同刻旧到期先结算，新到货收入随后确认。缺额留原双方的arrears，合同到期阻止新增期次，不抹旧债；后续真实拨款及显式SettleDebt只付可用现金，不自动续约。

C3的Boot边界累计记录真实导出的量和源成本，逐笔与Shipment、目的池及损耗对齐，原六池不再假设从不跨城；不新增镜像资产。联合校验每个命令后的现金、原货、燃料当量能量、水、在途／WIP、成本及租约。成本使用明确的毛利桥：

`全部库存成本＋Boot WIP＋在途源成本及已付运费＋失败费用＋损耗费用 = 期初库存成本＋Boot实付服务费＋实付运费收入＋实际货价收入−实际售出部分的源成本`

损耗对应的源成本费用化，原货尚未交付不确认销售；买方的取得成本、卖方结转成本及已实现毛利分别保留，不靠统一重置库存成本守恒。这是机械核算与交付原型，不是长期经济平衡或正式税／股息计算已通过。

## 4. 唯一时钟、关图、断链和恢复

有Exchange时，Region.interaction_time唯一推进已接纳Boot作业、人口／货物／电水在途、合同期限和分期义务；直接BootAdvance拒绝。RegionAdvance按最早到期、到达、Boot完成、未发运合同截止截段，每微步≤60秒。同刻先登记并支付旧到期，再完成Boot及交付，最后供下一命令重新接纳；不自动重试订单或新增班次。

只有当前活动城增加development_elapsed。关闭源城后原已接纳作业继续消耗原WIP完成；关闭城不能新Start Boot，但期初已接受的有限订单可以从真实库存履约。换城不推进任何钟、不转钱、不复制库存、不补满资本。所有真实增量已经在一份权威表中生效；快照／水位只发布人口观测及该全局版本，库存／钱仍查原账，绝不再应用一次delta。

出发前断链拒绝；出发后人、货、电水缓冲保留唯一在途、目的接收预留、货价保护及全链租约，暂停剩余行程。修复后从余程继续，不从源重新发货。未发运合同过期／取消只阻新；已接纳交付即使跨过截止仍结清实际责任。保持全链预留是一种保守容量近似，未实现逐段车辆跟驰／拥堵改道。

每个命令统一prepare→持久WAL／根→apply，钱、货、损耗、成本、人口、钟、阶段、lease及回执同提交。未提交失败整批回滚；已发生投入／运费不能被后续故障回滚。IO不确定隐藏writer并停止新操作，重开后查原operation；失败ID也返回原失败，不因资源释放变成功，新ID才可重试。WorldView升级mycity-m0-state-v6，旧规则fingerprint不兼容拒载，未做历史存档自动迁移。

## 5. 运行与验收边界

```sh
cargo run --release --locked --offline -p mycity-headless -- exchange-probe fixtures/m0-exchange-opening.json /tmp/mycity-exchange-new
cargo test --workspace --release --locked --offline
cargo clippy --workspace --all-targets --release --locked --offline -- -D warnings
```

目录必须不存在。CLI实际执行正常、人口与货运共池、Boot与电交付共池、电断链、水断链、满在途槽、过期旧债七分支；每分支记录真实变体输入hash、共同状态hash和重开快照。顶层world／state_sha256为初始装配，最终状态见exchange_probe。电／水断链分别穿过合同截止后走余程交付，不把普通货物断链测试当成两种公用网络已验。

本轮不签收完整P-CAP：自愿承诺满槽拒新、已有义务／缓冲及收容预留已测；独立非自愿事实收件箱、满箱停钟与保留退出通道尚未实现。P-XMAP仍缺真实车辆／街网、完整水电物理、具名权益迁居、所有生产消费／日历合同及环境联动；P-MEM／P-LOAD及真实16GB联合门继续未验，不按小型世界通过推断全城运行。
