# M0：事实收件、有限背压、责任退出与查询

本阶段接续[区域实际履约](m0-regional-fulfilment.md)和[检查点／重试档案](m0-checkpoint-and-retry.md)。实现边界为同一个三城Rust实验存档、四个既有账户、八份固定合同与一个显式注册的可信外部来源；无UI或AgentKit。普通容量满不能取消已经发生的事实或既有责任。

## 两类事实、一个确认边界

### 已接纳合同产生的事实

显式`Inbox::Enable`选择实验处理条款，必须在所有合同仍Pending时执行。每次Dispatch在真实出库、保护货款和占用通道之前，同时预留一个Delivery工作记录。实际到达复用这个记录，记录交互时间、净交付量、发票、源批次凭证；与库存接收、货款支付、损耗、容量释放在同一事务／WAL根提交。

本实验的交付处理费固定5分／合同。已暂停的真实运输可登记一次Incident，约定承运人向买方承担25分责任；每个quote一次。它是明确的实验合同违约条款，不是通用法院判赔算法或真实维修费用。`Receive`只确认已有交付；重发同来源或用新请求ID再次通知，不新增实物、不重复收款、不重复产生处理费。

### 事先无法为具体金额预留的外部费用／责任

来源1须显式注册，注册状态由CURRENT根绑定。生产者有独立的、校验和保护的有界`producer-outbox.json`：先持久保存pending，才可宣告来源事实发生；无法保存则来源自己暂停。随后按来源event顺序投递到World，World接受一次并持久提交，最后才从pending删除并确认。阶段性事件和确认不要求两个文件假装成为一次原子写；World已提交而来源确认失败时，保留pending，重开后从原回执续接。

`ExternalFact`包含source/event、原债务人、原债权人、金额、交互期限及有限原因（应急维修／合同裁定）。该实验只接纳既有账户之间的费用责任，不向库存或现金注入任何资源。来源真实性由被授权的模拟生产者负责；这里没有实现任意网络来源认证或完整司法系统。

来源operation使用保留ID命名空间；普通动作不能占用。提交External须匹配已注册来源的持久pending队首、canonical operation和当前尝试revision。满World箱导致的暂时拒收不写成永远失败的旧operation回执：不确认、不推进来源水位，腾位后原事实仍可重投。改变已确认事件的内容拒绝。

每次重开，都要求来源以其独立已知的next_event完成对齐。空本地pending不能独自证明上次IO期间没有漏掉来源事件；存在待投递或来源未对齐时，拒绝新承诺和RegionAdvance，保留管理／结算等收尾入口。已注册来源文件缺失、损坏或scope不符拒载，不降级成“没有来源”。

## 容量保证与有限停止

| 池 | 实现容量 | 使用规则 |
|---|---:|---|
| 普通工作门限 | 4条 | 到达门限即拒绝新的发运、生产启动、迁移和generic容量承诺 |
| 工作记录硬上限 | 12条 | 交付预留、Incident和外部事实共池；外部接纳还须扣除既有在途尚可能产生的Incident预留 |
| 独立追收记录 | 16条 | 已收到但未付清的完整责任可移交此池，原债务人／债权人／来源／期限／金额保留；满池不再搬移 |
| 来源pending | 16条／64KiB文件 | 不确认事实留在来源；第17条不丢弃旧项，来源须暂停 |
| 热回执 | 1,024条 | 通常512条轮转；普通空间不能容纳轮转时，新普通工作停止，已有责任可使用剩余热窗口 |
| 存档目录 | 128MiB | 默认预留8MiB供现有责任；实验可持久降低配额，不能临时放大以绕过耗尽 |

四个在途Delivery加四个尚未发生的Incident已在准入时保障空间。外部事实只能使用扣除这些预留后的余额；不能先塞满外部记录，再让真正的运输事故无处登记。实际交付始终使用原预留记录。

普通磁盘预检、普通自动／手动检查点都按普通额度。应急资格由**授权成功后的Prepared实际责任变化**决定，不能只看动作名字：无权限、无效、重复Receive、零支付、无变化管理操作不能花预留。单次应急事务限定一个控制动作；批量普通操作仍受普通配额。

应急推进须有实际可运行作业、未暂停的在途／迁移或尚有期限的既有周期义务。全部暂停且没有其他可运行责任时，不能靠空转时钟持续花预留。链路故障／修复按既有合同及边记录有限标记，重复开关不能无限取得应急资格。必要且经过同一资格检查的控制提交，只有热回执真正到1,024时才可用应急检查点保存全部状态及凭证、再轮转。

所有空间都是有限的。必要事实也无法可靠持久化时，不发布对应模型推进，不确认来源；读查询仍说明额度／pending／未对齐／暂停运输。硬满安全停止，不承诺无限事故、无限债务或无额外存储条件的自动恢复。永久断链的实物处置、破产／减记、通用来源认证和存档扩容迁移是完整产品后续，不在这里凭空清债或删除货物。

## 退出与现金／责任守恒

- Pending合同取消只撤销未履行承诺；不能取消已经在途的货物并使其消失。
- 故障作业的残余物、费用及接收库存继续存在；ClearFailure只释放其工作租约。
- Settle按现金扣除保护款后的实际余额付款；不足则部分支付，余额继续欠付。
- Handoff转移管理责任。未收到的Delivery仍留在原工作槽等待实体交付；已收到的责任可原样搬至独立追收池，释放工作槽，债权债务双方及未付款金额不改写。
- Archive仅允许已收到且付清的记录。移交后的追收记录也须付清才可结束；旧来源及原始动作仍由合同和永久重试档案追溯。
- 费用应计不等于现金。处理费计买方费用／承运人收入，Incident计承运人费用／买方补偿，External按声明的原双方形成应收应付；付款才转现金。它们没有加入库存购入成本，原实物成本桥继续单独校验。本阶段未将T08完整工资税利润执行器与Region联合，不能据此签收全行业损益和长期经济平衡。

## CLI分页与追溯

`mycity-headless query WORLD RULES SECTION [LIMIT] [CURSOR]`只读打开既有存档。RULES为创建时的规则身份（探针采用源码指纹），LIMIT为1—64，默认16。单writer期间独立CLI会受存档锁约束；运行中的探针直接调用同一查询API，不开放第二writer。

| SECTION | 返回内容 |
|---|---|
| contracts | 固定合同条款、状态、发票、源批次与成本 |
| fulfilment | 在途、已交付凭证、工作事实及独立追收责任 |
| arrears | 已登记周期欠款、事实未付款及原双方／来源 |
| capacity | resources、真实leases、工作与追收容量 |
| blocked | 普通／应急磁盘边界、来源pending／未对齐、满普通箱、暂停运输和保留租约 |
| recovery | 检查点、热窗口、WAL／档案增长、来源对齐、各城本地年龄与区域水位 |
| receipts | 热／冷原始回执分页，包含提交sequence、actor、operation、原动作及结果，可追溯入账、支付和移交 |

游标绑定查询种类、业务sequence、根generation、模型与来源／容量快照。业务写入、检查点、来源pending变化或恢复状态变化后，旧游标拒绝，调用者从首页重新取得一致快照。档案页只读取命中段，不把历史全装入RAM。

## 验证及未验边界

[收件测试](../crates/city-storage/tests/inbox.rs)覆盖工作箱12／12、Incident预留不被外部挤占、来源16／16、普通与硬磁盘边界、无权限／空操作配额旁路、512条轮转边界、未付清移交与部分偿付、恢复时来源水位、三种来源确认IO不确定、11个交付真实退出点及3个来源真实退出点、分页及游标失效。原有检查点测试仍跨越2,100个提交和多个热窗口。

本阶段原始证据置于[收件交付目录](evidence/m0-t09-inbox/tests.txt)。30分钟真实组合运行另立证据，不由这里的短测代替；M4／32GiB结果始终不等于16GB联合验收。完整车辆、公用真实物理、全部企业账、破产司法、UI和AgentKit未在本阶段扩展。

### 回执的直接结算关联

成功回执按action下标保存`created_facts`及`settled`：Dispatch／Incident／External创建的事实ID直接返回，显式Settle／RegionSettleDebt记录本次实际转现金额（不足时为实付部分，零支付为0）。来源／原双方从同条原始动作及合同追溯，后续Settle／Handoff／Archive使用相同事实ID。即使工作记录已归档，也可从冷回执直接连接“来源→事实ID→各次实付”，不要求查询者重放整个模型才能猜出关系。同operation重试返回原实付回执，不能把该返回值再次当成新转账。

v0.5.18已取得[完整30分钟及独立验算](m0-continuity-acceptance.md#v0518最终结果本轮六包完成)。本页的短测与接口契约不单独承担时长证明，具体源码指纹、原始报告、48,895条回执扫描及延后范围以验收页为准。
