# v0.4.14 复合用途与共享空间

日期：2026-10-19。用户指出建筑所在格子／用地可以同时容纳人工绿化，多个建筑也可共享空间。本版只补设计，无游戏实现或几何／性能验收。

[空间契约](spatial-contract.md#61-地块内的复合用途与共享空间) 明确：格子是多对象索引，site是完整使用／校验范围，建筑主体、附属绿化、共享庭院及通道按实际几何、用途和空间层判兼容。建筑实体、地基、消防净空和保护边界仍为硬约束，共享不允许任意实体穿插。

模板最多8个共享／复合子区域，声明允许用途和范围。首轮支持有合法依据的地面附属绿化、庭院及通道，复杂屋顶／立体开发仍需结构与空间模型后再开放。单一所有者／明确管理责任方与多个使用方分开，使用许可不自动形成共有产权或公众进入权。

共享绿地／通道只是一份实际对象，多楼引用不重复面积、维护、容量和环境贡献；法定绿化率的计入份额必须明确，不能每楼各抵扣全额。关闭、售让、拆楼或改围墙检查全部使用方的接入／消防及协议；分割、合并和责任移交保留植被贡献与未结义务，不因主楼删除级联清除共享空间。

咨询advisor后补明访问权不等于各自独享容量，关系数量也须有预算。每共享空间最多32个使用建筑引用，全世界8192条×16 B＝0.125 MiB，从原4 MiB索引域的实体反查0.5 MiB划出，后者减至0.375 MiB。原几何、4096植被状态、一般合同／住房权益和分页正文共同准入，不另造共享矩阵或无限权利清单；实际布局超假设需调整设计。区域载荷36.5078125 MiB、40 MiB额度及应用2.65 GiB目标保持，缓存缩减的真实代价待测。

工具、对象模型及总览已同步。静态检查通过：40份Markdown、269个相对文件／章节链接、围栏和2份现有JSON，另检查diff空白、版本及4 MiB配额划分。32引用限制的是已登记的建筑使用权／责任依赖，不限制公众公园的普通访客或景观受益建筑数量。同格复合用途、无权共享、实体／消防冲突、面积和成本不双算、同时施工、共享关系满额、拆楼保留公共空间、摘要关闭／恢复均列为待实现验收。
