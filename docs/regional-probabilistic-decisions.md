# 属性驱动的概率机制通则

设计补充：2026-10-21，发布v0.5.60。将v0.5.58的区域投资示例提升为跨系统建模原则：不是逐行业列举规则，而是让开发者识别同一类问题，选择必要属性、概率语义和最粗的可用计算粒度。文件路径保留以兼容已有引用。本通则尚未实现、调参或验证性能，不改变现有M0实验配置。

## 1. 何时应用：先判断计算的性质

开发者新增或修改模拟机制时，先区分以下三种计算，而不是看到“决策”就调用模型或加入随机数：

| 计算性质 | 默认处理 |
| --- | --- |
| 已知因果与确定义务：物量、费用、到期、权限、容量、实际履约 | 按原规则计算并精确记账；不能用概率代替应付工资、实际库存或合法资格 |
| 同样条件下允许有不同结果，微观细节不值得逐个模拟，但存在可解释的统计倾向 | 优先考虑本地属性驱动的概率机制；适用于自主选择、事件发生、群体转变等，范围不限投资和区域 |
| 需要开放式理解、调查、生成方案或解释 | 沿City Team等已有模型职责处理；不因本通则取消已有对话／规划能力 |

若简单确定规则已经足够，不必为了“更真实”加随机。概率机制必须解释它代表的未建模差异，并能回答“哪些条件使其更可能，哪些使其更不可能”。缺必要事实用unknown，不靠随机补造历史或隐藏设计缺口。此前[粒度收敛](model-granularity-and-convergence.md)、[家庭—企业反馈FB37](household-business-feedback.md)及确定性交易排序仍有效；新策略须版本化启用，不静默替换已有机制。

## 2. 属性来自哪里：主体及上下文，不限行政区域

统一形式是：**主体／作用对象＋相关上下文＋已提交状态 → 倾向／概率分布 → 有界抽样 → 候选或类型化事件 → 原权威流程 → 状态反馈**。

输入按因果关系选择，不为每项机制复制全部世界属性。可组合的来源维度包括：空间与区域条件、经济与市场条件、气候与自然条件、居民／家庭或兼容人群特征、企业／设施特征，以及现行制度、时间和历史状态。这些是取值来源维度，不是要穷举的行业清单，也不要求每个对象同时具备全部维度。

属性读取范围由机制决定：居住区、商圈、通勤圈、流域或单个有责任主体可以不同，不能一律取全城均值。气候应读共享气候来源，现金应读实际所有者，市场缺口应读去重且可达的需求；不能为同一场天气在每个行业独立重抽，或把“富裕区域”当成某企业拥有可用资金。

聚合仅合并对本机制有相容反应的来源；必要的财富分布、资格、产权、条款和接入差异保留。不把平均财富变成共同钱包，也不为收入×年龄×气候×行业的全组合建立常驻状态。单个主体属性可按需参与计算，不意味着为每个人新增调度器。

## 3. 概率代表什么：每项机制必须声明

概率不是一个没有单位的万能分数。每项机制须选择并声明下列含义之一：

- **发生概率**：某对象在指定游戏窗口内发生某事件的概率。
- **选择分布**：在已定义、相互区分的可行选项间如何选择；包含“不行动”选项时一并定义。互斥选项不能分别独立抽签后全部接受。
- **群体比例／转变量**：有来源的群体在窗口内有多少份额发生转变；可用有界分布、累计余数或受验证的期望近似，不要求逐成员抽签。必须满足总人数、容量和不可重复归属约束。

它们不等于AI模型置信度、盈利保证或现实统计预测；不能直接相互替换。有限离散主体用一个概率即可，持续流量若期望累计已足够，就不为每件商品制造随机事件。

公式由所需行为决定，不强制全游戏共用一个加权和。简单的 `p = clamp(b + Σ(w_i × x_i), 0, 1)` 可作为候选；分段曲线、查表或相容的选择评分也可使用。每个属性的单位、归一化、方向、作用范围及参数版本必须明确，缺输入不能默认为0。多属性交互只在有因果用途时增加，避免复杂度随行业数量膨胀。

发生概率可用均匀u∈[0,1)且u<p触发；p=0不触发，p=1必触发，50%没有统一准入意义。实现须冻结数值量化及抽样算法。共享属性不意味着共享同一个随机值：各机制用独立随机域；有真实共同原因的相关性通过共享原因／事件表达，而不是让所有行业同时抽中。

## 4. 抽样后发生什么：倾向不能越过硬约束

自主选择的抽样结果只产生意图或候选，不直接创造企业、建筑、就业、收入或需求。执行仍检查实际主体、资金、权限、资格、库存、场地、时窗和共享容量，并经原唯一writer提交；明确不可行的选项可提前筛除，提交时仍复核。市长不能用随机结果代私人同意。

自然或故障等类型化事件按其已有契约落实际后果，不能机械地全部解释成“经营意图”，也不能因为缺处理预算删除已发生危害。概率决定是否发生，影响对象、损失、责任及后续处理仍需有界且有来源的规则。

已接受的行为／事件去重，执行结果回到原事实，后续从更新后的事实重算倾向。不得把预测当交付、把在建容量当已运营容量，也不得让多个候选重复花同一笔钱或占同一份资源。未配置的新后果保持unsupported。

私人医院只是这一通则的一个说明：客群支付能力、医疗需求、竞争、成本与投资者自身条件共同影响投资意图，之后仍走合法建设／运营流程。不据此建立医院专用概率框架，也不推导“富人区必定超过50%”。

## 5. 时间、随机与恢复

每项机制声明固定游戏评估周期或已有类型化事件触发点；变化可标记待更新，但不自动获得额外抽样。不能每次读属性、重试、查询或每显示帧都抽一次。投资的7游戏日仅保留为待验证候选，不是天气、居民、企业等全部机制的统一周期。

概率绑定窗口，改变评估频率必须定义换算／事件过程，不能把周概率直接当日概率；分段推进与快进须沿同一版本化随机轨迹处理。硬失效和已确定义务按原事件立即处理，不等软行为周期。

随机身份至少绑定世界seed、机制／策略版本、稳定主体或统计组身份及代际、评估窗口／触发来源；区域身份仅在该机制确实按区域计算时参与。算法版本冻结，模拟与视觉随机域分离。相同输入下，分页、worker数量、重试、读档、画质、相机和现实倍速不改变结果；拆合群体／分区不得获得额外试次，缺合法映射时不开放该转换。

抽样可由稳定键重算，但已处理游标、输入快照／规则版本、已接受结果和责任沿原事务来源持久恢复。重试不换输入重抽，查询不推进模拟。关闭城仍依[R54](regional-snapshots-and-interaction-ledger.md)处理，不能借通用机制恢复关闭期间的内生发展或补抽历史。

## 6. 给coding agent的最小实现契约

遇到上述统计倾向类计算时，在对应机制的设计／实现中给出以下信息即可，不另建一份不断增长的行业案例目录：

| 必须明确 | 内容 |
| --- | --- |
| 用途与边界 | 为何需要概率而非确定规则；主体、作用范围，以及不允许近似的事实 |
| 输入与来源 | 必要属性、单位、有效窗口／覆盖、共享来源与unknown处理 |
| 输出与规则 | 发生概率／选择分布／群体转变中的哪一种，计算与参数版本，因果方向及硬门 |
| 推进与恢复 | 何时评估、随机身份、去重、游标、拆合与保存恢复 |
| 执行与反馈 | 唯一writer、如何接原事务／类型化事件、结果如何回写事实 |
| 资源与验证 | 最大对象／组／选项数、批次／工作区、持久字节及检查方法 |

实现优先复用已有属性查询／有覆盖汇总、共享参数、有界批处理与确定性随机工具。通用部分负责概率运算、抽样与恢复契约，领域规则负责取哪些属性及何种后果；不造一个包含全行业字段、替各系统修改状态的万能模拟器。不要求一次实现所有领域，新增机制按通则接入即可。

预算按实际评估组／主体×有限选项／指标控制，禁止每帧全城扫描和全组合常驻状态。表、索引、队列、缓存及历史都纳入[总体运行预算](product-runtime-budget-and-versions.md)，不授予额外隐形额度。预算不足标待评估并按原安全边界退化，不把未计算当未发生；实际加速幅度待同负载测量。

## 7. 通用验证要求

验证相同输入／随机身份的重放一致性，以及跨分页、重试、倍速和保存恢复的等价范围；检查概率合法区间、互斥选项归一、群体人数守恒、p=0／1与量化边界。通过改变单一相关属性检查声明的影响方向与饱和边界，不要求所有领域都服从同一种单调关系。

对独立试次检查频率与配置分布相容；有共享原因时另检查相关性，不能误当独立样本。覆盖未知输入、满额、冲突、重复接纳、在途／在建反馈和失败退出；抽样不改变资金／库存／责任守恒。不以静态公式或单例通过声称完成经济平衡、整体性能或可玩性验证。
