# v0.4.10 多方参与的市政事项流程

日期：2026-10-18。玩家明确要求建设、拆除与大型工程受程序、多方及预算约束。本版只统一设计，没有游戏实现或工程／性能验收。

## 流程与边界

[事项专题](civic-project-workflow.md) 连接意向→调查／比选→影响与产权安置→法定意见／决定→资金准备→工程接受→阶段施工→验收／投运→观察与归档。Goal、Plan、Project、Monitor仍分别判断；筹备档案不创建已接受Project，也不取得施工地和未来施工资金。

小维护依法简化，重大事项默认14游戏日意见期；公共投资建议达当年建设拨款10%或私人新增总建筑面积10000 m²等进入重大审查，更小项目也可因搬迁／关键网络等影响触发。上述为游戏参数，不是现实法规；私人自费不因市政无拨款被拒，公共补贴／配套另查。

市长、部门、财政、运营方、产权人／居民、议会与司法角色分开。意见不等于一致同意或无限否决，公众多数也不消除产权／安置义务；法院不为每个工单预先盖章。正式方案冻结版本，实质变更重走受影响程序，同一功能／目标拆单仍汇总累积影响。

预算不足给缩减、独立可用分期、延期等选择，既有拨款不是现金；每阶段落实确定承诺与安全收尾，不能先造成不可逆事实强迫追加预算。铁路未实现，大车站只作流程示例／能力缺口，不承诺可施工或运行。

## 档案与算账

原128×16 KiB＝2 MiB工程配额扩大覆盖筹备、实施、停工和收尾，阶段复用同一槽，不另增128筹备。准备受理前准入；组合中独立工程分别占槽。未付工程款、整改、安置及安全收尾未结继续占槽；合法交付和责任移交后，维护／运营合同／Monitor由既有状态承担，工程归档释放槽，施政目标仍可继续观察。

区域有效载荷32.7578125 MiB、36 MiB内余量3.2421875 MiB保持；单模型、32人工任务、单完整预演、索引与磁盘配额不增。共享范围变广可能降低并行筹备／施工数量，不据此声称没有资源代价。
