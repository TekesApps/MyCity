# 地下、地面与空域：六个用途层与实际高程

设计补充：v0.4.15，2026-10-19。按用户要求，给管线、地铁预留、地面建筑和空域少量易懂的层次，同时让住宅噪声诉求、立法与路径限制接上现有闭环。以下深度／高度均为待校准游戏参数，不是现实工程规范、适航标准或真实空域法律。

## 1. 建议采用三层地下、一层地面、两层空域

| 展示／用途层 | 建议游戏范围 | 主要用途及边界 |
| --- | --- | --- |
| U1 浅层地下 | 相对地面深度0—3 m | 普通水电支线等；具体埋深、管径与安全间距按模板，不是同层任意重叠 |
| U2 中层地下 | 深度3—10 m | 干线／综合管廊等预留，地基也可能穿过；未实现的设施仅作规划能力 |
| U3 深层地下 | 深度10—40 m | 地铁／深隧的空间预留；不因此获得轨道建设与运营能力 |
| G 地面用途 | 与地形、道路及建筑基准面接触的用途 | 地面道路、建筑、庭院与绿化；建筑实体可以向上、地基可以向下跨层 |
| A1 低空 | 离地高度0—120 m | 近地空域规划／限制；0 m不意味着可贴地飞行，最小安全高度另查模板 |
| A2 上方空域 | 离地高度120—600 m | 较高空域的规划／限制；并非不受噪声、障碍物和管辖约束 |

范围解释采用有确定边界的区间：U1为[0,3)、U2为[3,10)、U3为[10,40]；A1为[0,120)、A2为[120,600]。超过40 m深或600 m离地的对象／活动不在初轮支持范围，返回unsupported_range，不是无限可用空间。边界仅决定分类，净距和实际包络仍需校验，不能贴着3 m／120 m边界规避冲突。

六层是显示过滤和用途分类，不是互斥的六层棋盘。地面不是一块把建筑截到零高度的薄片；高楼可以穿过低空／上方空域，地下室、桩基、竖井也可跨地下多层。航空用途限制和建筑限高分别声明，禁某类飞行不自动拆楼，处于“空域层”的建筑也不因此取得飞行权限。

地铁站出入口、竖井、地面换乘和地下线路具有跨层接入关系；线路投影相交不代表连接。当前地铁／轨道、复杂桥隧和飞行运输仍是后续模块，不在首版仅靠分层标签实现。

## 2. 层标签不能代替真实坐标

所有已提交空间仍用同一米制x、y、z与垂直基准。地面高度记为terrain_z(x,y)，离地h＝z−terrain_z，地下深度d＝terrain_z−z；AGL／深度只是查询、设计与规则的参考系，最终几何固定world-z，并记录地形版本。不能混用相对地面高度和绝对海拔。

道路纵断面、地下中心线、管径／管廊包络、建筑地基、维护与施工空间分别保存。沿坡的等深管线可以随地形变化，恒定绝对高程的管线则可能跨深度类别；先明确设计模式，再生成最终包络。每段沿线检查，不能只用起点或中心格的地面高度。

地形改造不会把已埋管线或已建建筑自动上下平移。改地形计划须重新检查覆土、净空、地基、接入和受影响规则；需迁改则形成真实工程与费用。运行安全的AGL／深度使用当前权威地形；法规另声明current_terrain或frozen_terrain及其版本，首轮默认冻结制定时的地形参考以固定法律范围，若明确按当前地形则每次整地重查法域与全部依赖。绝对高程规则固定z，不与AGL互换；不能仅凭更改地形显示或层标签绕过禁令。冻结地形按已有版本块／证据分页引用保留，不为每条法律复制整张高度场。

首版水电仍可用沿路走廊＋保守离散深度槽，不承诺任意连续三维地下碰撞。可提交模板需给出实际中心深度、外包络及相容规则；无法证明地基／其他管线分离时返回needs_detailed_validation或unsupported，而不是因层名不同就通过。后续精细模块可以替换算法，但不能改变这些语义。

## 3. 不同层怎样共享或冲突

先用平面索引和高度／深度范围筛选，再检查空间层、真实包络、用途、必要净距与权利。不同地下层能在二维投影上经过同一地点，但桩基、竖井、出口与施工坑可能穿层，必须纳入全部影响范围。同层也可能是合法分开的两根管线，不能一层只准一件物体。

管线或地铁需要明确接入端口、方向、能力及转换／连接对象；只在图上重合不能自动交换水、电或旅客。地面道路若跨越地下线，连接关系与物理相交分别处理；首版不支持的桥隧／立交不能通过分层开关绕过。

地下设施的地面出入口、检修口、疏散接入、竖井、开挖坑／施工包络及需占用的土地均属于同一方案，不能只检验深处隧道主线。缺少相应模板或维护／疏散能力时不承诺可施工／投运；“在别人地下经过”仍需宪章或已登记权利依据。

地表产权、地下使用许可、通行／维护权与空域管辖分别校验。买一块地不自动取得无限深度或无限高度的排他权；首版采用宪章预置、可判定的有限权利规则，不展开复杂矿权／分层土地金融。共享规则沿用 [空间契约](spatial-contract.md)，六个用途层不新增六份土地格或独立产权账本。

## 4. 空域法律需要表达什么

每条有类型空间管控引用：管辖／宪章依据、冻结平面region_ref、适用用途／活动类型、垂直参考系及范围、游戏时段、效果、公布／生效／过渡规则与版本。规则正文分页，使用既有256规则槽，每条最多8条件／8效果／8外部引用，不创建每格一份禁飞法。

规则效果区分：禁止指定活动进入、仅允许声明时段／走廊、限高／限深、要求满足已有噪声指标等。几何禁穿越是可判定约束，不等同于已证明地面没有噪声；噪声上限需要对应声源模型和有覆盖的受体观测。提高飞行高度不能自动视作解决噪声，缺乏模型时只能报告unknown／unsupported。

针对居民区的规则必须说明地域来源。首版默认在提案中冻结具体住宅区域及版本；以后新增住宅不会不经程序自动扩大该条禁区，也不会因把zoning临时改名就解除冻结规则。若未来支持按实时用途动态筛选，需另声明版本、受影响对象重查及过渡机制，不能与冻结边界混用。

同一地点可能叠加区域宪章、城市规则、临时限制及法院命令。按既有法阶、管辖和明确替代关系组合限制；只要仍有适用禁令，另一个普通许可不能默默豁免。例外需预先列明受支持活动、签发权限、时间与证据；“紧急飞行”不是agent自报即可通过的通行证。边界外限制由预先接受的区域规则处理，市法院不能单方取得邻城／全部天空管辖。

## 5. 居民因噪声要求禁止穿越住宅区

流程为：家庭／群体的真实暴露或诉求→部门核实来源、范围、时段及模型覆盖→提出冻结区域和适用高度／活动类型的法案→财政与替代交通影响评估、法定意见／议会表决→公布及生效→路线／许可重新校验→持续观察和必要司法救济。

居民反对不是立刻禁行，投诉数量也不代替声学证据；议会可以基于明确政策选择禁止指定路径，但须公开依据及代价，不假称每项限制都有已验证的噪声改善量。既有法律程序、表决、辖权、预算和法院停止令仍适用。

游戏规则示例：“禁止指定航空活动在每天22:00—次日07:00穿越冻结住宅区域R的AGL 0—120 m范围”。时段跨午夜，生效有明确日期、时刻和游戏日历；按 [运行一致性](spatial-runtime-contract.md) 首轮禁区垂直范围默认闭区间0≤h≤120 m，时段左闭右开[22:00,24:00)与[00:00,07:00)，不能以对象分类已属A2豁免120 m边界限制。路线查整条走廊包络、实际通过时间与地形，不只查起终点／中心线。紧贴边界的安全／导航包络仍须留在合法范围，不能借量化误差穿越。

若只禁止A1，A2是否可用还要查其他禁令、建筑／树木障碍、模板高度和安全条件；若法案覆盖整个初轮0—600 m范围，则不能擅自改走A2。当前范围以上也不是逃避禁令的可用航线。即使避开住宅上空，周边声传播仍需单独观测，不能从“未穿区”推导“无噪声”。

存量活动采用通过前明确的维持、限期整改、禁止新增或退出方式；法律生效使相关计划／路径版本失效，不能倒改此前已发生费用或暴露。未来飞行模块须提供在途安全分流／退出、目标与落点容量、授权和实际费用，不能新法生效就让在途飞行器消失／瞬移，也不能无限沿旧违法路线运行。该能力未完成前不得接纳依赖它的运营承诺。

无合法路线保留未满足交通／运输需求及义务，返回infeasible需有完整限定域证据；只因搜索预算耗尽则unresolved。不能允许agent为了达成任务改高程／居民区标签绕法，也不能把路径失败当作已成功降噪。

## 6. 基础能力与后续运输模块分开

| 能力 | 现行设计边界 |
| --- | --- |
| 六层语义、z／深度／AGL、模板范围、只读展示和计划检查 | 本版基础空间契约；工具仍须如实声明哪些计算已实现 |
| 已支持水电沿路深度槽、地基避让 | 首版受限模型，不升级为任意三维施工 |
| 类型化空间政策、规则版本与合法性检查 | 可对已支持动作生效；其余保留草案／规划约束，不能声称已限制真实运输 |
| 地铁／铁路运营、复杂隧道／桥梁施工 | 后续模块；分层只预留表达，未实现则unsupported |
| 实际航空需求、运营、调度与噪声源 | 后续模块，需完整交通／费用／噪声／安全与预算设计；不是新增逐机agent |

例如航空运营尚未实现时，可以评审“这类区域应如何禁穿越”的规则草案及几何冲突，但不能回报已改航、已收费或居民暴露下降。是否可正式提交／生效，由能力声明及规则实际能约束的动作决定；不让不存在的运输服务满足市长目标。

未来运输优先使用有限稀疏走廊／班次和聚合流量，而非完整航空管制或逐旅客生活。新增运输模块须先定义需求、终端、运行时段、能源、噪声源、实际容量、跨图交接与资金，再单独预算、验收和开放。

## 7. 时间、跨图、工具与预算

空间规则和时段在统一游戏日历推进，生效、夜间边界及法院命令截断稳定区间，沿用同刻阶段屏障。邻城未打开也保留适用地域／高程规则与版本；几何／规则改变使相关跨图摘要和候选路径失效，不能把不开图的地方当成没有地下设施或禁区。

capabilities分别返回layer表示、受限地下校验、空间政策、铁路／地铁、航空运营、航空噪声模型等能力，不用一个supports_3d布尔值涵盖全部。catalog／get_object返回z包络、深度／AGL参考、用途层及权利来源；resolve_region可返回带垂直／时段条件的区域引用，底层平面region_ref保持不可变。evaluate_plan报告分层兼容、障碍、管辖、规则版本及unknown；所有写入仍走原计划／工程／法案事务。

六层不是六套地图数组、不铺三维体素或全格两两矩阵。几何参考和有界高度范围放在既有几何／对象描述；法规使用既有规则槽／工作页，索引、正文和预演继续按已有域准入，数据过复杂则拒绝新增或报告需详细校验。垂直、时段及其他条件合计仍不超过每条8个，并遵守既有多边形顶点门槛，不预先枚举整年每小时事件。

计入建筑端口及v0.4.18空间占用组后，现行区域载荷39.0078125 MiB、额度44 MiB、余4.9921875 MiB，应用2.65 GiB目标不增，这是分层基础元数据的复用预算，不包含新增完整地铁／航空运营状态。实际布局／索引超配需先重划或调整设计；不能把未来轨道、飞机、复杂三维声场都藏在本次零增额里。

## 8. 待实现验收

- 同一坐标地下管线／地面绿化相容，但地基／竖井跨层冲突仍拒绝；实体与规则净距不因标签不同消失。
- 坡地按逐点地形区分AGL、深度与绝对z，改地形不自动移动存量设施；相交线无连接节点不连通。
- 住宅冻结范围、垂直区间及跨午夜限制可复算；相邻合法区域或另一层的许可不能抵消仍有效禁令。
- 噪声诉求走表决程序，规则生效触发旧计划失效；未支持航空／噪声模型不能假称已改航或改善环境。
- 未来模块的在途转移／退出、期限、费用与未满足需求守恒；没有安全处理能力前不接受相关承诺。
- 跨图与存档恢复保留同一规则、地形版本和游戏时间，搜索超限unresolved，超范围unsupported_range，不默认无条件通行。
- 分层索引／几何／规则与原混合负载联合预算，未来完整地铁或航空模型另做16 GB验证。本版是设计与算术检查，不是这些运行验收已经通过。

## v0.4.18边界与历史基准

[空间运行契约](spatial-runtime-contract.md) 区分半开分类层、默认闭边界保护体积与左闭右开时间段，检查整个实体／安全包络和实际使用时间。硬法令／开放变化先使旧通行凭据失效，在途仍需有规则的安全处置；不混用当前安全地形与冻结法律基准。仍被法案／义务引用的地形、模板和几何版本在原磁盘预算内固定分页，不因只留最新两个检查点删旧依据；空间表示不自动开放轨道／航空或复杂声学。
