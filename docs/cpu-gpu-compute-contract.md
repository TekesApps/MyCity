# CPU／GPU计算分工与提交契约 CG39

v0.4.40 [ME40](market-entities-and-equity.md)另从模拟域其他用途划出3.375MiB，现余310.65MiB；本文第6节314.025为CG39发布时基线。计算16MiB／剩余工作188.8MiB与区域31项不变，股份／财务状态留CPU。

本篇定义首版的计算边界，关联[运行参数RUN36](minimum-operating-parameters.md)、[收敛原则](model-granularity-and-convergence.md)、[交通重算](traffic-state-and-recalculation.md)及[性能预算](performance-budget.md)。这是设计约束，没有Rust工程、着色器或实测加速证据。

CPU先提供可验证的模拟基线；GPU绘图，并在通过正确性及整机负载门后承担有限数值计算。在macOS上通过wgpu的Metal后端提交compute，不另写一套原生Metal城市核心。具体wgpu版本、适配器能力、限制和shader版本在实现时冻结；Metal支持的功能不等于wgpu全部暴露。

## 1. 工作负载和唯一权威

| 工作 | 首版执行位置 | 权威／限制 |
| --- | --- | --- |
| 游戏时钟、事件顺序、工程阶段、随机种子与存档 | CPU | 唯一推进逻辑时间；GPU完成时间不能决定事件先后 |
| 钱包、工资／税／租金、库存、合同、容量预约、权利与许可 | CPU | 整数／定点与原账本唯一写入者；不以浮点归约结果结算 |
| 精确地块／建筑占用、出入口、道路拓扑、法规硬检查 | CPU | 延用厘米整数坐标等既有约束；显示几何不能授权占地 |
| OD形成、路径搜索、路口／路段容量分配、跨图交通 | CPU | 保留真实交通原数据及增量重算；首版不做GPU逐人寻路 |
| 家庭／企业反馈、市场撮合、公服分配、维护与司法 | CPU | 聚合与稀疏事件优先；不因有GPU增加逐人常驻状态 |
| 空气EI网格的源项投影、扩散／衰减 | GPU候选，经准入启用 | 使用RUN36同一源与数值网格；CPU保留提交权与完整已提交场 |
| 噪声NI有限核、有限接收点采样 | GPU候选，经准入启用 | 线性指数，不是物理dB；覆盖／距离包络及法规判断仍归CPU |
| 地形／建筑绘制、实例动画、展示热图 | GPU | 只读已提交快照；展示插值不能反向成为交通／暴露事实 |
| 大批候选方案评分、交通代价归约、网络求解辅助 | 后续候选 | 先证明热点、误差及内存落点；不因本篇自动进入首版 |

GPU是有版本的数值执行器，CPU仍按既有S00—S13写入责任提交结果；不是为同一字段增加第二个系统写入者。未通过准入的环境计算使用CPU基线，禁止先默认GPU结果可信再补验证。

## 2. 作业、同步与因果屏障

每个作业冻结：world／branch／map、游戏时间区间和阶段、原提交序号、源／地形／路网／规则版本、数值策略与精度版本、kernel版本、设备代际及任务ID。只读输入用已有版本页与有界工作页固定，不复制整个世界；被固定的页也要计费。

完整流程：CPU冻结输入 → 有界上传 → GPU计算 → 拷贝到回读槽 → 异步映射完成 → CPU验证版本、覆盖、有限值与误差资格 → 原系统一次提交 → 释放视图并unmap／回收。回调只发送完成信号，不直接改城市或推进日历。事件循环持续处理回调；不能在主线程同步等待GPU而使映射永远无法完成。

同时最多一个正式世界的逻辑数值阶段、一个在途计算提交；两只回读槽用于有界交接，不代表两个世界时钟或两个可独立提交的阶段。唯一完整预演仍受原全世界单预演限制；GPU计算提交由同一仲裁器串行准入，预演不能饿死正式世界和绘图。回读槽满则背压，不增长待办结果队列。

逻辑阶段可以分页跨多个提交，但只在源、格点与时间覆盖完整后发布；中途结果不对外成为城市状态。依赖结果的下一模拟阶段在因果屏障等待，UI可继续显示上个完整快照。不得用旧污染值批准新工程、消费旧容量或漏计本期暴露。渲染通过队列顺序／资源依赖读取完整提交版本，不能读正在写入的一半场。

取消尚未提交的作业可立即释放；已提交资源必须等完成、解除映射或确认设备失效后退役。旧版本、重复、取消后迟到及重开分支的回调只能清理资源，不可二次提交或释放仍使用中的槽。映射中的buffer不能同时供GPU访问；先释放视图、unmap，再复用。

## 3. 有界工作量与时间推进

首版只处理当前详细地图的环境场；小／中／大地图的32m环境网格为32²／64²／128²，不给所有邻城各建一份详细GPU世界。最多8个f32通道，启用通道依RUN36，未启用通道不自动获得机制。

每次GPU提交的候选上限：一个32×32格计算块、一个8192条×32 B声／排放源页、一个4096条接收点页；一次逻辑批次最多推进4个游戏分钟，并在更早的源事件／系统阶段边界截断。具体kernel可拆成更小提交，不能将上述上限相乘生成无限格点×声源矩阵。源超过一页就按稳定顺序分页；所有源页累积完成后才推进该数值步，所有块完成后才交换场。分页游标和归约工作区有固定额度，源总数仍受原对象／活动池上限约束，不能截断超出第一页的排放。

RUN36的数值步仍为h≤1游戏分钟，遇事件分裂，保持原数值锚点；“最多4分钟”表示最多四个完整分钟步及必要的事件切分，不是把h改成4。事件切分很多时提前结束批次，提交工作项数不得无界增加。只有中间没有依赖该场的行为／阈值／暴露提交屏障时才可合批；否则缩至最早屏障。已发生暴露按原时间窗积分和原写入者提交，不能只回读批末场代替窗口内累计暴露；需要额外累计工作页必须在既定scratch内准入，否则逐步回读。source／receiver／tile页是工作页，不新增主体、计量器或历史。CPU负责空间预分桶，GPU按稳定顺序归约；首版不依赖无序浮点atomic。

实际dispatch数量、耗时和最大事件切分数需在实现准入时冻结；以上空间／时间上限不是已证明的帧预算。绘图、资源上传、Retina输出与compute共用GPU和带宽，应按测量缩小提交。算不完就降低实际日历推进速度并显示状态，不跳过源事件、数值步、账单或既有交通后果。小镇的提交／回读开销可能超过收益，不承诺GPU总比CPU快。

## 4. 精度、阈值与可重放边界

金额、库存计量、权利、身份、提交序号及游戏时钟留在CPU整数／定点域；坐标按既有厘米整数权威、角度按既有精度。GPU只处理有单位／范围定义的f32数值场和显示数据；首版不要求shader的64位整数或f64，也不使用f16作为环境权威场。

数值策略须固定边界条件、源积分、步长、归约次序、舍入／发布格式、非有限值及负值处理。不得把NaN默认为零；负值仅可按已定义且记录的数值规则处理。CPU参考实现的运算精度和每步发布格式须与策略一起冻结；更高精度的对照实现只作误差证据，不能偷换正式模型。WGSL浮点规则不能保证跨设备／编译器／后端逐bit一致；稳定次序也不足以自动保证一致。

误差门必须分别覆盖单步差、长窗口累计偏差及阈值／行为决策。单步误差小不意味着连续30天结果可用。准入前给EI／NI分别确定有依据的绝对／相对误差、累计误差包络和受支持窗口；本版不凭空指定一个epsilon当安全证明。误差包络尚未建立的GPU场只用于展示／对照，不用于改变市民、许可或费用。

对近阈值结果，以有证据的区间而非单点决策：只有整个误差区间在同一侧且覆盖有效才可判定。跨阈值或误差未知时，CPU必须从已验证的检查点及完整冻结源历史重算相关窗口，不能只对已经漂移的GPU值再算最后一步。预算不足则等待／返回unknown，不能以“差不多”批准硬约束。自然服务／环境到居民的完整关系仍属CD-03开放项，本篇不宣称关闭。

默认CPU基线；GPU数值模式在明确检查点、误差与负载准入完成后启用并记录。不得依据墙钟超时或机器型号静默切换模型。兼容的执行器切换仍须检验同一提交场／策略；若需要改变数值策略，在CPU已提交边界记明新版本，只影响未来，不承诺与旧路径逐bit相同，不重写已发生暴露、收入和责任。

## 5. 保存、故障和恢复

CPU始终持有完整的已提交场、时间锚点、来源版本与原系统已发生效应；GPU不能是唯一真值存储。回读未完成就不是已提交状态。存档保存CPU已提交检查点与必要阶段游标，不保存GPU命令／指针；未提交计算可丢弃，按同一任务身份和输入重算，按原提交序号防止二次产生暴露或费用。保存／重开仍遵守原City兼容与日志保留边界。

设备丢失／映射失败／内存不足时，UI保留旧快照，逻辑世界停在可恢复屏障；不能显示城市已推进却没有该时段环境结果。递增设备代际，拒绝旧结果，退休旧资源后重建；只重算尚未提交部分。若转CPU，须从完整CPU检查点按上节策略切换规则执行；无法证明兼容则明确停算，不能自动把故障变成零排放。设备失效不免除未结债务或既有维护义务。

## 6. 16GB统一内存与16MiB工作配额

沿用应用2.65 GiB常态目标、3 GiB软上限、4 GiB载入／保存峰值警戒。GPU计算从原**0.20 GiB求解／单预演工作空间**划出16 MiB，不向区域44 MiB表挤新条目。其余工作空间仅余**188.8 MiB**，供全部求解、一个预演、写时复制和固定快照共同使用；不是各有一份188.8或0.20 GiB。

| 计算额外资源 | 上限MiB | 计算／归属 |
| --- | ---: | --- |
| GPU环境ping-pong两场 | 1 | 128²×8×4 B×2 |
| 源驻留页和两个上传槽 | 0.75 | 8192×32 B×3 |
| 两个完整场回读槽 | 1 | 128²×8×4 B×2 |
| CPU额外冻结检查点一场 | 0.5 | 128²×8×4 B |
| 接收点输入／输出／上传／回读包络 | 1 | 4096×32 B输入及双上传、4096×16 B输出及双回读，共0.5625，余量内含 |
| 状态、脏块、游标与归约元数据 | 0.25 | 固定池，不能表外扩队列 |
| 空间桶／前缀和／临时scratch | 4 | 所有compute共用，不逐功能复制 |
| 对齐、命令与compute pipeline／实现余量 | 7.5 | 同时最多4种计算pipeline；实际驱动成本需测量 |
| 合计 | **16** | 从原204.8 MiB扣除 |

原0.35 GiB模拟域内的CPU环境双缓冲不在此重复计费：小图0.0625、中图0.25、大图1 MiB。这是原已提交场／更新基线；表内GPU副本、回读、额外冻结场是真实新增副本，不能用统一内存之名省略。源事实、历史、对象和索引继续占原域，额外冻结版本页／上传负载必须装进上述工作配额，不能无限固定原页造成隐藏增长。

纹理／显示附件仍在原渲染预算；新热图纹理先在该域准入。渲染若直接读计算资源，需保证已提交版本不被覆盖；需要新复制／保留页就计入相应预算，不能借用两个可写场假装免费三缓冲。资源允许别名复用时只计一次实际分配，但真实CPU／GPU副本分别计入；进程footprint与驱动统计可能重叠，验收按资源归属去重，不将观测指标机械相加。

Apple Silicon的统一物理内存不是CPU16GB加GPU16GB，也不等于wgpu保证零拷贝。映射／上传／回读行为和对齐取决于API与后端。16MiB是设计准入上限，不是驱动已证明的占用；pipeline编译／缓存、暂存与辅助进程均须计入原总预算及峰值。重建时先退休旧整套资源，再分配新整套，不能默认容许旧16加新16；若后端释放有延迟，必须测量峰值、暂停准入或留在CPU，不能靠swap掩盖。

区域账仍为31项43.8828125／44 MiB、余0.1171875 MiB，其他模拟用途314.025 MiB；本篇不增加主体、区域表或逐居民GPU状态，不以这些小计证明16GB整机达标。

## 7. 实现前与真机验收门

1. 冻结wgpu／shader／策略版本与实际adapter限制，布局验证上表字节、对齐、pipeline与全部副本；没有支持的功能就保留CPU基线。
2. 用同一输入比较CPU参考与GPU：单步、完整日／月、源切换／跨边界、极端密集源／多页、不同速度、保存恢复；证明累计误差和硬决策一致性范围，不能仅比截图。
3. 验证迟到／重复结果、旧分支、满槽背压、取消、映射失败、设备丢失、保存时在途计算；恰好一次提交、未完成不发布、不重放已发生效应。
4. 在实际16GB Mac上，同一满载与小镇输入，叠加既定显示比例、交通重算、单预演、保存及日志；比较CPU基线和GPU模式的整机游戏日吞吐、CPU／GPU p95／p99、帧间隔、上传／回读耗时、在途资源及峰值。不能只报kernel耗时或用32GB机限额替代。
5. 若无整机收益，保留CPU数值路径；若内存或正确性不合格，停用候选而非删除真实交通／债务／环境后果。[CD-09](city-design-closure-checklist.md)仍需实际输入装配、实现和联合验收，本篇只补定义。
