## 4. 经济原型：分清算对、运转和好玩

### P-E0：可逐笔对账的30日机械闭环（M0必需）

这是有意简化的实验经济，**不是正式居民食品／工厂profile，也不测行业平衡**。仅四个主体：财政G现金10000、家庭F现金2000、加工企业C现金6000、有限库存持有人S现金12000，总30000币；S初始600Q原料，取得成本冻结为4币/Q、总2400币，以期初非现金资产／权益分录登记，不增加现金。S是出售既有库存的主体，本窗不生产／雇员；卖出300Q结转成本1200、收入1200，利润及利润税0，余300Q成本1200。不将零新增生产成本推广给真实供方，也不将卖库存收入全当利润。

每游戏日，C先保护原料采购和工资：买10Q×4＝40币；F有效劳动8h×10＝80币；10Q原料实际转换10Q实验品（本profile废物0、没有水电需求，均显式声明）。仅为原语实验的零资源系数不可复用成正式建筑。实验在同一可达运输段上完成接纳、1h在途和到达，单日总货限20Q、在途占用容量10Q；初始时窗让到岗／到货先于生产、产成后销售，同一货不两处占有。

F每天买6Q×20＝120币，G采购并实际消耗4Q×20＝80币；C收入200，原料40、工资毛额80，利润80。工资税10%每天随薪支付8，F净收72；利润税10%每日应计8、day30统一支付240。没有财产税／租金／折旧／分红：本实验没有相应资产／租约，明示不测试这些机制，而非默认为正式企业免税。日期从2001-01-01 00:00起，day30指累计30×86400秒的边界，不借公历月名替换30日。

### 统一预算与测量方法

不增加新的常驻模拟系统，实验profile／查询／少量计数器分别占已有模板／UI／运行域；诊断热环**最多8MiB，计入运行时0.45GiB内**，详细追踪默认关闭或流式导出。实验日志／输入／保存共同受20GiB世界预算和至少2GiB安全余量，保留关键失败样本；不另开无界性能时序／世界复制。机器可重建的负载文件可独立清理，但不得删唯一恢复证据。

M0依同一全产品分域上限：模拟0.60、几何0.30、资产0.85、渲染0.25、UI/工具0.40、求解/单预演0.25、运行0.45GiB，总3.10；**M0实际消耗应按启用范围报告，不主动把额度填满当“性能稳定”**。L1专测全预算压力；L2常态目标≤3.10、软阈3.5、峰值警戒4GiB。显式保留192MiB单预演、32MiB compute、128MiB额外COW的原域归属，不能另加三笔；冲突时共享仲裁与背压。首次M0无真实预演算法时只分配／写入有界工作页并明确替身，正式预演吞吐到0.1再验。

计费值是去重后的实际owned资源账；同时报告进程树footprint、GPU分配／驱动额外量、系统memory pressure／压缩／swap变化，观测可能重叠不可机械相加。若footprint远高于资源账须查归属，不能只引用较小数。Rust字符串／map节点／索引／历史hash／分配碎片、图像解码／pipeline编译／保存临时文件与旧代退休峰值都需包含。借用了R03的预算不代表旧预算自动证明新增实现达标。
