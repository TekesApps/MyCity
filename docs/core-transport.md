# 0.1 交通基础模型

状态：交通基础有向图/OD模型已在 v0.5.107 独立实测；交通到市场的 Store 结算接入已在 v0.5.119/v0.5.122 完成限定范围实测，详见[交通到经营的真实结算接入契约](core-town-transport-integration.md)。v0.5.134另以固定最大输入实测单次纯交通CLI；不表示完整城市交通、全城市场分配或 M0 性能验收完成。

## 依赖与边界

- 消费建筑/站点显式登记的道路节点出入口和通行模式，不根据坐标距离自动开路。`authorized` 是权限/审批系统生成的可信输入，不能直接映射成玩家提供的字段。坐标几何留给地图/道路接入层；本模型只接收已获准的拓扑连接。
- 道路用有向边表示，包含自由流时间、每个模型时段容量、通行模式及可选跨城边界来源键。每个节点固定归属一个城市，边的起终城市必须与两端节点一致。OD 是群体需求，不是个人或车辆实体。
- 时间用整数秒（与 `units::GameTime` 同量纲）；当前容量以每次分配批次的出行人数计。拥堵时间用确定的整数 BPR 近似，避免浮点差异。
- 当前 `region::Region` 只有有限城市快照/迁移路由，不含路口、道路出入口与道路拥堵；`exchange::Exchange` 的有限路线是资源履约，不可替代交通图。后续经济/迁居接口读取本模块的可达性、出行成本与未满足需求摘要。
- 账本、时钟、存档、容量授权及 `transaction::Engine` 不由交通纯模型自行持有；v0.5.122 的有限 Store 接入复用统一命令与存档，并另行记录其适用范围。交通模块本身仍提供确定性纯计算输入/输出。

## 文件、接口与交付

- 仅新增 `crates/city-core/src/transport.rs`、`crates/city-core/examples/transport.rs` 和本说明；当前单元测试与模型同行，`lib.rs` 只加模块导出。
- 有界地图/出入口/OD 输入；检查 ID 唯一、端点/出入口存在、方向、容量、时间和权限。
- 每个全局 OD source ID 只能入账一次；每条跨城边界有唯一 source key，输出按 key 汇总边界载荷以便核对。
- 路径分配按稳定 ID 次序处理群体；饱和边暂时不可用，余量可走其他路径，否则列入未完成出行。每批群体路径会暂存，最多512批、最多65,024个边索引；完成装载后按最终边流量回算OD平均出行秒数，和边拥堵成本一致。未服务输出标明无开放路径、容量不足或分配预算耗尽。同输入结果逐字节稳定。
- 同节点且两端入口合法的OD视作可达，零路段、零成本，不经过道路容量。
- 每份输出包含规范化revision、拓扑、入口权限、道路容量/状态、边界来源及需求输入的SHA-256指纹。`Assignment::matches` 会重算并比对指纹及revision；相同revision下输入被改动也会判旧结果无效。
- 道路断开/扩容需产生新revision；指纹会拦截漏递增revision的修改。本版全量重算，不声称有增量缓存。
- CLI example 命令为 `cargo run -p mycity-core --example transport -- normal`，末尾场景参数可换成 `closed`、`congested`、`unreachable`。测试覆盖未授权邻近入口、权限拒绝、节点城市标签伪造、同节点OD、最终成本、断路、容量/扩容、重复边界来源、预算耗尽、输入指纹和重现性。

## 适用范围和预算

当前原型限定128道路节点、512有向边、128入口、512群体OD。线性选点 Dijkstra 最多512轮路径分配，每轮至多128节点×512边；对分配失败OD再以有界BFS辨别断路与容量耗尽，因此极端上限约67.2M次道路边扫描，另有节点选择与索引查找。最多65,024个路径边索引，元素类型为`u32`，仅索引payload上限即260,096B；旧版130,048B估算误按2字节计算，现予更正。v0.5.134最大输入实测中，单个完整Assignment的Vec owned capacity为313,344B（无路场景为61,440B），Opening各输入Vec capacity合计39,936B；值按各Vec的`capacity × size_of::<T>()`求和，不含allocator元数据、Engine调用方副本、内部瞬时scratch或并发生命周期。

该固定输入四场景的首轮assign合计111,047,625ns，重复确定性核对合计104,410,751ns；整段进程由`/usr/bin/time -l`记录wall 0.73s (wrapper: 0.752s)、RSS 3,686,400B、peak footprint 2,949,432B。运行时另一个workspace有Cargo测试活动，且没有quiet-performance准入，因此这些只是Apple M4/32GiB及外置HP P900 USB/APFS SSD上的功能性单次观察，不能称为clean性能验收。它们不是增量内存、分配峰值、16GB或完整M0验收；分配峰值仍未测。详见[最大输入实测与原收据](evidence/core-transport-capacity-134/STATUS.md)。超限输入显式拒绝。该原型验证机制，不证明完整地图吞吐、均衡交通流或经济/交通联合性能；仍按有界群体计算，不增加逐人状态。

## 完成门

代码完成不等于通过。主线冻结该源后串行执行格式、测试、CLI 和 workspace 验证；交通机制通过后仍须与建造占道和动态经济真实联调。按OD ID顺序逐批装载且不回滚既有路径；因此结果确定但不是全局 Wardrop 均衡，也不代表需求者随机选择。完整城市交通、分时OD、公交线路班次、随机效用校准与大规模性能测试延期到后续版本。
