# v0.4.39 CPU／GPU计算分工审查

本次仅补设计，不展开AgentKit，不创建游戏实现。基线v0.4.38；主契约为[CG39](cpu-gpu-compute-contract.md)，关联[性能预算](performance-budget.md)、[RUN36](minimum-operating-parameters.md)与[City缺口清单](city-design-closure-checklist.md)。

## 本轮定义

- CPU保留时间、交通、账本、容量、法规、行为和存档的唯一权威；GPU绘图，空气／噪声作为经准入的wgpu／Metal数值候选。后续求解辅助不自动变成首版支持。
- 冻结输入版本、任务身份与设备代际；异步上传／计算／回读后由CPU一次提交。明确映射互斥、满槽背压、迟到／取消结果及因果屏障。
- 数值步仍h≤1分钟；有界块／源页和最多4分钟合批不准跳事件、漏源、跨行为屏障或用批末场代替累计暴露。
- 单步、累计和决策误差分开验证；未知误差不能批准阈值。近阈值从可信检查点和完整源历史重算，不能只重算已经漂移场的最后一步。
- CPU保存完整已提交场；故障只重算未提交部分，已发生费用／暴露不再生成一次。模式切换在有记录的提交边界进行。
- 原0.20 GiB工作域划16 MiB，余188.8 MiB共同供求解／唯一预演／固定快照；上传、回读、CPU额外冻结、GPU双场及恢复重叠均有约束。应用2.65／3／4 GiB、区域31项43.8828125／44 MiB不变。

## Advisor审查与证据

advisor初审提出：长窗误差不能由单步接近替代；存档必须有完整CPU已提交场；设备丢失不能墙钟超时静默改策略；限制GPU提交负载；映射／退役生命周期必须闭合；16 MiB逐项计入原工作域并阻止恢复时旧新整套双占。本轮已将这些约束纳入正文，随后对草稿再次只读复核，未发现必须修正的矛盾或遗漏。复核确认分页／事件覆盖、累计误差与CPU重算、存档／迟到结果、16 MiB及188.8 MiB算术和重建峰值边界自洽；实际数值与整机收益仍未验。

静态检查通过：94份Markdown、788条相对链接／锚点及围栏，90类目录／23类首版、27类契约、143公共语义字段、原ID集合、31项区域预算，以及8行计算配额／全部副本和188.8 MiB余量算术；不执行游戏或着色器，不证明CPU／GPU一致性、耗时或实际16GB足够。

## 保留开放门

实现时仍须冻结wgpu版本和实际adapter限制、数值策略及累计误差、事件分块／dispatch耗时、真实布局及驱动峰值，并在实际16GB机器叠加交通、绘图、预演与保存后比较整机吞吐。没有收益或不合格就保留CPU数值基线，不能通过删后果达标。

CD-03环境与自然服务对居民的完整关系、CD-09统一负载与真机验收等原缺口继续开放；本篇完成计算分工定义，不宣称City全部设计或实现完成。
