# MyCity 完整准备设计：市长、City Team 与精准建设

版本：评审草案 v0.4，2026-10-18。目的：在动手开发前，统一玩法、空间尺度、工具权限、模拟闭环与验收标准。本套文档提供明确原型默认值，并已读取本机配置和完成静态规模算账；尚无代码、游戏性能基准或真实模型接入验收。

## 1. 我们要做的游戏

v0.4.23 [两案例实算](worked-examples-housing-retail-and-stalls.md) 与 [审查记录](review-v0.4.23.md) 将模型落到4户＋底商和两摊公共广场的完整窗口。工期完成后才收入、保护现金仍需月内可支付、库存夜间有真实储位、退出预先落实接收／运输；各方金额与数量对账，仍是后续B设计演算而非实现／平衡／16 GB验收。

v0.4.22 [经济运行契约](physical-economy-runtime-contract.md) 与 [本轮审查](review-v0.4.22.md) 修正容量不等式／故障超占用冲突，补活动与资源共同可行、计量／舍入、维护／更换、共享竞争需求及许可退出／退款。原模拟域显式预留0.125 MiB后续B绑定扩展，其他用途从314.15变314.025 MiB；原区域39.0078125／44 MiB及应用2.65 GiB目标不变。新增记录／索引、求解收敛、平衡和16 GB性能仍待验证，不把候选机制提升首版。

玩家扮演市长，通过输入向 City Team 下达施政命令。团队负责调查、规划、跨部门协调和建设执行，城市模拟产生人口、交通、环境与经济后果，市长据此继续调整方向。

例：“河东发展住宅，先保证通勤，分期投资，保留树林，不要拆居民楼。”

这条命令需要落到具体对象与土地，形成有比例、有完整占地、有成本、有依赖、可预演和可追踪的建设计划。角色对话服务于决策与执行；地图展示真实方案和实际状态。

## 2. 核心设计结论

| 问题 | 建议基线 |
| --- | --- |
| agent 怎么知道“这里”在哪里？ | 把文字关系或玩家选区解析为冻结的版本化区域引用 |
| 可以操作多大土地？ | 按城市、项目、用途与动作授权求交，不用模型任意画出的范围代替权限 |
| 精确到什么尺度？ | 建筑、道路和管线接入级；厘米存储、常规 0.25 m 吸附 |
| 是否每栋楼占一个格子？ | 土地索引格 16 m，建筑占地连续表达，可跨多个索引格 |
| 能否自由缩放建筑？ | 模板限定真实尺寸和可调参数，禁止任意缩放后保留原容量 |
| 道路怎么弯？ | agent 给端点和约束，几何求解器生成曲线、路权与连接 |
| 只检查建筑中心够不够？ | 检查设施用地、主体、端口、外接走廊、地基、挖填和边坡 |
| 精度是否等于真实数据准确？ | 不等于；存储、几何误差、源高程准确度和模拟分辨率分别声明 |
| 谁决定能不能施工？ | 工具规则引擎和模拟提交边界；模型无直接世界写权限 |
| 自动建设要一直问玩家吗？ | 授权范围内推进，预算与拆除规则持续有效，越界与硬目标冲突才请求决定 |
| 谁运行日常经济？ | 模拟负责交通、市场、生产和环境；agent 按目标与事件介入 |
| AgentKit 负责什么？ | 会话与执行呈现；具体游戏工具由 MyCity 实现，通过公开 harness 扩展接入 |

## 4. 一局游戏的完整过程

### 市长下令

目标、预算、范围与禁止事项形成版本化任务。不存在唯一区域时绑定候选或询问；其余细节使用可见默认值。

### City Team 调查与协调

规划部门判断可用土地，交通部门检查岗位可达性和路网，市政部门核实水电，财政核查投资与维护，环境核查可支持的约束，商业部门评估供应。

首版允许单个协调 agent 承担这些职责，不以七个常驻 agent 作为开工前提。后续是否拆成子代理按真实 endpoint 能力、体验和成本决定。

### 制定精确计划

工具生成地块、道路、管网、设施、分区和建设阶段。每项动作列出最终几何、模板版本、占地、依赖、成本和授权。

公共设施可以精确建造。私人住宅与企业通过分区和经济模型发展；直接公共开发必须明确产权和预算，不随意生成私人建筑。

### 预演与执行

先验证全部硬约束，再用隔离快照预测交通、人口与环境。预测携带假设和有效期。提交时重新校验当前状态，原子记录操作、项目与预留。

执行可以分期；已经生效的步骤与待执行的步骤分别展示。中途取消停止未提交动作，不把已发生的经济和人口后果抹掉。

### 汇报与下一轮治理

团队引用实际模拟指标说明完成情况。规划容量、建设完工和实际入住是不同结果；交通改善或污染目标也不能由一句“已完成”代替证据。

## 5. 精度与规模如何取舍

首版默认中地图 2.048×2.048 km，16 m 土地索引格、4 m 地形采样、32 m 环境采样。建筑和道路使用连续几何，不受 16 m 格锁死。

厘米存储是为解决可重复布局和边界校验；常规四分之一米吸附是为控制编辑与求解复杂度。道路曲线采用 ≤5 cm 弦误差预算，默认额外留 10 cm 规划净余量，但保护边界不得侵入。

人口以群体、交通以有容量约束的汇总流量运行，首版不做逐人生活和逐车全城寻路。画面个体用受流量、方向和拥堵约束的随机动画表达，摄像机与显示密度不改变模型。开发机为 M4／32 GB，产品以真实 16 GB Mac 验收；中地图正常档是 5 万居民和 4000 建筑，常态内存目标 2.65 GiB、软上限 3 GiB、峰值警戒 4 GiB；实际吞吐仍需记录地形、道路、建筑、出行对、订单与可视实例规模后实测。严禁全格子两两寻路和厘米网格化。

## 6. 最小可玩版本

- 一张中地图内两个同时运行的相邻行政／经济分区，支持高度图导入、等距视角和 macOS 高分辨率全屏。
- 文字命令驱动选址、曲线道路、水电、公共设施和开发分区。
- 住宅、商业、工业形成岗位、消费、生产和运输需求。
- 燃煤电厂有供煤、供电、岗位、污染和货运后果，影响跨城市边界传播。
- 自动市场完成撮合、发货、在途、到货和结算；商业负责人管理策略与异常。
- 地图显示方案、执行进度、拥堵、环境与供给，完整存档支持计划和在途订单恢复。

首版暂缓铁路、公交、桥隧、自由三维视角、连续三维地下设施、真实水文、复杂产业链、多玩家和模组。团队必须能说明这些能力缺失，不伪造验证。

## 7. 为什么这套工具足以支持玩法

高层工具减少 agent 手写坐标；低层草案动作保留可检查性。版本化区域让“河东”“这块地”有确定含义；模板规定真实建筑尺度；完整施工占地避免只看中心点；硬约束校验防止突破预算和保护地；操作去重与回执防止断线重复施工。

这些机制必须贯穿从规划到实际提交。只有候选可视化而没有执行校验，或者只有 API 名称而没有几何规则，都不足以算精准建设工具。

## 8. 完成准备阶段的标准

本文阶段先完成设计评审；下一步实现准备需要形成工具 schema、公共类型、模板数据、几何样例和首个 endpoint 的工具桥接验证。

开发以地形与几何原型开始，尽早用真实工具跑通市长命令，不等整套经济完成才接 agent。阶段完成证据分别覆盖静态协议、模拟回放、真实 harness、真实模型、地图交互、Mac 真机和性能成本。

## 9. 待讨论而非阻塞项

- 三档地图建议为 64／128／256 格见方，均为 16 m 格；以中地图和 16 GB 为首轮验收基线，具体性能待实测。
- 首版是否由同一市长管理两个城市账本？暂按此设计，保留跨区授权。
- 首个 endpoint 及模型选择；工具扩展完整回路需实际验证。
- 私人开发、公共住宅和城市自主经营各占多少玩法比重？
- 候选规划的展示方式与视觉风格。首台验收 Mac 已核对；默认汇报频率、时钟与预算已形成可配置基线。

在这些项确定前可以做可配置原型；所有数值都应作为版本化配置，不能散落在工具提示词和几何代码里。

## 10. v0.2 评审结论

主要闭环缺口已在文档层补齐：目标／授权创建、投运依赖、时钟、持续监测、结果窗口、自动再规划边界、私人开发竞态及回执持久化。实现能力、经济平衡、几何库稳健性与本机性能仍须后续验证；具体见 design-audit.md。

## 11. v0.3 容量澄清

小中大仅指整张地图的容量，最小土地格格式不变。不采用嵌套城市格；v0.4 已补充同一世界详细／摘要地图的必要打开对齐，不能沿用早期“不切换”的描述否定跨图运行。其他未打开地图的精细资源不常驻；已签约外部服务以轻量容量和结算摘要参与。当前地图内各分区正常联动，统一跨图运行已在 cross-map-runtime.md 定义；多图同时详细仿真和联网多人仍不承诺。

## 12. 跨区公共服务

按玩家新增要求，医院、警察与消防支持共享和市政费用结算，详见 [公共服务协议](shared-public-services.md)。服务由有效容量、可达性、响应时间与合同约束，小地图无需自建所有设施。未加载邻图可以通过有界供方摘要参与，但容量、在途交付与账单仍需真实推进。

## 13. v0.4 跨地图闭环

邻城未打开仍运行摘要。RegionRuntime 使用统一时钟、容量池和账本处理供需、交付和费用；重开只转移表示，不重播生产收费。存档与回滚以整个联动世界为单位，防止跨图资金和货物套利。

## 14. v0.4.2 审查修订

本轮结合 advisor 只读意见修正优先级和公共服务容量口径，补齐当期水电投入、共享瓶颈、权属、长期合同／收尾、退款债权及有界内存／磁盘。计入本地 harness 后常态内存目标调整为 2.65 GiB，软 3 GiB、峰值 4 GiB不变。审查及可复算案例见 [v0.4.2 记录](review-v0.4.2.md)；无游戏代码和实测性能结论。

## 15. v0.4.3 工期、拆除和环境

玩家明确要求真实尺度工期与多档日历速度，包括1游戏日/现实分钟、1游戏日/现实秒。建设和拆除均持续推进并计入占道、运输、空气污染及噪声，阶段、费用、半成品、废料和清场验收保持可追踪。高速用有版本聚合策略，事件密集时显示实际倍率，不承诺与逐10秒数值相同。

## v0.4.11闭环审查补充

[统一闭环契约](closed-loop-contract.md) 是生活、就业、议会司法、工程及观察之间的现行状态边界：每户必要状态替代同质画像权威；同刻到期分页并设置阶段屏障；终局纯金钱义务移交有界债权表后释放案件／工程槽；持续应计不等于每小时现金付款。v0.4.11当时区域小计36.2578125 MiB、上限40 MiB，相对上一版再划4 MiB、相对旧32累计划8 MiB，仍在原模拟域内。应用2.65 GiB是待测目标，大图扩展场景6万人／4096 OD，不改变土地格尺寸；修订与证据边界见 [本版审查](review-v0.4.11.md)。

## v0.4.13统一对象模型

[城市事物统一模型](city-object-model.md) 把资源需求、用途容量、人与物关系、周边作用、自然演变及维护责任形成共同语义，并复用已有业务权威。自然植被与受管理绿地分别表达生长／条件和管理质量，不每棵树运行agent。新增共享4096×64 B植被状态0.25 MiB，v0.4.13当时区域载荷36.5078125 MiB、额度40 MiB、余3.4921875 MiB，应用2.65 GiB目标不增；历史小计不作为现行准入。审查与待验收边界见 [本版记录](review-v0.4.13.md)。

## v0.4.14复合用途与共享空间
