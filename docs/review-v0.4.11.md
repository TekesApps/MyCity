## 发现与修正

| 原缺口／矛盾 | 本版设计处理 |
| --- | --- |
| 4096同质画像分组满后无法记录某户失业／失房等差异 | 32768条家庭必要状态原位更新，画像只作统计；同户不同劳动者／课程保留分别引用 |

| 工程合法交付后纯尾款仍永久占128槽 | 现场和安置责任完成、确定尾款移交后归档，Goal／Monitor独立继续 |
| 每小时交租等细分现金流水在高速下写放大 | 持续应计与实际支付分开，工资日结／租金30日结算，稳定区间可审计压缩，现金阈值截断 |
| 同刻换法、支付、换届／课程与新开工次序不够明确 | 先封闭此前区间事实，再应用当刻限制及既有到期事项，完整快照后接纳新动作 |
| 初始行业／教育／财政可能循环依赖未来收入 | 开局有限现金、库存、资格来源、宪章与拨款明确；没有输入不会自动生成产业／合格教师／补贴 |
| 大图10万人／16384 OD超过住房／账户及全局OD额度 | 扩展闭环场景改6万人／4096 OD，256×256地图格数不变；旧负载需未来另行预算 |
| 路径／索引4 MiB与4K附件256 MiB只给总数 | 明确4 MiB内部划分和75%场景比例的4K输出附件组合，新增格式／缓冲需重新准入 |

## 预算与容量结论

旧区域载荷32.7578125 MiB，家庭权威记录从0.5改2 MiB、净增1.5 MiB，新增65536×32 B债权描述2 MiB，合计36.2578125 MiB。区域额度36→40 MiB，余量3.7421875 MiB；从原0.35 GiB模拟域其他用途再划4 MiB，相对最早32 MiB累计划8 MiB。应用常态2.65 GiB、软3 GiB、峰值警戒4 GiB保持。

4K输出采用75%线性场景分辨率、双颜色／深度、保守三张显示图像、单后处理图及16 MiB阴影，附件假设199.9111328125 MiB，256 MiB内余56.0888671875 MiB。原生4K／HDR／MSAA并未获得性能承诺。家庭、住房、企业、OD等是全世界共享额度，混合负载需按一个场景向量联合准入，不能每张图都取最大值。

设计上未出现仅由固定16 m格子或家庭记录导致的数量级内存障碍；**16 GB目标仍合理但尚未证明**。重点未知成本为交通失效重算、环境子步、同步到期处理、资产和像素、账本分录／磁盘增长及预演／保存峰值。默认远端模型；本地大模型不在当前预算。
