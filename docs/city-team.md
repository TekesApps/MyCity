# 市长 + City Team 玩法与 AgentKit 架构

状态：2026-10-18 准备阶段设计 v0.4，尚未实现或验证游戏工具调用。本文把市长与团队确立为核心玩法，并明确技术职责。

闭环细则以 [运行闭环](runtime-loop.md) 为准；[性能预算](performance-budget.md) 限定团队、预演与模拟并发。Goal、Plan、Project、Monitor 分别持久化与判断完成，不能合并成一个聊天任务状态。

## 1. 玩家扮演市长

玩家向 City Team 表达发展方向、约束、优先级和资源分配，由团队落实具体建设。核心操作可仅靠文字输入完成；地图、图层和进度反馈用于观察与判断。

示例命令：“在河东发展新城区，先解决通勤，住宅分期建设，不要影响下游水质，总投资控制在五千万以内。”

首版尚无真实水文模型，“不影响下游水质”应报告能力缺失并提出可验证替代项，经市长接受后修改目标，不能声称原要求已验证。

团队将其转换成结构化目标：作用区域、人口或岗位目标、预算、环境约束、建设阶段、完成指标和汇报条件。缺少细节时使用可见的合理默认值；存在重大目标冲突时提交具体取舍。

循环：下达目标 → 调查 → 部门协调 → 形成计划 → 校验与执行 → 观察真实后果 → 汇报与调整。

## 2. 部门职责与协作

| 角色 | 主要职责 | 典型关注点 |
| --- | --- | --- |
| 城市负责人 | 理解命令、协调部门、汇总计划和汇报 | 目标达成、依赖与冲突 |
| 规划负责人 | 选址、土地用途、开发密度与分期 | 可建设性和空间组织 |
| 交通负责人 | 路网、通勤、货运与拥堵治理 | 可达性和网络容量 |
| 市政负责人 | 水电、管网、公共设施及跨区医疗／警务／消防服务 | 接入、供给、响应及维护 |
| 商业负责人 | 区域贸易政策、供应保障和招商建议 | 库存、到岸成本和供应风险 |
| 财政负责人 | 投资预算、税收和维护开支 | 支付能力及长期负担 |
| 环境负责人 | 污染、环境约束与治理建议 | 跨区影响与环境代价 |

部门以不同指标审视同一计划。交通部门可能要求提前建设主干道，财政部门要求分期，环境部门建议调整选址；协调者消解常规分歧，对无法同时满足的约束向市长给出方案和代价。

这些是产品职责，不等于固定七名员工。编制、兼任、工资、知识积累与交接以 [团队编制与知识](team-staffing-and-knowledge.md) 为准；小中大默认2／4／6人，预算充足的小城也可扩编，首轮各城统一16席位、全世界128名册槽上限。

这些是产品职责，不强制每个部门各运行一个模型或常驻会话。首版用一个协调 agent 加按需部门分析，按名册的专业与工时组织任务，全世界最多一个活动模型请求；工资和真实模型费用分别检查。是否采用子代理，取决于所选 endpoint 的实际能力和后续成本测量。

## 3. 执行授权与玩家控制

[议会与司法](governance-council-and-justice.md) 提供独立制度约束：团队是行政，不控制议员票数或判决。议会预算不替代玩家授权，玩家授权不绕过法律／停止令；行政执行还须检查拨款承诺额度和现金。依法产生的裁决责任、市场或合同日常执行由制度／模拟引擎记录，不要求市长再次同意自己承担既定义务。

市长可以持续授权，例如：“项目累计投资不超过五千万，空地建设自动执行，拆除已入住建筑先问我。”授权按城市、项目、动作类型及预算范围保存。

常规建设在既有授权内自动推进。只有超出授权、改变硬约束或需要重大取舍时请求决定，并提供具体地图方案、成本和影响。不会每铺一段路都要求确认。

累计预算检查包含已支出与预留金额，不能靠拆成多次小操作绕过上限。建设预算和后续维护负担分别展示。

停止命令阻止后续尚未提交的动作；已经生效的建设保留并明确报告。撤销草案、补偿性拆除和恢复模拟检查点是三种不同操作。拆除不能消除已发生的迁移、交易或污染后果。

## 4. 系统职责

```text
市长的输入与城市地图
          ↓
MyCity 宿主：输入、身份、权限、模型配置与产品界面
          ↓
TekesAgentKit：SessionRuntime、Run／Transcript／Composer 等状态
          ↓
所选 SessionEndpoint 与 harness：模型推理、公开工具扩展
          ↓
City Team：目标理解、部门分析、计划与结果解释
          ↓ 工具调用，经明确的产品适配层
MyCity 工具服务：快照查询、几何规划、预演、校验与提交
          ↓ 命令队列，在模拟提交边界应用
模拟核心：人口、交通、生产、市场、环境与城市账本
          ↓
只读快照、操作回执与地图反馈
```

AgentKit 管理 agent 客户端会话与执行呈现，不承担游戏状态权威或城市规则。MyCity 宿主提供凭证、runtime 配置、工具服务、授权政策及窗口；不读取 harness 私有数据库。

City Team 不能直接写世界状态或存档。曲线几何、地块生成、寻路、预算、订单结算和规则校验由确定性算法处理。模型负责意图、取舍和工具编排。

实际模型工具注册发生在所选 harness 支持的公开扩展通道，不能把 AgentKit 的会话能力等同于通用工具执行能力。需要验证请求、工具调用、结果回传、取消和重连的完整路径。

## 5. 精准建设工具契约

基础设备为 16 GB，一次详细运行一张地图，已连接邻图以摘要继续运行；小中大尺寸不改变 agent 工具格式、格子尺寸或建设精度，见 [地图容量](map-sizes.md)。

完整 API 以 [Agent 建设工具协议](construction-tools.md) 为准，空间规则以 [空间与精度契约](spatial-contract.md) 为准。工具是 MyCity 待实现的能力，不是 AgentKit 现成接口。

调用主线：capabilities → resolve_region → inspect／catalog／find_sites → create_plan → propose_layout／edit_plan → evaluate_plan → apply_plan → operation_status／observe。

此前概念接口 city.plan_district 收敛为分步规划与评估。所有修改必须通过最终几何、范围、模板、预算和授权校验；地图预览与提交回执引用同一几何。

区域引用冻结自然语言指代，建筑与道路按真实米制尺度生成；地形、索引格和环境场分别采样。不能只检查建筑中心，必须覆盖全部设施与施工占地。

## 6. 计划生命周期与一致性

计划至少包含目标、约束、候选方案、步骤依赖、预算预留、世界版本和验证结果。Plan 状态为草案、已评估、过期、已接受或放弃；Project 另外管理执行中、部分完成、受阻、建成与取消。Goal 是否达标由 Monitor 的窗口证据判断。

提交在模拟线程的明确边界进行，原子检查授权、对象引用、当前世界版本、空间冲突及预算。过期草案先重新评估；预演使用隔离快照，不能影响正式城市。

单次建设命令保证全部生效或全部失败；多阶段项目可以部分完成，必须保留各阶段回执。持久化操作 ID 与结果以提供幂等提交，重复请求返回原结果；相同 ID 携带不同参数应拒绝。

断线或超时不能视为执行失败。先通过 operation_status 确认结果，再决定恢复；不自动重发未知结果的修改。agent 的文字描述不能替代回执。

预测是特定假设下的估计；完成情况使用实际模拟指标核验。报告区分“建议”“已提交”“已建成”“目标实际达成”，不把建设完成等同于人口目标已达成。

## 7. 团队节奏与自动市场

按 [市民生活](citizen-households-and-living.md) 汇报不同家庭的教育机会、岗位、收入／储蓄、住房负担、消费和满意度短板，不只看全城均值。居民自主合法交易由模拟推进，City Team不能以市长身份控制私人钱包、指定购房或编造心理结论。

按 [行业与就业](industries-employment-and-effects.md) 调查产业方案：财政／商业／交通／环境负责人共同报告实际可填岗位、技能与工资、产品买方、投入供应、通勤／货运和排放瓶颈。不要只用理论岗位、销售总额或行业乘数宣称经济受益；私人资金与市政采购预算保持分开。

目标与监测由宿主目标服务和模拟调度器持久化，agent 不在线仍采样。模型在新命令、阶段完成、重要异常或需取舍时运行。监测条件和汇报间隔由游戏任务系统执行，避免每个模拟步调用模型。

商业负责人根据市长目标提出和调整采购、储备及贸易政策。日常撮合、物流、到货与结算由市场系统自动推进；企业继续独立记账。模型离线时城市仍可运行，等待决策的团队任务保持待处理。

首版为团队任务设置调用与费用预算，支持停止和取消；每目标默认最多 3 次自动再规划、至少间隔 1 游戏小时，失败或到期进入受阻，避免无限自治循环。重大进展与异常汇报优先，稳定运行不重复生成无意义报告。

## 8. 会话、城市与恢复

每次工具请求绑定城市世界 ID、团队任务 ID、有效授权和会话身份；不能从另一个世界的会话修改当前存档。市长修改目标时递增目标版本，阻止旧计划继续提交。

城市存档保存结构化目标、授权、计划版本、项目步骤、操作 ID 与回执，以及对应模拟时间。会话历史由 endpoint 公开协议读取；保存必要的公开会话定位信息，不复制或解析私有数据库。

加载旧存档会产生新的世界分支身份，隔离旧会话仍在途的写请求。恢复会话不意味着自动继续旧项目；先核对世界、目标和执行回执，再在原授权仍有效且状态一致时恢复。

模拟重复运行的输入是已接受的城市命令日志，不要求重新调用模型生成相同文字或计划。模型决策的非确定性与模拟规则的可重复性分开验证。

## 9. 首版接入与证据边界

首版选一个 endpoint，把单个协调会话和上述工具闭环打通；其他 endpoint 之后依据能力矩阵适配。不预设所有端都支持相同子代理、临时分支和工具机制。

接入时固定已发布 tag 或完整 commit，提交 Cargo.lock；开发 path override 必须显式。MyCity 的游戏规则和工具放在消费侧，不要求修改 Kernel。AgentKit 共享能力缺口需单独评估，避免将游戏业务放入通用库。

本次已查看本地 TekesAgentKit README、AGENTS.md 与 docs/session-endpoints.md：现有基础包含独立 SessionEndpoint 和无渲染器状态层，不能据此声称 MyCity 工具或正式游戏 UI 已完成。

验收分别报告工具协议／合成模型、真实 harness、真实模型端到端、地图交互、macOS 真机和性能成本证据。模拟回放通过不代表自然语言玩法通过。

## 10. 首个端到端场景

市长输入：“在选定区域建一个可持续运转的小镇，预算内自动施工，保留这片树林。”

团队调查地形、可达性与供给，生成建设方案，按授权完成道路、水电和分区。城市实际出现人口、岗位、通勤和商品交易；玩家再说“通勤太慢，优先解决，但不要拆居民楼”，团队据此调整。

验收应证明整条链路由真实工具推动，预算和保护区域约束生效，地图与账本吻合；若目标不可行，团队说明原因并提出可执行替代方案。

## 11. 跨图职责

团队可查询邻城供需、容量、履约、交通和账单，按授权管理跨图合同。容量与资金分配由区域引擎完成，不因当前会话在哪张图而优待本城。进入邻图只切换详细表示，不能改写账本或重置等待；工具与政策见 [跨地图运行](cross-map-runtime.md)。

## 12. 工程进度汇报

City Team管理真实尺度的建设／拆除日历，不把接受项目当作完工。汇报当前阶段、实际工作量、有效工时、费用、阻碍、预计完工与验收条件，解释占道、空气污染和噪声。玩家改变全局速度不授权缩短工期、跳验收或额外支出；具体规则见construction-lifecycle.md和game-time.md。
