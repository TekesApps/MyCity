# 模拟与技术设计

本文是准备阶段设计基线 v0.4（2026-10-18）。用户提出的六项核心需求属于目标；具体算法、数值和模块拆分属于建议，需通过原型验证。

## 玩法入口与 AgentKit 边界

玩家作为市长向 City Team 发命令，团队负责把目标转成建设和政策。具体职责与 AgentKit 接入见 [City Team](city-team.md)，时钟、目标状态、投运和持续观察以 [运行闭环](runtime-loop.md) 为准；负载与本机判断以 [性能预算](performance-budget.md) 为准。

模拟核心是城市状态的唯一写入权威；agent 通过工具提交经过校验的命令。日常交易、交通推进和人口变化不依赖模型持续在线。

## 1. 核心循环

土地与设施 → 居住／就业／消费／生产容量 → 通勤和货运需求 → 交通分配与拥堵 → 可达性、到货时间与经营成本 → 人口和企业变化 → 下一轮需求。

交通应影响实际经济结果。界面需要能解释失业、商品短缺、人口流失和企业停产的原因。

## 2. 空间表示

不同系统使用适合自己的空间结构，统一使用世界坐标与稳定 ID。

| 层次 | 表示 | 用途 |
| --- | --- | --- |
| 地形 | 高度场与分块网格 | 海拔、坡度、地形渲染 |
| 土地 | 规则栅格 | 分区、占地、基础环境采样 |
| 建筑地块 | 连续多边形，映射到土地格 | 沿街开发、建筑出入口 |
| 交通 | 节点、连续曲线边、有向通行关系 | 道路、交叉口、通勤和货运 |
| 市政网络 | 独立的水网、电网拓扑 | 连通性、容量与服务分配 |
| 环境 | 分块标量场 | 污染、噪声和吸引力 |
| 城市分区 | 行政边界与账本 | 政策、预算、统计和区域市场 |

“格子”默认指土地栅格；“城市分区”指具有政策和账本的区域。两者不能混为同一模拟单位。

首版允许规则占地近似沿街建筑，先验证曲线道路与出入口连接；精细地块切割后续扩展。

空间基线见 [空间、比例与建设精度](spatial-contract.md)：1 单位为 1 米，默认中地图 2048×2048 m，土地索引格 16 m、地形采样 4 m、环境采样 32 m；建筑和路权按连续几何表达，不被索引格限制。所有数值为可调整原型参数。大中小地图分别为 64、128、256 格见方，见 [地图容量](map-sizes.md)；首版以 16 GB 内存为基线。

## 3. 地形导入与检索

### 本地导入

优先支持 16 位灰度 PNG，兼容 8 位灰度图。导入面板设置地图物理宽高、最低／最高海拔、海平面与方向，提供缩放预览。

导入流水线：解码 → 检查尺寸与格式 → 映射海拔 → 重采样 → 计算坡度／水域 → 分块 → 保存地形及来源元数据。

普通灰度图的像素值不自带真实海拔或距离；8 位图可能产生台阶，需要明确预览。首版水域来自海平面阈值，河流与水文模拟另行设计。

### 应用内搜索

后续提供地名搜索、范围选择与高程下载。地理编码服务与高程提供方分别适配，记录数据来源、许可、坐标系、分辨率和处理参数。

真实地形导入必须处理投影、垂直基准、无效值及拼接边界。高程数据提供方、离线缓存与授权方式在接入前确定；不依赖抓取任意搜索图片。

## 4. 道路与沿线管线

道路编辑采用曲线控制点，内部按误差阈值细分为模拟和渲染片段。道路具有宽度、方向、速度、容量、坡度和道路等级。

首版支持平面交叉口与简单通行关系。桥梁、隧道和立交暂缓；遇到不支持的相交或坡度必须给出明确反馈。

新建道路默认携带可配置的水、电走廊。操作层允许一起施工，模型层分别计算水源供给、电源供给、网络容量和服务结果。

沿线建筑通过出入口连接道路，通过接入点连接管网。平面道路相交不自动意味着所有管线都相接。

拆路／升级前显示建筑断联、供水供电中断和成本影响。几何编辑与拓扑修改作为一次完整命令提交，失败不得留下半条道路或悬空网络。

## 5. 人口与交通

详细的模拟／动画分离、随机性和可视预算见 [人口群体与市民表现](population-and-presentation.md)。首版明确不做逐人完整生活和逐车全城寻路。

### 人口互动与上限

[市民生活](citizen-households-and-living.md) 将教育／技能／资格、就业收入、真实家庭资金、消费、租赁／全款购房和多维满意度连为闭环。学历不直接给工资、心情不直接删人口，住房容量／产权／居住权分开；有限培训和受限住房市场纳入首版，学龄人口学及按揭金融仍暂缓。

行业定员、技能／资格、班次、产出与工资消费链以 [行业与就业](industries-employment-and-effects.md) 为准。物理工作位、参考FTE、已雇佣、到岗工时与实际交付分别统计；同一劳动力不能被多个行业／班次重复占用，各行业不套统一岗位／格子系数。

首版按居住位置和基础就业属性聚合人口群体，记录居民数、就业、收入与消费需求，不强制每位市民拥有独立实体。

住宅人口受住宅容量、供水供电、可达岗位、污染和生活服务约束；企业受岗位、劳动力、投入品、运输能力和需求约束。

住宅模板与 zoning 决定物理容量；供水供电、就业和环境决定增长与迁移吸引力，不在断供当步直接删除已有居民。新迁入受空余容量、实际可分配水电和已匹配岗位限制，不能每栋建筑重复占用同一份岗位或电力。负吸引力通过有上限的日周期迁出作用；生育、死亡等复杂人口学首版暂缓。

企业以模板配方、实际劳动力、供给和库存计算当期产量，消费和工资采用同一游戏时间单位；发电等运行投入按分钟预留／计量，不由小时制造任务重复消费。参数和变化率写入版本化规则表；经济平衡是后续验证项，框架完整不代表平衡已完成。

“互动上限”暂按容量与可达性共同约束理解，不采用每对格子固定人口额度；这一解释需要在后续产品设计中确认。

### 交通模型

基础需求、岗位和路网持续保存，路线选择阶段性求解，稳定时复用分配方案。运行中的积压、在途与费用不能靠重算清除。具体失效、收敛与可选逐人通勤方案见 [阶段交通](traffic-state-and-recalculation.md)。

起终点需求包括通勤、消费与货运，映射到真实道路出入口。路径成本同时考虑行程时间、拥堵与必要的货运费用。

初期使用有容量约束的汇总流量分配，记录未完成出行与延迟运输。道路断开、交叉口瓶颈和容量饱和必须反映在可达性中。

路径选择与拥堵反馈采用有限轮次迭代或跨步平滑，避免所有出行瞬间集体换路造成振荡。人口迁移比交通变化更慢，避免一堵车整片住宅立即清空。

可视车辆用于表达汇总交通结果，不能反过来成为唯一的流量来源。首版不承诺逐车跟驰、信号灯和车道变换精度。

## 6. 跨格子与跨城市影响

| 作用 | 传播规则 | 主要后果 |
| --- | --- | --- |
| 电力 | 电网连接与容量分配 | 建筑运行和生产能力 |
| 供水 | 水源、管网连接与容量 | 居住与生产能力 |
| 空气污染 | 排放、风向、扩散和衰减 | 居住吸引力与健康指标 |
| 噪声 | 距离衰减与道路流量 | 居住吸引力 |
| 就业 | 可承受通勤时间与岗位匹配 | 就业与迁入 |
| 商品 | 订单、运输路径和到货 | 库存、生产与消费 |

燃煤电厂提供电力、岗位，同时消耗煤炭并产生货运、污染。首版可用可配置常量风场，不能把示意扩散宣称为真实大气模型。

当前地图内多个分区共同参与模拟，已连接的未打开地图以摘要继续运行；供给与结算不能冻结，详见 [跨地图契约](cross-map-runtime.md)。分块加载和行政边界不得截断作用。相邻环境块交换边界数据，跨城市道路与管网保留真实连通关系。

## 7. 自动区域市场与商业负责人

商业负责人作为 City Team 成员解释目标并调整贸易政策；日常撮合与履约采用可解释模拟规则，不依赖大模型逐笔决策。

市长设置公共采购预算、储备目标、采购优先级及对外贸易政策。私人企业自行经营；商业负责人管理区域供需撮合和公共采购，不把所有企业交易都算入市政财政。

候选供应商按到岸成本比较：商品价格 + 运输费用 + 拥堵／可靠性成本 + 政策费用。

订单生命周期：需求 → 报价与撮合 → 资金／库存预留 → 发货 → 在途 → 到货 → 结算。对无法履约、无路可达、库存不足及超时订单提供取消／延期规则。

商品移动必须受运输能力约束；不能仅因成交就瞬间出现在目的地。首版货运是有体积和到货时间的聚合批次，并计入道路流量。

账本分开记录企业收入成本、市政收支和区域统计。外部进口作为明确的地图边界供应商，保留成本、容量和交货时间，避免凭空出现商品。

首版可采用简化的固定报价和周期撮合，先验证流量、库存与资金守恒，再引入价格反馈和更复杂竞争。

## 7A. 跨地图共同运行

供电、供水、公共服务、贸易与交通由同一 RegionRuntime、统一游戏时钟、类型化容量池和交换账本管理。邻城不加载详细资源，但持续消耗运行投入、处理本地需求及跨城义务。容量预留、占用、实际交付和支付分别记录。

具体类型、优先级、交付计量、费用、地图重开与区域存档以 [跨地图运行](cross-map-runtime.md) 为准。city_id 是财政主体，map_id 是地图，world_id／branch_id 对应整个联动世界；不能给每张地图各造一份独立跨界订单。

## 7B. 公共服务共享

医疗、警务与消防可跨行政分区或地图边界提供，详见 [共享公共服务与费用结算](shared-public-services.md)。医院以吞吐和床位占用计量，警务以执勤／处置能力计量，消防以队伍并发和周转计量；路网旅行时间决定能否有效覆盖。

协议购买不等于实际服务：既有占用和未转占用的预留各扣一次，本地保障是其中的归属／优先级，不能重复扣除。供需统一调度容量并对每次交付结算，外部供方摘要不加载完整邻图。摘要与真实设施不能重复计算供给和费用。

## 8. 时间推进与一致性

世界使用同一游戏日历，档位按每游戏日对应现实10分钟、1分钟、10秒或1秒表达，见 [游戏时间](game-time.md)。精细／聚合事件策略分别处理，不要求高速遍历全部10秒细步；渲染独立。

建议每步顺序：校验并提交到期命令／原子组 → 应用网络版本与失效路径 → 按已发布交通状态推进在途运输并接收入库 → 按各自周期更新供给、生产消费与新订单 → 推进环境 → 在慢周期进行人口和私人开发 → 采样监测并发布快照。新交通分配按明确周期发布，不由后台线程墙钟完成时机决定生效步。

每步使用明确的上一期状态和提交边界，防止同一步重复消费库存。生产完成后生成的货物在后续撮合阶段才能出售。

随机种子、命令顺序和稳定 ID 写入存档。初期要求同一构建、同一配置、相同输入可重复运行；跨平台位级确定性尚不承诺。

## 8A. 持续工程与环境后果

建设和拆除按真实尺度的游戏工期推进，不能即时生成／删除实体。阶段工作量、班组、投入、养护、停工与验收见 [工程生命周期](construction-lifecycle.md)。占道和工程车辆改变交通，扬尘、机械排放、昼夜噪声改变暴露；拆后废料须运输到有容量的处理点，清场前地块保持占用。

## 9. Rust + wgpu 工程边界

建议工作区结构（当前尚未创建）：

```text
crates/
  city-core/       # ID、单位、配置和共享数据
  city-sim/        # 人口、交通、环境、生产与市场，无窗口依赖
  city-map/        # 地形导入、栅格、道路几何与空间索引
  city-render/     # wgpu 渲染、地形分块、道路和建筑实例
  city-app/        # winit 窗口、编辑工具、UI 与模拟调度
  city-tools/      # 查询、方案、预演、权限与幂等提交
  city-team/       # AgentKit 接入、团队协调和任务投影
  city-storage/    # 存档版本、加载、迁移与导入缓存
```

模块拆分可随原型收敛，避免过早细分大量 crate。依赖版本在实际创建工程时核对并锁定。

模拟核心可无界面运行，通过命令接收修改，通过只读快照供渲染与 UI 使用。CPU 先承担模拟，GPU 首先用于绘制；发现性能热点后再评估计算着色器。

使用分块地形、建筑实例化、视锥裁剪与按需重建。道路拓扑和环境场分别维护脏标记，不因一次小编辑重建整张地图。

## 10. macOS 与视觉目标

底层使用三维坐标、地形和建筑几何，首版以等距正交相机提供 2.5D 体验。支持缩放、平移和分档旋转；自由透视相机为后续可选项。

窗口使用 winit，绘制使用 wgpu。UI 按逻辑尺寸布局，表面按物理像素配置；处理 Retina 缩放、外接屏、全屏切换和窗口尺寸变化。

场景渲染比例可以调整，文字和操作界面保持清晰。原生全屏、外接屏表现和性能均需在真实 Mac 上验收，接口存在不等于体验已经验证。

## 11. 存档与解释能力

区域 manifest 记录参与地图、同一游戏时间与提交序号、各图检查点及摘要映射；每张地图记录尺寸、统一土地格格式版本和物理范围。仅一张图回滚不能使已结算跨图交易复活。

存档还保存 City Team 的目标、授权政策、计划版本、任务状态、监测窗口、项目预留和执行回执；会话记录与城市存档分别拥有明确权威。日志与回执崩溃一致性以 runtime-loop.md 为准。

存档包含地形、道路／管网、建筑、人口群体、企业、库存、在途订单、账本、环境场、模拟时间和随机状态，附格式版本。

检查点采用临时文件完成后替换，配合原子持久化的城市命令日志，保证世界变动、账本、预留和去重回执一致；加载前校验引用与版本；不支持的版本应明确拒绝，不能静默丢弃订单或资金。

提供人口／岗位、交通流量／拥堵、污染、供水供电和商品运输图层。点击区域或建筑可查看约束来源，例如“可达岗位不足”“供煤延迟”“邻区污染输入”。

## 资料研究补全

需求／容量／吸引力、空置、对象模板与实例、生活垃圾和关键设施维护采用 [原作资料研究与设计补充](sc4-research-and-gaps.md) 的边界。生活垃圾复用现有库存／货运／结算，关键设施状态占区域0.5 MiB；完整人口学、污水水质和金融仍为后续专项。

## 城市制度

[市民议会、法案与司法](governance-council-and-justice.md) 将群体诉求、立法预算、行政执行、司法审查和整改连接到同一模拟状态。City Team只能依法行政，不能控制票数或判决；法案有版本、公示与生效时间，停止令有范围，补偿不造现金。首版使用规则化群体代表和类型化案件，制度状态0.375 MiB计入原区域预算，不新增逐人政治模拟。

## 城市事物的共同属性

[城市事物统一模型](city-object-model.md) 作为建筑、道路、树木及管理绿地的共同语义底座，区分身份／空间、权属／运营／维护、资源需求与实获、有用途的人员容量、人与物关系、周边作用和生命周期。采用可选类型化能力，不要求每种物体都有生产配方，也不复制住房／岗位／账本／交通的权威状态。新增有限植被演变与管理状态，复杂生态及铁路等能力仍按unsupported边界处理。

## 垂直空间与空域政策

[垂直空间专题](vertical-space-and-airspace.md) 采用地下三层、地面一层、空中两层的用途分类，实际world-z、地形参考、包络和净距决定几何，不新增六套格子状态。居民可因噪声诉求推动带地域／高度／时段的管控法案，规则生效使相关计划重查；几何禁穿越不代表声学已达标。地铁／铁路、飞行运营和航空噪声仍须独立模型、预算与验收，不由分层表示自动获得。

## 入口决定交通接入

[建筑出入口专题](building-access-and-traffic.md) 把模板门位／朝向和实际连接走廊作为住宅、岗位、顾客、货运及维护访问的端点；不能按最近道路或所在格默认可达。道路侧、高程、单行／转向、时段、共享容量与权利共同限制。端口为有限真实状态，不是逐人agent或每门每帧寻路；新增2 MiB紧凑状态及剩余余量以性能预算为准。

## 对象、空间与运行一致性

[交叉契约](spatial-runtime-contract.md) 规定硬质庭院／共享走道的实体映射、唯一占用／瓶颈与原出行／服务来源、最大自然增长包络、法规和开放的硬失效，以及关闭待移交的权利占位。新增0.5 MiB后现区域载荷39.0078125 MiB、额度44 MiB，原模拟域内部重划，应用2.65 GiB目标不增；不引入逐对象agent或自动开启轨道／航空。
