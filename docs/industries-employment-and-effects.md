# 行业、就业承载与产业互动

设计补充，2026-10-18。行业不能只用建筑等级、格子数或一个统一岗位密度表示。每类经营活动需要自己的空间、设备、岗位、技能、班次、投入／交付、需求与外部性；具体产能和就业由实际运行结果决定。首版以有限行业链为基础，不以完整真实经济复刻为目标。

## 1. 参考依据与游戏参数

- [英国就业用地评估指导](https://www.gov.uk/guidance/housing-and-economic-development-needs-assessments) 将行业、物业类型、就业／建筑面积、建筑面积／用地面积分开评估。MyCity同样不直接以地块面积乘一个全行业常数。
- [HCA Employment Density Guide第三版，2015年](https://www.kirklees.gov.uk/beta/planning-policy/pdf/examination/national-evidence/NE48_employment_density_guide_3rd_edition.pdf) 区分FTE与实际人数及面积口径。其历史参考包括专业服务12 m² NIA/FTE、制造36 m² GIA/FTE、末端配送70 m² GEA/FTE；这些是特定时期英国用途的基准，不是2026年全球通用标准，更不是同时在场人数。
- [BLS劳动生产率说明](https://www.bls.gov/k12/productivity-101/content/what-is-productivity/what-is-labor-productivity.htm) 用产出／劳动小时表达劳动生产率；MyCity用实际工时约束劳动投入，不把岗位容量当作已完成工作。
- [ONS投入产出方法](https://www.ons.gov.uk/economy/nationalaccounts/supplyandusetables/articles/inputoutputanalyticaltables/methodsandapplicationtouknationalaccounts) 提供区分行业间投入与最终需求的方法参考。游戏采用稀疏订单与实际履约，不机械套用宏观乘数生成额外产值。

以下行业数值均为**MyCity原型示例，待校准与平衡**。模板分别保存现实参考的来源／年份／地域／口径、转换假设和游戏调整；不能把某份行业报告的FTE系数直接当作安全容纳人数或逐班岗位标准。

## 2. 七个不同的就业与产能数字

| 指标 | 含义 |
| --- | --- |
| 空间／设备承载 | 合法可用面积、设备工作位、出入口与服务条件允许的上界 |
| 参考FTE | 某个参考运营制度下的满时工作量，不等于自然人数 |
| 可招聘名额 | 企业按经营需求、预算、设备和排班实际开放的职位 |
| 已雇佣人数 | 已匹配到真实居民劳动力份额的主要雇佣关系 |
| 某班计划／实际到岗 | 本时段安排及真正可到达的人员与工时 |
| 实际劳动能力 | 各必要工种及资格的到岗工时能支持的工作量 |
| 实际产出／交付 | 同时受设备、劳动、投入、资金、空间及可服务需求限制的结果 |

FTE统一以40游戏工时／游戏周为参考，1周7游戏日；模板排班另外定义，不能为了开三班就让同一批居民每天工作24小时。示例：20个同时工作位连续24小时×7日，需要3360工时／周，即84 FTE；若全为40小时制员工则需要84名员工，而不是20名员工。兼职、休假和替班会改变人数，首版暂不做多雇主兼职。

历史密度给出的FTE已包含其统计运营口径，不能先按它算FTE再无条件乘班次数。要改变运营时间，必须通过明确的工作位、设备班次和劳动排班推导，且说明与参考口径的区别。

## 3. 模板如何决定合理容量

行业模板定义经营类型、适用物业／设备、面积口径、参考FTE／工作位、排班、技能与资格配比、劳动配方、工资规则、设备能力、最小安全班组、运行投入、库存／接收容量、交付方式、待机／满负荷影响以及维护要求。行业模板与建筑模板分开，一个外壳可以适配不同合法经营用途，不能任意换模型外观而保留不相容产能。

办公室／零售可按净使用面积NIA、工业按内部总面积GIA、仓储按外部建筑总面积GEA记录参考；地块面积、停车场、绿地、卸货院与设备区不能都算作办公面积。转换系数由建筑模板给出，不能在多个环节重复扣除或放大。设备型设施优先以设备及班组配方定员，不仅靠面积。

| 示意经营地点 | 原型参考工作量 | 必须再检查什么 |
| --- | --- | --- |
| 300 m² NIA零售店 | 20 m²/FTE，对应15 FTE | 营业时段、收银／补货班次、可达客源和实际消费能力 |
| 1800 m² GIA一般制造厂 | 40 m²/FTE，对应45 FTE | 设备产能、必要工种、原料、水电、出货与仓储 |
| 4000 m² GEA配送仓库 | 80 m²/FTE，对应50 FTE | 自动化、装卸设备、泊位、车流和订单处理率 |
| 600 m² NIA专业办公室 | 15 m²/FTE，对应40 FTE | 后续扩展：有支付能力的服务订单与资格，不能凭楼面积创造收入 |
| 电厂／泵站／医院等 | 逐模板配置设备、服务能力及必要班组 | 医疗吞吐／床位、管网流量等仍使用各自单位，不套统一面积产量公式 |

表中游戏系数不同于上述历史资料，目的是展示计算口径，不是完成了现实行业校准。办公室示例仅供扩展评审；没有服务需求模型时不纳入首版真实经营。

实际可招聘数还受需求与可支付工资约束。空楼、待投运设施或没有订单的企业不自动全部满编；反过来已雇佣者不会因一日销售波动马上被删除。招聘、缩班、解聘、停业与恢复有慢周期、合同／法规依据及可解释原因。

## 4. 劳动力、技能与通勤

每份可参与劳动力在同一时段只有一个主要雇主；群体可分份匹配不同企业，但人数总和不能超出该群体可用人数。首版最多3个技能层级，必要专业资格使用有界标签，最多8类；按需要在现有5000群体预算内分组，不做人口×行业×技能×收入×年龄×健康的全组合。

技能层级高不代表可以替代所有专业。医院、电气操作、驾驶等必要资格由模板和可用群体明确声明，首版没有对应资格模型时须限制承诺或返回unsupported，不把所有高级员工视作医生兼工程师。若允许较高技能填较低岗位，该劳动份额只能分配一次，不能同时填补两个缺口；技能培训需要已有机制的时长与成本，不直接创造岗位、订单或新劳动力。

劳动资格／参与率与选举资格比例是不同参数；不能因为选举用0.6就把劳动力也设为人口的0.6。就业与失业统计以明确的可参与劳动力口径为分母，未参与者、尚未求解的需求、已雇佣但迟到者分别列示，不把所有未到岗居民都算作失业。

雇佣匹配记录住宅接入、雇主地点、工种／班次、人数、计划工时与工资账户引用，交通OD来自同一匹配。到岗位所在城市的出口不算已经到岗；跨图保留真实雇主和来源，不能每经过一城重复记为就业。

已雇佣、实际到岗、未完成通勤分别统计。堵车可造成迟到／工时损失，随后影响产出和经营，不能当步把全部迟到者改成失业；就业匹配也不能把服务半径内所有居民都算成已雇佣。

城市算账示例：5万居民×0.55劳动资格比例×0.8参与率＝2.2万劳动力；本城居民1.8万在本城就业、2000在邻城就业、2000失业。若本城另接纳3000跨城员工，则本城实际雇佣2.1万；招聘总名额2.3万时空缺2000。居民就业2万与本城就业2.1万不是矛盾，分别按居住地／工作地统计；这些比例仅为游戏样例，不是人口预测。

## 5. 最小行业关系

以下为首版应接通的活动类别，不要求每种各有一套不同代码；行业模板与真实能力以capabilities为准。最多16种行业模板，不是全游戏最多16种建筑。

| 类别 | 主要投入与交付 | 就业／交通／环境作用 |
| --- | --- | --- |
| 燃煤发电 | 煤、必要水、班组、维护→当期电网流量 | 通勤、煤炭运输、实际负荷排放；不能同时在工业层再发一份电 |
| 供水 | 合格水源、泵站电力、班组→当期水网流量 | 影响居民和企业的可用水，缺电／水源条件不足不能持续满供 |
| 一般制造 | 有限原料、劳动、水电→一般消费品及明确废料 | 生产岗位、进出货、作业噪声和实际生产排放 |
| 零售 | 采购一般消费品、劳动、水电→库存转售和销售服务 | 提供消费可达性、购物与补货交通；不再制造同一批商品 |
| 物流／仓储 | 班组、装卸／车辆服务能力、水电→真实运输／存储服务 | 通勤与货车，运输收入归实际承运主体；不创造被运货物 |
| 环境卫生 | 收集／运输、处理班组和设施→接收、处理及有限最终存量 | 影响垃圾积存、运输和处理排放；接收库容与处理率分开 |
| 医疗／警务／消防 | 对应资格班组、运行投入和设施→类型化服务能力 | 吞吐、床位、执勤／队伍占用和响应沿现有服务契约，不按库存商品处理 |
| 建设施工 | 符合资格的施工工时、设备／投入→工程工作量 | 临时就业、工程车、占道、噪声与废料；工程结束不把班组永久算入建成建筑岗位 |

首轮可交易实体商品代码最多16种，每个配方最多8项输入、8项输出，静态配置按需共享；管网流量、床位和消防队伍仍用既有类型化资源，不与实体商品单位混算。可先覆盖煤、一般原料、一般消费品及已实现的垃圾／废料去向；未实现的钢、水泥、食品细分不宣称已核验供应。

农业、餐饮食品细链、办公专业服务、科研、旅游、金融、采矿与复杂自动化是后续模板／模型扩展。预览可以说明可能的关系，但没有具体供需、付款及外部性模型时不能显示为已真实运行。尤其“高科技”不等于无货运、无维护、无噪声或天然低耗电。

## 6. 实际产出取瓶颈

模板在给定运营制度下，把设备、关键劳动、投入、资金和空间条件换成同一输出工作量上界，再取可行瓶颈。不能把设备产能×人数占比×岗位容量再次相乘得到虚假产量；所有投入只由一个权威计量过程按实际运行扣除，未用预留释放。

劳动能力逐必要工种计算；某工种缺口不能由另一种过剩人数平均抵消。24小时设施每班都检查最低安全班组，不能用全天平均配齐来证明夜班合规。设备故障／维护状态引用已有关键设施表，不新增一份条件状态；企业有多少员工也不能突破设备与可接收能力。

制造样例：某8小时白班模板40名员工满配为基础24、技术12、专业4，设备上限每小时10产品。雇佣20／10／3，实际到岗18／9／3时，三类关键工时比例均为0.75，劳动上限7.5产品／小时。原料支持6、水电支持8、可用出货／仓储支持5，则实际每小时5产品，8小时40产品。该配方若每10产品耗11原料并产1废料，则当班耗44原料、产40产品和4废料，去向守恒；与面积表45 FTE的另一模板不是同一个实例。

这一最小瓶颈示例不要求所有服务沿同一公式：电力按实际交付和损耗计量，医院有持续床位占用，物流受共享通道和到货时刻限制，零售按实际售出扣库，卫生保留填埋存量。行业模型提供劳动／经营约束，各设施／服务引擎仍是唯一交付权威，不能双算容量、工资、消耗或账单。

上述制造配方的原料、产品与废料使用同一物料当量口径，不能拿吨、件与立方米直接相加。现实排放和品质损耗另按来源及模板校准，不以这个样例声称完整物料学已完成。

## 7. 工资、消费与企业账本

劳动安排前落实本区间工资资金窗口；首版不默认无限工资信用。窗口不足时减少后续安排／停止新招聘，不先让员工免费生产再以卖不掉货为由删除工资。按已公布劳动规则计提已发生劳动及停工保底，保留应付与实际支付区别；已发生义务不因停产或解聘消失。

工资从雇主账户实际转入居民家庭／群体家庭批次的真实owner账户，再形成可支付消费余额；地区收入指标只是这些支付的统计，不是第二份现金。人口群体和产权账户分开，统计群体拆并不自动平均分配财富；实际家庭批次迁移／资产拆分使用有来源的份额和成对转账，保持现金、应收工资与既有义务守恒，摘要重开也不能重分配。

工资义务按运营单位的有界雇佣批次／工资规则计量，不为每名员工新开一条跨城合同或个人常驻agent。一般交易需要合同的仍使用既有合同额度；工资、能源、原料、维护、税费、运费各计一次。企业经营现金与市政财政分开，商业负责人可以建议和制定合法公共采购政策，不能随意挪用私人企业钱或把所有工资变成市政支出。

现有City Team及议会／司法机构的抽象专业服务支出，不额外算成本地居民就业或收入。施工班组若来自有限外部服务供方，其工时、费用与实际供给需要明确来源，不计成本地就业；本地承包班组则占用同一居民劳动力。City Team分析工时不能冒充施工劳动。

家庭在预算、价格、可达性和规则化需求下采购一般消费品，减少实际库存并记录最终使用和废物去向。没有资金的需求保留为未满足，不视作已消费；不能把居民“需求值”当作给商店自动打款的账户。首版无完整租金／地产金融模型时也不虚列其反馈已成立。

初轮可用版本化人均每日需求及有限收入档调整形成目标量，实际购买不超过需求、预算／到岸单价、可达库存与服务能力四个上界。消费时长／周期、库存消耗、废物比例和饱和上限需要明示；不能收入增加就无上限消费或在同一时段反复满足同一份需求。

零售采购与家庭购买是先后两次有归属转移的交易，不是同一商品产量翻倍。制造厂销售收入、商店销售收入、物流收入属于不同交易阶段；总营业额可分别展示，不能相加后称为净新增财富或GDP。居民收入、利润与税费分别计算；税只依据已支持税种、有效条例、正确税基和实际付款，不把销售总额无条件全变成税收。

## 8. 需求、库存与供应链

一般制造至少有一种居民／企业真实购买的产品，零售补货取决于实际销售、库存目标、付款与到货；不能用无限零售需求维持所有工厂。库存满、订单不足或出货受阻时限制生产；空闲维护、保底工资和待机排放若存在须显式配置，不能当一切成本都变成零。

外部进口／出口仍是明确边界交易主体，有有限供需、价格、现金来源／去向、通道与交货时间，不是无上限销售垃圾桶。没有本地完整链时可用公开边界供应启动煤、原料或消费品，成本与容量透明；电、水、劳动力和运输的启动条件沿现有bootstrap契约，不凭纸面未来供应自举。

上下游订单形成稀疏关系，按既有候选、库存与货运额度调度，不构造每家企业到所有其他企业的完整矩阵。近距离仍受实际接入、通道与装卸约束；运费付给实际提供相应运输段的主体，同一发运不能在订单层和行业层各加一遍货车负荷／运费。

供应链断点会产生局部库存、短缺、交货延迟和现金流反馈，按阶段与慢周期传播到缩班／招聘、投资和迁移。可以统计直接就业、各上下游真实匹配就业及诱发消费，但不能再用“每个工厂带动2倍就业”复制一份已经存在的岗位、劳动者或产值。

## 9. 外部性和市长决策

通勤来自实际雇佣与排班，货运来自真实发运，污染来自实际投入／生产／待机，噪声来自设备／交通及作业时段，垃圾来自实际消费和处理链。空厂不持续产生满负荷污染；满编岗位也不等于实际客流或货车流量。

行业效果至少显示：岗位总量／技能／工资与缺口、实际交付、投入短缺、企业收支、通勤／购物／货运负荷、水电与维护压力、空气／昼夜噪声／废料及受影响地区。产业聚集若未来产生效率改善，应有范围、条件和上限，不能用相邻建筑直接互相无限增产。

City Team应比较“新增多少可填补岗位、谁能到岗、谁付工资、产品卖给谁、瓶颈在哪、受谁影响及影响谁”，而非只报告GDP或建筑等级。法案／预算／环境限制和司法命令继续约束选址与运行；产业利益会影响市民诉求与代表选择，但企业数量不自动增加选票，停产不取消失业居民选举资格。

## 10. 跨地图、数据与16 GB预算

首版每个运营单位只有一个实际经营地点，绑定operator_id、owner、行业模板、建筑／设施和出入口；一楼可有多个依法分配面积的单位，但总分配面积不能超过实际容量。同一所有者可有多个地点，分别建运营单位，不把断联分厂的库存、岗位和设备隔空合并。住宅建筑不自动是一个企业，4000建筑也不等于4000运营单位。

全世界最多4096个未清算运营单位，每条128 B紧凑身份／模板／岗位与工资汇总／引用，载荷0.5 MiB，计入区域32 MiB；停业但仍有库存／工资债务的单位仍占槽。行业静态配方共享模板，动态岗位、库存、运行计量与路径分别引用已有预算，128 B不能承诺内联全部班次、技能和8进8出数组。当前详细建筑1 KiB状态只投影／引用同一运营权威，不再存另一份工资、库存或岗位。

岗位匹配边最多32768条×32 B＝1 MiB，明确从既有4 MiB“索引、分配器及变长路径”额度内划出，不另增总预算；该4 MiB内其余索引／路径可用量相应减少，实际开销仍需联合准入。达到配额时兼容聚合或报告unresolved并保留需求，不能把计算没完成伪装成已失业或已到岗；已接受的雇佣与在途不得删除。

16行业模板、3技能层、最多8资格标签、每模板最多4排班窗口和16实体商品是首轮上限提案，资格拆分仍受群体预算约束。4096单位与账户、库存、合同、计量、服务池、货运／OD均联合准入；多图不能各用4096，不能承诺8张地图各自同时达到全部负载上限。单位加入／私人开发前预检未来运行状态和收尾义务，不能先建成后丢掉旧企业。

新增0.5 MiB后区域小计29.6953125＋0.5＝30.1953125 MiB，余量1.8046875 MiB，总应用2.65 GiB目标、3 GiB软上限和4 GiB峰值警戒不增加。岗位匹配计量、群体、模板与临时求解必须按实际字节计入，不能用紧凑载荷算术替代16 GB证明。

未打开地图按同一劳动、现金、库存、配方和连接约束继续运行，保留各雇主／家庭账户及在途、工资、就业和环境后果。可按兼容条件聚合行业运行，但不能把缺关键工种、孤立电网或不同所有者混成全城平均后宣布全部满产。

## 11. 工具和验收

拟议只读工具city.industry_catalog返回模板、面积／FTE口径、岗位／资格配方、输入输出、参考来源、能力状态及作用范围；city.employment_status返回可用劳动、名额、匹配、到岗／工时、FTE、工资支付和unresolved；city.industry_status返回各运营单位／行业汇总、真实产出、缺口、库存、成本、影响与上下游证据引用。按已有分页、快照、覆盖和数据年龄协议，不能一次把全城所有配方和每个匹配塞给模型。

完整案例：住宅劳动力→煤电／制造雇佣→实际工资→零售购买→制造补货→真实运输→垃圾处理。分别断掉煤、道路、必要工种、工资资金或消费资金，观察链条怎样变化，并解释瓶颈与未满足需求。

还需验收：面积口径不混、FTE与三班工时不重复、关键工种缺失不能平均、迟到不瞬时解聘、工资收款后可消费、群体拆并／跨图重开不重分财富、库存满停产、商店／物流不造货、公共服务不双算、出口有限、停业保留债务、阶段求解在高速／摘要一致守恒，以及最大单位／匹配与单预演叠加负载。数值样例仅静态验证，不宣称经济平衡或真实产业校准已完成。

行业参数通过前，每个首版类别至少比较小／中／大3种实例的面积、设备、就业、排班、工资、耗能和运输；对需求、工资、通勤与输入供应做0.5倍／2倍敏感度检查，记录来源缺失和置信边界。不能只把全城就业总数调到好看，就认为各行业规模与相互作用合理。
