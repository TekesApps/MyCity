# v0.4.28：楼体、单元与共享设施交叉审查

日期：2026-10-19。仅设计文档，无游戏实现代码。

## 结论和范围

[统一分层契约](building-unit-shared-facility-contract.md) 逐项复核27物件族，并约束原90类目录，区分B楼体、H单元、F家庭、O经营者、共享／功能子区、公共设施、使用关系与收费／维护来源。34属性／16能力／14系统／26指标族和143通用路径保持，不新增动态表或提前开放后续类型。

沿街楼与成组住宅共用同一模型。项目／小区是组织范围，实际楼体、道路、管线／站点、产权和各方账户仍独立；共享一个真实设施不意味着各楼各获得完整产能，也不生成可以挪用各户钱的公共钱包。

## 发现的重复／遗漏与修正

1. **8子区与H套数混淆**：统一为H住宅布局、≤8共享／功能子区、后续≤4功能绑定、≤8外接端口四个数量。模板共享住房几何，实际H／几何／索引仍计费；不能把商业隔间伪装成H绕过组合门。
2. **host_ref误充连通性**：新增有限模板接入组语义，每资产布局最多8组，由H布局槽／O受支持范围解析合法门、内部共同通路／时长、角色／权限、容量与管网／隔离来源。内部不逐房寻路，但不能自动连所有门或跨他人套内；两翼封梯只失效实际依赖者。
3. **建筑使用边误充每户账务**：8192关系只是建筑依赖，H附属条款提供静态依据；独立付款／维护协议及应计按实际H／C／义务落点。只有原合法租约已含、同债权人／账期／清偿规则的费用可在H合计；自住房不能虚构租金。C950＋96新协议>1024，明确受阻，不藏H64新数组。
4. **共同部位主责缺口**：出售前落实真实管理／维护授权、必要接入及当前资金安排。最后一套售出不注销责任，空置／欠费份额不自动重摊其他人或市政；单元买卖仍保留，任意共有治理／规模化独立物业收费仍B。
5. **维护条件重复**：B结构／未拆出成套、独立共同K／单元K、原P或D按覆盖域互斥。整体健康只是派生；B→K迁移先移交年龄、条件／磨损、维护责任／欠账并排除旧覆盖，缺可恢复历史时不支持局部迁移。
6. **单口多锚与重复收费措辞**：旧空间运行文改为每U一锚点，真实多链路分别占槽且共享开口瓶颈；并发和吞吐是分别计量／校验，不因存在两个容量条件自动收两份费用。
7. **同址经营者口径**：按受支持主体×真实经营单元／地点计O，不因相同地址合并各方经营，也不拆名复制同主体的库存／人手／权利；普通单用途模板1O仍原样，多用途／商租不因此提前开放。

## 经济、容量和16 GB

反例核验：两单元各80但共享100 kW，不可同时110；故障后actual80／能力60保留20缺口。一次维护120按40／80分摊，代垫200后收80、另40欠付时四方现金仍1200，配对债权40不复制本金；楼内10／30只分同一40，不生成第二次维护。

本轮不增27项43.0078125／44 MiB、余0.9921875 MiB与314.025 MiB其他模拟用途；应用2.65／3／4 GiB目标不变。模板接入组正文共用64×4 KiB热页／几何和原分页，必要绑定从原布局／记录解析；8192使用边、C1024、H32768、K4096、U65536、X8192等全世界联合准入。实际字段、代际引用或索引装不下就阻新／重预算，不借“只增加关系”免开销。

原单楼三方案与四楼共享站、住宅底商／摊位案例的数值保持。新契约不会把后续复合／燃气或共有治理升级首版；24／26新建K、34／32改造峰值仍依独立设备真实来源解释。
