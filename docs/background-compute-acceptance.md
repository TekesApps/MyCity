# 可恢复后台计算闭环：冻结验收 W0

发布v0.5.25。目标是把现有空气CPU参考接成独立worker任务，由Sim唯一接纳和持久提交，再与调度、经济和跨城履约联合运行。本篇冻结实施和验收；不是worker实现或运行通过的证明。当前仅Rust模型与CLI，不做UI、渲染、GPU加速或AgentKit。架构基线见[软件架构](SOFTWARE_ARCHITECTURE.md)、[进程架构](process-worker-and-render-architecture.md)和[空气参考](m0-air-cpu-reference.md)。

## 1. 连续推进和完成条件

阶段提交后按依赖继续，不能以一次提交结束整个目标。完整闭环必须同时有真实独立进程、版本拒绝、Sim唯一写入、持久恢复、实际联合业务、故障注入及整个进程组测量的可重跑证据。独立advisor分别检查架构和最终联合运行；不把重复审查已有文档代替实现。经济平衡和完整M0仍未通过；没有真实16GB设备，16GB性能门始终未通过。

| 阶段 | 实施产物 | 必须实际验证 | 不能据此宣称 |
| --- | --- | --- | --- |
| W0 | 本文的协议、依赖、失败矩阵及预算归属 | 链接、版本和验收覆盖静态检查；架构独立审查 | worker／联合运行通过 |
| W1 | 空气场连续窗口、独立持久worker、有限协议及候选文件 | 两个任务复用同一worker；逐位对照CPU；源页／tile页／发布后失联；超限及坏输入拒绝 | 世界写入或恢复通过 |
| W2 | Sim任务状态、固定读集、结果接纳及Store资产／WAL集成 | 错版本／旧代际／重复候选；任务与场同根；资产发布和根提交各边界故障 | 独立Sim监督及联合长跑通过 |
| W3 | 独立Sim、宿主监督、有限重试和必要任务屏障 | worker与Sim实际被杀后恢复；单写锁；取消尝试不取消城市义务；已提交钱物不重复 | 整个进程组持续运行通过 |
| W4 | 有限真实业务联合实验、CPU对照及测量 | 至少1800秒墙钟运行；故障恢复；同一时刻全进程采样；最终advisor审查 | 16GB设备、物理断电、完整M0通过 |

W1依赖W0；W2依赖W1和现有Store；W3依赖W2；W4依赖W3及当前Timeline／Region／Boot／Exchange／Payroll／Claims。旧Economy与Region不能重复计劳动，联合使用真实工资、税债、价格及履约活动，不伪称完整P-E0同时运行。

## 2. 单写入与协议

首次只允许一个worker、一个在途任务；不为每个人或建筑开进程。Sim持有世界单写锁并先持久接受任务，再交付不可变输入。worker只读取任务文件和产生候选，不能打开Store、确认业务来源、付款或推进城市时钟。进程隔离是崩溃隔离，当前不承诺操作系统安全沙箱。

任务固定world／branch、规则及源码／策略身份、base_revision、场版本、输入与边界摘要、绝对计算区间[t0,T)、Timeline屏障、job ID、writer incarnation、generation与尝试数。任务管理事务和安全收件交接可以提高世界revision，所以不能简单要求结果等于最新revision；必须保证冻结读集及场版本未变。每个重新绑定和重试都先持久化代际，旧进程迟到结果失效。

控制JSONL单帧不超过64KiB，队列至多32条／1MiB；输入和输出各不超过8MiB，单任务内存沿用32MiB分区（输入8／scratch16／输出8）。域集成可施加更小文件门。stdout／stderr与文件都要有界；父进程必须排空管道或使用有界接收，不以无限output()收集。瞬态失败最多三次自动尝试，确定坏输入直接拒绝。耗尽后保持必要任务阻塞并可观察，不无限重试或静默跳过。

Sim验证任务、代际、固定读集、输入、起止时间、完整覆盖、数值范围与摘要。首版接纳再用同一CPU路径对照完整候选，明确这是重复计算而不是加速证明；独立f64参考的既有数值证据保留。候选不产生任何业务副作用，重复结果返回原提交或拒绝，不再支付工资／运费。

## 3. 时间连续和业务因果

空气当前State.new只生成均匀初场，不能每个城市窗口重新调用来冒充连续环境。必须从已完成边界保留field、integral、累计诊断和绝对时间锚，下一输入只描述未来源。开始后target固定，分页／保存／恢复不能新增数值切点。窗口边界是明确记录的数值切点；任意窗口拆分不承诺等于未切分的浮点路径。

首个实际源来自当前真实在途货运的确定区间和空间锚点，有限EI率必须明示为实验参数；暂停／未发货不产生同一活动源，交付后的衰减仍从旧场继续。它不是污染质量、车辆尾气标定或真实健康证据。实验网格和映射需在输入中可解释。

P0采集已冻结活动，P4观察屏障要求空气完成到T才允许P4观察及P5／下一窗口。此前P0／P2已提交的工资、税债和实际交付保留；worker失败只重算纯任务，不能回滚或重复实际履约。取消某次尝试也不能取消必要场更新义务。

## 4. 持久资产和恢复

大候选不得塞进32KiB WAL帧。Sim先有界读取、验证并复制到自己管理的内容寻址不可变资产，文件与目录持久发布后，WAL只写小引用。场、累计量、任务消费和屏障进度属于同一业务提交。恢复重放由Store提供已校验资产，不能依赖worker临时目录或在已提交重放时重新计算替代原结果。

Engine检查点含完整已提交空气状态。GC仅在CURRENT和全部待重放WAL校验后执行，保留活动任务输入及当前恢复引用；检查点已内化、旧WAL已退役且无活动引用的资产才回收。冷回执的历史摘要不自动要求永久保留整个候选，但原提交回执必须可查询。已提交资产缺失／损坏要明确拒绝恢复，不能先删除尾部再掩盖错误。

准入前同时预留输入、候选、导入临时文件、任务与最多三次尝试的控制槽／WAL余量；不得把已有Timeline续做票或8MiB应急空间当免费余量。每项须报告真实上限与实际占用。空间不足时在未接新义务前安全暂停，不能靠重启清除责任。

## 5. 故障矩阵与联合证据

| 注入点 | 预期事实 |
| --- | --- |
| worker源页／tile页中途被杀 | 无业务写入；新代际从固定输入重算，与直接CPU一致 |
| 候选写完但通知前失联 | 可验证候选或重算；至多一次接纳 |
| Sim已接受任务、尚未发出 | 重启发现持久义务；不能丢任务 |
| Sim已持久发布候选、尚未提交根 | 旧根仍权威；孤儿资产可安全回收 |
| Sim根提交后、回复前被杀 | 恢复原结果／原票；不重做钱物转移 |
| 旧代际／错输入／错场版本／重复结果 | 拒绝无状态改变或返回原票；不得开放P4 |
| 连续瞬态失败／取消尝试 | 三次封顶；必要任务阻塞可观察，不绕过屏障 |
| 等待期间收件箱满 | 安全交接仍可推进；工资／跨城付款不重复 |
| 候选损坏／超限／恢复资产丢失 | 显式失败、无半提交；保留可诊断状态 |

W4至少1800秒实际墙钟，包含实际工资税债、跨城发货交付、连续空气窗口及worker／Sim故障恢复；记录输入、命令、源码与规则摘要、操作／回执、场和累计量、关键守恒及错误计数。另跑同输入无故障CPU对照，比较业务最终状态和数值位；不同故障管理元数据不要求相同。

采样覆盖控制器、Sim、worker和任何同时存活的参考进程，逐样本记录时间／角色／PID／RSS及磁盘增长、任务延迟、队列和重试。报告同时刻RSS之和的峰值，不能把各自不同时刻峰值相加；RSS可能重复计算共享页，不冒充去重物理占用。记录宿主内存、交换／压力和采样间隔，明确短暂峰值可能漏采。真实宿主32GiB证据不能签收16GB门。

## 6. 预算与当前状态

沿用A55：进程／IPC96MiB、投影64MiB、任务表8MiB和高峰128MiB属于已有运行时预算；首个worker任务32MiB占solver256MiB，不额外加到全应用3.10GiB之上。空气纯State上限2MiB，域State、事务克隆、序列化及多进程运行时须重新实测，不能拿原Engine4MiB上限自动覆盖新增字段。磁盘资产、WAL和双检查点另算，不以压缩文件大小替代内存。

W0架构审查已指出并纳入：连续场缺口、大候选WAL不适配、P4因果屏障、固定读集而非最新revision、任务独立预留和全进程测量。W1—W4尚未实现或验收。后续在各阶段证据中更新实际结果；本冻结标准不因实现困难而降低。
