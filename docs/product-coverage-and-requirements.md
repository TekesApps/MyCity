# 完整产品覆盖矩阵与需求追踪 P53

v0.5.2总体基线。目标是MyCity完整产品的总体方案，不以23个首期模板或90个CAT的数量证明完成。功能不在第一个可玩版本实施，仍须有总体机制及可检验契约；只有名字或“后续”标签不算设计完成。本矩阵记录四视角覆盖、需求去向、总体机制证据和阶段计划。

## 1. 统一设计深度与证据

每个能力卡必须回答九项：①需求从哪里来／何时触发；②设施、所有权与运营责任；③输入输出／物量／容量及共享约束；④实际成本、定价／收入及资金；⑤交通／环境因果；⑥法源／多方程序；⑦失败／保全／退出；⑧玩家可见来源与效果；⑨聚合、唯一writer、调度和16GB增量。可继承明确的通用规则，但能力专有差异必须说明，不能只写“参考Root”。

完成证据分层：总体契约D_full、可构造原型输入A、实施I、经济／性能／试玩V。D_full可以定义确定算法、有限schema与候选参数，不要求先有代码；但必需依赖必须有提供者、单位、失效行为和预算，不能以未来“会生成”替代。现有D_first和A_doc_first只证明v0.5.0切片，不自动等同D_full。

## 2. 四个视角的功能面

| 视角 | 必须能解释的活动／结果 | 覆盖能力 |
| --- | --- | --- |
| 玩家能做什么 | 输入施政目标、选单体／路段／区域、调查与比选、授权／拒绝／修改、协商程序／预算、分期施工、观察后果；调整班次／收费／采购／政策须有真实主体与权限；成长、困难、长局和退出 | G01—07、T01—07、U01—05、R01—04 |
| 市民如何生活 | 出生／成长的群体变化、家庭与住所、学习资格与工作、不同工资周期、消费／休闲／公共服务、持股、出行停车换乘、环境／安全、诉求与选举、迁居／死亡后的权利清算 | L01—06、G02/04、E01/03/04、T01—07、N01—03 |
| 企业如何经营 | 登记主体、投资／股份／资产、选址与空间、雇佣、采购／制造／服务、库存货运、租赁摊位／客流／竞争、公交港口机场／航空公司、能源公用、实际收入成本／税／分红、亏损／关停 | E01—05、G02/03/05、L03、T01—07、U01—05 |
| 城市如何运转 | 地形／产权／规则、道路及多式交通、公用网络、产业／财政、环境／灾害／公服、区域贸易与共享、立法行政司法、维护更新、保存／恢复及跨图同钟；关闭画面仍保留因果 | 全部能力；重点G01—05、U01—05、N01—03、R01—04 |

同一能力可以服务多个视角；每个视角还要独立走正常、受限和退出路径。建筑不是唯一入口：班次、法规、家庭转变、企业倒闭、储备不足和旧责任也必须触发系统行为。
