# 原速度门的周期预算排程（待实现/未验收）

advisor核对冻结speed与§3/§7后的裁定：速度门没有要求小时结束才释放；可以周期开始释放、周期结束为deadline。60s/day时，小时h的release=t0+(h-1)*2.5s，deadline=t0+h*2.5s。全部720目标及额外事件/动作顺序保留，后续周期不能因提前完成而提前释放。实际等待/IPC/持久化不扣除，不增加1800s容差。

实施前固定边界：独立CPU证明工作先完成，独立报告耗时并始终包含在观察树；经营t0在实际Sim创建/打开请求前记录，因此真实Store初始化及所有原启动动作计入首日与总预算。经营终点为原30日最后必要业务/空气接纳/时间线完成均已持久确认。最终恢复证明等独立证明段另报全包装时间，不能把业务写入或任何到期未完成的必需任务移出经营段。具体保存/查询到期范围与段界在manifest预先写清，不能运行后挑选。

逐日固定周期起点到该日期末完整提交≤对应day_wall_seconds，另报相邻日提交边界间隔、全部小时释放/提交/完成/积压。强制60档30日≤1800s，1/10高速未达原样失败。600/60/10/1四档均实跑，无等待吞吐另报。

这不改变耐久规则：8h仍h*40s末端释放，最后业务边界必须跨28800s；不能把速度分支的提前释放用于8h。当前仅设计接入点，未实现/未测，不算速度验收。
