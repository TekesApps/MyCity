`observe_query`, return the original Page plus bounded source/version/coverage and row
observations. One Store query supplies limits/cursor/hash/progress/errors. Same exclusively
borrowed Store Region supplies narrow population-snapshot age; it is not general row age.
Absent observation/ETA/reason/forecast providers stay typed Unknown. Transport remaining
seconds are not ETA or delivered service. A generic row may be a business record OR live
storage/source diagnostic; neither label implies prediction or business success.

Both old raw session Query and new ObserveQuery require trusted argv Caller::System.
Account gets `query_operator_required`; JSON cannot grant operator identity. Receipt first
uses original Store hot/archive validation, then matches original JournalRecord.actor to
trusted Account ID. Own successful and failed original records remain recoverable. Other
actor/System records and nonexistent IDs share unknown/null for Account; System can diagnose
all. Action wallet participation does not confer receipt visibility. Storage errors remain
errors; unknown visibility cannot justify repeating a transaction under a new operation ID.

No query changes money, ownership, occupancy, random outcomes, game clocks or obligations.
No new provider, cache, scheduler, process, receipt namespace or capacity pool is introduced.
This does not provide full Account-session isolation: Status and other controls/diagnostics
still need their own policies. Store::query remains an internal host diagnostic API.
