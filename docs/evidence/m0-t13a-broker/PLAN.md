# T13A-3i: broker-owned worker and supervisor revocation

This phase preserves acceptance-v1 and all original loads. Rust model/CLI only. It implements an actual prerequisite of the original >=4h Sim-fault recovery, not a replacement for actual8h.

The Client owning the actual Sim Child mints a supervisor capability in memory, registers a session, passes only a distinct session capability into Sim, and binds the actual spawned Sim PID before sending work. Spawn failure can cancel only unbound empty sessions. Lost bind reply requires owned Sim kill/wait followed by the same idempotent generation revoke. New session registration is blocked while an earlier session remains registered. No supervisor secret in ready/files/events/inherited Sim environment.

Broker owns each actual worker Child. Sim binds an ephemeral unpredictable Unix socket before Start; broker connects and moves its descriptors into child stdin/stdout, drops all other copies/Command, stderr separate. No payload relay or extra broker reader threads. Worker stores existing candidate bytes in hash files. Control action categories remain bounded. No fabricated Child from PID; Direct/legacy and Broker modes mutually exclusive.

Normal Stop and supervisor Revoke use one broker-owned try_wait/kill/wait then actual return path. Active work is interruptible. Revoke does not depend on Sim receiving a successful Start reply or remembering worker ID. Only a Client with actual Sim wait can issue the trusted revoke path. Broker death fails closed; restarting broker cannot reclaim Child ownership in this phase.

Keep actual page scans every1s. Persist periodic aggregate checkpoints every30s rather than a full JSON event per scan; all grant/fill/stop/revoke/failure transitions still logged. This is diagnostic aggregation, no reduction in business or physical balance checks. Calculate worst-case event envelope against8MiB and actually measure long-run behavior later. Original steady sampling and8h deadlines unchanged.

Tests: normal multi-job same slots/Child wait; actual Sim death before Start, after worker spawn before reply, Filled, compute phases and Published; lost revoke request/reply and duplicate revoke; stale generation/capability/result, no new session before old reaped, spawn/bind failure cleanup, worker not exiting requiring actual kill/wait, broker death no false credit. Re-run original full30d/724workers/3011receipts with same source when ready; a finite fault test is not an8h pass. Independent advisor reviewed descriptor ownership, timeout/deadlock and capability boundaries. Pool0.25MiB diagnostic cap/native/fd costs require evidence, not automatic acceptance.

Implementation clarification: Start reply loss is fail-closed (busy), not in-place idempotent success; actual Sim wait, broker revoke and a received-receipt acknowledgement precede a new session. Broker SIGKILL does not run Rust Drop, does not promise automatic worker reaping, and cannot reuse old ready. Registration capability is minted by Client before Sim spawn, unbound cancellation has no Child; supervisor capability is never passed to Sim. Endpoints are exact boot/generation/hash(session-key) short paths, mode0600, unlinked immediately after connect and cleaned on verified session revocation.

Diagnostic per-row hard limit1536B plus original8MiB total is enforced. Conservative envelope:768worker attempts (original724 plus retry headroom),960periodic checkpoints in28800s,16session handoffs×4events,64exception transitions =4928rows×1536=7,569,408B<8MiB. This is an envelope for diagnostics, not a new smaller business load or actual8h proof. Scans remain1s. Control abuse may hit the original failure cap; it does not erase records. New session/capability isolation unit and fixed maximum-width event test supplement real-process faults.
