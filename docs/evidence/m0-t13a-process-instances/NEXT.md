# 下一依赖：费用与真实压力

本轮只消除实例目录覆盖风险及明确的响应／日志副本，不宣称诊断总账或64MiB联合压力已闭合。正式三轮和8h前还需：

1. 驱动诊断份额：transcript／计时／golden行／报告构造计入8MiB；CPU参考、IPC与最终完整验证的临时编码另列外部工作区，同时计入64MiB。不能把33.95MB旧驱动峰全算诊断或全免诊断，不能把sync_channel(4)当作仅四个活副本。读线程、阻塞发送、调用者与解析帧分别有归属。
2. 外部池：64MiB固定页ticket绑定运行代次、进程实例及owner，总授权不超池。owner真实容量＋已触页余额＋转换中额度＝授权额度，未授权余额仍由总池实际持有。分配前释放对应余额，失败补回；所有真实引用销毁后再触页补余额，确认进程退出后才回收票。realloc按旧＋新并存收费，不按最终容量；IPC复制各收一份。COW和外部池不能重复退款。
3. 稳定边界核对3.10GiB；转换缺口须记录顺序与持续时间，真实高峰仍在3.5GiB软限／4GiB保护内。不能定时读取终身峰后填padding，不能给serde／Value预留10MiB实际2MiB却一直少压8MiB。先实现生命周期清楚的worker输入／候选owner，再扩到其余所有者；未闭合就报压力下界。
4. 冻结其余分支、四档速度、三场景各3×35min与真正8h／96保存／三类故障。保持原负载和失败记录；真实16GB仍not_run。
