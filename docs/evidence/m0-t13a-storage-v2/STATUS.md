## 2. 格式、恢复与兼容

完整Engine以原始有界JSON写出；借用视图包括所有现有字段，journal固定空，不先构造整份JSON Value或复制后再删除热票。字节导出与writer均有4MiB硬限，和既有恢复上限一致。字段编码顺序变化使字节hash改变；独立验证完整30日期末JSON全部字段与v0.5.31相同，业务摘要仍为17b4cbd4271a18e8bd3ec0ddfe1b1bfe2b33081e3a3f87db79ccd7f87464f432。

永久Receipt正文／索引有独立hash、genesis、连续提交序列及前段引用。空窗口不追加空段，仍真实写新World及根。96次后仅保留183／184两份原生World图像和最新manifest；gen89原票段保留全部88原票，95个空窗口没有追加空段。Current／Previous World、原票正文和WAL开城均校验；不只读索引。Cold复用一次当前World装载，不重复加载完整世界三次。

CURRENT持久后才退休热票／切换WAL和GC；重开先验证全部权威依赖再清理候选。前一图像仅为Engine历史状态，不是可独立执行的历史Store，也没有从旧点重建当前的WAL桥接。当前或历史依赖损坏拒开，不静默回退丢已确认后果；物理断电未测。

新建世界须显式调用create_spatial_v2／scale-store-probe-v2；Genesis与Root绑定checkpoint_layout=2。旧字段缺省0，保留v1路径，不自动迁移。独立Rust读者通过Cargo给出的精确rlib，实际打开v0.5.33归档世界，核对完整Engine字段、全部88原票、缺票及sequence88，所有原文件字节不变，见[兼容性](compatibility.json)。

## 3. 真实验证及范围

[独立审计](verify.py)重算源码胶囊／每个实际世界文件／CURRENT／Root／genesis／World及Receipt链hash，核对96条保存记录、两份Engine图像及全部原票；完整期末所有字段与旧参考对照，非只看总资金。压缩世界zip仅用于归档，测量写的是实际非稀疏字节。

定向测试实际覆盖10个进程退出点（World、Receipt、索引、manifest、WAL、Root、CURRENT替换／持久、GC中途及结束）；每次恢复完整状态与原成功／失败命令。1042条真实事务覆盖热窗口自动轮转、定期保存和连续空保存，全部原票分页、原命令重试、冲突payload与缺票。另测后台已staged但未Accept时保存／重开／Accept，再保存／GC，资产回收后原票仍在；当前／历史World、原票正文及索引损坏拒开。退出测试不等于物理掉电。

开发初测的两个测试错误（不支持的反向库存合并、JournalRecord未实现PartialEq）及clippy提示保留原日志；没有放宽模型约束或性能上限。最终Release全量251项通过，fmt／clippy及静态文档／预算检查通过；原始结果见tests-release.txt。独立advisor复核了实际归档大小／hash及关键组合，见[审查](advisor-review.md)。

仍未测：真实L2分级／全部30日持久业务及动态原票增长、四档经营速度、全部10类计算分位、L1＋L2联合内存／磁盘、三场景各三轮稳态、真实8h／96保存和最终advisor审查。GC逐文件重复遍历索引链是待实际经营测量的风险，不从暂停世界单段结果推断它永远够快。完整M0 not_accepted，真实16GB not_run。
