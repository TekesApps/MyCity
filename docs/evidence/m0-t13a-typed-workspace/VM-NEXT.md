# 原normal超限后的下一实验

本轮失败保留，不继续为同一已知失败配置堆三轮。先单独定位运行时组件；不在正式窗口中插入vmmap，不改原数量/算法工作/扫描脏写频率、64MiB pool可用能力、128MiB工作预留或3.10/3.5/4GiB门限。

下一次使用同一固定exe和原L1满级装配的独立smoke诊断，记录为“VM归因，非正式性能”。新目录创建前明确最多三代磁盘峰、完整恢复输入和终态退役条件，继续复用target；已保护的current7/8不复制、不改写。

1. 关联observer/root/pool/layout/driver的PID、Mach出生身份及parent关系；在稳定空闲和快照在途各采集一次完整组。每个VM工具调用记录起止单调钟、调用前后身份，身份变化或读取失败保持unknown。
2. 使用本机vmmap的`-summary`及按页/宽输出，保存原文；同时记录线程栈、页大小、arena实际地址/长度、bootstrap隔离量及当时allocator计数。只依据实际映射交集与组件来源分类，不将footprint−grant差额直接称为native所有权。
3. 分别列出：已在Native/stub/IO/metadata/pool中收费的存储；未重复收费且具有真实用途/所有权/生命周期的运行时组件；共享映射、压缩、对齐和仍未归属量。共享页不按每进程虚拟大小累加。
4. 若事实支持同用途置换，预先发布逐组件账和新的pressure manifest：额度来自已确定用途的运行时域，不是本轮18.49MiB差额。组件缩小/退出时未用份额恢复受控已触达占位，避免压力空洞；metadata/diag/bootstrap/栈不得重复抵扣。外部64MiB已代表pool，不能再扣给进程开销。
5. 置换实现重新冻结源码，正确性/恢复回归后，重跑原formal；物理门修复前不把单轮页计算达标外推正式整体通过。任意受保护数量/能力下降或阈值变更另报冲突，不能擅自调整。

同用途置换依据为[m0-model-scale-performance §2](../../m0-model-scale-performance.md#2-l1数量与记录合同)及R03；本方案只准备诊断，不预先授予任何组件置换字节。正常VM读权限不足时留证，先采用本用户可用的只读工具，不中断其他任务或放宽权限。
