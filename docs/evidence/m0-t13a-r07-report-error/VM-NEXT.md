# 下一依赖：R07新版实际VM归因

原normal仍失败；不复核已冻结城市设计，也不扩大残差信用。当前只完成R07功能、错误传播和恢复验证。

1. 新诊断来源以有界流式清单输出layout arena、每个真实R07映射及pool背板的地址/实际长度/用途/分配代次；地址不进入城市快照。固定上限与输出内存计入原metadata或诊断授权。
2. 同一PID+birth、R07 epoch/映射量、清单版本夹取原始footprint和vmmap。idle及snapshot-inflight分别留实际前后读数、原文和工具耗时；若中途状态变化，该次不能当稳定区间，不无视转换。
3. 对各地址覆盖、resident/dirty及整进程footprint分别陈述，不混为同一指标；具名剩余区域确认所有者/生命周期，unknown不抵扣。
4. 旧v99明确有page table in kernel，但不能沿用旧数。当前memmap2 0.9.9源码中Mac的MAP_HUGETLB为0；不能仅加huge选项就称Mac大页优化。
5. 优先验证真实成本优化。若引入新的OS独立分项字段，先验证SDK布局、单位、物理计费语义、身份及错误行为，再与vmmap交叉；wholefoot减arena仍只是总量核对，不能改名成为独立字段。工具扰动实验不签正式性能。
6. 当前safe接口没有已批准layout/pool分项输入。找不到可验证输入时，明确报告该限制；不估算页表信用，不调宽原normal或缩原负载。

正式三轮/四速度/稀有层及28,800秒联合运行仍待上述真实瓶颈解决；8小时日志容量须依据实际9B metrics编码及完整L2/其他日志总量核对，当前L1短测投影不构成超限或通过证明。
