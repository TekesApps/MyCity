# T13-A满级存档：实测阻断与下一步格式

本页区分已测旧格式和待实现的新格式，不修改现行v1文件解释。T13-A冻结96次保存、原票永久可查和20GiB世界预算不变；当前默认128MiB配额先保留作原负载对照，不用扩容掩盖重复世界归档。

## 1. 已测阻断

[完整存档下界工件](evidence/m0-t13a-storage/STATUS.md)：真实64账户／128库存／8图／64工资／20000债项期初，88条启动命令实际持久执行。同一世界不推进时间，请求96次保存；第20次被正常配额拒绝。19份世界图像逐字节相同，88张原票完整保留。Engine原始JSON1836348B，旧外层Vec<u8>数字数组及元数据将每份扩为约6291224B；仅96份不变世界的下界604048802B，未含实际经营新增原票。

这不是完整L2业务／Sim吞吐或长跑验收。共享启动函数重构另跑原30日CPU参考，完整业务hash仍为17b4cbd4271a18e8bd3ec0ddfe1b1bfe2b33081e3a3f87db79ccd7f87464f432。

## 2. 下一实现的最小拆分（尚未实现）

- World文件：直接写完整Engine导出字节，另有有界manifest绑定schema、sequence、WAL chain、genesis／规则身份、字节数及SHA256。避免把JSON字节再次编码为十进制数组。
- Receipt段：本轮热窗口全部成功／失败原票正文、提交序列范围、操作ID索引、上一段引用及hash。永久保存；不只保留结果摘要或成功票。空热窗口保存仍真实执行，不必追加空段。
- Root：分别引用当前World、前一保留World、Receipt链头、当前WAL与外部资产依赖。当前与前一World共两个已发布点，另预留完整候选空间。
- Cold open：验证完整回执链正文及索引、World和WAL；复用已验证快照的sequence／chain／Engine，避免三次加载同一完整世界。原票查询只读相关Receipt段，不加载整份World。

前一World首先是明确sequence的历史检查点，**不是可以静默回退的当前世界**。首个格式实现不提供自动回退；当前World损坏必须拒开，不能丢掉后来已确认的付款。如果将来增加从前点重建当前点，须先保存完整WAL桥接和全部中间worker资产依赖，并逐票证明恢复到当前sequence；未实现桥接不能声称双点自动故障恢复。

## 3. 发布和回收顺序

1. 计算旧依赖仍在时的新World、全部Receipt正文／索引、新WAL、根及保留点的实际峰值准入；同时保留真实2GiB磁盘安全余量。
2. 写入、fsync并校验新World与Receipt／索引／WAL，持久目录。
3. 发布新Root，再原子替换并持久CURRENT。CURRENT是唯一选根权威，旧槽位不提供静默回退。
4. 此后才退休热原票／切换WAL并GC。只移除新权威根及其两个保留点均不依赖的世界／候选；任何已提交Receipt段都不删。外部worker缓存按同一依赖集合回收。

旧CURRENT仍可能有效的窗口内不得回收它的依赖。新CURRENT持久前崩溃须能开旧完整状态；持久后须能开新完整状态；原命令重试始终只产生一次后果。临时孤儿须能识别并有界回收，不能先删旧根腾出准入空间。

## 4. 兼容和验收

保留v1读取／原实验写入路径，新scale世界显式选择v2；格式标识不能用猜文件名推断。旧世界的全原票迁移另做显式操作：验证旧链、抽出全部原票、写新世界与链、核对sequence与正文，再原子发布。迁移未实现或空间不足须拒绝，不先删旧档。

实现后先重跑相同96次暂停世界保存，比较原票、状态与实际容量／冷开时间；再跑真实经营的回执增长及L2全源调度。崩溃点至少包括World、Receipt、索引、新WAL、Root、CURRENT替换／持久及GC过程；每点核对完整状态、最老成功／失败票、原命令重试、同ID冲突payload及缺票查询。零热票保存、自动热窗口轮转与定期保存交错、同sequence连续保存均须覆盖。

即使下界通过，也不能代替原冻结三场景三轮稳态、真实8小时／96次保存及最终advisor审查；真实16GB仍单列not_run。
