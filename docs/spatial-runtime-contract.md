# 对象、共享空间、分层与交通的运行一致性

现行补充：v0.4.18，2026-10-19。本轮交叉审查修正最近几个专题之间的状态归属、容量占用、自然增长和规则失效缺口；与旧版口径冲突时以本文及现行性能预算为准。本文仅为设计，无游戏运行／16 GB性能证据。

v0.4.25现行粒度与预算以 [整体分配审查](granularity-allocation-audit.md) 为准：34属性／14系统／27物件逐项区分保留、聚合、延后；新增基础本地供应计费绑定使用原区域余量4 MiB，现为27项43.0078125／44 MiB、余0.9921875 MiB，应用目标不增。下文39.0078125／26项是此前基线，不作本版准入；未验证布局／索引与16 GB实机性能。

## 1. 一个空间实体必须有明确状态归属

| 真实对象／关系 | 权威归属与额度 | 不能假定的事情 |
| --- | --- | --- |
| 建筑附属庭院／平台等子区 | 宿主建筑／设施的有界子区域，最多8区；模板与实例几何有版本 | 单靠space_ref不能生成新对象或所有权 |
| 独立硬质广场／院落 | 实际建筑／独立设施对象，计入该场景设施数量、状态和几何预算 | 不因不种树就成为无状态免费公共设施 |
| 可供穿行的共享走道／车道 | 有明确方向／模式的真实网络边、必要节点及空间引用 | 不能作为不计路网额度的额外捷径；外部门默认仍只作起终点 |
| 植被／绿化 | 全世界4096条植物状态，空间附属于上述合法宿主或独立对象 | 植物表不负责硬质广场的全部管理／交通状态 |
| 建筑使用权关系 | 全世界8192条×16 B、每空间最多32个登记建筑引用 | 使用关系不是对象本体，也不是一份额外容量或产权 |
| 有独立持续占用／瓶颈的空间 | 下节8192条×64 B资源组，引用物理实体和规则 | 端口／使用方不能各自发布一份相同资源 |
| 外部门与外接锚点 | 全世界65536条×32 B、每建筑／设施最多8口、每口一个物理锚点 | 多角色／多住户不复制物理门与容量 |

场景表中的“建筑”按建筑与独立设施合计准入；附属子区不另产生一栋建筑，但有明确宿主和几何，不可超出8区后暗藏无界对象。邻城未打开时，实体身份／模板／几何版本及必要状态仍可在持久存档中解析；热页按原额度分页，不要求所有完整建筑描述常驻。

每类适用物理容量的唯一键为(真实物理资源、容量种类、单位、计量窗口)。同一车道的共享引用必须指向同一个容量组；一个空间同时受“同时人数”和“每小时通过量”限制时是两种约束，分别计费，但不能把二者相加当作更多容量。已有道路边容量、床位、装卸及库存等继续使用原权威：组只引用它们，不再发行第二份相同额度。

别名／跨图引用先解析到同一物理身份，创建／移交事务检查唯一键和几何相容关系；不能改个space_id就给同一车道再发行容量。容量接纳／占用／释放由可信模拟与原权威事务执行，agent仅能按既有工具查看、提出规则或合法变更方案，没有直接设置人数／占用／容量余额的接口。

## 2. 有限占用与排队必须能持久恢复

新增**全世界8192个空间占用／独立瓶颈组×64 B＝0.5 MiB**。组用于原道路／服务／库存等权威没有表达的独立庭院停留、门口有限接收或共享空间占用，保存物理资源／不可变策略引用、计量类型、占用／预留计数、版本与有界释放摘要。不是8192个新建筑，也不把每个访客建成agent。

64 B候选布局：物理资源句柄4 B、不可变策略引用4 B、游戏时刻基准8 B、占用／预留计数各4 B、代际4 B及控制／修订4 B，头部合32 B；另4桶×(相对释放时刻4 B＋数量4 B)＝32 B。控制字保留需要来源重扫等状态位，修订／代际不得无校验回绕；类型、单位、容量和用途从有界策略解析，几何从资源句柄解析，不外置无限动态字段。时间单位沿世界整数game_time精度，首轮可为游戏秒；相对时间将溢出前同事务无损换基准，不能截断期限。只合并同释放时刻及兼容条款／用途；计数溢出或精度不兼容在接纳前拒绝，既有事实不能舍入丢弃。真实字段装不下时重算，64 B不是sizeof证据。

类型明确区分并发占用与吞吐窗口，具体状态字段按类型解释；同一组不能在重放时从床位式占用变成每小时流量。这里的4桶主要用于有限聚合访客停留，不替代工资债务、病床／患者或任意法律期限。第5个不兼容停留批次在进入前背压，必要时排队于真实可容纳位置或暂缓出发；不能先让人进入再丢弃其释放记录。

候选布局按类型复用头部两个4 B计数字段：并发型为在场／预留量；吞吐型为当前明示窗口已发行（含已承诺）量／固定精度累计余数，窗口原点用同一时刻基准。分母、单位量化及重置规则来自不可变策略，具体预约和实际通过仍在原来源记录。需要并发和流率同时限制时引用两个不同种类的组／已有权威，不能在64 B外另开未预算的动态计数器；不支持的计量精度接纳前拒绝。

| 参与状态 | 原始身份／进度的唯一权威 | 容量组怎样参与 |
| --- | --- | --- |
| 通勤、顾客／访客的出行与停留 | 既有4096稀疏OD／有界需求记录，保存实际来源、阶段、数量及必要返回引用 | 批次持有占用引用，组只记录同一次占用的资源令牌／汇总 |
| 货运等候／装卸 | 现有10000在途货运及库存／交付记录 | 引用真实门／走廊组，不把等候货再复制成第二批货 |
| 急救、消防、维护等服务 | 现有2048派遣／交付／占用记录 | 保留原服务／占用计量，缺少的外部空间约束才另引用组 |
| 原道路上排队 | 原路段运行积压／真实OD或货运位置 | 不能再把同一批数量作为“门内新队列”加一次 |

批次出发前须能够表示去程、必要在场／工作学习时间和适用返回阶段；停留后不能释放其来源记录，使人在场占容量却失去身份／时间预算。可兼容批次引用同一OD模式，但不兼容时段／阶段必须保留独立有界需求描述，仍占4096联合额度。满额不代表行程完成或人口减少，也不保证65536端口能同时各有独立队列。

原来源仍约束同一居民的工作、学习、通勤和休息／访问时间，不能因为组只汇总人数就同时在两处满额工作或上课。已经在场的源记录不被次日新需求覆盖，必要返程描述也不能等离场时才发现无槽。候选OD模式可共享模板，不代表在途／在场状态可以不计费。

来源记录和容量令牌的接纳、到达、占用、释放与离开原子关联并幂等重放；它们是一个实际占用的两种视图，不是两份人／库存。释放摘要可由有界来源扫描／分页反查核对，反查缓存只是加速；不能为了省引用丢掉谁在等、谁在场。若现有OD／服务表示不能支持所要求的停留／返回或释放精度，则接纳前返回unsupported／unresolved，不开隐藏的访客系统。

有返程／配送／服务身份的占用由原来源状态驱动释放，桶只是同一来源的有界到期摘要；事件只触发一次原子释放，不得先按桶减人再由OD／交付回执减第二次。独立吞吐采用明示计量窗口和策略余数，不能套用访客离场逻辑。维护／故障使合法容量降低时保留实际超占用及安全处理，停止新的不相容进入，不能将当前人数直接裁成新上限。

预约结束／停留到期只触发来源核验，不证明人／货已经真实离场；实际退出相应物理范围或完成合法资源移交后才释放占用。既有在场者因封出口、服务延长等改变到期事实，可能让4桶无法再无损表达；此时保留原来源和实际计数，标记摘要失效／需重扫、停止新增接纳，通过已有有界来源扫描及持久到期索引重建，不拒绝已发生延期，也不合到错误时刻。原来源的期限和阶段仍持久保存，桶不承担独立事实权威；无法重建完整四桶时继续受控重扫，必要时降速，连原来源／安全约束也无法可靠保持才按既有规则停在安全边界。摘要失效不是空闲，不能先腾容量后等人实际走掉。

容量组、释放桶和原来源槽在接纳新对象／使用承诺前一起准入，独立容量组满时拒绝新增承诺，不合并不相容空间。已进入者在关门／新禁令后依原位置和已规定安全退出／等待方式处理；允许释放资源不代表允许穿墙、穿禁区或瞬移。必要安全状态无法保持时在游戏时刻安全边界停止推进并报告，不能无状态继续。

## 3. 硬限制变化先使执行失效，再做路线重算

开放时间、使用权、法令、法院命令、道路转向、实体障碍、地形与入口有效性都是通行合法性依赖。到生效时刻T先按既有同刻阶段封闭此前事实，再登记限制／转换状态：旧的正面可达结果立即不能授权新的受限进入。不能因为交通重算尚未轮到该对象，就继续依据旧缓存通行。

成本／旅行时间的软估计可带数据年龄继续观察，硬权限／几何／容量不能用“结果陈旧”豁免。现有在途按预先定义的过渡／退出规则处理，已发生工时、交付、污染与费用不倒改。公共通道的临时施工、开放关闭与新法是不同来源，均需实际适用权限，不能擅自称紧急而取得额外通行权。

路径缓存至少区分网络／接入／地形／法规修订、模式／用途／通行资格类别、源／目标锚点、方向及时间适用范围；合法性凭据的valid_until不晚于已知的下一次相关开放／规则边界。共享几何路径不等于共享所有人的进入许可：需求仍按实际主体／建筑使用权验证，不能以复杂缓存键替代授权。容量和实际排队在入场时再查，缓存路径不预订一份永久空位。

出发时可走不保证到达时门仍开。校验沿线及终点的预计实际使用区间，拥堵或等候改变到达时刻就重查；已进入的批次保留阶段和受阻状态。首轮不预生成全年每分钟时间展开图，不能可靠验证的窗口分段／限缩或报告unresolved，实际倍率随工作量降低。

同一有向边内的锚点保留位置与真实距离。1000 m边上距起点100 m和700 m的两口，允许方向下距离为600 m；不能同时吸附同一端点得到0 m，逆向也不能自动沿600 m原路返回。真实可穿行共享通道计入路网，不用一栋楼的入口组合制造捷径。

## 4. 自然增长必须有预先验证的空间包络

种植／登记时同时冻结可增长掩膜、当前状态与生命周期最大树干／树冠／根系的保守包络及模板版本，并检查相容用途、地基、道路／入口净空和已存在规则。只支持已校准／可判定的简单包络，不引入完整植物生理。放不下最大受支持包络时换模板／范围或拒绝，不能等以后长大再靠截掉画面解决。

在该已验证包络内的成熟／覆盖变化属于原对象动态状态，摘要可以按同一规则推进，不算绕过详细校验的新永久几何。扩大包络、改变模板、移树或新建对象仍走详细评估与合法工程。后加建筑／管线／共享通道也必须避让该已有增长约束，不能只检查幼树当前大小。

若通过明确修剪策略维持小于自然最大包络的净空，该策略必须有实际维护能力、费用、阈值与不足时处理；首轮未能可靠表达这类保证时不允许靠未来修剪承诺通过硬冲突。自然增长原位更新不申请新槽，也不能因满槽冻结已有植物。

成长／受损使已有影响或通行状态改变时，更新适用依赖并执行上一节的硬失效／有界重算。衰退或死亡不自动释放树干／树桩和清场占用；只有模板明确不存在残留实体或已完成合法清理才可释放相应几何。植被贡献、独立树移交及景观评分仍只计一份，不把可视树数当成真实覆盖。

## 5. 垂直分类、法规体积和地形要采用同一口径

U1／U2／U3、G、A1／A2只是分类；实际设施、施工坑、根系／树冠与保护规则检查整个保守包络。中心线在许可层内而包络越界仍可能冲突；缺少精细模型时返回needs_detailed_validation，不按层名自动放行。

用途分类的半开区间与法律边界不是同一个东西。法案必须明示垂直比较及空间边界：首轮保护体积默认闭边界，禁区0≤h≤120 m在120 m仍有效，即使对象分类已为A2；日夜时间段则采用左闭右开，例如[22:00,24:00)与[00:00,07:00)。不能把“类别不在A1”当作不满足该法案的证据。

运行净空／覆土采用当前地形；法规按其冻结／当前地形引用逐点计算，不混用参考。冻结法案、已接受工程、在途／共享权利仍依赖的地形／模板／几何版本必须保留可复算来源，按原磁盘／分页预算固定，不能因只保留最新两个检查点就删掉唯一旧基准。热页有限、历史块可共用；磁盘不足沿既有安全暂停规则，不把冻结法律改成当前地形来省空间。

首版2.5D／保守深度槽不能证明的体积交叉仍unsupported／待详细验证；这不会自动开放轨道、航空、任意地下／屋顶开发或复杂3D声学。禁穿越的几何证据与真实噪声测量继续分别报告，树冠／绿地同样不自动提供隔声或污染净化。

## 6. 使用关系的结束与物理责任分开

关闭共享入口、撤销许可或共享关系到期可以立即停止新的相应用途，但不能删掉在途、在场、维护、争议或已接受付款义务。每空间32、全世界8192使用关系额度包含关闭待退出／移交的占位，不只算当前开放关系；已接受权限不能因换版本复用槽而被误授权。

几何分割、合并、宿主拆除或从模板附属区改为独立空间时，先准入目标对象／关系／容量及来源引用，原子移交既有面积、覆盖、权利、资源令牌和责任；失败保持原状，不创建半个新空间。若只剩确定金钱债权，可按既有债权移交规则归档释放关系，法律／现场限制未移交前不释放。历史按分页保留身份代际，引用不静默指向后来的新空间。

维护费分摊采用公开、版本化的实际计价依据，合计不能重复覆盖同一成本；业主／使用者份额变化不产生第二份服务交付。缺资金／缺人导致质量变化与接入限制时保留未满足服务和债务，不能自动免费修复或用生活满意度掩盖不合规通道。

## 7. 预算与联合场景

原载荷38.5078125 MiB＋占用组0.5 MiB＝**39.0078125 MiB**。区域额度从40调整为**44 MiB**，余4.9921875 MiB，避免只剩0.9921875 MiB还用未知外部状态凑数。新增4 MiB在原0.35 GiB模拟域内部划转：相对旧40版其他模拟用途再减4 MiB，相对最早32版累计划转12 MiB。应用2.65 GiB常态、3 GiB软上限、4 GiB峰值警戒均不增加。

8192组是物理资源约束，不是65536门口各带8192组；一个物理门可有多个角色／锚点记录并共用一组。原道路／床位／库存已表达的约束不能再造组重复发容量，有独立新约束才占组。有限停留／等待来源、4释放桶、8192使用关系、OD、货运和服务额度共同准入，不能按每项最大值分别承诺所有地图满载。

接续既有“中图50000人＋7邻城各1000人”的部分联合向量，可再构造当前4000建筑／独立设施、邻城各300个，合6100个；实际端口当前20000＋邻城各1200＝28400；新增独立瓶颈组当前5000＋邻城各300＝7100；使用关系4000＋邻城各300＝6100。峰值并发停留只在其中明确支持的子集，例如500组×4桶＝2000桶；每批仍需事前有原OD／需求状态可记录其出行、在场与返回。该向量不保证所有7100组都有独立访客，也不证明人口／就业平衡，完整场景还需列各源、实际队列和索引字节。
