# 城市事物的统一属性与关系模型

现行设计修订：v0.4.14，2026-10-19，初稿v0.4.13。按用户要求，从建筑、道路到树木和绿地，共用一套可解释的基础语义，再按类型展开，支持有明确边界的复合用途／共享空间。本文定义对象契约与有限自然演变，不是代码结构或完整生态模拟；其他专题仍负责各自唯一权威状态。

## 1. 每个事物是什么、需要什么、影响什么

统一对象不是要求每件东西都像工厂一样输入原料、输出产品。它描述：在哪里、属于谁、能做什么、需要什么条件、容纳或服务谁、怎样与周围互动、怎样随时间变化、谁负责维护与承担费用。

采用“共同身份与空间＋可选有类型能力”的设计。树不用填写发薪表，住宅不需要制造配方；不适用的能力不分配完整状态，更不为每个格子或对象启动agent。以后代码可采用组合／分表，本文不预先绑定Rust继承层次或ECS库。

| 属性组 | 需要表达的内容 | 主要权威／引用 |
| --- | --- | --- |
| 身份与来源 | 稳定object_id、类型、模板／规则版本、世界分支、创建／替换来源 | 现有对象身份与事务日志，不另建副本注册表 |
| 空间与接入 | 实体占地、土地权利、使用／施工范围、入口、网络接入、影响几何 | 空间契约；格子只是索引，影响范围不等于所有权 |
| 权属与责任 | 所有者、运营者、使用权主体、维护方、财政／收费依据、管辖 | 现有账户、产权、协议及制度引用；自然物可无经营者 |
| 需求与投入 | 电、水、燃料、材料、工时、到货、接入、费用等适用项 | 有单位的需求／最低保障／目标／实获，现有资源与工资权威 |
| 产出与交付 | 商品、电力、可交付服务、废物等适用项 | 行业／设施唯一计量，不由通用对象层重复生产 |
| 承载与使用 | 住宅家庭／人数、工作位、访客并发、床位、教学席位、存量／吞吐等 | 对应容量池／住房／岗位，不能合成一个“人数容量” |
| 人与物关系 | 所有、租住、工作、访问、就医、学习、通行、维护、受影响 | 有稳定双方、作用角色、时间与来源的关系；复用现有记录 |
| 周边作用 | 空气排放、噪声、交通需求、阻挡／通达、景观／休憩等已支持作用 | 来源贡献→场／网络／服务→受体，不直接修改所有邻居幸福值 |
| 状态与时间 | 建造、运营、闲置、损坏、成长、衰退、拆除等适用状态与阶段 | 游戏日历和对应生命周期，不按画面帧或相机更新 |
| 维护与后果 | 维护目标、实际工时／材料／费用、质量、欠维护及风险／减容 | 维护交付与账本，不把拨款当作已完成养护 |

这些是共同查询语义，不是每个对象都有一份巨大的通用记录。单位、能力、来源、更新时间和模型版本必须可查；零需求、not_applicable、unknown和unsupported分别表示真实为零、不适用、缺观测、尚无模型，不能相互代替。

## 2. 输入、输出、资金与影响分别记

每条资源能力声明资源类型、物理／游戏单位、时间口径、待机／负荷曲线、接入条件、最低与目标量、替代条件和短缺后果。额定耗电不是始终实际满额耗电；断供后降载、停用或保留居住／权利，由对应类型规则决定，不能把人和建筑直接删掉。

资金支出不是一种物理原料，岗位不是产出的市民，噪声也不是可出售商品。资源投入、现金转移、人员时间、可交付服务、外部性分别有账与单位。实际水电、煤、商品、工资、维护或垃圾只能计量一次，通用对象查询只是引用／投影。某对象没有生产能力不意味着它不占空间、不影响周围或不需要管理。

结构工程用料与运营耗材分开；建设时用过的钢材不能每期再消耗，已燃烧煤不能在行业配方再扣一次。利用率、排班、季节或成熟度改变需求时，版本化规则截断稳定区间，按同一权威提交器累计。

## 3. 容纳多少人，必须先说是什么人

| 容量类型 | 含义与限制 |
| --- | --- |
| 居住 | 合法住宅单元、家庭与人数上限，实际居住／居住权分开；不是楼里可站多少人 |
| 工作 | 空间／设备工作位、FTE、招聘、雇佣和班次到岗分别保存 |
| 访问／休憩 | 合法开放时间和同时访客上限，来访者仍属于原家庭，不新增人口 |
| 医疗／教育 | 床位、诊疗吞吐、学位／课程席位各用自己的计量与占用时段 |
| 交通 | 人次／车流／货流的时段通过能力与积压，不能加进住宅人口上限 |

设施“最多容纳100人”不能直接推成100个岗位、100套住房或每天100次服务。实际交付还受工作人员、资金、资源、接入与安全条件约束；员工、居民、访客的重叠按时段和角色处理，不能同一人同时满额工作、学习和休憩。

混合用途建筑的住宅、商铺和公共部分引用各自单元／经营者／容量池。父对象汇总子对象，不能自己再发布一次同样容量；医院员工和病床不是同一容量，公园维护人员也不是公园自动生成的居民。

共享空间也不被一栋建筑独占：合法庭院绿化、人行连接可以位于建筑site内或为多栋建筑共同使用，格子索引允许多个对象。每栋楼引用同一实际空间／绿化对象的用途、可使用范围和管理规则，不复制对象的面积、容量或维护交付。实体碰撞、用途兼容、土地权利、消防净空及统计口径按 [空间共享契约](spatial-contract.md#61-地块内的复合用途与共享空间) 校验；共享绿地可改善周边景观，但私人进入权不因此变成公共休憩容量。

## 4. 人与对象通过角色和权利连接

“甲家庭租住A单元”“某劳动份额在B运营单位工作”“服务批次占用C床位”“D承包方维护E绿地”都是不同关系，不抽象成一条无意义的关联度。关系需可解释谁可使用／操作、承担哪些费用、何时有效和怎样终止；不是所有关系都必须有金钱合同。

居住关系读取住房登记，工作读取雇佣边，服务读取派遣／占用，通行读取交通需求和网络，受污染读取实际接入与暴露。通用层不另保存全城“每个人×每个对象”的邻接矩阵。所有者、运营者、维护方可能不同，租客不自动承担整栋楼维护，市长也不能因物体在本城就拿私人账户付钱。

住宅租金／押金、工资日周月结、财政维护合同各按已有条款；自然生长既不是居民收入，也不是免费完成了一笔市政养护订单。

## 5. 对周围的影响怎样传播

每种作用说明来源单位、运行状态、有效几何、空间／网络机制、时间窗口、上界及受影响渠道。空气通过现有环境输送，噪声按已支持距离／遮挡与时段，消防通过道路响应和实际队伍，工作机会通过通勤匹配。不能统一成“相邻一格＋5”，也不能为每个对象扫描全部其他对象。

正面作用同样有边界。多个公园景观／休憩作用先按覆盖和有界规则合成，再进入家庭已有满意度维度，不无上限叠加；不能新增一份隐藏人口解锁点数。景观吸引力不等于空气污染已被消除，公园也不能抵消断粮、失房或未支付工资。

树冠遮阴、风场、净化和隔声只有已实现且可校准的模型才可对相应指标生效。首版植被可以影响明确的景观／休憩评分；真实碳汇、细颗粒吸收、热岛温度、水循环和复杂声学屏障仍为unsupported，不因模板写了“环保”就给空气浓度减值。同一影响只进入对应场／服务一次，家庭暴露和满意度从结果读取。

## 6. 树木与自然地表也随时间变化

初轮用有空间边界的植被／绿化斑块表示同类自然状态，保存覆盖／成熟度、条件、管理模式、最近游戏时刻、规则与采样种子等有界摘要；必要的重要独立树也可占一个相同状态槽。视觉上的成千棵树从斑块及种子有界采样，不逐棵运行agent、寻路或完整植物生理。

无人维护仍可自然生长。初轮自然增长是版本化游戏规则，在已登记生长范围和适用条件下增加成熟度／覆盖度，达到饱和值后不再无限增大；缺乏适宜条件可以停滞或按明确规则衰退。不承诺成熟个体永不衰退，也不在没有病虫害／野火模型时凭空添加其事故后果。

规则示例仅用于验证：成熟度m在0—1之间，适宜条件恒定时按m(t＋dt)＝min(1,m(t)＋g×dt)推进，g以每游戏日计；m＝0.4、g＝0.01，10游戏日后0.5，100日后封顶1。具体速度需按游戏模板校准；不是现实树种生长预测。自然能量／降水条件先采用明确的环境情景参数，无供水合同的野生树不自动从市政水网扣钱，也不宣称已完成水量／生物量物理守恒。

首轮自主增长限制在登记斑块及合法生长掩膜内，不自行新增跨地块斑块、无限繁殖实体或夺取建设用地。更复杂的跨界播种／根系侵入需以后专项；这是一条模拟范围限制，不是假称现实树木不会越界。树冠可视范围、生长允许范围与土地占用分别声明，不能通过裁掉画面来假装拆迁／移树已经完成。

种植、改变管理模式、移除或移栽受土地权利、保护令、费用和实际作业约束。新树不立即达到成熟效果；清除后原保护责任、残枝／场地处理和费用仍按适用程序，不能换模板重置。自然更新原位改状态，不因新对象槽满停止已有植物增长。

生长掩膜排除既有建筑实体、地基及不相容路权／用途范围；建筑site内已明确兼容的庭院绿化不被一并排除；生长不是自动取得相邻土地权利。自然衰退／死亡可以减少有效覆盖，但残留物、障碍、后续清理及费用是否适用由模板声明；状态变了不代表已清场或完成永久几何工程。首轮未支持的死亡机制不凭空触发事故，已支持的受损／衰退事实也不能因槽满拒绝。

斑块合并须兼容权属、环境条件、管理责任及保护等级，并保留状态贡献与来源，不能将不同责任平均。视觉样本提升为独立登记树时，先校验几何／来源贡献和必要槽位，在同一提交中将该覆盖／作用从原斑块表示移交独立树；反向纳回也需相同的合法移交。不能让原斑块和独立树重复贡献，不以直接相加树冠面积代替重叠覆盖规则；无法确定可移交份额则返回needs_detailed_validation，不凭点击样本创造新树。减少可视实例数不改变真实覆盖、维护成本或作用。

## 7. 自然地与受维护绿地的区别

| 模式 | 自然演变 | 管理投入与可承诺服务 |
| --- | --- | --- |
| 非经营自然植被 | 在初轮允许范围内生长／衰退 | 没有虚构的园丁工资；保护巡查等另有实际责任方和预算 |
| 受管理绿地／公园 | 同样有自然演变 | 修剪、清洁、补植、适用灌溉等各有工时／资源／费用，完成后才维持管理质量与约定开放能力 |
| 临时停养或废弃绿地 | 生物状态与管理状态分别变化 | 可继续长草木但整洁／开放服务可能降低；不立即归零、变成裸地或自动转为合法建设地 |

生物成熟度、植被条件和管理质量不是同一指标。不修剪可能仍长得茂盛，却不再提供同等整洁／开放服务；付维护费也不能立刻让幼苗变成大树。拨款、现金预留、订单、实际到岗／作业、质量结果分别记录。

维护由真实有来源的运营者／市政服务方交付，检查可达性、班次、工时、资金、材料和空间；工资按自己的有效条款，不能把City Team顾问人数当园丁。只有接入灌溉／照明等能力的绿地才有相应市政水电需求，不强制每片林地通电通水。

首轮明确作业只支持已具备资源与服务规则的清洁／修剪／补植及已接入的灌溉／照明；用到残枝等需声明兼容废物去向和接收容量，占现有16实体商品类型预算，不能暗增第17种或删掉废物。没有相应类型／处理能力则限制该作业并返回unsupported，保留自然演变；复杂肥料、农药、病害治疗和绿化商业收益暂缓。维护不足可以积累欠维护和减容；自动修复不得绕过采购／人工和法律程序。

## 8. 五种事物怎样展开

| 事物 | 需求／消耗 | 人与容量 | 主要作用／演变 |
| --- | --- | --- | --- |
| 住宅楼 | 使用相关水电、维护、垃圾处理 | 单元、家庭、住户、产权人与租约 | 通勤／消费来源、居住质量、维护与真实工程 |
| 工商业经营地点 | 适用水电、材料、工资与物流 | 设备工作位、实际雇佣、访客／服务关系 | 实际产出、货流、排放和噪声，缺投入减产 |
| 道路 | 建造用料、适用照明与维护 | 时段通过量／积压，非居住容量 | 连通、拥堵、车辆排放／噪声；路面、车辆贡献不重复 |
| 野生树／植被斑块 | 有限自然情景条件，无默认市政水电账单 | 通常无居住／就业容量，可有保护／受影响关系 | 有界生长与明确景观作用，不自动完成维护或产生碳收入 |
| 管理绿地 | 适用维护工时／清洁／补植／灌溉费用 | 开放／访客容量、维护劳动和责任方 | 植物生长＋管理质量，实际维护后维持已支持服务 |

铁路可沿用相同属性语义，但不因此进入首版可建设／可运营能力。新类型只有落实状态、模拟、工具、费用、生命周期、摘要与预算后才标supported。

## 9. 时间、摘要与闭环

自然／管理状态按游戏日历及有界更新批次推进，稳定区间可按明确公式累计；场景条件、工程、保护令、维护或阈值变化截断区间。相机离开或切到邻城不会停长、免维护费或重置质量。

背景图保存相同的斑块ID、模板、空间／权利引用和状态摘要，维护占用现有工时／服务／账本；重开从同一时刻重建视觉，不重抽权威植被数量或重新收费。新几何／范围仍需详细校验；自然增长不需要每次市长批准，管理合同和扩大范围则按已有权限。

所有者、经营、容量和影响的改变标记依赖，使服务、环境、交通与家庭观察在规定边界更新；不每帧全城全对象扫描。适用停止令和法律先校验；拆除／维护项目的档案、尾款及归档仍按 [闭环契约](closed-loop-contract.md) 执行。

## 10. 存储预算与工具

共同语义复用既有对象／几何／账户／住房／岗位／服务／环境记录，不新增一份“所有对象×全部属性”的权威表。自然与管理植被新增**全世界4096条斑块／重要树状态×64 B＝0.25 MiB**；所有参与地图共享，独立重要树与斑块共用槽，不能每张图各4096。一个公园可有多个斑块并分别计费；管理方、服务和资金只引用一份真实权威，不能每片树再复制公园岗位和预算。

64 B是身份／空间模板／责任与管理引用、覆盖成熟度／条件、更新时间／版本与种子的紧凑目标，不包括变长几何、完整维护合同和每棵树数组。几何归0.25 GiB几何域、空间索引和反查仍用现有模拟／4 MiB索引域、历史页归磁盘、视觉树归0.85 GiB资产／实例预算；均联合准入，不能把0.25 MiB当全部新增资源实占证明。

共享庭院／通道使用既有空间对象和有界几何／关系引用，绿地仍只占原4096植被状态的一份。模板最多8个共享子区域，每空间最多32个使用建筑引用，全世界8192条×16 B＝0.125 MiB使用关系从既有4 MiB域的实体反查配额划出，后者余0.375 MiB，不生成建筑两两矩阵。正文／许可清单分页，仍有数量及实际字节准入；受支持跨主体协议占现有一般合同额度，住房附属使用权沿既有权益描述／条款引用，不能另藏无限共有协议。共享引用不默认新增每对象一份财务主体；实际布局／目录超配须减少新接纳量或重预算，现行38.5078125 MiB载荷和40 MiB额度不据此增加。

区域40 MiB额度不变，载荷36.2578125＋植被0.25＋建筑端口2＝38.5078125 MiB，余1.4921875 MiB，应用常态2.65 GiB目标不变。接纳地图／种植／扩大管理区前检查状态槽、字节、几何及未来作业／收尾；不足拒绝新增或调整尚未承诺的表示，已有斑块原位演变。兼容聚合不得抹除不同权属、保护限制和管理责任，不删除既有义务凑槽。

## 11. 验收边界

- 住宅、工厂、道路、自然树和公园读取同一语义，not_applicable／0／unknown／unsupported不同；模板不支持的影响不能执行。
- 同一资源只扣一次、父子容量不双售；住户／工作人员／访客不混成新增人口，工时守恒。
- 同样游戏时间下自然增长一致、成熟度封顶；暂停不长、切图不停长，满槽不拒绝旧斑块状态变化。
- 同一绿地断维护后植物可继续长但管理服务下降；支付但没到岗不能算维护完成，幼树不因付钱立即成熟。
- 灌溉／照明仅对适用接入生效，野树无虚构水电账单；处理废物需要真实类型／运输／接收容量。
- 生长范围、保护令、清除作业和权利一致；可视样本不伪装真实可产权树，新几何不在摘要绕过校验。
- 4096斑块最大状态叠加现有8地图／工程／预演／保存，复核实际布局、索引、依赖更新及16 GB峰值。以上均待实现；复杂生态和医学／碳汇效果没有因本文获得验证。
