# 楼体、独立单元与共享设施的一致性契约

设计裁定：v0.4.28，2026-10-19。整体复核27类物件及90类目录所复用的身份／空间／权利／接入／容量／费用／维护关系。补充 [Root](root-component-contract.md)、[空间运行](spatial-runtime-contract.md)、[字段字典](capability-field-dictionary.md) 与 [物件契约](common-object-contracts.md)；涉及本文明确修正的口径，以本文为准。仅设计，不宣称所有后续机制、字段布局和16 GB性能已完成。

## 1. 不同身份轴不能互相代替

| 对象／关系 | 唯一身份与原落点 | 不代表什么 |
| --- | --- | --- |
| 楼体／独立设施 | 原B和几何、Root查询入口 | 不自动是一家企业／一个家庭／一份整楼钱包 |
| 住宅独立单元 | 原H，unit_id可解析host和模板布局槽位 | 不是独立楼体，不按套数复制外部门；只支持已声明套内权益，非任意份额地产市场 |
| 家庭 | 原F／账户／成员劳动来源 | 不随房屋转手变成房屋资产或被注销 |
| 经营地点／主体绑定 | 原O及host／合法使用范围，账户与合同另引用 | 一栋楼／同址不强制只有一个经营者；多个O不自动取得多个独占房间或产权 |
| 后续功能绑定 | 原0.125 MiB候选扩展，展开最多4功能 | 不等于4套住宅上限；多用途／多商户仍各有机制门 |
| 共享／功能空间子区 | 原宿主最多8区，或真实独立设施（二选一） | 不是住房H的全部套内布局，也不是每层再发8区 |
| 物理外接端口 | 原U，宿主总≤8条端口记录，每记录1外接锚点 | 不是每户一套外部接路，不是一个门8条免费链路 |
| 道路／管网／真实共同设备 | 原D／几何或独立B／K，按适用类型 | 不是使用方各一份的免费网络／容量／健康值 |
| 建筑→共享空间使用关系 | 原8192×16 B，每空间≤32建筑引用，含待退出 | 不是每户产权登记、付费人数、公共受益人数或额外容量 |
| 单元附属使用／费用依据 | 原H冻结条款／合法来源；适用C、义务另占额度 | 静态依据不自动产生无限动态物业账单 |
| 项目／小区／成组范围 | 原计划／事项／冻结区域的组织视图 | 不必新增“小区Root”，不默认有围墙、公共道路或可挪用住户钱 |

“一个真实经营地点一个O”按受支持的经营主体×经营单元解析，同一地址可以关联多个真实O，但须有各自合法范围与实际状态／额度；同主体同单元不能拆名复制库存、班组或权利。首版普通单用途模板仍保持自身记录数，不能据此提前开放全部多租户／商业机制。

## 2. 四种数量与面积口径分开

以一栋24套H为例：可为1个住宅用途功能、24个住宅单元、最多8个明确共享／功能子区、5或6个外接端口。不能因24>8而删房，也不能把100个商业隔间登记为H绕过后续4功能／8子区限制。具体资产的住宅套数、几何正文和记录须事前有界配置，H／几何／索引不是免费。

同一层的排他套内、公共走廊／结构和未分配面积按固定口径分割，不重复出租；GIA／NIA／site不相加。所有住宅布局可共享不可变模板，实例H保留实际绑定／必要差异；不在宿主B后增加一套每房间动态对象。共享／功能8子区上限约束明确的共同／功能空间描述，不能为任意室内异质用途无限生成例外。

住宅单元主产权沿H；楼体的结构／地块／剩余权利及共有部位使用依据分别沿真实合法来源，不能用一个楼体owner_ref覆盖24个实际单元所有者。普通限定单元买卖保持；复杂共有份额、任意产权层级或治理投票规则仍后续B，不借“多产权楼”默认实现。

## 3. 单元接入组：有宿主不等于能走所有门

首版不做每房间寻路，但必须有经验证的**模板接入组**。每个已支持资产布局最多8个组，声明以下有界内容；超过需要先拆受支持资产／收窄用途或另行设计，不能在实例H后藏无限表。

| 接入组必要依据 | 存储与唯一来源／失效 |
| --- | --- |
| 单元／使用范围→组 | 由H的unit_id／布局槽或原O使用范围与冻结模板版本解析；非新加每单元动态路网 |
| 允许模式／用途／外部门集合 | 冻结模板正文，候选仅来自宿主已登记≤8个U；主体权限仍沿H／C／法律，不由组授予 |
| 内部共同通路／支撑 | 模板已验证的连接、所跨共同范围及通行／支管依赖；几何计原域，不能穿私有套内形成捷径 |
| 真实时间／容量来源 | 有内部时间或瓶颈的粗profile和原资源键；无对应模型不得宣称零时间／无限吞吐，独立约束才占X或原D／服务权威 |
| 水电／候选燃气接入 | 各资源自己的原D／U、支撑／分配／隔离来源；人体通行和管网连通分开，不因同host自动都接上 |
| 变化依据 | S01结构／分组绑定、S04人货通行、S05网络运行、S10条件、S12权限各按字段单写；同刻事务硬失效后再分批软重算 |

组正文共享模板64×4 KiB热页／原分页／几何域，8不是新建8个动态实体。必要实例绑定用原H／O模板布局或其既有有界引用，实际字段／反查装不下须阻止新配置，不追加免费side table。单元临时隔离等个体差异只有原来源能表达才支持；不能因采用共享模板就丢掉个别禁止进入。

例如24套分东／西翼各12套，分别经两组到各自楼梯／门，气／电支撑再引用各自既有来源。东翼楼梯封闭，只立即失效依赖它的12套，不默认全楼失效，也不让东翼穿过西翼某私有单元或随机获得新门。可合法共用另一楼梯须原组／几何／授权已验证，实际过路／内部时长与共同容量重新计算。

布局／接入组改版须使受影响计划失效，已发生行程／费用仍固定旧版本与来源至合法释放，不热换layout槽授权另一扇门。

楼内必要时间由已支持粗profile计入总到达／服务时间，楼外路段距离仍精确按锚点。到城市格或楼外门不自动证明已到所有住户／床位／装卸点；超出室内模型的精细响应判断返回unsupported／needs_detailed_validation，不伪称满足真实消防规范。

一个U记录最多1物理外接锚点；同一开口确有两条不同外接链路时，两条记录都占总8口且引用同一物理瓶颈，不重复发容量。角色／用途可以共享同一记录，不能新增角色就多一个锚点。公共穿行另有真实道路边，住宅门仅作相关起终点，不产生免费穿楼通道。

## 4. 产权、管理、使用、付费和维护五种角色

每个受影响范围必须可追到：实际所有权依据、合法管理主体／授权、实际使用方、服务交付／费用债务方、维护作业方／责任方。可以是同一主体，也可以不同；“物业／公共／市政”标签不能直接生成法人、账户、员工或财政。

- 出售套内产权前，楼体／共同部位的真实管理责任、必要通路／管线使用依据、当前维护安排和付款来源须明确。可沿已有主体／模板限定规则；不要求首版先实现完整共有治理。
- 买卖成立不等于永久维护资金有保障。卖完最后一套不自动注销楼体／共同部位主责方，不将成本强转住户或市政；短缺影响真实条件／服务，不能免费维修。
- 空置单元没有居住家庭，仍有真实产权／费用责任主体。按条款区分固定维护与实际用量，零用量不消除保全责任；户型或楼均值不代替实际未付。
- 租客、经营者离开／换人，不解除旧业主或原债务人的历史责任。产权交割／换payer先封闭旧区间、移交附属权与未来责任；旧债保留原主体或有合法受让，不因卖房消失。
- 共享实体拆分、楼体拆除、关闭必需通道、设施迁移必须重查所有合法依赖者、在途／在场／服务、资本／账务／清场；失败保持原状态，不能先删父对象再找子责任。

楼体owner／管理关系只能指向已声明合法来源；对共同部位责任若当前范围无法表示，相关新交易／改造先补已有可支持来源，不能自创一套永久免费承诺。普通单元买卖不因此整体取消，超出限定权利的配置另标缺项。

## 5. 容量和计量：同一物理来源只提供一次

每项能力按(物理来源、种类、单位、窗口)解析唯一原提供方。父楼、单元、门、共享边和功能绑定只能引用该能力，不能各再发布一次。楼外馈线、内部支路、实际设备、岗位／床位／房间人数和空间吞吐是不同约束，按共同可行量同时检查，不相加当成产能。

例：两单元各允许80 kW但共用100 kW馈线，总承诺不能算160；同窗60＋50＝110时须限供／留10缺口或真实扩容，不可因各自<80就全放行。新增共同用途还查时段、清场／转换和优先级。故障从100降60而actual80，保留80与20缺口，阻不相容新增，不能裁actual。

并发人数与每小时通过量分别**计量／校验**，不是自动收两份费用。若合法条款确有不同收费项目，才各有真实计价依据、收款人、区间和原票；容量检查本身不产生收入。道路／床位／网络已有的约束不再开X发行同样资源。

物理总表＝相容子分配＋公共实际用量＋明示边界损耗，父汇总与子实际用量不能在城市总量再相加。分配量不冒充独立测量，费用份额不反向创造交付或改变物理流率。水电基础绑定仍32768×128 B、最多两资源；天然气沿原M／C候选门，不在“共享”名义下隐藏第三资源／独立用户。

## 6. 分摊和账务落点，不增加隐形物业费表

建筑→设施的8192使用边登记建筑依赖／责任；单元附属使用依据沿H冻结条款，真实付款主体和持续收费状态还要有适用的H／C／账户／义务来源。32个建筑使用方不是32户上限，也不是32份免费物业账本。

| 费用情形 | 允许的落点／限制 |
| --- | --- |
| 原合法租约已含管理／维护费 | 仅同一债权人、账期、清偿规则且原条款明确包含时在原H住房费应计；不能把异质费用无权合并 |
| 自住房或不同收款方的独立维护协议 | 实际持续协议占C1024及相关义务／到期源；不能为自住房虚构租金，也不能往H64后接动态物业账 |
| 基础水电与后续气费 | 沿原本地供应绑定／M／C真实责任边界，公共分配同原交付守恒；不借物业费再收同一已包含能源 |
| 共同设施由已有主体直接负担 | 原主体账户／合法预算与实际作业／协议，使用关系不自动向住户收款；财政来源不能由“公共”标签生成 |
| 代垫／转收 | 原实际交付费用一次，责任人份额之和覆盖一次；代垫方付款及后续应收分别真实记，不复制本金 |
| 新物业费市场／任意共有治理 | 仍后续B，需独立字段／计费／权利／退出／布局和预算；不是本轮已完成机制 |

C按真实持续协议占槽，不每期账单另开一份C；债权按同双方、来源、币种／期限／优先级等合法条件合并，明细仍可查。来源剩法定金钱义务可依法移交原义务表释放旧活动槽，不要求收清所有债才允许旧方退出，也不允许为挪槽免债。

分摊必须声明分母、覆盖范围、空置、违约、未分配份额／尾差及变更生效。权重非负，对同一原成本覆盖一次；不能把欠费方权重改0再自动向其他人补收。若条款有服务管理费，独立说明真实项目，不能混进原成本重复赔付。

例：两楼A／B共享一次真实维护120，约定1/3与2/3，则应承担40／80。已有合法管理主体R先以自身资金200付供方120，再收到B80而A暂欠40：A现金500、B420、R160、供方120，总仍1200；R对A应收40配同一应付，不能另发一份“设施维护费120”再向两楼收120。若R只有100且无合法可用信用／拨款，不能先声称完成并支付120；延期／未满足及条件后果如实记录，不从未来应收生成20现金。

楼内二次分配不复制维护作业：A的40若依法由两个责任单元按1/4／3/4承担，应付10／30，合计40。若某单元空置，其产权／合同责任方仍按原条款承担；缺该来源不自动向另一个人加收。多层分配中的每个动态债务／协议都真实占额度，不因总成本只有120就免来源账。

## 7. 维护状态按真实作用对象划界

| 受维护对象 | 唯一条件／安装来源 | 禁止双算 |
| --- | --- | --- |
| 楼体结构及未拆出的一体化部分 | 选定B原状态及冻结覆盖范围 | 不把其整体condition当作独立K炉具条件的第二写入值 |
| 独立共同设备 | 一个真实设备／K或已支持设施状态 | 多栋／多个单元只引用，不各存健康、安装年龄或重复交付 |
| 单元独立炉具等重要设备 | 已支持独立K及真实宿主／单元引用 | 不因给24户装灶就重置楼体／饭煲／通风原年龄 |
| 植被斑块 | 原P条件／成长／管理质量，成熟和质量分开 | 不因共用庭院而每楼一份生长／维护状态 |
| 路／管线与阀门成套 | 原D／适用K的明确作用范围与状态来源 | 同条管线不在每段／每户重复维修；异龄局部拆换须有对应状态 |

楼体“综合健康／服务可用度”可从结构和依赖设备派生，是D展示，不能直接维修该分数同时修好所有子设备。S10写真实对象条件／作业，原资源提供方据此求有效容量；S01工程安装／交接与S08支付不成为第二condition writer。

从B同质成套拆出独立K，先联合准入新记录／旧依赖／索引，在同一提交中移交实际安装时间、条件／磨损、维护责任／欠账及设备覆盖，原B删除对应权威覆盖而保留引用；不得重叠计龄、资源负荷或维护收费。若粗旧状态不能恢复目标异龄／累计，不能随机补史或标新安装；不支持该局部迁移，先限制新方案或另行设计有依据的表示。

K满时拒绝新独立设备承诺，既有条件／故障继续原位更新。新旧并存、拆卸／待清运仍计峰值K、库存／债务／工程等；不能先释放旧设备身份再假装已清场。单楼案例的24／26新建K、改造34／32峰值保持原算术。

## 9. 16 GB预算与场景反例

本轮不新增动态表，仍27项43.0078125／44 MiB、余0.9921875 MiB；其他模拟314.025 MiB、应用2.65／3／4 GiB目标不变。H32768、O4096、U65536、K4096、共享边8192、X8192、基础供应绑定32768、通用M4096、C1024、义务65536等按全世界共同准入；静态接入组／单元条款使用原模板与几何页，绑定／反查／到期也计费，不借“小区”名新开表。

一栋24套可占24H但共用两个人行口；若依法共享庭院，建筑到庭院可只有1条使用边，不因此再发24份门／容量或免24方实际费用来源。四楼共用庭院是4条建筑边、1实体及真实容量；若96户各有独立维护协议，即占96条C，不能因只有4条建筑边改成4份免费收费状态。原C已有950时，剩74，96新协议无法全接纳；不能自动把96个付款人合成一方或从H64追加账务。改用已有合法包费条款要真实可用，不能为通过预算强改产权／租约。

该限制不是16 GB物理内存一定不足，而是当前已声明字段和条数设计的边界。若要全世界22800户各独立物业收费，必须先设计足够的计费表示与预算；本轮不承诺。类似地，6100建筑使用关系不是6100个受益家庭或6100个已证明合法内路。

重点验证：①24H／8区／4功能／8口独立计数与非法商隔间伪装；②两翼门／楼梯或不同支管失效，仅依赖单元受影响；③双门同瓶颈不发双容量／重复收费；④父表／分配／公共实际量与费用守恒；⑤空置／欠费／换业主及最后一套售出，旧债与共同维护责任不消失；⑥B成套→K迁移不刷新年龄／负荷，缺历史拒改；⑦实体拆分／关闭／拆楼不能删他方使用权／在场／债务；⑧C／U／K／共享边／模板页／索引满额拒新不删旧，摘要恢复和单预演不复制实体。

实际布局、类型化句柄、几何／模板接入正文与索引、完整联合场景／误差／吞吐和真实16 GB目标机仍未验。静态定义、例子与链接检查只证明关系可追踪和所列算术一致，不等于已经能跑完全部闭环。

## 10. 两楼共享设施的连续窗口验证

[两栋楼案例](worked-example-two-buildings-shared-facilities.md) 固定8家庭／12住房记录／21账户，用正常30日、空置转售欠费30日、拆除10日验证本契约。限定买卖仅针对实际空置无租约单元；买方可继续租住另一单元，产权变化不覆盖其租约／实际居住。空置不改固定费用分母，转售不注销旧债或移交全部共同责任。

拆除前分别取得单元处分依据、住户实际迁移、他方替代接入／未来费用同意。先完成并验收旁路，再切换和排空旧在途，最后退役／清运；已回购不等于已安置。若另楼不接受192新条款，本方案受阻，不能单方把剩余费用强摊。维护交付、原段保全、新段初期巡检、断接与清运分别覆盖，现金支付不能替代实际作业。异常分支仍保留已发生费用、权利和占用，不能套用成功轨迹的清零日期。

不加表；实际产权／租约沿H、家庭沿F、共享责任按C及原义务，所有在途和新旧并存从原额度准入；见案例第9、10节。

## 11. 长期欠费与最低维护的边界

[催缴／司法／维护案例](worked-example-shared-facility-arrears.md) 区分旧本金、未来实际交付、未完成维护、回收风险与物理状态。最低包要有已有效的合同／制度依据、实际工时／材料／到达及条件／负荷／观察期限；不按任意预算比例宣布“足够安全”。例中36维护＋42公共电水＝78，OA23.50／OB54.50；不倒改旧110.50、不强摊OA、不向已付租的住户重复收费。

降级不保证永久运行。资金不足先在新承诺门停止未落实的作业，不删除持续消耗／安全义务；共同设备真实故障可能影响两楼，另一楼权益保护不等于凭空独立保供。停供须指向真实资源／安全条件或明确有效程序，不将欠费当故障，不连坐撤销他方使用权。代垫／援助／责任移交须另有真实资金、授权与追偿／赠与规则，不能靠共享关系自动融资。

## 12. 共享设施真故障后的恢复与接管

[第50日故障案例](worked-example-shared-pipe-failure.md) 将供水干段失效、初始事故原因、合同延迟与旧欠款分开。共享设备真实失效可影响两楼；应急隔离／公平限量按受影响者与实际能力执行，不根据房东是否欠费决定基本供给。临时旁路是真实有工期／验收／源额度的管线，不是复制各楼容量或水商品链。

公共主体有限直接采购不把S旧债变现金，也不默认取得追偿权；居民援助和承包迟延赔偿按家庭／时段／损害范围核重。恢复物理条件不刷新全网年龄、原试算期限和欠债；移交必须另有真实主体／有效方案／资金保护及未完责任。例中S仍0.48、原债199.52，但已单独落实30日共同维护78的公共采购；未交付不能当已完成费用，期末后继续重评，不保证永久财政兜底。

## 13. 交接与财政退出，不继续扩展数值事件链

[全局退出门](global-design-coverage-and-freeze.md#3-本轮补齐的有限援助管理交接通则) 区分付款人、实际作业与原管理主责。到期先结原真实区间／余数／义务，新任务／权限／资金合法落实后再接，不同时收两份维护；旧债归原主体，不自动退款给新出资者。新运行资金不能再担保全部安置／收尾；没人续付仍保留原权利与安全责任，不能自动变为无限财政、守约业主强制代垫或住户失权。本线设计暂冻，只有全局审查暴露新的独立机制缺口才补场景。
