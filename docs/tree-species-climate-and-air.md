# 树种、地理适生与空气作用

发布v0.5.24，设计补充T57。需求：不同树种对环境的作用不同，能否种植／长期生存必须受地图经纬度与当地条件约束。本篇只补设计；[T12-A](m0-air-cpu-reference.md)尚无植被作用项，本次不改变其公式或冻结的数值证据。

## 1. 经纬度进入适生约束，不能只画纬度禁区

使用“地图地理配准→生态／气候区→树种适生筛选→具体种植地点”的路径。经纬度决定地理位置和区域数据来源；同纬度不保证温度／降水相同，经度也不是一个独立的树木生理开关。还需气候、海拔、土壤／水分和场地条件。USDA耐寒区基于年极端最低冬温的多年平均，并明确温度以外还有水分、风、土壤等因素；不能把美国耐寒区编号当全球适生或最高温模型。[USDA使用说明](https://planthardiness.ars.usda.gov/pages/how-to-use-the-maps)。Forest Research的ESC同样匹配地点／土壤等因素与树种生态需求，而非仅按纬度筛选。[ESC说明](https://www.forestresearch.gov.uk/tools-and-resources/fthr/ecological-site-classification/)。

| 输入 | 设计契约 | 缺项处理 |
|---|---|---|
| 地理位置 | 原始CRS、与WGS84的版本化变换、地图边界／中心经纬度、来源及精度 | 灰度图不包含经纬度；不从亮度、本地x/y或城市年龄反推 |
| 地区气候 | 年极端低温／高温及持续性、温度／水分季节型、降水／干旱、半球与物候 | 无真实数据时可明确选择合成气候场景，不冒充自动查询或现实匹配 |
| 场地 | 海拔、土壤／排水／含水、盐风／暴露、光照、可用根区和合法生长范围 | 必要数据缺失返回unknown，不用0表示安全／适生 |
| 树种适生profile | 生态耐受范围、最适范围、条件性支持需求、季节叶量／成熟变化、出处及参数版本 | 名称／模型外观不构成生理或净化参数；缺参不启用对应作用 |
| 自然分布／园艺引入 | 原生区域标签与生态耐受分别保存；引入另查实际适用的许可／保护规则 | 非原生不等于必死，也不因“能活”自动取得合法引种资格 |

当前T07合成灰度图没有地理配准，这仍是实现缺口。用户导入后须补明确地理信息，或选合成气候预设；不得默认为所有树种适生。邻城使用同一地区环境规则和版本，不能因开关地图换一套气候。季节读取共享环境窗口而非城市发展年龄；北／南半球与旱雨季由气候profile决定，不给全世界套同一落叶月份。

## 2. 同一地区的树种仍有差异

共享树种profile至少分开：耐寒／耐热与持续性、耐旱／耐涝、土壤／盐分与根区要求、生长曲线／成熟树冠、常绿／落叶与季节叶量、养护用水／工时／修剪残余物，以及已启用环境作用的参数和有效条件。品种／种源差异有机制依据时用规格变体，不能仅换贴图改变数值。针叶、阔叶、常绿、落叶等是功能分组，不替代具体树种及其适生数据，也不能断言某组对所有污染都更好。

判定分开“是否允许新种植”和“已有树的状态演变”：

| 结果 | 新种植 | 已有植被与运行后果 |
|---|---|---|
| 适生 | 可进入土地／许可／工程及预算流程 | 按季节、成熟、实际水分与condition计算，不保证始终满效 |
| 条件适生 | 必须声明实际灌溉／根区改造等支撑、容量与持续费用 | 支撑不足后受胁迫、减缓生长或按受支持规则衰退，不能仅付钱就恢复 |
| 不适生 | 普通露地方案拒绝；已有温室／环境控制模型和真实能耗时才能另评设施方案 | 不因气候标签改变立即删树；按已定义持续时间／状态规则处理受损和退出 |
| 未知 | 不给“适生”保证，调查／明确合成配置后再提交 | 保留已知状态与覆盖年龄，相关收益不假定满额，缺测不写成死亡 |

人工灌溉不能抵消未满足的耐寒／耐热要求；温室、供暖／制冷也不能只是一项收费标签。幼树、成熟树、衰退树的作用不同，种下即获得成熟净化能力或砍老树补幼树立刻等效，均不允许。已有树的成长／养护／砍移继续遵守实际游戏时间、权属、作业与清理责任；关图沿R54不暗中补跑自主成长或创建净化／碳收益。

## 3. 空气作用通过同一环境系统

树木不是固定“周围空气＋5”的物件。未来模型按树种参数、成熟度、季节有效叶量、健康／水分、非重复树冠覆盖及当地暴露计算，再由S11更新对应环境场；家庭和企业读取结果，不能再叠同一份直接幸福值奖励。碳统计、EI游戏指数、物理颗粒质量与噪声是不同量，不互相兑换。

Forest Research说明植被能通过叶面／吸收等过程影响污染，但也可能改变空气流动，在某些地点滞留污染、在另一些地点减少暴露。因此不能把更多树或更密树冠一律作为更大净化收益。[城市森林说明](https://www.forestresearch.gov.uk/climate-change/advice/urban-forests/)。

设计上的空气接口包含“有限清除／沉积能力”和“与布局有关的通风适用性”两部分：

- 有效能力使用`树种参数 × 有效冠层 × 成熟／健康／季节／水分因子`的有界聚合；各因子有单位／范围，重叠树冠不重复累加，实际清除不能超过当前可处理负荷。
- 参数未校准、通风条件未建模或接收位置未知时，标unsupported／unknown，不能给正加成。当前T12-A既有0.01h消散是冻结基线，不能直接再扣一遍“树清除”造成重复计算；引入树作用需独立策略版本并重新比较CPU参考。
- EI是游戏指数，不能把减少的EI写成实际吸收了多少吨颗粒或CO2。以后启用物理沉积，须有叶面／土壤、冲刷／再悬浮或清理去向；碳收入还须真实可核算的独立合同，不能凭树冠无限产钱。
- BVOC／花粉、复杂街谷风场、真实污染物吸收和热岛等仍为后续机制，不用一个通用“净化系数”假装实现。未启用项明确unsupported，不当作真实为零；需要它们才能证明安全的情形，不输出达标结论。

## 4. 聚合与16GB增量

继续使用全存档4096个植被斑块／重要独立树的既有额度，视觉树不新增逐棵运行状态。一个斑块按同树种／相容群组聚合；混植只在相容成长／季节／养护条件下使用有界配方（最多4种且权重归一），不能把状态差异大的树平均掉。无法合并就占用原有斑块槽；共享庭院／重要树的覆盖移交不能重复作用。

新增设计预算不假定能塞回旧64B：4096槽×两个u16引用（species_profile、site_zone）＝16KiB旁表；共享树种／相容混植profile至多64×256B＝16KiB；最多256个已加载场地分区引用摘要×64B＝16KiB，合计48KiB＝0.046875MiB，从M-env原6MiB天气／资源／边界／索引份额划出，余5.953125MiB。引用复用原槽generation，槽重用须一并失效，不能用旧树种配置污染新物件。

分区64B只存气候／土壤数据引用、来源版本及有效性摘要，不塞完整气象序列或全球植被栅格；外部数据缓存仍需另有明确来源／配额，超额未准入不能“免费读取全地球”。profile上限包括混植配方而非各64份；完整字段布局、字符串／索引和跨系统联合量须在实现前实测，以上仅规划。3.10GiB总额与16GB门不增加，也不以48KiB证明整机通过。

S10按实际状态事件／季节区间更新成长与养护，S11按脏块／输入变化更新作用；不每帧对每棵树跑生理，也不做每树×每格全对全矩阵。来源按原环境最多8通道和有界页准入，树种细分不自动新增第9通道或另一套空气求解器。

## 5. 完成条件与实施去向

本次完成地理／树种／环境作用的设计约束；不是树种数据库、地理服务或运行实现。后续必须分别验证：同纬度不同气候适生不同；无配准灰度图返回未知；半球季节差异；额外灌溉有实付与资源约束；非适生幼树不能靠换贴图得成熟收益；树冠重叠和共享设施不双算；缺参数不产生空气／碳收益；新空气策略的清除上限、去向、通风限制、保存与跨图一致；4096槽及48KiB增量实际布局。每个命名树种的参数有来源并装配后才可开放其相应机制。

归属：地图来源／气候上下文、对象与养护、S11环境、之后的受体影响；不并入P-WORKER的进程隔离验收。下一模型主线仍是单worker纯任务隔离，树种细节保留在总体目标，不能为了赶实现删掉。
