# 定期选举与议员表决

设计补充，2026-10-18。按玩家明确要求，首版就包含定期选举产生议会代表，再由代表对具体提案投票。本文件取代v0.4.6暂缓正式选举、仅预置群体代表的假设；复杂政党组织、竞选资金、逐人政治agent及市长选举仍暂缓，玩家继续扮演市长。

## 1. 任期与日历

默认正式议会任期2个游戏年，采用游戏公历周年，不固定为730天；2月29日周年在非闰年落到2月28日。同一规则用于计算后续固定选举日，选举延期不把整条日历悄悄后移。

空城由建市宪章规定的过渡议会及限额初始拨款维持。过渡机构仅能执行宪章列明的开局建设、已有义务和必要维持事项，不自我扩权或取消选举。按统一日历每30游戏日检查一次首次组建条件，首次达到100名模型合资格居民后启动30日选举程序；100是待平衡参数，不是自然人口或现实法定标准。首届首次排定投票日T成为常规日历锚点，之后每2周年举行常规选举，实际延期／晚交接不改变该锚点。

常规投票日记为T：

| 时刻 | 阶段与冻结项 |
| --- | --- |
| T−30游戏日 | 启动本届程序，冻结登记时点、选民归属与名册、席位数量和计票规则 |
| T−14游戏日 | 冻结候选名单、顺序、政纲和资格；公示 |
| T−1游戏日 | 固定民意观测窗口、投票率／偏好参数与种子，开放投票 |
| T | 关闭投票，按冻结输入计票、公布结果并进入资格／程序确认 |
| T＋1游戏日 | 无有效停止交接命令且确认通过时，原子交接新议会；旧届正常权限到此终止 |

首次程序也使用同样30日长度。任期截止与交接日分别记录；下一届仍锚定原定T每2周年，T＋1的交接间隔不累积延长任期。有效停止令可阻止交接，不能由市长口头决定不认结果；案件与复核按司法规则处理，不通过重抽选票解决。

## 2. 谁具有选举权重

首版没有完整年龄模型，以常住人口×版本化资格比例估计模型合资格居民，默认比例0.6；不是逐人核验年龄。失业、低收入或不通勤不能因此失去资格，企业和City Team也不额外获得选票。

城市合资格总人数为floor(登记快照常住人口×资格比例)，再按稳定居住登记单元分配整数人数，余数按确定规则处理；总人数不能超过常住人口。各登记单元来自冻结住宅／群体及真实居住归属，不按工作地点登记；两城通勤者仍只属于一个登记住所。

同一登记时刻的城市程序组成同一登记轮次，共用区域冻结快照和登记索引，每个选举人口批次只归一个城市；不同登记日期是不同轮次，分别按当时唯一常住地登记。跨轮次迁居后合法参与两城不同任期不算重复投票，首版不另设跨日期资格锁定期。同城同届不允许重复登记。冻结批次有稳定registration_batch_id、人数、所属城市与snapshot_ref，后续人口拆分、合并或迁移不能改变该届名册。登记截止后迁居者本届仍按登记时住所投票，新住所不再为同轮生成第二份选票；截止后新增人口等下一轮。

名册、迁移关联及合并前的登记证据分页持久化，不依赖当前群体ID还能否查询。它们是有界热页支持的群体批次，而非给每个居民创建常驻政治对象。

## 3. 市民怎样选出具体代表

首版全城是一个多席选区，默认9席，采用封闭候选名单比例分席，不先引入复杂选区划界。每城最多3份名单，每份须提供9名有确定顺序、互不重复的合资格候选人；名单可以代表不同公开政策主张，不等于已经实现完整政党模拟。城市财富和地图面积不增加票权。

市长不能任意删除合资格名单、改名单顺序或指定赢家。候选人由规则化政治系统产生，采用有来源的资格、政纲、专业／履历摘要和稳定candidate_id；其政治身份仍是抽象状态，不另增住宅人口。候选人不能在同轮跨城／跨名单重复参选或跨城重复占席。

每个冻结人口批次根据公开的议题权重、候选政纲和实际城市观测计算投票率与名单偏好，再批量分配整数票。首版不做逐人agent，但必须满足：各名单有效票＋无效票＋未投票＝合资格人数；名单票非负，未观察到的民意标记缺失并使用公开中性先验，不能伪造已测事实。规则版本、舍入处理、观测窗口和固定种子全部记录。

结果由版本化计票算法生成，不由模型叙述决定。有效票大于0时，不另设最低投票率门槛；名单按有效票比例计算9席配额，先分整数部分，再按余数从大到小补足。相同余数按有效票较多者优先，再按该选举轮次已冻结的抽签序决定；0票名单不能获得席位。每份合资格名单有9名候选，任何名单都能容纳全部席位，避免分到席位却没人任职。

按名单已冻结顺序选出具体议员，不由agent临时补人。得票比例、席位数、当选人和分配过程可查询；最大余数法只决定席位，不改变每名议员表决权。

## 4. 异常、递补与有限留任

没有合资格人口、没有合资格名单或有效票为0时，不得用平票规则产生赢家。进入有原因的延期，默认30游戏日后重新登记并再走完整程序；保存每次尝试的事实与结果。合法程序失败的重选和对同一结果反复重抽明确区分，玩家／agent不能为了改变结果主动触发重选。

普通任期到期且新届尚未合法产生时，旧议会仅按宪章有限留任，处理既有义务和必要维持事项，不能通过延迟选举取得无限正常立法权。常规日历锚点保留，下一次选举按原定周期；延迟跨过下一常规周期时合并处理当前待成立任期，不倒补多场选举、重复发席位或恢复完整过期权限。

缺少机构运营资金不得默认为执政者获胜、取消民意或自动延长完整任期。基本登记、结果与权限状态持续由规则引擎保存，额外解释／文书受实际费用及任务配额限制；不足以安全推进或持久化时，按既有资源背压暂停并报告，不跳过选举。

任期内空缺优先从同一名单尚未当选、仍符合资格的候选中按顺序递补，依据同一届选举结果且只占一个席位。名单耗尽则席位空缺，不由市长任命；法定通过门槛仍按9个法定席位计算。空缺导致长期不足法定人数时，启动宪章规定的30日提前改选程序，原常规选举日不顺延；提前改选的过渡任期到下一常规交接日结束。

候选公示后资格失效须留证据与程序回执，不能临时换人而声称旧票仍适用。若当选资格争议无法依法递补，按停止交接／重选规则处理，模型不自行认定政治对手失格。

每城最多一个有效组建程序。新触发提前改选／延期重选时，若常规程序已启动或下一常规T在30日内，则合并为该常规目标任期，不并行发出两个交接事件；达不到法定阶段时限则明确延期，不能为赶日期跳过程序。积压程序进入下一常规周期时同样确定唯一目标任期，保留仍适用的程序证据，登记／候选等前提改变则重新执行相应阶段。被替代程序递增版本并停止生成交接，旧结果只保留历史；交接原子检查程序版本、目标任期和现任council_revision，过期结果不得覆盖已就任新会。

## 5. 当选之后怎样投提案

议会仍一席一票；普通9席议会至少5席参与且至少5票赞成才通过。获得5000张选票的议员与获得500张选票的议员，进入议会后各有一票。弃权、回避、缺席和反对分别记录。

代表有冻结的政纲立场和任期内议题偏好，可因新证据、选区／群体后果及公开取舍改变具体提案的立场；不是市长命令到达就自动支持，也不是所有提案机械跟随同一全城满意度。偏离政纲需记录理由，选民在下一轮可通过绩效与偏好重新选择；不按每个显示帧随机换立场。

每次表决锁定bill_revision、council_revision、term_id、会议与证据版本。换届时先登记确认结果→原子发布新term_id／council_revision→处理同刻未完成事项。旧会已经完成的有效表决、已通过但待生效的法案继续保留，不能换新议员重写旧票；尚未表决提案交新会重查程序与证据，必要时重新评估，不自动作废或默认通过。

已生效法律、拨款、司法命令、债务、合同和工程不随换届清零，行政／玩家授权也不自动变化。新会想调整政策需另提修订并处理存量义务。City Team专家能改善论证，但不能多生成一张议会票或修改选举结果。

## 6. 成本与资源

人口登记、观测汇总和计票按阶段批处理，正常日常运行不持续逐人算选票。模型只可解释竞选主张、帮市长准备提案或总结结果；可信政治系统独立决定登记、计票、席位与议员表决。未打开的城市也按统一日历执行，倍速遇到登记、候选冻结、投票、确认、交接与延期边界必须截断。

新增全世界共享额度：候选记录768×256 B＝192 KiB，活动选举周期32×1 KiB＝32 KiB，计票工作页32 KiB，合计256 KiB＝0.25 MiB，纳入区域32 MiB。32周期和768候选联合准入，不保证32城同时各有27人；启动程序前检查周期、候选、席位与必要状态，预留将来交接所需槽位。旧届与新届交接复用同一席位槽并更换任期引用，不把两届议员当成双倍议会。

确认后，当届完整名单及递补顺序分页存档；递补时根据同一冻结名册加载必要页，不能当已结束选举而丢弃资格证据。768候选槽计当前提名／计票及实际递补使用的热描述，不要求所有历届候选永久常驻；递补前也须联合准入并预留必要槽。重新参选者使用同一身份、不同选举资格引用，公开名单／计票证据与离任历史持久化，不得混淆不同届结果。城市加入或改变席位配置也要预检未来选举的必要容量，不在投票日才静默宣布无资源而永不换届。

冻结人口名册、票数明细和历史证据纳入原10 GiB世界存档预算分页，不藏在32 KiB工作页内。单页最多8 KiB，热读取及批量计票工作合计受32 KiB约束；保留人口／选票总计与可复算校验摘要，不能只留最终赢家。同步选举时顺序处理和分页，不扩成每城一套模型／快照内存副本。

v0.4.7加入此分项时区域小计29.4453125＋0.25＝29.6953125 MiB；后续行业等分项加入后的当前合计见 [性能预算](performance-budget.md)，总应用2.65 GiB目标不增加。既有单活动模型请求、32项分析／文书任务、单完整预演、共享知识热页、8192事件环与存档边界继续有效；实际状态大小和16 GB目标机性能仍待验证。

## 7. 查询与验收

新增拟议只读工具city.election_status：返回本城term_id、选举轮次、时间表、阶段、登记／投票／弃权总数、名单票、席位／当选人、确认状态、覆盖和数据版本。city.governance_status关联当前届与代表投票；系统不暴露修改最终选票／赢家的行政写接口。

验收包括：两周年与闰年；首次空城／100人资格门槛；截止后迁移与跨城通勤不重复登记；人口合并不改变冻结名册；选票和席位守恒；余数平票；零票重选；递补耗尽与缺额；同刻换届／提案表决；旧法案继续生效；暂停／高速／邻图与保存恢复；32周期和768候选联合准入。重复查询、模型重试、摄像机和画面采样不得改变同届结果。
