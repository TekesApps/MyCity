# v0.4 整体设计审查与修订记录

日期：2026-10-18。范围：当前 MyCity 准备文档，从玩家命令、City Team、精准建设工具，到城市运行与观察反馈；另核对本机并做静态规模评估。本轮只修设计，不写游戏代码，也没有运行游戏基准。

## 1. 结论

v0.4.3 当前基线：16 GB 内存，一张地图使用统一的 16 m 土地格，小 64×64、中 128×128、大 256×256。默认验收中地图，5 万居民／4000 建筑；常态内存目标 2.65 GiB、软上限 3 GiB、峰值警戒 4 GiB。下列 v0.2 闭环修订仍有效，但旧 32 GB／大地图资源提案已由新基线取代。

v0.1 已覆盖玩法和几何工具，但“计划提交后怎样持续运行并证明目标达成”存在实质缺口，设施投运、时间、回执和运行资源也有歧义。v0.2 在文档层修正下表问题，并同步原有入口、工具、空间、模拟和路线图。

本机为 M4、10 核 CPU／10 核 GPU、32 GB 内存。4.096 km 地图和 65,536 土地格有合理实现可行性；此判断依赖聚合人口、稀疏交通需求、邻域环境场和受限预演，不能外推为逐人逐车、无限规模或已达到 4K60。

## 2. 闭环审查结果

以下表记录早期v0.1→v0.2审查；其中旧10秒统一步长等已由v0.4.3游戏日历取代。优先级表示当时不修复的影响，文档补齐不代表实现测试通过。

| 优先级 | v0.1 缺口／矛盾 | v0.2 修订 |
| --- | --- | --- |
| 高 | 命令只有文字，缺少目标创建、修改和归属 | 市长命令 ID、Goal 服务、amends／supersedes、目标版本与工具 |
| 高 | 目标、方案、施工和达标共享模糊完成状态 | 分离 Goal／Plan／Project／Monitor，另有设施投运状态 |
| 高 | 只有授权引用，没有谁创建授权的机制 | 宿主根据玩家事件／既有政策创建，agent 只能提案，不能自授权 |
| 高 | 建筑要水电、连接又要建筑，执行容易互等 | commissioning_group 检查组内最终拓扑，原子提交；未投运不计服务 |
| 高 | 水泵、电厂、供煤存在启动循环 | 显式边界供给、初始库存和启动资本，缺失时报循环，不用未来资源 |
| 高 | “持续观察”只有 observe 查询，没有调度实体 | 注册持久 Monitor、指标、窗口、事件与离线采样工具 |
| 高 | “改善通勤”没有分母，断路可能让平均值变好 | 同时报告成功旅行时间、未完成需求和需求总量 |
| 高 | 全部硬约束统一检查，实际入住被误当可施工证明 | 区分施工不变量、规划容量、运营结果和软偏好 |
| 高 | 未定义多久达标、缺样本怎样处理 | metric_spec 包含采样、持续窗口、截止时间与缺测语义 |
| 高 | agent 能不停观察、再规划并花钱 | 次数、冷却、预算和受阻规则，默认最多 3 次自动再规划 |
| 高 | 建筑、回执、预算、预留可能分开落盘 | 城市事务日志和一致检查点，持久化后回执，恢复统一重放 |
| 高 | 重试先检查新世界版本，可能把已成功操作当失败 | 先查幂等记录，再对新操作做前置检查 |
| 高 | 项目全局版本可能被自己的第一步作废 | 接受时 CAS，后续按当前状态和项目回执验证，不复用初始版本硬比较 |
| 高 | 预留减去所有已保留土地，可能禁止项目用自己的地 | 只排除他项目冲突预留；共享走廊按类型兼容 |
| 高 | 私人自动开发未纳入建设版本与预留 | 自动开发同样检查并增加版本，不可抢预留地 |
| 高 | 每格互动被理解成全格两两计算会爆规模 | 禁止全格 OD 矩阵、厘米网格与逐格模型；稀疏需求、分区聚合 |
| 高 | 几何精度采样可能膨胀路网拓扑 | 曲线采样和寻路节点分开，拓扑只保留必要节点 |
| 中 | 模拟步长、生产周期和倍速含义缺失 | 10 游戏秒步长、1×目标每秒 6 步，系统分别更新，倍速不增大步长 |
| 中 | 后台求解由现实完成时机决定，会破坏回放 | 固定逻辑周期、工作配额和结果发布边界，超预算降低实际速度 |
| 中 | 预演前后整城哈希不变与正式城市继续运行矛盾 | 固定输入快照不可变，预演不写正式世界；允许正常世界推进 |
| 中 | 环境更新频率与风场／扩散稳定性未关联 | 数值子步、负值和通量监测，不靠扩大步长加速 |
| 中 | 项目预留超时未区分现实与游戏时间 | 游戏项目按游戏时钟，短期锁按现实超时；暂停不耗项目期限 |
| 中 | 分区建设与私人开发、产权及费用模糊 | 分区不直接造楼或转产权，公共开发单列授权与资金 |
| 中 | 所有商品／建设材料都似乎可验证 | capabilities 明确资源域，首版运行煤炭＋一般商品，未实现材料不冒充核验 |
| 中 | 商业负责人既像逐笔 agent 又像市场引擎 | agent 管策略与异常，日常撮合和履约在模拟规则内 |
| 中 | 部门可并发整城预演，消耗无界 | 首版一个协调会话、一个完整预演、分层预测和资源预算 |
| 中 | UI 宣称 60 FPS，但当前外接屏显示 30 Hz | 区分引擎吞吐与实际刷新模式，60 FPS 验收要求可用的 ≥60 Hz 模式 |
| 中 | 人口容量约束容易被实现成断供立刻删除人口 | 物理住房容量与增长吸引力分开，负向变化日周期渐进 |
| 中 | 前后指标变化直接归因为建设 | 实际趋势与同快照对照预演分开，后者明确为模型估计 |

追加玩家明确方向：首版排除逐人完整生活与逐车全城寻路。市民／车辆以受模型约束的随机动画表达，可视实例与人口统计完全分离，详见 population-and-presentation.md。

## 4. v0.2 旧规模评估记录（已被 v0.3 预算取代）

- 土地 65,536 格、地形约 105 万样本、环境 16,384 单元，各层独立更新。
- 正常档定义为 10 万居民、8,000 建筑、10,000 聚合群体、20,000 有向路网边、16,384 活跃稀疏 OD 预算；不是每位居民一个 agent。
- 明确假设下部分基础有效载荷约 112.8 MiB，不能当成应用总占用；正常档总应用约 5 GiB 作为预算，常态软上限 6 GiB、峰值警戒 8 GiB。
- 全格两两 f32 距离表单独就要 16 GiB；厘米网格即使每格一字节也要 156.25 GiB。此类实现明确禁止。
- 实际热点是缓存失效后的交通寻路、几何批量求解、4K 渲染、资产和隔离预演；不是单看格子数量。

以上是硬件读取和静态推导。没有从芯片型号推导 FPS，也没有把短时内存空闲量当作游戏可用配额。

## 5. 仍待验证的事项与停止条件

以下是实现／平衡／实测工作，不再以文档模糊默认值掩盖，也不在本轮开始编码：

| 项目 | 后续证据／停止条件 |
| --- | --- |
| AgentKit 工具桥接 | 所选 endpoint 公开扩展真实往返、取消、断线恢复；不支持则调整接入方案 |
| 机器可验证 schema | 公共类型、JSON Schema、错误码与工具注册一致；本文示例不是已实现 API |
| 几何稳健性 | 含孔多边形、曲线包络、退界、旋转、极小侵入回归；无法可靠判定则拒绝 |
| 拓扑与投运组 | 新对象引用、组内提交、缺启动资源和降额场景，守住不虚报服务 |
| 模拟平衡 | 需求、迁移、价格、生产、污染与费用参数需观察，不保证好玩或长期稳定 |
| 交通预算 | 三档及断路全失效场景，报告未收敛与近似；不满足正常档则调整算法或目标规模 |
| 本机渲染与内存 | Release、实际显示模式、30 分钟混合负载；超预算先降视觉与预演并发 |
| 灾难恢复 | 各提交边界中断，回执、世界、账本、预留、监测一致，无重复扣款 |
| 真实模型玩法 | 连续完成命令→精确建设→观察→调整；不能由合成 provider 通过替代 |

完整设计的含义是关键职责、边界、状态和失败路径有明确答案，不代表所有数值已经验证，也不承诺后续原型不需要修改。

## 10. v0.4.3 工程时间与快速日历

按用户澄清，真实尺度工期通过可调游戏日历推进，建设和拆除均非即时。咨询advisor后，将原子接受、持续作业与原子投运分开；保留半成品与现场，受阻一日改为告警。摘要推进已冻结工程的工作量与后果，最终几何验收仍需详细校验。

高速1日/秒不能靠每秒8640次完整细步实现；改用版本化事件／聚合策略，保留资源、费用、排队、污染累计暴露及噪声峰值。新增工程状态2 MiB包含原区域32 MiB，使预算小计28.508 MiB、余量3.492 MiB；应用总目标2.65 GiB不变。实际算法与速度未验证。
