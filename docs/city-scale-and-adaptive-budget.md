本文把现有规则接为可校准流程，不建立另一套权威模型。总体入口仍是 [PRODUCT_BLUEPRINT](PRODUCT_BLUEPRINT.md)；全产品容量／资源以 [P53 R03](product-runtime-budget-and-versions.md#3-r03全产品联合内存与容量) 为准，跨城以 [R54](regional-snapshots-and-interaction-ledger.md) 为准，系统粒度沿 [收敛契约](model-granularity-and-convergence.md)，执行器沿 [CG39](cpu-gpu-compute-contract.md) 与 [A55](process-worker-and-render-architecture.md)。实验、证据和分期见 [校准计划](simulation-budget-calibration-plan.md)。本设计不追溯修改任何历史结果。

## 0. 首要产品约束：全游戏预算、推进目标与业务承载

BUDGET-2补充：先定义整个游戏共同遵守的资源包络和服务目标，再实测其中可持续处理的城市业务负载。**不先承诺单城最高人口，不按人口固定分配计算资源。** 人口是可读的城市结果，承载能力是“目标硬件＋资源预算＋模型可信度＋推进／响应目标”约束下可持续处理的负载集合，不是一个脱离条件的总分。

### 0.1 一份应用总预算

计费范围包括App、Sim、所有worker／broker、产品启动的辅助进程及CPU/GPU全部实际分配；进程或地图增加不会获得新一份总额。正式产品保留UI／渲染份额，本轮headless实验不借此承诺完整产品可跑。测试专用oracle／观察器开销单列，同时计入实际整机压力；随产品启动的诊断／监督则归产品总账。系统和其它应用需要独立余量，不能靠停止其它项目或持续swap维持资格。

| 资源维度 | 共同规定 | 预算状态与准入 |
| --- | --- | --- |
| 内存 | 沿P53/A55，全游戏去重常态目标3.10GiB、软阈3.5、加载／保存峰值警戒4；各域见第5节 | 设计候选，非已通过；瞬时双存活、统一内存GPU和native均计，不能每进程／每城复制额度 |
| CPU计算 | 以每1现实秒窗口的**核毫秒**计量全部产品线程实际CPU时间之和；1个核心运行1ms=1核毫秒，包含调度、打包、IPC、校验、提交和产品观察成本 | 目标设备可持续总额`cpu_core_ms_per_wall_second`待测；峰／滑动窗及响应门一起准入，不能只用线程数或跨机CPU百分比替代 |
| GPU计算 | 同一1现实秒窗口内共享GPU的compute／未来render执行时间与队列等待分开记，内存仍归唯一分配账 | `gpu_busy_ms_per_wall_second`及单批最长占用待测；重叠执行只算时间区间并集，不能把每kernel耗时相加当设备忙时；取不到忙时标not_observed，以受控全路径／队列／未来渲染响应测量限定资格 |
| 存储及I/O | 沿P53单世界20GiB软限、16GiB警告、至少2GiB恢复余量；新增实验另受轮预算和留存规则限制 | save/recover延迟、写入B/游戏日与峰值I/O待测；不以磁盘有容量推断吞吐；不能删旧责任维持速度 |

核毫秒是成本计量，不代表实现了操作系统硬隔离；CPU大核／小核和频率不同，数值必须绑定实机。GPU忙时也不等于专门为游戏保留了设备。CPU核毫秒、GPU毫秒、内存字节不相加成一个无单位分数；联合准入要求各维分别满足。CPU/GPU数值预算或必要响应／误差界尚未冻结时，仅可运行已协调的校准实验，不能发布“支持该承载配置”。

### 0.2 服务目标先于人口上限

| 目标档 | 游戏秒／现实秒 | 1游戏日的目标现实耗时 |
| --- | ---: | --- |
| 观察 | 144 | 600秒 |
| 经营 | 1440 | 60秒 |
| 快速 | 8640 | 10秒 |
| 高速 | 86400 | 1秒 |

沿game-time，暂停不推进。这些是请求目标，不是所有城市都保证达到的倍率。每份支持报告必须同时给出目标／实际速度、逐日最坏耗时、玩家操作p95/p99响应、必要任务最老年龄和截止违约数、模型误差／unknown覆盖、稳态／峰值资源。响应和任务年龄的具体合格数值需在实验前随目标设备与任务类别冻结；未定义不能以任意迟到宣称支持。

实际倍率以完整提交的游戏时间除以完整现实运行时间计算，包括CPU/GPU等待、校验、保存和切换；另列主动暂停和故障，不从对外主指标静默扣除。只有资源／误差合格且必要队列不持续积压，才能称该档可持续。最低可信粒度仍达不到时降低实际倍率并说明原因，不改变游戏工期、人数、债务或已接受承诺。

### 0.3 城市业务负载与支持边界

每份配置将S空间、D开发、A活跃业务、H历史四轴和第2节具体向量绑定同一world。记录数量之外还记**每游戏小时**新需求／交付／到期／源变化数量、热点集中程度、依赖失效扇出、脏区比例和查询解释范围；这些决定同人口城市的计算差别。活动城、关闭城必要履约和全部历史共同消耗预算，不按八城各给满额。

支持结果是一组条件记录：`硬件/存储 → 共同资源额度 → model/policy/error资格 → S/D/A/H负载及变化覆盖 → 可持续推进档/响应范围`。可展示其对应典型人口区间，但不能外推为任何布局、产业、历史或突发强度下的“最高人口”。第2节人口与记录数是代表实验点，具体单城与世界承载上限维持未测。

### 0.4 局部复杂情况：在总额内转移计算投入

Sim既有准入层统一持有CPU／GPU时间额度和内存工作页租约，沿第4节完整边界生效。按系统＋区域＋相容群组分配，划分最低必要计算、可调计算和突发余量三种**用途**，不是另建三个调度器。对CPU和GPU分别满足`必要额度＋可调额度＋突发余量≤该资源窗口总额`；比例留C1/C3实测冻结，未分配突发余量不得假定免费存在。内存不能借未来UI／渲染预留或恢复安全页来伪造突发容量。

以道路堵塞为例：

1. 根据真实边／容量／积压变化，找受影响OD、邻接瓶颈、配送和到岗依赖，按版本失效相关缓存；影响范围未知就扩大失效集合并计成本，不能只看镜头框。
2. 在有资格的策略内缩短该区域交通窗口、增加候选／重算频率，保留实际队列／在途／未满足量；将必要影响传给供给、经营和后续需求，不能只多算交通图而漏实际后果。
3. 额度先取已预留突发余量，再收缩可选预演、重复预测和低紧急度软重算；稳定区域优先缓存／增量／等价合批。旧到期、最低维护、跨城必要履约和安全退出继续保有最低工作额度，延期软结果附数据年龄，不使稳定区域饥饿。
4. 新任务同时预留CPU／GPU预计成本、工作页、转换双活和校验／提交成本；已接受必要边界仍履行原续做票。已派发GPU不假定可抢占，限制单批长度，下一批再让额；不能对正执行任务瞬时撤回其实际内存。
5. 突发超出可转移额度时先限制新的计算／业务风险承诺，降低实际快进；无法可靠保全义务则安全暂停。拥堵／压力消退后按防抖、最短保持和回本条件逐步还额并恢复软重算，不一次补算全城。

局部额度和未用份额是有到期的计算租约，可在同资源总窗内回收重分配；既有权利、资金、在途和法律责任不是可回收的“预算”。实际成本按唯一任务／分配身份结算，避免父子计时重复扣额；预测不足导致窗口超额时如实记录超额并收缩后续可选准入，必要阶段保全后降低实速，不能撤销已经执行的计算或将其藏到下一窗口。额度不足、成本预测偏差、转换开销或持续积压均记录原因，不能用静默删业务满足总额。此分配协议待实现，调度器仍以完整因果覆盖和唯一writer提交为准。

## 2. 规模轴、人口区间和代表城市

### 2.1 空间容量不等于业务负载

沿用16m土地格：小64²、1.024km边长、**1.048576km²**；中128²、2.048km、**4.194304km²**；大256²、4.096km、**16.777216km²**。连续厘米几何、32m环境网格、128m初始交通区和256m重建块仍各司其职，不新增地图尺寸或厘米密铺网格。

每个场景分四轴登记：S空间（土地／地形／合法可开发面／边界）；D开发（楼面／实际住房／设施／路网）；A活跃业务（每游戏时段的需求、到期、源变化、在途、撮合及查询）；H历史（未结责任、已结回执、事件日志、快照、存档增长及恢复读量）。同人口的工业城可能有更高货运、库存及排放；衰退城人口少而空楼、债务和历史仍多。禁止按人口同比裁掉历史。

人口估算单位统一为人／户／m²楼面：

`Adev=Amap×d×b`；`Nhome=Adev×r×FAR×o/s`；`Njob=Jserved/(p×e)`；`Nest≤min(Nhome,Njob,Nutility)`。

其中d为扣除水体／保护／基础空间后的可开发比例，b为实际开发比例，r为住宅用地占已开发用地比例，FAR为住宅容积率，o为有效居住楼面占用率，s为人均有效居住楼面，p为劳动参与人口占比，e为参与者就业率，Jserved为有合格劳动／班次和交通可达性支持的岗位（含有证据的跨城通勤），Nutility为峰时基本服务约束。实际住房户型／家庭规模分布还须满足F/H槽和实际占用，不能用平均户规模代替逐权利校验。就业结构需分行业、工种、班次及进口依赖；空岗数量不能直接当可服务岗位。

## 3. 系统粒度和跨系统依赖

各系统可执行契约见[收敛契约BUDGET-1补充](model-granularity-and-convergence.md#budget-1系统执行卡)。 [BUDGET-3模型策略与依赖兼容契约](model-granularity-and-convergence.md#budget-3模型策略与依赖兼容契约)逐模型明确最低可信、等价优化、允许误差和升降档；预算分配以满足依赖的策略组合为单位，不允许模型独立降档破坏消费者输入或漏必要后果。只用共享执行卡，不为每系统创建独立调度器或无限等级。一个scope是“系统＋地图／区域＋相容主体群”；空间区域不是资金／产权容器。

依赖链：权利／几何与工况变化→接入／路网／公用容量版本失效→供给、交通和到岗候选→同一权威路径接纳真实活动／交付→库存／钱债／维护／排放→环境和人时暴露→需求、经营、迁居候选→原合法动作。旧结果只能作初值，不能把未来工资、预测销量或邻城快照当现货。关键依赖版本变更局部传播；无法确定影响集合就保守扩大失效范围并计成本，不能为了预算漏传播。

不同系统可用不同分组和频率，但必须在消费者需要的逻辑时点满足完整覆盖。上游未完成则阻塞依赖，不发布半城“已完成”时点。现实墙钟不改变法律／交付顺序。

## 4. 运行时控制方案（待实现）

### 4.1 权责和输入输出

Sim内复用既有调度／资源准入层，增一个**策略选择职责**，不是第二个时钟或writer。App只请求目标倍率／解释对象；观测器提交资源信号；worker/GPU只报候选和实际成本。Sim决定并持久记录策略；领域writer验证／Store提交，P4仍等待必要场完成，P5排空后才能下一完整边界。对应源码 `timeline_driver.rs`、`timeline.rs`、`background.rs`、`crates/city-storage/src/lib.rs`，不是声称这些文件已有控制器。

每任务类别按scope采集wall/service CPU、p50/p95/p99与样本数、队列长度／最老任务年龄、每游戏小时事件密度；owned/allocator/native／stack／共享页、工作页租约、缓存命中／失效／固定页；状态变化率、预测残差／误差债、阈值距离／不确定区间；玩家已授权查询／规划需解释的时间窗；目标及实际游戏秒/现实秒。样本不足或缺测标unknown，不能当零负载。等待GPU／IO单列，父区间与子区间不相加。

输出为一份有限策略向量：聚合键／分组大小、更新时间／稳定跨度、候选K、迭代I、缓存租约、执行器、CPU并发、预演／重算额度。共享策略目录只登记有转换和误差资格的条目；控制器不能自由组合出未验证的新模型。K/I沿各域既有限额（P53每发布最多3轮／4候选，交通来源搜索16候选是不同阶段预算，不能互换扩大）。可选查询优先级只影响未承诺软任务，不抢旧到期／安全退出。

### 4.2 有限控制周期与防抖

以下参数是**独立实验起点**，不改冻结M0：每1现实秒最多提出一次策略调整；观测窗30秒、至少100样本才评价尾分位（不足则扩大窗口或用保守上界）；压力进入阈值为对应域授权80%或p95超任务预算持续3窗，恢复需低于60%且p95低于预算80%持续5窗。时间跨度、K/I和并发每次只动一个已验证档位。最短保持30现实秒，代价预算用`Cconvert / max(节省成本率, ε)`估算回本时间，预计不能覆盖则不切；节省未知只做可撤销试验，不宣称收益。

墙钟阈值只决定提案；策略在`phase=None && last_complete`且**新续做票准入前**生效。phase/lane/cursor冻结时不改变分组、排序、numeric切点或已承诺边界的工作量。必要硬事件随原规则截段，不等防抖；阈值重叠／故障可申请提前细算或暂停，但不能越过提交屏障。保持时间同时有下一可生效游戏边界；恢复后重置墙钟采样为unknown，保守保持已提交策略满30现实秒，回放直接执行已记录策略，不用无法重建的历史CPU耗时再次决策。

先缓存／增量／等价合批，后已验证近似；若误差区间接触硬门、预测残差超该策略阈值或出现新故障，局部细化并追溯必要窗口。近似资格不足则不升级为“已发生”，保持unknown／阻塞必要判断。不可用增加步长破坏环境数值稳定性。

### 4.3 切换协议、恢复和超限

1. 在完整边界冻结旧策略及作用scope，测量转换预计输入、双存活状态、索引和工作页；联合预留成功才接受转换。没有额外页则延后／CPU保留／背压，不原地破坏旧状态。
2. 生成纯转换候选，保留身份、权属、数量、时间覆盖、已发生随机occurrence及结果、余数、工程投入、积压／在途、事件游标与跨城应用水位。重建索引费用和冷缓存费用计Cconvert。
3. 验证守恒与转换覆盖；新策略／误差资格、旧新边界、代际及状态一并经原writer/Store提交。重复操作返回原票；提交前失败保留旧根。已发任务依读集与代际拒收或完成旧段，取消attempt不取消义务。
4. 持久最小内容：scope、model/numeric/policy版本、转换序号和边界、必要分组到来源映射、累计误差债／适用窗、余数、事件水位、seed/domain/occurrence或已提交抽样结果、必要任务及CPU检查点。只读成本采样可重建，不持久GPU指针或每帧全历史。

摘要从未保存的房间／设备／微观轨迹为unknown；拆分只能重分配仍可解析的真实来源，不能补造个人财产、年龄或历史峰值。不可逆信息损失须在策略目录列明，并阻止依赖该信息的解释／后续模型自动细化；需要该能力时从保留原件重算，否则unsupported。

预算超限先禁止可选预演／新缓存／新高峰任务，收缩并发与非关键候选，退役未固定的可重建页；必要任务按年龄防饥饿，已接受边界使用原续做预留。若最低可信策略仍算不完，降低**实际倍率**并报告系统、最老任务、必要剩余工作及恢复条件；无法安全存下责任则停在可恢复屏障，拒新风险承诺。不能减少人口、删债、漏供给或跳时。压力恢复按低阈持续与最短保持逐步恢复，避免一次恢复全部缓存造成反弹。

## 5. 资源包络、CPU/GPU及速度

预算继承P53/A55，单位GiB=2³⁰B，MiB=2²⁰B。16GB设备是目标硬件容量名称，实际字节、芯片、OS与其它应用必须重测，不能把所有剩余内存视为应用可用。

| 归属 | 共同候选额度 | 本设计计费规则 |
| --- | ---: | --- |
| 权威模型／索引／历史热页 | 0.60GiB | 旧358.4＋新236=594.4MiB，余20MiB是布局保护；不能直接领取给控制器 |
| 几何／索引 | 0.30GiB | 单详细图、后台稀疏；转换旧新索引同活峰值计入 |
| 求解／唯一预演 | 0.25GiB=256MiB | GPU最多32MiB是域内上界；CPU任务每份32MiB最多2份；预演192时停GPU、只容1任务及余32MiB |
| 运行时／IPC／保存／恢复 | 0.45GiB=460.8MiB | A55进程IPC96＋投影64＋任务8＋高峰128=296，余164.8承担其它已有页；控制观测／切换元数据也从此细分，不另加域 |
| 未来视听／渲染／UI工具 | .85＋.25＋.40GiB | 合计1.50GiB预留，本轮不实现，也不借给headless证明未来完整产品可跑 |

| 系统与其它应用 | 不承诺可占满剩余容量 | 数值余量=实测物理容量−去重应用驻留−系统及其它驻留；同时看pressure/压缩/swap和恢复余量，非16减4就有12GiB授权 |

控制器首阶段候选上限：运行时原任务8MiB内划256KiB，最多256个scope槽×256B=64KiB、成本／阈值摘要128KiB、策略／切换索引64KiB；原任务余7.75MiB须验证仍可容纳，装不下即设计未准入。详细原始性能采样归外部测试工具成本／磁盘，不在每主体无限记录。策略持久字节／WAL归原模型／保存域，新增schema布局仍待测，此包络不覆盖无限任务轨迹。

按allocation_id记录拥有域、reserved/committed/resident、父子引用及共享映射。父Vec载荷和对象owned统计去重；GPU驻留、上传、回读、CPU冻结页若实际各有分配就各计；统一内存不表示零拷贝。RSS同刻和可作上界观察但不冒充去重物理量，footprint与GPU驱动统计不能机械相加。常态、转换、保存、恢复、设备重建分别报告峰值和采样遗漏。

CPU/GPU逐系统试验及完整成本沿[CG39补充](cpu-gpu-compute-contract.md#budget-1联合计算校准)。所有矩阵行先优化CPU，再测GPU全路径；不以shader内核时间判胜。可持续速度定义为完整逻辑时间增量/包括等待、校验、持久提交、切换和摊销保存的现实时间，同时报告逐日p05/p50、最坏窗口和队列趋势。若队列年龄持续增加，即使短窗倍率高也不称可持续。目标档144／1440／8640／86400游戏秒每现实秒沿game-time，尚不承诺任何行达到。
