# 空间、比例与建设精度契约

版本：设计草案 v0.4，2026-10-18。本文给出可用于原型的明确默认值，不代表已实现、已测性能或真实工程设计标准。与已有文档数值冲突时，以本文作为新提出的空间基线；变更需记录版本。

v0.4.28 [单元与共同空间](building-unit-shared-facility-contract.md) 将H套内／公共结构面积和共享功能8子区分开，模板布局与真实几何同样计费；独立单元须有已验证公共接入，不经他人套内形成捷径。楼体拆分／共享空间转独立／产权交割先移交他方权利、容量、费用及维护责任，失败保留原状。

v0.4.27 [单栋与多栋共享](worked-example-building-cooking-energy.md#9-多栋沿街或共享设施的兼容演算) 兼容临街公寓和成组住宅：每楼有真实场地、门及合法接路，组团不自动形成围墙／道路或公款；共享设施另有权利、容量、维护和真实付款来源，分摊不复制实体。

[三档地图](map-sizes.md) 只改变整张地图的横纵格数，最小土地格始终为 16×16 m；以 16 GB 为基础目标，不采用嵌套城市格机制。

## 1. 设计决定与理由

agent 要精准建设，依靠稳定对象、约束和几何工具，而不依靠截图估算像素。市长可以只输入意图，地图选择也是可选的指代辅助。

采用连续世界坐标 + 多分辨率采样，不用单一格子承担所有事情。行政边界决定权限与账本，土地多边形决定建设范围，道路和地块决定可布局几何，建筑模板决定实体尺度。

建议首版明确到建筑级和道路级：能决定某栋建筑放在哪块地、朝向哪条路、占地多少、如何接入水电。室内房间、门窗和单根钢筋不属于玩法精度。

以上数值优先解决中小尺度城市的建筑、道路和管线布局。扩大到数十公里地图前再测内存、寻路和模型数据量；不预先承诺无限地图。

区分四种“精度”：存储分辨率、几何算法误差、源数据准确度、模拟分辨率。厘米坐标只用于可重复布局，不意味着厘米测绘、4 米地形或 32 米污染具有相同准确度。

土地格只缓存用途覆盖比例、对象索引和汇总统计，不能用“格子中心落在区内”代替多边形包含判断。跨边界格可关联多个地块；用途冲突以权威土地多边形和规则判定。

## 3. 坐标框架与地理导入

世界平面采用本地投影米制坐标：x 向东、y 向北、z 向上；原点为本局地图西南角的平面位置，高程零点由导入配置决定。角度从东向逆时针增加：0° 东、90° 北。

经纬度不能直接进入道路距离、面积或退界计算。真实地图记录源坐标系、目标投影、地理锚点、垂直基准、旋转、比例和变换版本；合成高度图明确标为合成／未地理配准。

高度图第 0 行默认表示地图北侧，导入预览允许翻转，但变换结果持久化。若像素样本代表顶点，N 个样本跨度为 (N−1)×间距；若代表面积像元中心，使用对应的像元边界变换。原始 GeoTIFF／DEM 元数据优先，不能混用 N 与 N−1。

对 16 位灰度 PNG，线性海拔映射为 z = z_min + gray / 65535 × (z_max − z_min)；8 位分母为 255。无效值单独掩码，不能把缺测值当低地。水域掩码与海拔分开保存。

厘米量化使用有符号 64 位整数坐标。几何交叉和面积计算需评估并采用足够宽的中间类型或健壮几何实现，避免溢出；几何库与跨平台重复性仍需原型验证。渲染在局部块原点使用浮点，摄像机移动不改变模拟权威坐标。

## 4. 区域表达与自然语言落点

可寻址区域包括：行政区、命名片区、玩家选区、已有地块、道路沿线、对象缓冲区、候选地块和显式多边形。

自然语言例子及落地方式：

| 指令 | 几何解释 |
| --- | --- |
| “河东” | 对指定河流的约定东岸区域求交；有多条河时先绑定对象 |
| “这条路两边各 50 米” | 以指定道路外侧路权边界向外作 50 m 缓冲，分两侧输出 |
| “距电厂至少 500 米” | 按电厂设施用地边界到目标用地边界的最短平面距离 |
| “距市中心 3 公里内” | 明确引用中心点，并说明直线半径；路网距离需显式指定 |
| “沿街建住宅” | 从道路路权外边界生成地块并满足出入口和退界约束 |
| “保留这片树林” | 绑定当前选区或已有树林多边形，创建禁止清除／建设的约束 |

每个引用返回不可变 region_ref，含 world_id、branch_id、geometry_revision、来源、面积、包围盒、带孔多边形、地图预览引用。多边形环不自交，孔洞严格包含，输入越界和退化形状明确报错；首版不静默修复用户几何。

首版将指代解析结果冻结为几何引用，后续边界变化使其过期；不会跟随“东岸”或“树林”偷偷扩大施工范围。动态查询必须显式重新求值。

“离道路 5 米”必须说明从中心线、车行道边界还是路权边界计量。默认使用路权边界，并在计划里展示解释。缓冲区按二维距离，坡面距离和路网旅行时间使用不同字段。

## 5. 可操作土地范围

区分查看、规划、施工三种范围。跨城数据可按产品权限查看，方案可分析更大范围，施工仅能作用于当前授权土地。

有效建设范围 = 世界可编辑范围 ∩ 城市管辖范围 ∩ 项目授权范围 ∩ 允许用途范围 − 保护区 − 无权占用土地 − 他项目已预留冲突区域。项目自己的合法预留不是禁止自己施工的障碍；共享路权与管线走廊按类型兼容规则处理，不粗暴禁止所有几何重叠。

范围同时带动作能力：查询、划地、平整、建路、铺管、放建筑、升级、拆除、修改政策。只读区域不能因相邻施工被偷偷修改。

权限校验针对所有直接改变的几何：路面及路权、施工走廊、建筑用地、出入口、外接管线、地形挖填及边坡，不只看建筑中心点。污染、通勤和价格等间接后果另外评估，不要求被影响邻城都在施工授权内。

跨城市道路和管线必须取得各段对应授权；无授权时只能生成方案及缺失授权清单。首版可由同一市长管理两个独立账本分区，但不能把跨区成本静默记入某一方。

保护区边界不可通过几何容差放宽。边界上的道路段或建筑即使仅侵入 1 cm 也应拒绝或在草案阶段向内退让，不能提交后裁掉一角。

## 6. 建筑、地块与模板

每栋建筑至少有以下边界，不能混为单个点或一个方格：

| 对象 | 含义 |
| --- | --- |
| 设施用地 site | 包含主体、院落、停车、维护和必要退界的完整使用／校验范围，不表示其内部所有面积都由建筑实体独占 |
| 建筑基底 footprint | 与地面相接的实体外轮廓 |
| 实体包络 envelope | 含高度、旋转和突出结构的占用范围 |
| 地下范围 | 地基或地下设施的范围与深度 |
| 接入点 ports | 外部门位／朝向／接近范围，适用步行、车辆、货运或水电等角色，进出与连接分别声明 |
| 外部连接 | 从接入点到道路／管网的连接线和占地走廊 |

模板为带版本的 catalog_asset_ref，声明真实米制尺寸、允许旋转、可否镜像、层数／高度、最小地块、退界、坡度、接入点及服务容量。agent 不得任意缩放住宅来塞进窄地块，也不能通过缩小电厂模型保留原额定能力。

可参数化模板明确参数上下限、离散档位、容量与成本公式。首版支持矩形或简单凸基底；复杂用地用多边形，复杂曲线建筑和室内布局暂缓。

示例游戏模板（用于设计与测试，不是现实建筑规范）：

| 模板 | 建筑基底 | 最小设施用地 | 高度／朝向 | 其他约束 |
| --- | --- | --- | --- | --- |
| 低层住宅 H1 | 12×16 m | 20×28 m | 9 m；0.1°档位 | 前退界 4 m，其余 2 m，需道路与水电 |
| 小型商店 C1 | 18×24 m | 26×34 m | 8 m；0.1°档位 | 独立货运入口，连接可达货运道路 |
| 小型水泵站 U1 | 8×12 m | 16×20 m | 6 m；0.1°档位 | 需要水源资格、电力与维护道路 |

真实可放置与否由模板、地块形状和接入规则共同判定；面积足够不等于能放下。12×16 m 基底经旋转后必须重新求边界，不能沿用未旋转包围盒。

[建筑出入口与交通契约](building-access-and-traffic.md) 要求每个建筑／设施最多8个有实际位置、向外朝向及用途的对外端口；旋转／允许镜像时与建筑几何同步变换。临街或同格有路不能替代门前到正确道路侧／高程／方向的合法连接。每口最多一个物理外接锚点，不同接入用多个口并共享真实瓶颈；单行、转向、过街、墙／绿化、净空与权利逐段检查。改门须合法改造，不自动把门挪到最近道路。

### 6.1 地块内的复合用途与共享空间

一个16 m格子可以索引多个对象；地块也可以同时包含建筑主体、人工绿化、步行通道及其他相容用途。格子不是“一格只能摆一件物体”的占用锁，site不是一整块不可再放附属设施的实体。实际实体、排他用地、相容使用区与施工／安全范围分别判定；建筑仍须满足完整site和接入要求，不能因绿化可共享而缩小合法用地。

模板需声明有界子区域的几何引用、空间层／适用高度或深度、允许用途、排他／共享类型、接入及必要净空。首轮每模板最多8个共享／复合子区域，复杂于此的方案分成明确对象或返回unsupported，不能截断限制后接受。只声明建筑退界不等于此处可植树，消防通道、设备维护和地基保护范围仍逐项检查。

| 情况 | 首轮处理 |
| --- | --- |
| 建筑site中的庭院／退界绿化 | 模板及土地权利允许、避开主体／入口／消防净空时可放置人工绿化 |
| 多栋建筑共用同一庭院、步行连接或绿地 | 引用同一真实空间／绿化对象，验证各方使用依据与接入，不为每楼复制一块面积 |
| 植物树冠与允许的步行区上方重合 | 只有模板明确允许且净高、树干／根系、通行／安全约束满足时兼容，不按二维投影一概拒绝 |
| 花坛占据必需消防通道、树干撞入建筑、树根进入不相容基础范围 | 拒绝；共享不能免除实体及安全冲突 |
| 屋顶花园、架空建筑下的复杂用途、立体开发权 | 首轮未具备承重／结构与相应空间校验时unsupported；统一模型不等于已支持施工 |

共享许可只适用于明确对象、区域、用途、时段与规则版本，不能一个shared标记允许任意重叠。需要不同所有者权利时，引用已登记、受支持的许可／协议及期限；同一业主场地内的附属绿化可按合法模板／管理规则授权。复杂共有产权／分层地权仍不支持，不因“共享空间”自动改地籍、出租或给予公众进入权。

重叠site可因合法公共空间引用而相容；建筑主体包络仍不可非法重叠。先按对象几何粗筛，再按用途／层／高度与兼容规则精查；没有精细支持则返回needs_detailed_validation／unsupported，不猜测可穿插。房屋、道路、管线各用同一空间占用和事务检查，不另建一套忽略既有预留的绿化放置器。

共享绿地面积按实体几何并集／规定口径统计一次，公共通道通行能力和维护服务也是一份。每栋楼可显示“可使用同一200 m²庭院”，但两栋引用不能将全城绿化算成400 m²；用于法定绿化率／退界的计入份额按显式规则，不能每栋都无条件抵扣全额。景观覆盖与实际可进入休憩分别计算，私家庭院不自动作为公共公园容量。

共享空间的维护方、付费主体／分摊、开放时间、容量、保护及关闭条件必须明确。分摊只是同一实际费用的支付来源，不另增维护交付；已包含在物业／养护价格中的成本不能再收一次。共享空间建设、修剪或停用影响多个入口／使用者时更新全部相关依赖，替代通道和阶段净空需在施工前评估。拆除某栋楼不自动清除仍服务其他建筑的共享绿地；终止许可和责任移交按现有程序，不能删引用便免除义务。

首轮采用一个明确所有者／管理责任方和多个使用方，不新增复杂共同所有权。每个共享空间最多32个登记使用建筑引用（含关闭待退出／移交占位），全世界最多8192条紧凑使用关系×16 B＝0.125 MiB，从既有4 MiB索引／路径域中实体反查的0.5 MiB划出，反查热页相应减至0.375 MiB，区域载荷总额不增加。关系记录引用空间、使用建筑、不可变权利／规则及类型状态，完整条款沿既有预算分页；16 B是待验证紧凑布局，不能省略必要身份／代际。32引用只限制需要登记的建筑使用权／责任依赖，不是公园只能接待32人或只有32栋楼能受益；公众访问按开放与实际容量、景观受益按作用范围处理，不为每个受益建筑额外创建使用权边。数量与实际字节共同准入，不把列表藏进无限正文热页；满额拒绝新共享承诺，原有使用关系、期限及义务保留。

多个使用方具有访问权不代表各自有一份完整访客／通行容量；实际访问与维护占用相容性按同一对象的时段容量调度。出售、分割／合并、拆楼、改围墙、改变开放或许可时，检查全部依赖方的出入口、消防条件和有效条款。空间划分及关系变更须守恒移交实际面积、植被作用、权利与维护责任，不借换ID、删除父楼或重新划区清空既有状态。

## 7. 分区开发与精确放置

住宅／商业／工业的 zoning 是允许用途与密度，不等于立刻建成所有建筑。私营建筑随需求和模型规则开发，必须同样通过几何和网络校验。

agent 有两类建设：公共设施精确放置；分区开发设定地块、密度、退界和可选模板。若市长授权公共住宅或直接建设项目，才可下达明确住宅建设计划，并计入对应成本与产权。不得通过直接生成私人楼房绕过经济模型。

沿路地块由几何求解器生成，输出完整地块、道路临街关系、建筑候选布局及失败原因。首版支持弯路旁的规则建筑近似排列，无法开发的窄角和残地保留空地。

默认不自动合并已有地块、拆迁建筑或清除树林。合并、分割和清除是明确的草案动作，分别受授权校验。

## 8. 道路及管线精度

道路输入可选“连接两个既有节点”“沿指定走廊布线”“按控制点建设”。agent 优先给起终点和约束，由路径／曲线求解器产出候选，不必手写大量控制点。

中心线曲线、纵断面、路面宽度、路权宽度、施工走廊、最小半径、最大坡度与连接方式分别保存。道路模板给出合法参数范围；曲率、拓宽、交叉口转弯包络及边坡都要纳入占地。

例：一条车行道宽 7 m、路权宽 12 m 的道路，边界检查至少使用中心线两侧各 6 m 的走廊及交叉口扩展，不是仅检查中心线。数值是游戏模板，不是现实工程标准。

工具可以在 0.50 m 内建议吸附已有端点，但必须返回原位置、最终位置、位移和选择依据。吸附后重新检查长度、坡度、占地、保护区和权限。多个候选无唯一解时拒绝自动选择。

权威离散几何在草案中生成并冻结，模拟长度与占地依据这份几何；视觉 LOD 可以更粗，但不得造成拓扑变化或误导建设预览。保守走廊包含弦误差与量化余量。

道路交叉先检查高程和显式 junction_mode。首版只允许合法平面交叉；不同高程交叉若需要桥隧则报告不支持，不自动连接。水、电分别连接到对应网络节点，线条视觉相交不代表连通。

首版地下管线可采用沿路走廊及离散深度层，不承诺连续三维地下碰撞；该简化必须在工具能力中声明。建筑首版采用平面包络加高度区间做保守碰撞，不支持高架跨楼、悬挑共址或立体地块产权。

[垂直空间与空域契约](vertical-space-and-airspace.md) 采用U1／U2／U3地下、G地面、A1／A2空域六个用途层，具体分类参数、深度／AGL及支持范围以该契约为准。层标签不替代world-z、实体包络、地形版本、施工／地面出入口和权利校验；不同层也可能冲突。地下三层不表示已支持地铁，空域分层不表示已支持航空运营。地形修改不自动移动设施，也不能静默改变冻结法规的垂直基准。

## 9. 地形操作与真实数据边界

平整以施工多边形、目标高程／坡面、最大挖填、边坡扩展、最大土方预算定义；预演输出切填体积和全部改动区域。

建筑用地要检查基底覆盖范围的地形坡度、最大高差与地基规则，不能只采样中心点。首版可用固定基础平台简化，不支持的悬挑或地基自动报错。

4 m 采样不能可靠描述原始数据里缺失的窄沟或挡墙。把 30 m 来源重采样到 4 m 也不会增加真实细节。工具结果显示 source_resolution_m、source_accuracy（未知可明确 null）、processing_version。

“不要影响下游水质”是高层目标。首版只有空气污染场和简化水域时，不能声称已验证水文影响；必须返回 unsupported_constraint 并提出可验证替代约束，例如水域保护带和禁止特定排放。硬约束不能静默降级成软偏好。

## 10. 几何判定、吸附和误差

提案允许自由输入坐标，先在声明的吸附规则下求解，再量化并运行完整验证。每一步变换均返回坐标变化，最终提交以 canonical_geometry_hash 指向的几何为准。

几何量化误差每轴不超过 0.005 m；任何计算误差不能作为突破硬边界的许可。采用保守外包络验证实体占用、保守内缩验证可用土地，算法无法可靠判定时返回 numerically_ambiguous。

边界接触规则按类型声明：地块允许共享边；建筑实体包络不得非法重叠，且需满足净距；道路通过合法交叉口共享用地；网络仅通过连接节点建立连通。距离比较在量化后的最终几何上执行。

几何细分达到误差预算需要的点数超限时应拒绝并提示分段，不静默降低精度。厘米级存储、5 cm 曲线近似和 10 cm 默认余量分别使用，不能合并成一个“误差容忍度”。

## 11. 对象版本与空间冲突

对象引用至少含 id、revision、world_id、branch_id。拆除后 ID 不复用；新建筑即使在原址也获得新 ID。region_ref、模板和授权同样版本化。

首版提交可采用保守的全局建设版本校验：地形、道路、建筑、土地、管网和保护边界变化使 construction_revision 增加；单纯模拟时间推进不使几何计划每帧过期。私人自动开发与模型触发的实际地形／网络变化同样增加建设版本，不仅 agent 建设才算修改。

财政、库存、占用和授权在提交时按当前状态重新检查。评估报告带 simulation_tick，过旧的交通／人口预测按有效期重新评估。后续才引入对象读写集与空间局部版本，减少无关建设冲突。

## 12. 验收与待验证项

| 场景 | 必须满足 |
| --- | --- |
| 原比例 | 20 m 地块在不同缩放／显示器下仍是 20 m，面积不变 |
| 跨格建筑 | 12×16 m 建筑可跨 16 m 索引格合法放置，不被格子截断 |
| 旋转建筑 | 朝向变化重新验证全部包络与接入点 |
| 含孔区域 | 保护林地形成孔洞，规划不得填入 |
| 道路贴边 | 中心线在区内而路权越界时拒绝 |
| 边坡越界 | 主体合法但挖填边坡越过授权时拒绝 |
| 极小侵入 | 量化后侵入保护区 1 cm 仍拒绝 |
| 曲线误差 | 测得最大弦误差 ≤ 0.05 m，占地验证采用保守包络 |
| 吸附歧义 | 多个可连接端点不能静默连接任意一个 |
| 跨区连接 | 各段授权与成本归属正确，缺授权只能预览 |
| 地形来源 | 源分辨率与重采样间距分别显示 |
| 未实现目标 | 下游水质模型缺失时不声称环保目标已通过 |

待原型决定：几何库及稳健性、细分策略、每计划顶点数、地块生成质量、地形块预算和大世界渲染漂移。上述建议参数可调整，但必须保持单位、边界与精度的语义一致。

## 13. 精度与更新成本

厘米量化用于几何点，不生成厘米栅格。土地索引、地形、环境各自分辨率和更新频率独立；交通拓扑节点不随曲线几何采样点无限增加。规模与本机预算见 [性能评估](performance-budget.md)，时钟与跨系统周期见 [运行闭环](runtime-loop.md)。

## 对象空间与自然生长边界

[统一对象模型](city-object-model.md) 要求占地、权利、使用／施工、生长掩膜和影响范围分别声明。道路占地不等于噪声范围，树冠可视范围不等于可取得土地；首版植被只在预登记斑块及允许范围内改变覆盖／成熟度，不自动跨地块新建实体。提升独立登记树需验证几何和来源贡献、原子移交原斑块表示；权属／保护不同的斑块不能平均合并。自然衰退不代表场地已清理，永久用途变化仍走合法工程及精细校验。

## v0.4.18实体和包络的一致性

[运行一致性](spatial-runtime-contract.md) 要求硬质共享区归真实宿主／设施，穿行边计路网；space_ref不创建免费对象。最大受支持植物增长包络预先验证，后续建筑／管线和入口避让；摘要成长不扩大包络，死树残留未清不能释放通路。分割／合并／拆宿主先准入目标对象／关系／容量，再原子移交面积、植被贡献、占用和责任；失败保持原状。分类层不豁免整个保护包络，冻结法律／在途仍引用的地形／几何版本沿原磁盘配额固定保留。
