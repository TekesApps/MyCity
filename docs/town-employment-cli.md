# 就业变动、工资与购买力的限定CLI

运行：`cargo run --release --locked --offline -p mycity-core --example town_employment -- --switch-day=10`。有效日期1–27；已实际验证1、10、27，0和28被拒。每次运行6组、各28游戏日，复用真实Engine、Timeline、TownSettle；JSON报告实际工资、欠额、工时、生产、成交和库存。

默认第10日换岗的三组对照：

- 欠薪压力：原企业开局现金1000；换岗时旧欠薪3100，随后旧雇主用销售收入补发，最终为0；留任最终欠薪11500。结束工作停止新计薪，不删除旧债，也不禁止旧雇主补发。新雇主只支付自己的工资。
- 生产：较充足期初资金下，28日累计留任产量200、销量112；换岗产量100、销量100。先终止旧合同，再在同一边界建立新合同；原工厂以后没有新增劳动，不靠固定日销量产生效果。第27日换岗时累计结果可相同，不能强迫所有日期都有同幅度差异。
- 购买力：双方都换岗，共用开局、旧工资、商品/路线和供应设置，只改变新时薪100/20分。实际购买87/43件，另一个逐日预算oracle按每件总费用102分核对一致。新雇主拥有来源明确的1000件零售库存；第1日边界场景实际卖出的商品收入也纳入现金对账。

每组核对非重叠工时、应计/已付工资、旧欠额补发、全城现金和“期初产品＋生产－销售＝期末产品”。完整同开局由Scenario继承与共用builder共同证明；汇总字段断言本身不是完整字节一致证明。

固定参考需求4件/日、28日112件。参考未满足量按112减实际销量，不能用 `unmet_market_demand=0` 推断自然需要全部满足。默认生产换岗组参考缺口12，收入高低组25/69；不同口径分别保留。

任职决定是可信CLI输入，没有内生求职、技能匹配、全局雇佣权限或劳动法律办理。目标雇主的工资由期初资本和可能的零售收入支持，没有定义其新生产/服务配方。全部开局现金/库存均有来源，但未建立持续自融资或校准经济平衡。交通和公用仍是profile替身；本例不是持久化恢复或真实道路供给联调。

六组顺序执行，没有新增持久模型字段或逐人agent。实际小CLI观察0.04秒、RSS9977856B、footprint8667472B，不是干净性能或真实16GB验收；M0原未通过门不变。固定来源、失败历史、独立核对和保留位置见[证据页](evidence/core-employment-131/STATUS.md)。
