# 市政事项流程：多方参与、分级批准与分期实施

设计补充，2026-10-18。玩家明确：市长提出拆房、盖楼或大型车站目标，不等于可直接改动城市。市长决定方向，City Team组织可执行方案，产权人／居民、议会、财政、运营方及依法介入的司法机构按各自职责参与，阶段条件满足后才能继续。

本文件把现有制度、工具与工程规则串起来，不代替各自状态：Goal是施政目标，Plan是具体方案，Project是已接受的物理工程，Monitor是结果观察；新增事项档案只是关联它们的程序记录，不把四者合并为一个“已完成”。

## 1. 有流程不等于所有动作走同一程序

| 事项 | 程序强度与处理 |
| --- | --- |
| 查询／查看地图 | 只读与权限检查，不走建设审批、不改变城市 |
| 日常维护／重复采购 | 在已有效的合同、授权、拨款和模板范围内按工单执行；异常扩围重新分级 |
| 一般建设／改造 | 明确选址、产权、影响、预算、必要公示、实施与验收；不默认每次再立一部法 |
| 重大项目／征收搬迁／关键网络改造 | 完整比选、影响与产权安置方案、法定公示／听证、所需议会拨款、资金安排与分期承诺 |
| 法案／市民申诉／司法案件 | 走既有立法或司法程序，关联工程但不替它开工 |
| 家庭消费／租住／买房／企业交易 | 走居民或市场专用的身份、资金、权利与履约流程，不要求市长逐笔批准或召开听证 |

公共或私人建设都不能越过空间、产权、工程、环境与法律条件；私人开发的支出来自真实开发主体，不自动计入市政预算。私人建设可使用依法授权的标准化程序，但不能因此即时造楼或自动安置居民。

首轮重大触发条件包括受占用住宅搬迁、征收、保护范围变化、关键主干路／管网或区域枢纽、跨城依赖及显著服务中断。公共支出另建议达到本城当年有效建设拨款基数B的10%即进入重大审查；B绑定预算版本，B为0且有新增公共支出时报告缺拨款。

私人自费项目不因市政B为0而被错误拒绝，按空间／影响门槛分类，初轮建议新增建筑总面积达到10000 m²即进入重大审查；搬迁、关键网络、环境与服务影响仍可在更小规模触发。私人项目涉及补贴／公共配套时，该公共部分再查市政拨款。阈值是待平衡宪章／条例参数，估计范围跨过门槛或影响未知时进入needs_review，不因小地图或改名自动降级。

同一事项按共同目标、地理／资产、功能依赖、资金批复和时间窗口关联，汇总投资与累积影响。明确的共同功能关系不因跨年自动解除，也不能通过更换goal_id或拆成多个小工单规避门槛。相邻但独立的维护不强行合并，关联证据不足时标记needs_review，不能由模型自行宣布互不相关。

## 2. 一条完整流程

| 阶段 | 输出与继续条件 |
| --- | --- |
| 意向与受理 | 明确市长目标、范围、约束与能力；登记事项不表示已批准建设 |
| 调查与需求论证 | 现状、需求来源、产权、网络、服务和基本财政事实，未知与不支持能力明确标注 |
| 方案比选 | 至少说明不做／维护既有设施、缩小规模、分期或新建等可行选项及代价；不能把空白替代方案称为已验证 |
| 影响与权利安排 | 交通、水电、环境、行业／就业、住房／安置、运营与维护后果，明确受影响者和处理责任 |
| 公示／听证／法定决定 | 固定方案版本、意见与答复、产权同意／合法替代依据，以及需要的议会法案／拨款 |
| 融资与实施准备 | 总投资授权、合法承诺额度、当前资金、阶段依赖、采购／承包与安全收尾条件分别落实 |
| 冻结并接受工程 | 几何、阶段、费用、条件与有效版本通过工具最终校验，才创建已接受Project并按范围预留 |
| 分阶段施工／拆除 | 实际工时与投入推进，各阶段在重新检查条件后开工，受阻保留现场和义务 |
| 验收／投运 | 实物合格、当前运营条件与供给／人员分别验证；不以签字代替能力 |
| 运行观察／结案 | 真实通勤、服务、财务、环境与安置结果对照目标；未结款／整改／维护义务保留 |

前几步可以形成不同深度的草案，尚无能力或无可行资金路径时提前停止昂贵调查。调查本身使用实际人员工时、模型额度及必要外部服务费用，须有小额筹备授权／合法预算；不是免费、无限预演。正式建设未批准，不代表可以先占地、迁人、拆房或签下全部施工合同。

普通事项可合并依法允许的调查与评估步骤；重大事项默认至少14游戏日意见期并有听证／回应记录。若还需立法，沿既有法案公示、会议及生效程序，阶段可依法并行但不能互相冒充完成。工作人员分析耗时和最低程序日历分别满足，倍速只改变现实等待。

## 3. 谁参与、谁决定

- 市长提出政策目标与玩家授权，承担取舍；不代替议会投票、产权同意或法院裁决。
- City Team调查、协调和提出方案，财政、交通、规划、市政、商业和环境意见有来源与版本；兼任与专业缺口沿团队编制规则处理。
- 财政检查拨款、承诺、现金流和长期负担；运营／公共服务方核实未来运营条件，不把预期收入当已到账款。
- 产权人、住户、企业及受影响群体提供事实、意见、同意或异议。涉及产权时取得同意或现行制度明确允许的合法处置依据，并落实通知、安置和补偿；公众多数赞成也不抹除这些权利。
- 议会对需要的法案、重大拨款／政策作出决定；专业评估和公众意见是证据，不是额外议会票。
- 工程检查与审计核验已批准范围及实际结果；司法在有管辖依据的争议、申诉或依法审查条件下介入，不要求每栋楼先打官司。

多方参与不要求所有人一致同意，也不赋予每条反对意见无限否决权。意见须留痕、分类回应并说明取舍；投诉是否暂停、暂停哪一步由有效程序／停止令决定，不能一投诉全城停工，也不能因市长着急就全部忽略。

## 4. 钱不够时怎样继续

总投资上限、议会可承诺额度、已支出／未付义务、当前现金与预留、后续运营和安全收尾分别显示。研究通过、议会支持或有人愿意承包，都不能替代实际资金。

团队可以提出缩减规模、调整路线／地点、独立可用的分期、延期积累资金，或在双方同意且能力可用时购买区域服务。税费、公共补贴或采购政策变更走法律／预算程序；首版不自动贷款、发行债券或把未来税收作为现款。

分期只能把现金落实到可安全执行的阶段，不重复获取整项预算。阶段开工前覆盖本阶段确定承诺、必要投入及安全停工／收尾；没有后续资金承诺时停在可安全维持的边界，并明确未完成的功能。不能先拆居民楼或挖断主干道，才用不可逆事实强迫追加预算。

组合项目的整体目标与阶段独立效益都应说明：仅完成站前道路不表示车站开通，仅盖站房不表示铁路可运营。审批取消、落选或资金不足不自动退款，已支付勘测、已购材料、工程实物和依法形成义务按原规则保留／清算。

## 5. 版本变更与恢复

公示、产权安排、拨款、玩家授权和工程评估均引用确定的方案版本。改变拆迁对象、范围、主要交通／环境影响、功能或总投资等实质内容时，重新执行受影响的程序；小改动仅在预置容差与同一授权内处理，不能由agent自行定义“不重要”。

通过的法案／拨款并不保证任意未来方案可执行。当前法律、产权、现金、资源、停止令与世界版本仍在接受工程、阶段开工及投运时重新检查。旧会已完成的有效表决保留，但不为后来改造的方案背书。

进度报告分别标记：已提出、待论证、待意见／批复、已获制度许可、待资金、工程已接受、施工中／受阻、实物完成、已投运和目标达成。监督发现问题可触发整改或新提案，既有安全／合同／居民义务不因事项被标“取消”消失。

## 6. 大型车站的例子

“建一座大车站”首先是待调查目标。团队要说明现有出行／货运需求、线路与铁路系统是否支持、站场与接入、土地和居民影响、工期与全寿命费用；若投资超过资金能力，给出可比较的缩小、分期或暂缓方案。

**当前铁路仍是unsupported扩展**，本例只说明流程；不能只获得议会支持就生成可运行站房／铁轨或签施工承诺。可以在明确筹备授权和能力边界内形成概念建议，或评估当前已支持的道路通达性改善；不得假装已完成铁路容量／时刻表／站场验收。

未来铁路能力具备后，正式方案才进入相应听证、产权、拨款、资源、分期建设与联合验收。铁路、市政、商业、财政、居民、议会和必要司法各有作用，而非每位参与者都被调用一次模型后自动盖章通过。

## 7. 有界档案与工具

现有全世界128×16 KiB＝2 MiB工程热描述配额，明确改为**筹备、实施、停工及收尾共享的128个活跃事项／工程档案槽**。筹备接受前就检查槽位，阶段转换复用同一档案，不是128个筹备再加128个工程；已接受工程、半成品和未结义务不能被新意向挤掉。

事项档案可在筹备阶段只引用Goal、候选Plan及程序证据，**不因此创建已接受Project、不取得土地／施工资金**。档案至多关联一个当前冻结建设包／Project；组合项目中可独立批准／施工／验收的工程分别占槽，用共同program_ref汇总投资和影响，不能用父档案藏无限子工程。每档案仍最多16物理阶段／有界引用，正文、听证材料及历史按原日志和10 GiB磁盘预算分页，关系索引计原4 MiB配额。

满额时明确暂缓新增筹备，未正式接受的意向可作为玩家可见的未受理请求，但不建立无限RAM计划／材料队列。单活动模型请求、32项人工任务、单完整预演、44 MiB区域及原模拟域保持；128档案覆盖范围变广会减少同时施工／筹备空间，需要验收，不新增一份2 MiB。

未完成整改／安置、安全收尾及未落实移交继续占活跃槽。验收和责任移交完成后，日常维护、运营合同及Monitor由对应既有状态承担；只剩已确定金钱尾款时，先原子移交到有界未清偿义务表并保存工程／付款引用，才可归档释放槽。未移交债务或仍有现场责任不得释放。Goal尚未达标不必锁住已合法交付工程档案，Goal／Monitor继续观察，不能借归档免债或切断证据，见 [闭环契约](closed-loop-contract.md)。

拟议工具city.matter_register在有效授权内登记范围、筹备预算和关联，返回matter_id及受理／待配额状态；city.matter_status按冻结快照分页返回当前门、参与方、方案／制度版本、缺失条件、费用和各对象回执。登记不是施工接口；工程仍使用evaluate_plan／apply_plan／project_control，不提供“跳过审批”按钮。

## 8. 验收

- 小维护在合法工单内完成，不被强迫走大型听证；扩围后重新分级。
- 私人自费项目不以市政拨款为资金前提，公共补贴部分另查；面积／影响门槛不可省略。
- occupied住宅拆除缺安置／产权依据被拒，不能以市长授权或公众多数替代。
- 大项目缺钱保持待资金，缩减／分期不超总授权，不先不可逆施工。
- 关联项目拆单仍汇总成本和影响，无关维护不会随意合并。
- 实质变更使相应批复／评估失效，旧票和旧授权不为新方案背书。
- 投诉与停止令有明确范围，安全保全继续，司法不强制参与每一小工程。
- 128共享档案在筹备前准入、接受工程时不重复分配，未结义务不因结案丢失。
- 正常运营设施在完成责任移交后释放工程槽；只剩金钱尾款须先原子移交债权，未移交债务／现场整改仍占槽，Goal／Monitor不随归档丢失。
- 铁路未支持时大车站不能进入可施工承诺；模型／地图／快进／重开不跳程序。
- 工程验收、实际投运、施政目标达成分别有证据，签字和模型汇报不能替代城市结果。

## 两楼共享设施的拆除前置案例

[连续窗口演算](worked-example-two-buildings-shared-facilities.md) 明确“已有拆除意向→被拒→获得处分依据／真实现金→安置完成→旁路验收及合法切换→旧在途退出→拆除／有限清运→终止旧责任与观察”的条件链。出售一套后原业主不得单独处分整楼；回购空房不代替仍住其他单元的租客程序。外部使用方不接受替代通路／新费用则方案受阻，保留旧权利，不用多数所有权或预算批准覆盖他方权利。City Team观察分项回执、未满足条件与已发生事实，不把一个成功命令当全链路完成。

## 9. 事项工作台与程序性推进 W50

设计修订v0.4.50。市长通过Agent提出意图、约束和授权，**不直接控制居民、业主、企业、议员、法院或承包方的决定**。Agent工具提交的是受程序门约束的动作；地图点选、玩家批准、预算充裕和快进均不能越过该门。本节补足玩家的待办／进度体验，不增加另一套工程或审批权威。

### 9.1 每项需求都有去向

命令受理立即返回request_ref与回执：已关联事项／既有目标、待澄清、待配额、只读已答复、明确不支持或被拒及理由。重复重试使用同一operation查询原回执，不重复登记、采购或发赔偿。请求可以关联多个真实事项，但每个独立建设包仍占原档案槽；纯查询只留对话／查询回执，不人为生成工程。

统一工作台从原Goal／matter／Plan／Project／合同／案件／Monitor投影，不复制其权威状态。玩家从聊天、选中建筑／路段／区域、城市摘要均可打开同一事项：

| 可见信息 | 显示口径 |
| --- | --- |
| 目标与责任 | 原指令／硬限制、目标对象、城市、事项ID、当前方案版本、承办成员及实际参与主体 |
| 当前门与下一步 | 调查、待协商、公示、待表决、待资金、待资源、施工、受阻、验收、观察；列具体缺项、谁处理、玩家现在能做什么 |
| 权益与协商 | 受影响地块／权利、业主／实际住户／商户／网络运营方分别列明；送达、意见、答复、协议／裁决与支付／安置回执可追溯 |
| 时间与工作量 | 已用游戏日、法定最早日期、实际工时／材料、剩余有界估计及前提；未知或等自主决定时显示“暂无可承诺日期” |
| 钱和现场 | 已花、已承诺、已保护、缺口、补偿／安置、后续维护；已动工范围／封闭／绕行与当前安全责任 |
| 结果与历史 | 原方案、修改原因、批准／拒绝、施工／投运回执、观察窗与实际指标；结案和目标达成分开 |

列表默认64／最多128条分页，支持“需要我决定／团队办理／外部等待／施工／受阻／已完成”和城市／对象过滤。提醒定位到具体事项／门而非只跳聊天；玩家可直接说“现在有哪些卡在协商上”“为什么这条路还没开工”。不将所有参与方同意显示成玩家自己勾选的复选框。

未获活跃档案的请求可以保留为**未受理意向**，不占土地、不保留施工价、不保证处理时间；不能显示“已开工排队”。其轻量索引最多128条、每条最多1 KiB，计原UI／工具0.35 GiB内128 KiB；详细原话沿原日志／10 GiB磁盘预算。额度满则拒绝新增登记并返回可见原因，允许玩家归档／合并旧意向后重试，不静默丢弃或无限增长。受理转移时原子关联到原128活跃档案，共享原2 MiB／关系4 MiB预算；32分析任务与模型请求配额另行校验，档案存在不代表有无限工作人员。仅将未受理意向归档不会解除任何已形成合同／现场／司法责任。

### 9.2 道路加宽：先协调权利，再施工

[E49](agent-command-targeting-and-editing.md)的加宽几何／成本只是候选工程，最少4日等数值是工程下限，**不是收到命令到通车的总时间承诺**。工作台必须呈现以下依赖：

1. 调查完整永久／临时占地及道路两侧实际影响，包含入口、管线、通勤、商户装卸、施工噪声与安置；影响边界按来源计算，不只按“左右一格”。
2. 按真实权利识别参与者：产权人讨论土地／建筑处分，租户讨论居住／搬迁权及可赔损失，经营者讨论租约／经营受阻，管网与道路运营方讨论迁改／接续。一个业主签字不能代表租户放弃自己的权利。
3. 形成路线／缩窄／分期／不建设等比选和协商包，列补偿对象、估值来源／时点／不确定性、真实损失及避免双赔的source_key、资金和安置条件；参考地价不自动成为成交价或已付现金。未能形成有依据的报价就继续调查或更换方案，不让LLM编造产权同意。
4. 沿第2—3节执行适用公示／听证／议会与产权程序。协商记录可以是同条件权利群体的有界汇总，但独立权利、异议和付款对象仍保留引用；不要求每位市民一轮LLM对话，不以满意度总分替代同意。
5. 自愿协议由有权主体依现有利益／权利／合同规则接受或拒绝；玩家只能改变自己有权提出的条件。截止日未回复不等于同意。谈不拢可改线／缩范围／延期；只有已有明确征收法源、管辖、必要程序与救济时才提出法定处置，不能仅以“公共利益”开启首版未支持的强制征收。
6. 必要处分权、安置和付款／合法受限资金安排、拨款、施工资源／绕行及有效许可全部落实，才接受对应工程／允许破坏性阶段。议会同意不代付补偿，口头承诺不代安置完成；诉讼或异议是否阻哪一阶段读取有效停止令。
7. 现场按实际投入推进，验收及投运后进入约定观察窗；费用尾款、修复、投诉和安全移交仍分别跟踪。取消或修改方案只停止尚未合法提交部分，已生效协议、欠款及已搬迁住户责任继续处理。

以上是同一流程规则，桥梁等延期类型也可登记意向／说明支持边界，不能因流程完整就宣称有桥梁执行能力。

### 9.3 快进、暂停和完成

“加速办理”默认解释为提高游戏日历速度或跳下一安全节点；若玩家要求缩工期，团队另算真实班组／排班／成本／资源与允许的工程下限，不默认花钱即可压缩法定公示、养护或投票周期。

公示14游戏日仍要经过14游戏日；施工、工资、居民生活、贸易、污染和协商期限同步推进。待玩家明确取舍／新增授权、关键硬失效及已定义安全节点截断跳转，通知可定位处理；普通外部等待不是全世界暂停，其他事项及城市继续运行。游戏全局暂停停止权威日历和物理进度，仍可查询、沟通和准备草案；法律生效／施工等世界提交仍走IL43的一致提交边界，不能在暂停时偷走程序日历。

全局暂停时的沟通／草案仅包括玩家输入、只读查询和不推进模拟工时的分析；居民／业主的正式答复、团队实际调查工时、送达与协议生效，仍按原规则在相应游戏时间及一致提交阶段处理。LLM回复不等于参与方已同意，反复暂停不能免费完成模拟调查。

“暂停这个事项”只请求暂停可控的团队后续提交／工程阶段；不能冻结议会、法院、居民或合同到期，也不能将不安全现场直接停掉。报告哪些已暂停、哪些保全／外部程序仍继续及费用。关闭聊天或模型离线不终止已受理程序，既定规则、人员调度与工程不依赖LLM逐日唤醒；新自然语言决策待连接恢复或结构化授权入口。

工作台不把整个治理流程伪装成一个线性百分比。程序门用状态／日期，协商用已核对权利与未解决条件，工程可显示各阶段已交付净工作量／所需量；若有整体估计须标“预测”及依据。市长可见“程序许可完成，工程0%，尚未开工”，不能把听证结束写成道路完成80%。

### 9.4 验收补充

- 仅文本提出加宽后，工作台能串起精确路段、各权利人、协商／补偿、预算与工程，地图选择不改变任何同意／付款。
- 业主同意但租户安置未完、已批准但补偿未资金化、协商无回复／拒绝时，阻住相应破坏性阶段并给出合法选项；快进不清除阻断。
- 14日公示与4日最短施工分项可见，等待期其他城市系统继续算；无依据时不显示确定通车日。
- 同一需求重试不多开档案／多赔；改方案保留旧责任并重跑受影响的门；工作台保存／恢复与权威状态一致。
- 拒绝／未受理／不支持的请求仍有可查询回执；待办满额显式拒绝，不能越过128档案／32任务／原16G预算。

本批单轮advisor检查仅要求澄清上述全局暂停边界，已补入；权限、128共享档案／32任务、未受理索引及费用未发现新增阻断。此为文档审查，工作台／协商／16GB运行仍待实现验收。
