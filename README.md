# MyCity

文档发布版本：`v0.4.27`。每次文档提交递增版本并推送对应附注 tag，规则见 [AGENTS.md](AGENTS.md)。

基于 Rust + wgpu 的城市与区域模拟游戏，以《模拟城市 4》的区域建设体验为起点，围绕交通后果、人口互动和自动区域市场建立自己的模拟体系。

状态：准备设计 v0.4（2026-10-18）；当前仅有设计文档，尚未创建 Rust 工程或验证运行性能。

仓库：[TekesApps/MyCity](https://github.com/TekesApps/MyCity)，公开发布，采用 [MIT License](LICENSE)。

## 项目目标

玩家作为市长，通过自然语言向 City Team 下达施政目标，由市政团队调查、规划、协调并在授权范围内落实土地、交通、市政设施和经济政策。玩家可以仅通过输入命令完成核心玩法，地图负责展示方案、建设进度和实际后果。人口、岗位、商品、污染与公共服务在同一个区域内发生联系，并跨城市边界产生后果。

优先做出能够解释“为什么城市变成这样”的模拟闭环，再扩充规模、内容和视觉表现。

## 核心玩法：市长 + City Team

市长提出目标与约束 → City Team 调查和部门协调 → 形成可预览的计划 → 授权范围内执行 → 模拟产生后果 → 团队汇报与调整。

例如：“在河东建设新城区，先解决通勤，住宅分期开发，不要影响下游水质。”团队负责将目标落实成选址、路网、管线、分区、预算和建设顺序；面对目标冲突，向市长说明具体方案及代价。

团队编制随需求与财政发展：小镇少人兼任，富裕小城也能扩充专家。人数增加带来专业覆盖和分析工作量，不自动增加模型并发或保证方案正确。

市民定期选出议会代表，代表对法案与预算一席一票表决；市长和City Team依法行政，独立司法依据证据处理程序、越权与补偿争议。市民通过选举、群体诉求、听证和申诉影响城市；议会许可、玩家授权和实际资金分别校验。

通过 TekesAgentKit 接入 agent 会话与执行状态；MyCity 提供城市查询、规划、预演和提交工具。人口、交通、环境和市场仍由独立模拟核心运行。

## 六项核心需求

1. 支持玩家自行搜索、下载并导入灰度高度图；后续支持应用内按地名或范围检索真实高程数据。
2. 支持 macOS 全屏与高分辨率显示；首版采用等距 2.5D 表现，完整自由三维视角为可选扩展。
3. 道路支持连续曲线；水、电等市政管线可以随道路铺设、升级和管理。
4. 模拟侧重不同区域的人口互动与承载上限；交通后果是模型第一优先级。
5. 格子和城市分区之间相互影响，污染、通勤、货运和公共服务不因行政边界而停止。
6. 城市分区之间的商品交易由市场自动进行，市长的商业负责人依据政策执行采购和销售。

建筑建设和拆除都按真实尺度的游戏日历推进；玩家调节日历速度，工程仍受阶段、实际投入和养护限制。施工／拆除的占道、运输、空气污染和噪声都纳入后果。

公共服务也支持共享：小地图或分区可购买邻区医疗、警务、消防能力，受容量、路网和响应时间限制，通过市政协议结算；无需每个地区都自建全部设施。

## 首个可玩版本

选择一张 2.048 km 中地图，在其中设置至少两个相邻行政／经济分区，完成高度图导入、曲线道路、住宅／商业／工业、供水供电、燃煤电厂和自动商品交易。最小运营闭环同时考虑生活垃圾处理与关键设施维护，能力未实现时须明确标记。

玩家通过向 City Team 发出命令完成建设和政策调整，并能够观察到修路改善通勤，工业发展增加货运，拥堵反过来影响就业与供应，电厂污染影响邻区住宅，商业负责人随运输成本调整采购来源。

## 当前边界

- macOS 为首个目标平台，其他平台暂不承诺验收。
- 首版不做逐人逐车完整模拟；人口按群体、交通按汇总流量计算，市民与车辆采用受模型约束的采样动画。
- 以 16 GB 统一内存为基础目标，一次详细运行一张地图；已连接邻城按摘要在统一时钟下参与供给、公共服务、贸易和交通。
- 三档地图使用相同格子格式：小 64×64、中 128×128、大 256×256；默认中地图，大地图待测。
- 铁路、公交、自由三维相机、复杂产业链、多玩家与模组在后续评估。
- 不以完整复刻原游戏内容为首版目标；代码、美术、声音与界面独立制作。
